## 现行工具

### `internal-reverse-proxy.js` —— 内网系统访问通道

**用途**：为蒸馏取证打开内网系统的访问通道。

**什么时候需要它**：目标系统位于内网，且内置浏览器**直连打不开**时。典型症状是
`ERR_CERT_AUTHORITY_INVALID` —— 内网多用自建 CA 签发的证书，内置浏览器不信任，
而内嵌 Chromium **不像完整 Chrome 那样提供"继续前往"入口**，导致无手动放行的机会。

**原理三步**：

| # | 机制 | 解决的问题 |
| :---: | :--- | :--- |
| ① | 忽略上游证书校验（`rejectUnauthorized: false`） | 绕开自建 CA 的信任链问题 |
| ② | 以纯 HTTP 暴露在 `127.0.0.1:<PORT>` | 本地回环 + 明文 HTTP，不存在证书校验环节 |
| ③ | 改写响应内容（URL 重写 + `WEB_HTTPS` 中和） | 否则前端会自行跳回 `https://<内网>`，再次失败 |

第 ③ 步同时处理了 `location` / `origin` / `referer` / `Set-Cookie` 的 `Domain` 与 `Secure`，
并转发 WebSocket 升级（SPA 的长连接依赖它）。

**用法（每次三步）**：

```bash
# ① 起代理（TARGET 与 PORT 均为必传，PORT 需独占）
TARGET=<内网地址> PORT=<独占端口> node tools/internal-reverse-proxy.js

# ② 在浏览器打开本地地址（而不是原内网地址）
#    http://127.0.0.1:<独占端口>/<路径>

# ③ 需要登录则交给规划人员手动登录 ➜ 取证 ➜ 用毕停止进程
```

**已知坑**：

| 坑 | 说明 |
| :--- | :--- |
| **端口必须独占** | 一个目标一个端口，**绝不复用**（复用会串台，指向错误的目标系统） |
| **TARGET 无默认值** | 脚本是通用工具，不内置任何内网地址，必须显式传参 |
| **仅支持 HTTPS 上游** | 若目标本身是 http，需改用 `http.request` 微调 |
| **脚本位置** | 本脚本已从临时目录固化入库，请统一使用本路径，不要再复制到 `/tmp` |

> ⚠️ **合规声明**：本脚本会**关闭 TLS 证书校验**，仅用于**自有内网系统的设计蒸馏取证**，
> 请勿用于第三方系统。
>
> 📌 **内网地址不入库**：使用说明中的地址一律以 `<内网地址>` 占位，真实地址由规划人员本地留存。
