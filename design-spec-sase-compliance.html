一、需求洞察与体验目标

1. 目标用户与核心任务 (JTBD)

  • 企业安全运维管理员 (SecOps · 最高频)
    • 使用情境：日常面对 2,000 ~ 50,000 台分布在不同部门、不同操作系统的终端；下发策略时最怕规则写错导致全公司电脑报障，等待巡检结果时最怕"黑盒挂死"，排障时最怕被强制跳页打断上下文。
    • 核心任务：“我要按部门或标签一键装配必装基线与违规黑名单规则并下发巡检，在下发前就知道会影响多少台机器，巡检时随时看到跑到哪一步，查出问题能原地定位根因、原地完成处置。”
  • 安全合规负责人 (CISO / 审计员)
    • 使用情境：不关心某一条底层流水日志，面临等保 2.0 内审外审与向上汇报压力，需要随时量化全员合规率与整改进度。
    • 核心任务：“我要一屏掌握全员合规率大盘与整改推进趋势，并能一键导出满足等保审计规范的整改台账，证明违规终端均已受控处置。”

3. 核心体验改进目标

  • 1. 规则装配：从"手工填底层参数"到"预置库勾选 + 目标范围即时测算" —— 单任务规则配置耗时由约 30 分钟降至约 3 分钟，规则复用率与配置准确率显著提升，下发前即可知覆盖台数与在线/离线分布。
  • 2. 执行监控：从"黑盒等待"到"三态进度可视 + 运行中加锁" —— 管理员 3 秒内掌握"已检测 / 合规 / 违规 / 离线跳过"四态计数与总进度，无需手动刷新；单台离线终端不再卡死全局任务。
  • 3. 结果排障：从"跳页翻日志"到"原地抽屉体检单" —— 单台终端从"缺哪些必装、中了哪些黑名单"到发起处置，全程不离开结果页，排查动线由 5 步以上降至 2 步（看结果 ➔ 开抽屉）。
  • 4. 闭环处置：从"线下催办"到"线上双通道 + 等保台账一键导出" —— 违规终端可一键弱提醒或联动零信任隔离，并可登记合规例外；整改台账一键导出，直接支撑等保内审外审。

二、设计思考、标杆 Job 匹配与经验采纳

1. 需求类型分析 (四子弹定局)

  • 需求类型定性：Type-07 检测任务与批量巡检类（对照 2.2 标杆案例库门户前置类型定性）。
  • 业务属性与严肃度：安全合规属高危严肃业务，一次规则误配可能导致全公司终端报障或漏检，因此界面以"稳、准、可回滚"为第一原则，克制稳重，严防误操作。
  • 色彩基调：基底底色 #F7F9FC，去框线化；状态一律用"浅底 + 深字 + 浅边框"三元组点染，危险操作收进更多菜单 + 二次确认，全系统仅品牌蓝主按钮与描边普通按钮。
  • 页面职责分工：首页只管「任务」大盘调度与执行态；结果页才看「终端 / 规则」聚合明细；抽屉看单台终端体检单；规则模板资产库管跨任务复用的规则装配。一句话：首页管任务、结果管聚合、抽屉管单机、资产库管规则复用。

五、页面体验与异常保护规则

  • 🛑 状态覆盖完备性：任务状态覆盖 WAITING / RUNNING / COMPLETED / PARTIAL_FAILED / TERMINATED；终端结果覆盖四态 已合规 / 违规 / 检测异常 FAILED / 离线跳过；处置状态覆盖 待整改 → 已提醒 → 已隔离 → 已例外。运行中（非终态）一律锁定编辑 / 重跑 / 删除 / 改名。
  • 🛑 加载态与空状态：列表与详情首次加载使用 IxSkeleton，局部操作使用 IxSpin；空数据必须保留工具栏与筛选条件，仅在数据区展示 IxEmpty，避免"页面坏了"的错觉。
  • 🛑 高危破坏性操作防呆：删除任务、删除规则模板、强管控隔离必须二次确认；删除类操作须用 IxPopconfirm / IxModal 原样回显对象全名或影响台数；覆盖性操作（若有）必须显式警告数据丢失代价。
  • 🎨 按钮用色铁律（核心安全带）：全系统只有品牌蓝主按钮（#1C6EFF）与描边普通按钮，绝对禁止红色实心按钮；危险操作收纳进更多下拉菜单，通过二次确认承载。
  • 🛑 离线与超时保护：单台终端离线或未响应超 10 分钟自动标记"离线跳过，待下次开机补检"，防止单台设备卡死全局任务；失败原因就地 Hover 展示，严禁跳出大弹窗。
  • 🛑 客户端文案人性化：向终端员工弹出的整改提醒必须是大白话（如"您的电脑缺少公司必备安全软件【DLP 数据防泄密】，请点击链接快速安装"），严禁出现底层报错代码。
  • 🛑 批量动作安全带：未勾选行时批量按钮必须置灰禁用（#EDF1F7 / #BEC3CC），勾选后激活并回显"已选 N 项"；批量处置前二次确认并回显影响台数。
  • 🛑 就地闭环与不打断：单机排障一律用右侧抽屉，看完即走保留列表游标与筛选；切换历史轮次后明细平滑刷新，不整页重载、不丢筛选条件。
