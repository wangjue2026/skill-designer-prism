一、需求洞察与体验目标

1. 目标用户角色与本质任务 (JTBD)

  • 企业安全运维管理员 (SecOps - 最高频主战角色)：
    • 使用情境与心智：求稳、防背锅、怕误杀、怕盲盒；日常负责全公司 2,000~50,000 台混合办公 PC 的安全基线管控，需要管理多个周期的巡检任务，最怕规则配错导致全员报障，最怕巡检耗时数小时不知道卡在何处。
    • 核心用户本质任务 (JTBD)：“我需要能以『任务』为载体，按部门或标签一键装配规则并发起巡检；任务完成后，我能顺着该任务的历史结果，在不跳页的情况下定位违规终端与违规进程，并完成批量处置闭环。”
  • 企业安全合规负责人 (CISO / 审计员)：
    • 核心用户本质任务 (JTBD)：“我需要宏观掌握每个合规巡检任务的合规达标趋势，能一键导出满足《等保 2.0》规范的合规证明报告，确保高危终端均已进入受控闭环。”

3. 务实体验目标（A ➔ B 对比跨越与量化度量）

  • 体验目标 1（任务配置效率与确定性 · 翻转 🚩 S1-P1）： 通过提供【必装+黑名单】预置规则勾选库与部门树即时测算 ➔ 用户由手工拼写参数变为 3 步勾选 ➔ 彻底解决配置易错与盲盒心理 ➔ 任务装配耗时从 30 分钟 ➔ ≤ 30 秒，覆盖终端大数秒级透明可见。
  • 体验目标 2（任务执行监控确定性 · 翻转 🚩 S2-P2）： 通过三态机进度控制（达标/违规/跳过）与 10min 超时自动熔断 ➔ 任务卡片实时反馈进度 ➔ 消除长时间未知等待的焦虑 ➔ 任务进度从“黑盒死信挂起” ➔ “三态进度秒级可见，离线超时 100% 自动跳过”。
  • 体验目标 3（任务结果排障与处置闭环 · 翻转 🚩 S3-P3 / S4-P4）： 通过专属任务结果明细页、In-situ 原地抽屉体检单与 SASE 零信任动态隔离联动 ➔ 用户在当前任务下直接定界违规项并一键发起阻断 ➔ 消除跳页断流与线下催办脱节 ➔ 排障跳页 6 次 ➔ 0 跳页原地闭环，高危终端处置响应从天级 ➔ 秒级联动阻断。

二、设计思考、发力点与标杆经验选型

1. 业务属性与严肃程度定性 (定“度”，不定“向”)

  • 业务属性与严肃度：企业安全管控与合规巡检 / 极高严肃度 (Mission-Critical)。高危阻断直接影响员工能否正常接入公司网络，交互必须极度克制、理性且具备严密防呆。
  • 色彩基调与视觉风格：深沉克制 / 石墨冷灰底色 (`#F7F9FC`)，全面去框线化，仅高危违规状态启用柔和红色（`#FEF2F2` 浅底 + `#D9363E` 深字三元组），确保操作专注且无色彩噪音。

2. 核心设计思考与发力点提炼 (源自 2.1 思考模型)

💡 设计思考中枢：在深入标杆案例库前，先思考**本次需求的重要设计点在哪儿、核心矛盾是什么**，从而明确在向标杆案例库学习时**重点汲取哪些机制与组件样式，有所侧重地进行经验装配**，拒绝漫无目的堆砌。
  • 核心业务矛盾穿透：本次合规检测的核心矛盾是以「任务」为主键的多轮作业调度与归档管理，与作业执行后针对「单台受检终端」的精准排障处置之间的层级映射断层。主界面管任务，详情页查终端，边界绝不能混淆。
核心设计发力点 (L1 方向) 来源场景 / 痛点旗帜 体验维度 标杆案例学习侧重点 (向标杆找什么) 期望达成的 A ➔ B 体验跨越
发力点 1：让任务台账清晰承载长字段与成对指标，新建轻量且影响面可预知 S1 / 🚩 S1-P1 防呆确定性 / 稳 重点学习 XDR/SASE 的单列任务卡片流 (EP-01)、抽屉新建 (EP-03) 与即时测算 (EP-04) 横向大表撑爆 15 列 ➔ 单列卡片流阅读边界独立；任务覆盖终端数即时可见

发力点 3：让任务多次执行具备时光机回溯，违规终端原地排障定界闭环 S3, S4 / 🚩 S3-P3, 🚩 S4-P4 最简闭环 / 信任感 重点学习 XDR 父任务历史下拉 (EP-08)、In-situ 终端抽屉排障 (EP-09) 与零信任联动 (EP-10) 复测刷屏冲垮列表 ➔ 一卡一任务族历史下拉；受检终端体检单抽屉秒级定界与动态阻断

3. 选定专家范式与系统机制 (L2 承载机制)

  • 专家范式选型：P-07 全生命周期巡检与合规 + P-05 多维下钻联动排障
  • 元设计机制：
    • 单列任务卡片流编排机制（解决任务字段长短不一、成对指标展示痛点）；
    • 多轮执行时光机聚合模型（以父任务为台账条目，详情页无边框下拉切换历史执行轮次）；
    • In-situ 原地抽屉双轴排障单元（左侧必装核对 + 右侧违规进程证据链）；
    • 零信任策略动态隔离联动通道（调用安全网关 API 将违规终端置入隔离组）。

EP-07 头部一句话大结论定性 SASE 【体验推荐】 承载发力点 3：进入任务结果页，头部直接给出结论（检测已完成，发现 160 台终端存在基线违规），比单纯堆砌数字更直观。

EP-09 抽屉就地排查与批量置灰 SASE / aES 【首选基线】 承载发力点 3：在任务结果表中点击单台终端，右侧滑出 800px 抽屉排查证据链，主表格不跳页；未选行时批量处置按钮置灰禁用而非隐藏。
EP-10 任务名原样回显防呆与分级处置 SASE / XDR 【首选基线】 承载发力点 3：删除任务时 Popconfirm 必须回显任务全名；弱提醒弹窗引导自愈，高危违规联动 SASE 零信任动态阻断内网访问。

六、页面体验与异常保护规则

  • 🛑 长耗时心跳防死信 (EP-06 机制延伸)： 针对离线或弱网终端超过 10 分钟未回传心跳，任务状态机自动将其归类为 离线跳过 (OFFLINE_SKIPPED)，并记录在案，严禁因单机离线阻塞全局巡检进度。
  • 🛑 In-situ 上下文视线锚定： 排障抽屉关闭或隔离完成后，底层任务结果明细表自动高亮保留在原先选中的终端行，绝不重置滚动条位置、不重置分页码、不重置已选筛选条件。
  • 🛑 高危操作二次防呆防线： 对【联动零信任动态隔离】与【终止巡检任务】强制挂载 IxModal / IxPopconfirm 二次确认，并用通俗自然语言告知业务影响面，严禁技术黑话。
  • 🛑 客户端文案人性化大白话： 下发给员工的弹窗文案强制采用自然语言：“您的电脑缺少必备安全软件【DLP数据防泄密】，请点击链接快速安装”，严禁向员工弹出底层十六进制报错代码（如 `Error 0x800401`）。
  • 🛑 四重防破坏安全带： 严格遵循 SASE 外层响应式框架约束，严禁破坏导航栏、严禁修改 API 绑定的实体字段名、严禁将组件行高脱离 8px 网格规范。
