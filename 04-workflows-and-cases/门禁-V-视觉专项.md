## 1. 定位（三禁分工）

| 门禁 | 回答什么 | 不回答什么 |
| :--- | :--- | :--- |
| 结构门禁（EX） | 东西在不在、位置对不对、能力项有没有丢 | 好不好看、等不等高 |
| 数据门禁（SP-C/D） | 数字对不对、口径通不通、`0` 与缺失怎么表示 | 视觉秩序 |
| **视觉门禁（V）** | **看得见的质量**：秩序 / 间距 / 排版 / 色彩语义 / 组件状态 / 图表编码 / 控件摆放 | 功能有没有、数字真不真 |

1. **只管下限与硬指标**，不管上限与风格（2026-11-19 裁定）。
2. **每条必须落到一个可指认的元素或一个可测数值**；出现"清晰 / 合理 / 有质感"即无效。
3. **取值不在这里**，一律引 `03-design-assets/`；出处见 §9。

### 3.1 九条两段必检：草图判什么、说明书画什么

> 立这一节的原因：这九条曾被整批裁进 `SKETCH_SKIP`，而没裁的条目又靠"目标集为空 → 输出 ✅"混过去。实测一份 40 页草图，10 条应判项里 **真正判到东西的是 0 条**——绿是空集的绿，不是合格的绿。

**三条硬约束（脚本已实现）**

1. **空集不许报绿**：找不到判定对象时输出 `⚠️ ...未判定（不是通过）`，回执按未完成项登记。
2. **同因只报一次**：40 页副本会把同一缺陷刷几十行，一律折成"根因（N 处）"，超过 4~6 类折叠成"…另 N 类未展开"。
3. **缺钩子算 FAIL，不算待核**：`data-region` / `data-act` 缺失时归属与分区根本无法判定，这是产物的问题，不是环境的问题，直接 FAIL。

## 4. 逐条详解（4 块：判据 / 怎么判 / 自测 / 常见错误）

> **本节按说明书档写。** 九条两段必检项（`V-04/05/06/07/09/10/14/23/25`）在草图档的判法与降级口径见 **§3.1**，两者冲突以 §3.1 为准。

### V-01 唯一 Container 与左基线

#### ① 判据

- **PASS**：页面只有一个内容容器；其左边界 = 单侧页边距 **M**：默认 **24px**，**≥1720 屏 48px**；页头、筛选条、主图、列表、分页左边界与 M 偏差 ≤1px；**不设全局 max-width**（内容铺满，不居中留白）。
- **FAIL**：出现第二个内容容器；某区左边界偏移 >1px；任何屏宽用 16px。
- **输出**：`❌ V-01  P3 列表  左边界 32 / M 24（差 8px）`

#### ② 怎么判

```text
M = (viewport >= 1720) ? 48 : 24
roots = 主内容容器（排除 position:fixed、全宽横幅、侧栏）
if roots.length > 1: FAIL("多个内容容器", lefts)
C = roots[0].getBoundingClientRect().left
if |C - M| > 1: FAIL("Container 边距不符", C, M)
for sec in [页头, 筛选条, 主图, 列表, 分页]:
    if |sec.left - C| > 1: FAIL(区, sec.left, C)
if viewport < 1280: 记 ⚠️（出横向滚动属规范内，仍按 M=24 判）
```

- 全宽横幅与 `position:fixed` 不计入；页头本身也有 `padding-inline:24px`，**不享受"满宽例外"**。
- 屏宽以 CDP 实际视口为准，不按代码写死值。
- **实现口径（v0.6.8）**：夹具可在 `<html data-viewport-width="1760">` 覆盖视口；根容器左边界取 `rect.x + paddingLeft`，并读取 `data-page-root` / `data-page-section`（无钩子时回退 `main` / `.content` 与常见区类名）。检测到多个根、全局 `max-width`、任一区左漂 >1px 即 FAIL；窄屏 <1280 只 WARN。草图阶段不执行。

### V-02 块落 24 栅格列线

#### ① 判据

- **PASS**：一级块左右边缘落在 **24 栅格列线**上（±1px）；gutter ∈ `{8,16,24,32}` 且**同一 Row 组内唯一**；两栏 span ∈ `{12:12, 16:8, 18:6, 20:4, 21:3}`，三栏 ∈ `{8:8:8, 6:6:12, 4:8:12, 6:8:10}`；其他整数组合须标 `data-span` 并注明"自定义比例"。
- **FAIL**：边缘不落任何列线；gutter 出现 12 / 20；三等分写 `width:33.3%`。
- **输出**：`❌ V-02  P2 第 3 块  右边界 1173（距最近列线 5px）  gutter=12`

#### ② 怎么判

```text
M = (viewport >= 1720) ? 48 : 24
G = 该 Row 组唯一的 gap，必须 ∈ {8,16,24,32}
W = 屏宽 - 2*M;  colW = (W - 23*G) / 24
x_k = M + k*(colW + G), k = 0..24
for blk in 一级块:
    d = min(|left - x_k|, |right - x_k|)
    if d > 1: FAIL(位置, "边缘不落列线", left/right, d)
span：读 data-span（1..24 整数），和须 = 24
   不在白名单 且 无"自定义比例"标注 → FAIL
if viewport < 1280: 只记 ⚠️
```

- **列线是计算值**：1366 屏下 `colW` 是小数，不许按整数 8px 网格判。
- gutter 按**区域**判，不按全页：卡片墙 16、Dashboard 24、大屏 32 都合法。
- `flex:1` 均分不可判宽 → 一律要求 `data-span`。
- **实现口径（v0.6.8）**：读 `[data-grid-row] > *` 的 `data-span` / `data-custom-span`；左列线 `M+k*(colW+G)`、右列线 `M+k*colW+(k-1)*G`（k=1..24），边缘容差 ±1px；gutter 取 Row 的 `column-gap`，同行多段 gap 不一致也 FAIL。span 白名单按降序归一比较；非白名单须整行标 `data-custom-span` 且和 = 24。草图阶段不执行。

#### ③ 自测

```bash
node tools/visual-audit.js tools/fixtures/visual/v-02-bad.html --profile=wireframe
# 期望：❌ V-02  P1 第 2 块  右边界 1173（距最近列线 5px）  gutter=12    退出码 1
```

#### ④ 常见错误

| # | 长什么样 | 为什么错 |
| :--: | :--- | :--- |
| 1 | 三等分用 `width:33.3%` | 边缘不落 24 列线（应用 span=8） |
| 2 | 水槽用 12 / 20，或同一 Row 内不一致 | 资产只给 8/16/24/32 |
| 3 | 两栏写成 6:4 | 对不上 24 整数比（应为 16:8） |
| 4 | 用 `flex:1` 平均分配 | 宽度不可预测，边缘随内容漂移 |
| 5 | ≥1720 大屏仍用 24 边距 | 该断点 M 应为 48 |

### V-03 容器嵌套克制

```text
VISIBLE = el => borderW>0 || bg !== 'transparent' || boxShadow !== 'none'
```

- **与父容器同色**的背景不新增一层（避免整页底色被算成框）。

### V-04 通栏克制

#### ① 判据

- **PASS**：通栏块（实测宽度 ≥ 内容宽 90%）的形态是 `topo / sankey / mx / scatter / tl`（**mx 含热力矩阵、tl 含甘特时间轴**），或**时间序列数据点 ≥12** 的折线/面积图，或它**不含图形载体**且属于 KPI 条。
- **`geo`（地图）暂不启用**：`EX-1.4-39` 的 `data-viz-kind` 未收录，两边同改前按普通图表判（可 ⚠️ 待核）。
- **FAIL**：通栏块里是柱 / 饼 / 词云 / 排名摘要 / 分布图（且不属于上述出口）。
- **输出**：`❌ V-04  P7 第 2 块  实测 1176/1176  kind=bar`

#### ② 怎么判

```text
W = 内容容器 clientWidth（CDP 渲染后取）
for blk in querySelectorAll('[data-viz]'):
    r = blk 宽 / W
    if r < 0.85: 放过
    if 0.85 <= r < 0.9: ⚠️ 待核；continue
    kind = data-viz-kind || 按载体推断
    if kind in {topo,sankey,mx,scatter,tl}: 放过   # mx=热力, tl=甘特；geo 待两边收录
    if kind in {line,area} && 数据点 >= 12: 放过
    if 块内无图形载体 && 祖先含 [data-kpi-strip]: 放过
    FAIL(位置, kind, r)
```

- 宽度取渲染 bbox，**不信任 `data-viz-w`**；不符 → FAIL 并标"声明不实"。
- 无 `data-viz` 的装饰图不判。
- **实现口径（v0.6.7）**：有 metrics 时按 `vizs[i].ratio` 判；无 9222 时按 `width` / `data-viz-w` 声明静态近似，宽度未知只报 ⚠️ 待核。形态沿用 `data-viz-kind`（`topo/sankey/mx/scatter/tl` 白名单、line/area 需 `data-points>=12`、KPI 条须无图形载体）；`geo` 只 ⚠️ 待核。草图阶段不执行。

### V-05 容器撑满与留白

#### ① 判据

- **PASS**：按块型分两档 ——
  - **内容块**（含表格/图表/卡片组）：内容宽 ≥ 容器宽 **80%**，内容高 ≥ 容器高 **60%**；
  - **宽扁块**（KPI 条/筛选条/提示条，块高 **≤72px**）：不判高比，只判单侧空白 ≤ 容器宽 20%。
- 任一块单侧连续空白 > 容器宽 **25%** → FAIL；内容底边距容器底 > 容器高 30% → FAIL。
- **输出**：`❌ V-05  P1 接入卡  内容高 96/168（57%）  右侧空白 420（36%）`

> 🛑 只判"容器不要空着"，**不判"该不该有更多内容"**（补内容属结构门禁）。
>
> ⚖️ **边界（与 `visual-styles/内容件/件型线框.md` §6.10「宁可留白，也不要用元素填满」不冲突）**：该条禁的是**往卡里塞无意义的装饰块 / 无名图标串 / 读不懂的胶囊**；本条禁的是**把容器做得比内容大**（凭空 `min-height`、四卡等高却内容两行）。一句话：**容器尺寸由内容决定**——既不许放大容器，也不许为了填满塞水货。两条同时成立。

#### ② 怎么判

```text
for sec in 一级区块:
    box, inner = bbox
    if box.height <= 72:                      # 宽扁块
        if (box.right - inner.right) / box.width > .20: FAIL(位置, "右侧空白", 比例)
        continue
    if inner.width/box.width < .80 || inner.height/box.height < .60:
        FAIL(位置, 内容宽比, 内容高比)
    if max(单侧连续空白) / box.width > .25: FAIL(位置, "单侧空白", 比例)
    if (box.bottom - inner.bottom) / box.height > .30: FAIL(位置, "下方空白")
兜底：可见子元素 <3 且无表格/图表 → 只输出 ⚠️ 待核
```

- 宽扁块自动进第二档（按块高判断，不靠类名）。
- 空白取"连续空白"，中间夹字不算。

### V-06 工具栏布局（左按钮区 / 右查询区）

#### ① 判据

### V-23 指标组容器与层级

#### ① 判据

- **PASS**：≥3 个并列统计数字位于概览 KPI 区 `wf-kpi--strip`，且**不得作为 `data-hero` 主图**；每个数字在独立单元容器 `wf-kpi-item` 内；单元含 label 与 value，且 value 字号 ≥ label ×**1.4**，或 value 字重 ≥600 而 label ≤400（**全组取同一条**）。

#### ② 怎么判

```text
for row in .wf-kpi--strip:

```

### V-24 同构对象操作位置一致

#### ① 判据

- **PASS**：同一列表内同类卡片，主操作**位置与顺序**一致；组内出现"无主操作"卡片时，其余卡片**操作槽位不变**（无操作卡保留占位）。

```text
for g in 按卡片 class 分组的组:

```

### V-25 行内标签纵向对齐

#### ① 判据

- **PASS**：同一语义标签占**固定槽位**：同类 left 极差 ≤2px **且槽宽差 ≤4px**；**槽位之后元素 x 坐标极差 ≤2px**；行尾数值右对齐且右缘极差 ≤2px。
- **FAIL**：徽标参差；宽度随文案变化导致后续元素位移。
- **静态可判部分（机检）**：数值列（单元格纯数值 ≥80%）必须 `text-align:right`；各行标签槽位的 class 序列必须一致（数量/类型不同即 FAIL）。

```text
for 标签类 in [级别, 风险, 状态]:

    if max(lefts)-min(lefts) > 2: FAIL(类, 极差, 明细)

    后续元素 x 极差 > 2 → FAIL("被标签顶动")
数值列：right 极差 > 2 → FAIL
```

- 无 `data-tag` 时按"同一列第 n 个标签"分组，**不按颜色聚类**。

### V-27 承载空间与信息量

#### ① 判据

- **PASS**：`[data-hero]`（**与 `EX-1.4-22` 同一属性，不新建**）内的主图有 **1 个共享承载空间**（同一轴 / 网格 / 堆叠条 / 节点-边画布 / 时间轴），且**数据单元 ≥3、真实数字 ≥2、数字/单元 ≥0.8**。
- **FAIL**：N 张卡片各 1 个数；有载体无数字；数字全在下方表格；hero 内放 KPI 卡。
- **输出**：`❌ V-27  P5 主图  载体 0 / 数字 4（未落在同一载体上）`

> `[data-kpi-strip]` 不受本条约束（归 `V-23`）；**认不出载体时只报 ⚠️ 待核，不判死**。

#### ② 怎么判（v0.6.6 实现口径）

> **认不出载体不判死**：命中 `.grid` / `.canvas` 这类**布局类**但内部无柱 / 格 / 节点（可指认数据单元）时，输出 `⚠️ 待核`，不 FAIL——否则历史草图会被误伤（实测已修）。`[data-kpi-strip]` 不计入单元；用例覆盖「同一轴 4 单元 / 横向链路 3 节点 / hero 内卡片墙」。

```text
hero = querySelector('[data-hero]')
if !hero: ⚠️ 未声明主图，跳过
carriers = hero 内 .canvas/.axis/.grid/.stack/.chain/.rank/.tl/.topo 或 svg[data-carrier]
if carriers.length == 0: ⚠️ 待核（可能是类名不同，不判死）
units = carrier 内可指认的数据单元（柱/段/格/节点/刻度）
nums  = carrier 内可解析数字文本（去重，排除序号/页码）
PASS ⟺ units >= 3 且 nums >= 2 且 nums/units >= 0.8
卡片墙排除：hero 内兄弟块 >=3 且各自 <30% hero 宽 → FAIL("卡片墙")
```

- 排行榜 / 步骤条算合法载体；`[data-kpi-strip]` 不算。
- 数字与单元必须落在同一 carrier 上。

```bash

```

## 7. 执行与门槛

| 手段 | 能判 | 不能判 | 什么时候跑 |
| :--- | :--- | :--- | :--- |
| 机检（DOM） | 类名/属性、token 用法、字号间距集合、按钮计数、色值白名单、动作分区、圆角阴影值 | 渲染后比例、重叠、可读性 | 提交前自动 |
| **量测（CDP bbox）** | 实际宽高、左基线、面积比、留白率、标签对齐、溢出 | 美观、信息价值 | 判宽/面积/对齐的条目必跑 |
| 走查 | 容器层级（兜底）、灰度可辨、六态图形与动作、形态关系、正文行长、标签槽位几何 | 可量化一致性（未接量测的那半） | 交付前一次 |

**量测怎么跑**：`tools/visual-measure.js` 连本机 Chrome（`--remote-debugging-port=9222`）取渲染 bbox，1440 视口。**会话复用**：所有调用共用一个带 `#prism-visual-audit-session` 锚点的标签页，只 `Page.navigate` 换 URL、不新建 / 不关闭标签页（避免批量过门禁时闪屏）；整批跑完后执行一次 `node tools/visual-measure.js --close` 关闭。`visual-audit.js` 调用它，`gate-ex.sh` / `gate-sp.sh` 无需额外参数。
**怎么开端口**（macOS，独立配置目录，不动日常浏览器）：
```bash
open -na "Google Chrome" --args --remote-debugging-port=9222 --user-data-dir=/tmp/chrome-prism-audit
curl -s http://127.0.0.1:9222/json/version | head -3   # 有 Browser 字段即通
```
**观察期（2026-11-26 ~ 2026-12-10）**：`V-05` 留白与 `V-24` 坐标是**新增量测部分**（不是新判据），期间只输出 `⚠️` 计数、**不阻断**；静态部分（`V-24` 顺序）照旧 FAIL。到日期自动转 FAIL；若误伤清单提前为空，用 `--measure-fail` 提前收口。自测不受观察期影响，bad 仍必红。
**连不上时**：该条输出 `⚠️ 未量测`，**不计通过**，回执"未完成项"里列明。
**背景不可解析时**（图片 / 渐变 / 半透明）：`⚠️ 未量测`，同样不计通过。

**门槛（二元）**

- **一条 FAIL 即整体不通过**，改到全绿才准出；没有严重程度可讨价还价。
- **"轻微"不进清单**：要么写成可判条目并硬拦，要么不写。
- `⚠️ 未量测` / `⚠️ 待核` **不进 FAIL、不阻断退出码**（实测：`report()` 只按 `!ok` 计失败），但**既不算通过，也不算已检视**：必须在回执"未完成项"里逐条点名，且**不得宣称"视觉已全量检视"**。拿 ⚠️ 当绿灯汇报 = 越界声明（见下方 🛑）。
- 想让它真的拦：开 9222 后重跑，或用 `--measure-fail` 把观察期条目提前转 FAIL。
- **`--profile=sketch` 的 10 条成品精度项**输出 `⚠️ 草图阶段不判`：不计通过、也不阻断（它们不是"未通过"，是"不适用"）；该阶段实跑 17 条，其中九条必检项的草图判法见 §3.1。
- **走查部分以回执勾选为准**：`V-17` 的灰度复核、`V-22` 的"每态有图形与动作"、`V-26` 无 `data-rel` 时的关系判断，都走勾选。回执没勾 = 未通过，它们不进机检退出码。

> 🛑 **禁止越界声明**：只跑机检就说"视觉已检视" = 未检视；无渲染环境须写明"仅完成静态检视"。
