# 改动检视协议（项目级 · 强制执行）

> **用途**：本项目内**任何对公共内容与公共逻辑的修改**，改之前必须过本协议，改之后必须留声明。
> **治的病**：头疼医头、特例问题特例修复、修完长出更多衍生问题。
> **不治的病**：具体设计好不好——那是 1.x/4.x/5.0 的事，本协议只管"改动是否在系统全局成立"。
> **状态**：协议本体已立；**挂载点（第十节）待确认，未挂载前不生效**。
> **最后更新**：2026-11-12

---

## 一、三条公理（一切判定的来源，不许再派生第四条）

### 公理 1：层级公理
任何改动只可能落在四层之一，**说错层就会把特例写成通则**：

| 层 | 定义 | 判定问句 | 语气权限 |
| :--- | :--- | :--- | :--- |
| **L0 不变量** | 换业务、换需求类型、换页面都成立 | "换一组数据、换一个 Type，还成立吗？" | 可以说"必须" |
| **L1 维度** | 可用来比较两个产物高低的度量轴 | "能用它给两个页面排序吗？" | 可以说"必须"，但要说明度量方式 |
| **L2 投影** | 某类需求 / 某类页面下的取值与做法 | "它有没有适用范围？" | **必须带适用范围**，不许写"必须" |
| **L3 实现** | 具体文件怎么写、哪个字段、哪行代码 | "换个人实现，还会这么写吗？" | 只是做法，不许上升为规范 |

> 🛑 **最高频错误**：把 L2 投影写成 L0 不变量的语气。判据：**这条改动如果只在某类需求成立，却写成"全部必须"，即为越层，直接退回。**

### 公理 2：半径公理
**被 ≥2 个文件 / 流程 / 门禁引用 = 公共。** 改公共必须走完整检视并列出全部引用点；改 `_output/` 下的案例产物不算公共，不需要检视。

### 公理 3：熵公理
规则是**组合关系，不是叠加关系**：N 条规则有 N² 组交接面。
**每次改动都必须回答"为了容纳它，删掉 / 合并了什么"。** 只加不减的改动，长期必然把系统压成"合规式平庸"。

## 二、改动前：四问（缺一问不许动手）

| # | 问题 | 不合格的答案 |
| :---: | :--- | :--- |
| **1 层级** | 这条落在 L0/L1/L2/L3 哪层？ | "就是个补充""按规范来" |
| **2 半径** | 它是公共还是局部？公共的话，引用点清单在哪？ | 只写"影响 5.0"，不列被 5.0 引用的门禁与工具 |
| **3 例外** | 把它放到 **≥3 个不同类型的既有产物** 上，是否需要新增例外？ | 只在一个案例上验证过 |
| **4 熵** | 规则 +? / 门禁 +? / 例外 +?，以及**被它替代或合并的是什么** | 三项全为正且说不出替代对象 |

> 🛑 **第 3 问的判据**：如果需要新增例外 → 它不是通则，是特例修复。**要么退回，要么降级为 L2（带适用范围）。**

## 三、改动后：三问（缺一问不许收工）

| # | 问题 | 证据形式 |
| :---: | :--- | :--- |
| **5 冲突面** | 与现存哪几条规则语义重叠或矛盾？逐条列，给裁决（谁让谁） | 冲突清单 + 裁决结果 |
| **6 回归** | ≥3 个**不同类型**的产物复跑，结论是否一致 | 复跑记录（可用既有 `_output/` 案例） |
| **7 可逆** | 改错了要撤回，是否只动一个文件？ | 若需牵动 N 处 → 侵入过深，改为挂载式 |

## 四、判定：三档，不许"差不多"

| 档 | 条件 | 处置 |
| :--- | :--- | :--- |
| **通过** | 四问三问都能正面回答；熵净增 ≤0 或有等价替代 | 直接落 |
| **降级** | L0 语气但实为 L2；或需适用范围；或只有单类型证据 | 改为投影层 + 加适用范围 + 先 `WARN` |
| **拒绝** | 需新增例外 / 三项熵全正且无替代 / 用形容词或拍数字当判据 / 封闭枚举无兜底 | 原地作废，不许"先试试" |

### 4.1 红牌（出现即拒绝，不讨论）

1. **同一类问题第 2 次出现，又提"再加一条检查"** —— 说明上次修在投影层，这次必须回到维度层重构。
2. **用形容词当判据**："要有质感""要克制""信息分层清晰"。
3. **拍数字当判据**：阈值说不出来源的（如"占比 ≥25%"）。
4. **封闭枚举无兜底**：凡"X 选 1"，必须存在"都不匹配"的合法出口。
5. **单案例推导写成全局"必须"**。
6. **只加不减**：新增条款却指不出被替代 / 合并的对象，也证明不了零重叠。

## 五、等价交换原则（反熵的核心）

新增任何一条判定，必须完成下列之一，否则不许入库：

- **替代**：明确废除一条等价的旧规则（给出旧规则编号）；
- **合并**：把两条语义重叠的旧规则并成一条（给出合并后编号）；
- **证明正交**：说清它与现存哪些规则**不共享判定对象**（不是"我觉得不冲突"，是指出各自的判定对象）。

> 判据一句话：**改完之后，规则总数不许比改之前多，除非能证明是"拆分"而非"新增"。**

## 八、三档之外的第四种动作：重构（不要忘记它）

当四问三问里有 2 项以上只能"降级"时，**不许逐个降级**，必须停下来问：
**是不是这一整层的组织方式错了？** 如果是，提"重构"而不是提"改动"——重构豁免本协议的熵公理（允许净减），但必须给迁移路径与回滚边界。

> 这一条是专门留给"31 条铁律、12 条 SP-W"这类存量债务的：**它们的正确处置不是再加一条，而是合并。**
