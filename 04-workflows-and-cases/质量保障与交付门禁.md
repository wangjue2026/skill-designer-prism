# 交付质量与门禁回执（Quality Gates）

> 定位：把「每次输出都严格、都高质量」从愿望变成可执行、可机器拦截的流程。
> 适用：方案系统设计主线（1.1 → 6.0）全部交付物；局部调优主线按 `EX-BC-01~02` 两条执行。
> **口径唯一来源：[`准出门禁总表.md`](准出门禁总表.md)。本文不定义任何新编号**，只讲执行纪律、回执格式与事故留档。
> 一句话：**没有回执不算交付；门禁不过不许汇报；脚本全绿不等于内容合格。**

---

## 一、两道入口（不合并）

| 类 | 编号 | 回答什么 | 什么时候跑 | 命令 |
| :-- | :-- | :-- | :-- | :-- |
| **A · 环节准出** | `EX-<环节>-nn` | 这一环的产物够不够格进下一环 | **每环做完立刻跑** | `bash tools/gate-ex.sh <环节> <产物> [上游文件]` |
| **B · 说明书准出** | `SP-<组>-nn` | 这份说明书能不能交给规划人员确认 | **出稿后跑一次** | `bash tools/gate-sp.sh <spec>` |

```bash
# A 类：逐环
bash tools/gate-ex.sh 1.1 _output/<业务名>/01-主场景-<业务名>.md
bash tools/gate-ex.sh 1.2 _output/<业务名>/02-体验目标-<业务名>.md _output/<业务名>/01-主场景-<业务名>.md
bash tools/gate-ex.sh 1.3 _output/<业务名>/03-突破点-<业务名>.md
bash tools/gate-ex.sh 1.4 _output/<业务名>/草图-<业务名>.html      # 内含 sketch-selfcheck（EX-1.4-04）
bash tools/gate-ex.sh 4.1 _output/<业务名>/草图-<业务名>.html      # 定稿页面清单前，静默跑

# B 类：出稿一次（gate.js sp ＋ design-spec-selfcheck.sh 串行取并）
bash tools/gate-sp.sh _output/<业务名>/design-spec-<业务名>.html
```

> 🛑 **只跑 `design-spec-selfcheck.sh`（11 项）不算过闸门**：它只覆盖 `SP-A` 与 `SP-W` 的机检部分，查不了条数、句式、颗粒度与自包含。这是 2026-10-22 那次事故的直接教训（见第五节）。

---

## 二、执行纪律（六条）

1. **不得跨环合跑**：`gate-sp` 只校验说明书，不校验 1.1~1.4 的产物是否存在；缺哪一环，SP 的 C 组直接判不合格。
2. **每一环只退一步**：EX 不过 → 退回本环重做，不许「带病往下走、最后在说明书里补」。
3. **机检（M）与人检（H）分层**：脚本只做 M 项；H 项以 `⚠️` 输出，交付时逐条人工核。**⚠️ 不是通过，是待核。**
4. **门禁 ≠ 停顿点**：全流程 30+ 条门禁，与人交互的停顿点仍只有 3 个（草图选定 / 说明书确认 / 触红线转轨）。**任何门禁都不得新增一次对话往返**——不过就自己修。
5. **跳过不算通过**：任何「跳过 / 无对应」都必须在回执里写明原因；`SP-D` 六节编码契约**不得跳过**。
6. **改判据必须三处同改**：`准出门禁总表.md` + 对应脚本 + 引用该章节的文档。只改一处即视为口径分叉。

## 三、每环必须落盘（不许「一次糊完」）

> 📁 **统一落在 `_output/<业务名>/` 一个任务文件夹内**（该目录已 gitignore，不进版本库；一任务一子文件夹，草图 / 说明书 / demo / 回测报告同目录，约定见 [`_output/README.md`](../_output/README.md)）。

| 环 | 产物文件 | 缺了会怎样 |
| :-- | :-- | :-- |
| 1.1 | `_output/<业务名>/01-主场景-<业务名>.md` | 目标无处挂靠，只能写口号 |
| 1.2 | `_output/<业务名>/02-体验目标-<业务名>.md`（一场景一条） | 说明书第 3 节只能靠模板猜格式 |
| 1.3 | `_output/<业务名>/03-突破点-<业务名>.md`（三档点子） | 第 4 节变成拍脑袋 |
| 1.4 | `_output/<业务名>/草图-<业务名>.html` + 选定记录 | 方向未定就深化，返工最贵 |
| 5.0 | `_output/<业务名>/design-spec-<业务名>.html` | 交付物不可追溯、无法回测 |
| 6.0 | `_output/<业务名>/demo-<业务名>.html` + `回测报告-<业务名>.md` | 无可运行验证、无回测留痕 |

> 落盘不是形式：说明书里每个数字、每条突破点、每个页面都要能指回上一步的产物；指不回去就是自己现编的（`EX-HO-01`）。

## 四、交付回执（汇报时必须贴这两段，缺一段不算交付）

```text
【Part A · 环节结果】
EX-0-01  读料：1.1/1.2/1.3/1.4 + N 份决策域，结论已写 ......... 通过
EX-1.1   场景 4 条，名称无阶段词，主场景均为"一份东西+工作" ...... 通过
EX-1.2   目标 4 条 = 场景数，场景名开头，无界面词 ............. 通过
EX-1.3   突破点 5 处，均有来源，均落场景 ..................... 通过
EX-1.4   两套方案，结构 5/5，用户选定方案一 .................. 通过
EX-4.1   动作覆盖 12 项均有落点（2 项本期不做）；继承对账差异 0 .. 通过
EX-HO    消费 / 交付 / 回链三项抽查无断点 .................... 通过

【Part B · 说明书结果】
SP-S  5 项：SP-S-01/02/03/04 机检通过，SP-S-05 人检通过
SP-A  6 项：（selfcheck）全绿
SP-W  5 项：SP-W-04 含 1 处人工确认（示例环境已声明）
SP-C  6 项：全绿
SP-D  6 项：全绿
结论：SP 可交付确认
```

`gate-ex.sh` / `gate-sp.sh` 退出码 **0** 才可汇报；**1** 一律先修，按报出的编号退回对应的那一环。**「跳过 / 无对应」不等于「通过」**，每一项跳过都要在回执里写明原因。

## 五、事故留档：2026-10-22 AI 资产发现需求

| 现象 | 根因 | 本应拦住它的门 |
| :-- | :-- | :--: |
| 未做草图确认就出了说明书 | 把「保留草图环节」误读为「把草图并进说明书」，跳闸门省一次往返 | **EX-1.4-05** |
| 体验目标 5 条、标题是「说得清/敢信状态」这类自造短语 | 没打开 1.2，只照 5.0 模板的粗骨架写 | **EX-0-01 + EX-1.2-02** |
| 目标写小（写到标签、跳转、点开） | 从需求字段清单反推界面，先有页面再补目标 | **EX-1.2-03** |
| 五条目标全挂同一个页面 | 写 Part1 时已在想 Part2，按页面而非按场景组织 | **SP-C-01 / SP-C-04** |
| 用 11/11 全绿当成交付标准 | 脚本只查结构，查不了句式/条数/颗粒度 | **SP-C + SP-D** |

> 结论：不是理解偏差，是该读的没读、该停的没停、该查的没查。这张表永久留档，作为 `EX-0-01 / EX-1.2 / EX-1.4-05 / SP-C / SP-D` 的存在理由。

## 六、与旧口径的差别（G0~G6 已作废）

| 旧（2026-10-22 临时产物） | 现状 |
| :-- | :-- |
| `G0~G6` 七道门、`tools/quality-gate.sh` 作为唯一交付入口 | **已删除**。G0→`EX-0-01`、G1~G4→`EX-1.1~1.4`、G5→`SP-A`/`SP-W`、G6→`SP-C`/`SP-D`，统一由 `gate-ex.sh` / `gate-sp.sh` 承载 |

> 发现任何文档仍在按 G0~G6 或 `quality-gate.sh` 执行，即为**过期文档**，按 [`准出门禁总表.md`](准出门禁总表.md) 第四节裁决：改文档，不改口径。
