# 经验未命中处理协议（Knowledge-Miss Protocol）

> 🎯 **定位**：全流程共用的**元规则**——任何环节"查经验库查不到"时，按本协议走，**不许自行降级**。
> 📍 **适用环节**：[1.3](../01-system-solution-design/①需求理解与分析/1.3-体验突破点拆解.md)（扫工作类型经验）／[4.1](../01-system-solution-design/④布局与结构/4.1-业务页面框架选型指引.md)（匹配主场景与经验）／[4.2](../01-system-solution-design/④布局与结构/4.2-业务能力与组件选型指引.md)（映射组件与件型）／[5.0](../01-system-solution-design/⑤设计说明书/5.0-设计说明书标准模板.md)（判据不覆盖）。
> 🔗 **上游**：[2.0-设计决策总览与调度](../01-system-solution-design/②设计思考与决策/2.0-设计决策总览与调度.md) 给调度规则，本协议给**未命中那一支的执行程序**；[横向库承接与场景拆解桥协议](横向库承接与场景拆解桥协议.md) 是本协议的**第 ② 级分支**，不另立规则。

---

## 零、一条总原则

> **未命中 ≠ 降级。**
> 未命中只说明"没有参考答案"，不说明"可以退回最朴素的形态"。

**为什么必须写死这条**：全流程过去的未命中处理只有一句话——"标 `无库经验 · 业务独立推导`，以现有设计资产规范自行设计"。实际执行结果是：**打上标签 → 退回表格 / 列表 / 标准组件 → 形式合规、实质平庸**。这类产出**过得了门禁**（门禁只查"有没有标注"），所以最坏的不是做得差，而是**差得合规**。

## 一、三级路由（逐页判，不逐需求判）

```text
需求进来
   │
   ├─① 匹配需求大类（Type-01~07）
   │    ├─ 命中且分册有料 ──────→ 用分册经验（EP-xx）
   │    ├─ 命中但分册空壳 ──────→ 视同未命中，进 ② ＋ 登记缺口
   │    └─ 未命中 ─────────────→ 进 ②   ⚠️ 不许找「最像的」硬凑
   │
   ├─② 匹配通用设计决策（D-01~11）
   │    ├─ 命中 ──────────────→ 用决策域经验（D0x-EPxx）
   │    └─ 未命中 ────────────→ 进 ③
   │
   └─③ 自行推导（五步）
        └─ 产出 = 方案 ＋ 三个必填标签（见第五节）
```

> 🛑 **路由必须逐页判**：一个需求里 P1 可能命中 Type-04、P4 配置页可能命中 Type-06。按页面判，才不会被主类经验"一并带过"。
> 🛑 **一个页面可以同时命中多类**（合法），但每一类都要能说出对应关系；**不许主类没命中、拉一个次类来顶**。

## 二、① 匹配需求大类

### 2.1 怎么算「命中」

不是看名字像，是看**这页的主任务是不是这类工作**。

| 算命中 | 不算命中 |
| :--- | :--- |
| 说得出"这页在做 Type-0x 里的**哪一件事**" | 只能说"都是安全相关的" |
| 分册里的原则**直接适用**，不需翻译 | 要绕一圈解释才套得上 |
| 套上之后，方案重心与该类分册的「主角」一致 | 套上之后主角完全对不上 |

> 🔎 **一句话判据**：**能不能用一句话说出"这页在做这类工作里的哪件事"**。说不出 = 没命中。

### 2.2 命中但分册无料 → 视同未命中

分册存在、类型判对了，但里面是**速查级**（只有几条零散考量、没有页面族 / 没有 Why / 没有 Token 硬指标 / 没有标杆案例）——**这等同于未命中**，直接进 ②，并登记缺口。

> 🛑 **这一条是死锁的解药**：旧链路"命中 → 用分册"隐含假设"分册一定有料"。遇到空壳分册时，AI 既抄不到东西、又不被允许走下一步，只能退回最朴素的形态——**这不是 AI 的错，是协议缺了这一环**。
> 📌 **判定「有料」的最低门槛**：① 有页面族或信息架构 ② 有可复用的 Why（判据句）③ 有至少一处 Token / 尺寸硬指标 ④ 有标杆案例。**四条缺二以上，按空壳处理。**
> 📌 **登记缺口**：在交付物观察区记一行 `Type-0x 分册空壳 → 已按本协议走 ②/③，建议补蒸馏`，并投 `05-learning-materials/`。

### 2.3 不许硬凑（硬凑比未命中更危险）

| 特征 | 表现 |
| :--- | :--- |
| **对应关系模糊** | 说"这页属于 Type-01 资产管理"，但说不出这页做的是资产管理里的哪件事 |
| **需要翻译才成立** | 分册原则套上来要绕一圈（"这里虽然不是巡检，但可以类比成巡检…"） |
| **主角错位** | 该类分册的主角（如"任务编排"）在这页根本不是重点 |

> 🛑 **为什么必须禁**：套上一个不匹配的大类，比诚实标未命中**危害更大**——它**有出处**。评审看到 `Type-01 · EP-02` 就不再追问，方案却整条歪了。未命中至少还挂着"业务独立推导"，会被追着看。
> 📌 **一旦发现自己在"找一个最像的"**，就是硬凑的信号，立即停手，改走 ②。

## 三、② 匹配通用设计决策

D-01~11 是横向尺子，回答的是**具体设计问题**（信息架构怎么定 / 容器怎么选 / 密度怎么排 / 检索怎么做 / 状态怎么表达…）。

执行见 [横向库承接与场景拆解桥协议](横向库承接与场景拆解桥协议.md)：

1. 把当前页面拆成「**设计问题 + 分析维度取值**」
2. 用取值向量去 D-01~11 母尺读数，命中 `D0x-EPxx`
3. 命中即用；**一个都读不到 → 进 ③**

> 🛑 桥协议里"未命中 → 标 `无库经验 · 业务独立推导`，自行设计"那一句，**以本协议第四节为准**——"自行设计"不是自由发挥，是走五步。

## 四、③ 自行推导（五步）

### 第 0 步｜先确认真的未命中（防误判）

不许一上来就说"没有经验"。三查：

| 查法 | 怎么做 |
| :--- | :--- |
| **换词查** | 同一件事各产线叫法不同（卡慢 / 慢 / 延迟 / 体验差 / 响应慢 / 打不开） |
| **换粒度查** | 大类没有，**子场景 / 单页**可能有 |
| **查相邻类** | 这件事常同时属于两类，另一类可能有料 |

产出：一句「查了哪个库、用什么词、为什么不算命中」。
> 🛑 **跳过三查直接进推导，判未命中认定不成立**，退回重查。

### 第 1 步｜把「经验问题」改写成「事实问题」

经验给不出答案，但**事实是确定的**：

| 要问清 | 例（DEM 卡慢定位） |
| :--- | :--- |
| **谁**，在什么处境下 | 值班工程师，接到"某某说上不了 CRM"的反馈 |
| 要做出什么**判断 / 动作** | 10 分钟内说出"是不是我们的问题、卡在哪" |
| 这个判断要成立，必须同时知道**哪几件事** | ① 这次访问经过哪几段 ② 每段实际耗时 ③ 每段正常值 ④ 哪段偏离最大 ⑤ 影响了多少人 |
| **做错了会怎样** | 指错方向，惊动错误的团队，耽误恢复 |

> 🔎 **动作要领**：把"这页该怎么设计"换成"这里到底要发生什么"。问题一换，就有可推的东西了。

### 第 2 步｜从事实推出「必须存在的东西」

任何界面元素存在的理由只有四种，逐条问：

| 理由 | 问句 | 推不出就是多余 |
| :--- | :--- | :--- |
| **判断需要它** | 没有它，这个判断做得出来吗？ | 做得出 → 删 |
| **动作需要它** | 没有它，这个动作完成得了吗？ | 完成得了 → 删 |
| **风险需要它** | 没有它，出错概率或代价会变大吗？ | 不会 → 删 |
| **信任需要它** | 没有它，人敢按这个按钮 / 敢把结论交出去吗？ | 敢 → 删 |

**产出**：一张「必须存在的清单」，每一条都挂着一个理由编号。

> 🛑 **推不出理由的，一律不许进页面。** 这一条同时治"装饰性图表"和"为了显得专业而堆的模块"。
> 📌 **四条要分开问，不许合并**：把"风险"和"信任"混成一句"重要"，就会推出"加个醒目提示"这种既防不住错、也建立不了信任的东西。

### 第 3 步｜定形与定位

对清单里每一条，依次定三件事：

| 定什么 | 问句 | 例 |
| :--- | :--- | :--- |
| **定性** | 它是**信息** / **操作** / **约束**，还是**反馈**？ | "每段实际耗时"= 信息；"回退阈值"= 操作；"不能误伤业务"= 约束 |
| **定位** | 它该**就地**、**同屏**，还是**下钻**？ | 判断要连着做 → 同屏；只在复核时才需要 → 下钻 |
| **定形** | 它用什么承载？（按**信息结构**选，不按业务经验选） | 见下表 |

**信息结构 → 承载形态**（通用，跨行业成立）：

| 这条东西的结构特征 | 承载必然倾向 |
| :--- | :--- |
| 顺序 / 空间关系本身就是信息 | 链路、拓扑、泳道、步骤条 |
| 只有跟基准比才成立 | 差值、区间带、阈值线、同比 |
| 随时间演化 | 时间轴、趋势、热力 |
| 由几部分构成 | 组成图、堆叠、树 |
| 多维权衡 | 并列对比、散点 |
| 因果链归因 | 分解条、瀑布、贡献度 |
| 需要排序取舍 | 列表（必须带量化列） |
| 逐条查找 / 配置 | 表格 |
| 单一结论 + 少量支撑 | 结论件 + 数字 |

> 🛑 **上表是"结构决定形态"，不是"业务决定形态"**。它不需要见过任何具体产品，只需要看清这条东西的结构。
> 🛑 **"表格"是合法答案，但必须是主动选的**——任务本质是逐条查找 / 配置时，表格就是最优解。**"没想、默认用表"与"想过、判定该用表"的区别，只在能不能说出理由。**

### 第 4 步｜验收（没有参考答案时的质量底线）

| # | 问句 | 不过关怎么处理 |
| :---: | :--- | :--- |
| 1 | **拿掉它，哪条理由不成立了？** | 说不出来 → 装饰，删 |
| 2 | **四条理由是不是都有东西承载？** | 有一条空着 → 这个任务在这页做不成，补 |
| 3 | **跟同类页面是一套语汇吗？** | 不是 → 要么统一，要么写明为什么不一样 |
| 4 | **能不能一句话说清"这里为什么长这样"？** | 说不清 → 没想清，回第 1 步 |

> 🔎 **一句话判据**：**每一条都必须能回答"它为什么在这儿"。** 答不出，判「这页没设计」，**不判「这页没经验」**。

## 五、留痕：三个必填标签（缺一即不许交付）

| 标签 | 写什么 | 用在哪 |
| :--- | :--- | :--- |
| **① 经验来源** | `Type-0x · EP-xx` ／ `D0x-EPxx` ／ `无经验背书 · 业务独立推导` | 4.1 逐页经验匹配表、5.0 页面元信息 |
| **② 推导过程** | 第 2 步的「必须存在的清单」+ 理由编号；第 3 步的定性 / 定位 / 定形结论 | 交付物附录或内部留档（**评审打回的依据**） |
| **③ 缺口登记** | 哪个类型 / 哪个决策域缺料、缺什么 | 观察区一行 + 投 `05-learning-materials/` |

> 🛑 **只写 ① 不写 ②，等于没推导**：标签是结论，过程才是可被检验的东西。评审只能靠 ② 判断"推得对不对"。
> 📌 **③ 是这套协议能自我进化的唯一出口**：这次推出来的东西，就是下一次的经验。

## 七、两个实例（一个偏信息、一个偏操作）

### 例 A｜DEM 访问诊断 —— 走完五步会得到什么

| 必须存在的东西 | 理由 | 结构特征 | 定形 |
| :--- | :--- | :--- | :--- |
| 这次访问经过哪几段 | 判断① | 顺序关系本身是信息 | 链路拓扑（终端→POP→连接器→应用） |
| 每段实际耗时 | 判断② | 数值要贴着位置 | 每跳标注 |
| 每段正常值 | 判断③ | 只有跟基准比才成立 | 基线区间 / 阈值线 |
| 哪段偏离最大 | 判断④ | 需要比较 | 最大偏离高亮 |
| 影响了多少人 / 应用 | 判断⑤ | 单一结论 + 少量支撑 | 影响面数字件 |
| 结论敢不敢交出去 | 信任 | 结论 + 依据同屏可核验 | 结论句 + 可展开证据 |

**这套推导没有用到 Type-04 分册的任何一条**。分册里的"四级连线语法""扩散半径置灰"是**精修**，不是**从零**。

### 例 B｜质量模型编辑 —— 证明这套不只管图

| 必须存在的东西 | 理由 | 定位 | 定形 |
| :--- | :--- | :--- | :--- |
| 当前阈值是多少 | 动作 | 就地 | 数字输入（带单位） |
| 改完会翻多少条 | 风险 | 同屏（改的时候就要看见） | 两数并列：换级 9 / 不变 28 |
| 改错了能不能回来 | 风险 | 保存前 | 确认 + 可撤销 |
| 系统凭什么这么判 | 信任 | 下钻（复核时才要） | 逐指标归因（分 × 权重 = 实得） |

> 📌 **例 B 里没有一张图**，全部是数字、输入框、确认。**推导不等于画图**——它推的是"该有什么、放在哪、用什么装"，图形只是其中一种装法。

## 八、常见误判（自查）

| 误判 | 长什么样 | 怎么判 |
| :--- | :--- | :--- |
| **把「没找到」当「没有」** | 只用一个词查了一次，直接标未命中 | 没走三查 = 未命中认定不成立 |
| **把空壳当有料** | 命中了类型，分册只有三五行，仍写 `Type-0x` | 按 2.2 四条门槛判，缺二以上按空壳处理 |
| **硬凑一个大类** | 说"这页属于 Type-01"，但说不出做的是哪件事 | 三特征命中任一 = 硬凑，改走 ② |
| **用「标签已打」当交付** | 标了 `业务独立推导`，没有推导过程 | 缺标签 ② = 没推导 |
| **退回默认形态** | 未命中后直接上表格 + 几个数字 | 拿不出「必须存在的清单」= 降级，退回第 1 步 |
| **把推导做成画图** | 一讲推导就只谈图表 | 推导管的是信息 / 操作 / 约束 / 反馈全部四类，图形只是一种装法 |
