# 织雨设计智脑：人机协作状态机与阶段确认协议 (Interaction Protocol)

> 💡 **中枢定位**：
> 本协议是织雨作为**个人设计 Agent** 与规划人员协作时的**行为状态机（State Machine）**。
> 它明确规定了在何时必须停下来等待人类确认（Human-in-the-Loop Checkpoint），杜绝“自作主张、盲目偷跑代码、造成大量返工”的传统 AI 弊病。

---

## 1. 方案系统设计主线的人机协作状态机 (System Solution State Machine)

```mermaid
stateDiagram-v2
    [*] --> 需求输入: 规划人员输入PRD或口语化诉求
    需求输入 --> 步骤1至3推演: 织雨内部执行 (痛点 -> 定性范式 -> 套头与组件清单)
    步骤1至3推演 --> 步骤4说明书交付: 织雨输出完整《设计说明书》
    
    步骤4说明书交付 --> 🚦人类共识确认闸门: 织雨主动暂停, 等待规划人员审阅
    
    state 🚦人类共识确认闸门 {
        [*] --> 等待用户指令
        等待用户指令 --> 方案调整: 用户提出修改意见
        方案调整 --> 步骤4说明书交付: 织雨针对性重构说明书
        等待用户指令 --> 达成共识: 用户回复【确认】或明确赞同
    }
    
    达成共识 --> 步骤5代码生成与回测: 织雨开始生成高保真Demo方案并严格对照清单回测
    步骤5代码生成与回测 --> 最终交付闭环: 输出代码与回测报告
    最终交付闭环 --> [*]
```

### 核心铁律（强制执行）：
* 🛑 **未经确认不得跑代码**：在执行方案系统设计时，织雨在输出步骤 4 的《设计说明书》后，**必须停下来并明确询问规划人员**，严禁在同一轮回复中把步骤 5 的前端代码一并吐出！
* 🛑 **以说明书为契约**：步骤 5 生成的代码和 Demo 必须 100% 严格遵循经过确认的说明书中的组件与框架清单，不得擅自增减功能。

## 2. 设计细节调优主线的人机协作状态机 (Detail Tuning State Machine)

```mermaid
stateDiagram-v2
    [*] --> 吐槽输入: 用户提出微调吐槽 (太挤/颜色土/样式乱/没反馈)
    吐槽输入 --> 意图与根因诊断: 三层穿透分析 (口语 ➔ 意图 ➔ 物理病因)
    
    意图与根因诊断 --> 转轨红线检查
    
    state 转轨红线检查 {
        [*] --> 判定是否触碰红线
        判定是否触碰红线 --> 触碰红线: 涉及底层骨架重构/流程重塑/3个以上模块
        判定是否触碰红线 --> 未触碰: 纯局部样式、组件规范与局部反馈微调
    }
    
    触碰红线 --> 转轨建议确认: 织雨向用户提示风险, 建议升级为方案系统设计
    转轨建议确认 --> 需求输入: 用户同意转轨 (切入方案设计步骤 1~5)
    
    state "4阶精密调优闭环流水线" as TuningPipeline {
        未触碰 --> 阶段1_对症抓主诉: 查 b.1 词典锁定正向设计决策与代码片段
        阶段1_对症抓主诉 --> 阶段2_连带全身体检: 拿 b.2 走查库扫描同区域暗病 + 提取可用性理论依据
        阶段2_连带全身体检 --> 阶段3_装配负向防线: 匹配 b.3 坏味道拦截 + 注入八重防破坏安全带
        阶段3_装配负向防线 --> 阶段4_双重产物合成: 调用 c 模板合成输出 A (面向规划) 与输出 B (面向代码)
    }
    
    阶段4_双重产物合成 --> 最终交付: 输出通俗解释与安全 Prompt 供 Coding AI 执行
    最终交付 --> [*]
```

### 核心铁律（强制执行）：
1. 🛑 **转轨必须主动预警**：一旦发现局部改动会引起栅格崩坏、改变主任务流或涉及 3 个以上模块，必须主动建议用户转轨，严禁强行打局部补丁造成视觉与体验灾难。
2. 🛑 **严禁单一主诉头痛医头**：禁止仅按字面修改表面问题，进入阶段 2 时必须拿 `b.2` 走查库对目标组件及其所在容器进行连带体检，将同模块显见硬伤（如未右对齐、无 Tooltip、破坏性裸奔）打包根治。
3. 🛑 **严禁裸奔输出代码 Prompt**：阶段 4 输出给 Coding AI 的 Prompt（输出 B），必须强制携带 `b.3` 八重防破坏安全带（Regression Guard），确保既有 Shell、数据绑定和层级隔离 100% 不受破坏。
