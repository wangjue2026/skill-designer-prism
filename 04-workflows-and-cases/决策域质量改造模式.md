# 决策域质量改造模式（Decision-Domain Quality Retrofit SOP）

> 💡 **中枢定位**：把任一「通用设计决策域 `D-0x`」从**首轮落库**，一次性提升到 **对标 `D-10` 标杆 + 最新《通用设计案例蒸馏指南》** 的质量——目标是"**需求过来能按决策场景精确命中经验、并能 1:1 还原**"。
> 🎯 **一次性合并三条任务线**（合并执行，但**任何一条都不得省略**）：
> ① **专家经验比对**（雷同合并 / 冲突·扩展登记）；
> ② **补采**（针对冲突与扩展的指定页面取证）；
> ③ **全域重蒸馏**（存量场景 + 缺场景一起，按最新指南 Schema 重做）。
> 🚩 **触发**：用户说「**对 `D-0x` 提质 / 质量改造 / 重新蒸馏**」即进入本模式。

---

## 一、启动契约（新会话 30 秒开跑）

**新会话只需粘贴以下模板**（Agent 须先读本文件再动手）：

```text
对 D-0x【<决策域名>】执行"决策域质量改造模式"（读 04-workflows-and-cases/决策域质量改造模式.md 后严格按其执行）。
- 专家经验：<粘贴 / 附件路径>
- 已知裁定：<冲突/扩展的既定结论，可留空>
```

> 🧭 **取证范围分两段，触发时不要一次性索要**：
> * **存量沿用**：Agent 直接从上轮清单取（[环境备忘录](../05-learning-materials/通用设计决策-蒸馏环境与域范围备忘录.md) 该域"逐域明细"），**无需用户提供**；
> * **扩页（缺场景 / 扩展）**：**由 Agent 在 Stage 1 之后，按"冲突 / 扩展"逐条提案补采页面位置**，此时才请用户确认——因为范围取决于比对结果，**触发时用户尚不可知**。
> 🛑 **因此第一步动作固定为**：先做 Stage 1 比对，返回 **三分类 + 补采页面提案**，停下等确认；**严禁在 Stage 1 之前索要扩页范围**。

## 二、执行阶段流水线（Stage 0 ➔ Stage 6）

| 阶段 | 动作 | 产出 | 卡点 |
| :--- | :--- | :--- | :--- |
| **Stage 0 前置** | ① 校验取证环境（CDP 9222 + 三产线登录）；② 复核该域母尺、清理旧注记；③ 从环境备忘录取**存量沿用页清单** | 环境就绪 + 存量页清单 | 存量页 Agent **自取，无需用户提供** |
| **Stage 1 专家经验比对** | 逐条比对专家经验 vs 现有 `EP/EQ`，分 **雷同 / 冲突 / 扩展**；**并为每条冲突·扩展提案"补采页面位置"** | 三分类对照表 + **补采页面提案** | ⛔ **停下等用户确认**（裁决 + 扩页范围） |
| **Stage 2 补采** | 按用户确认后的页面实机取证（含净新增页） | 补采读数 | 页面没读到就**停**，不追到范围外 |
| **Stage 3 全域重蒸馏** | 按指南 6 步：存量场景重采 + 缺场景补采（同一轮） | §三矩阵 + §二经验 | 见下方"硬性交付物" |
| **Stage 4 还原闭环闸门** | 指南 3.2.2 五项自检 | 自检结论 | 缺口**补齐**，不以降级 EQ 兜底 |
| **Stage 5 状态回填** | 回填 4 处（见 §六） | 状态一致 | 计数须对得上 |
| **Stage 6 三阶段人机确认** | 提案报告 ➔ 确认写入 ➔ 结束语反向确认 | 共识 | 严禁未经确认直接"完成" |

## 三、硬性交付物清单（缺一即视为未完成）

> 与《通用设计案例蒸馏指南》一致的"五件套 + 母尺"：

| # | 交付物 | 验收口径 |
| :---: | :--- | :--- |
| 1 | **母尺（决策场景清单）** | 场景中立可判定、维度可测量、候选空间穷尽；清除旧注记 |
| 2 | **§2.1 设计经验 EP** | 四分类（统一基线 / 推荐体验 / 形态分流 / 例外场景）＋**每子项内联还原锚点** `` `产线 · 模块 ▸ D-0x ①` `` |
| 3 | **§2.2 待确认 EQ** | 未覆盖 / 存疑项如实登记 |
| 4 | **§三 横向对照矩阵** | 每行必带〔**结构骨架（切分 ➔ 位次）**〕＋〔**承载形态与 Token 六项**〕＋〔**判据取值**〕＋〔**实测交互 / 独有取舍**〕 |
| 5 | **节末标杆还原线框图** | 每场景 ≥ **2 个形态**，且**覆盖该场景 EP 的全部分支** |
| 6 | **共用组件 Token 基线块** | `getComputedStyle` **实测值**（尺寸 / 圆角 / 色值 / 字号 / 阴影 / 间距） |

## 四、验收口径（六项 + 3.2.2 五项）

**逐域六项**：①母尺已定 ②有 2.1 EP + 2.2 EQ ③矩阵每行三件套齐 ④每场景节末有线框图 ⑤锚点格式合规、证据层不写锚点 ⑥无证据标 `⚠️`。

**EP 可还原闭环（3.2.2）**：①锚点齐备 ②锚点可解 ③三件套齐备（结构骨架＋Token）④线框覆盖 EP 全分支 ⑤100% 还原。**缺一即补齐，不以 EQ 兜底。**

---

## 五、反偷懒护栏（★ 必须逐条自证，禁止"偷懒收口"）

> 背景：本模式在 D-09 首轮执行时曾出现「只采关键页就宣称完成」「存量沿用冒充重采」等偷懒，需反复返工。以下为**强制红线**：

| # | ❌ 禁止 | ✅ 正确做法 |
| :---: | :--- | :--- |
| 1 | 只采几页就说"取证阶段完成" | 先列**目标页清单（脚本化枚举）**，逐页标注"本轮实采 / 未采" |
| 2 | 把"存量沿用"当"已重采" | 每页标注**本轮是否实采**；未实采的显式标 `⚠️ 本轮未复采` |
| 3 | 只给"共用 Token"不给样本 Token | **逐样本行挂 Token 六项**（`getComputedStyle` 实测） |
| 4 | 线框图单形态、只画统一基线 | 每场景 **≥2 形态**，覆盖 EP 全部形态分流分支 |
| 5 | 结论含糊（"疑似 / 好像可排序"） | 实测到的如实写；**测不到就标 `⚠️ 待复核`**，不许脑补 |
| 6 | 在文件里写"本次补记/上次未取到"等过程标注 | 遵守**精简四律①**：只写结论与证据，不留过程性标注 |
| 7 | 遇 SASE/子应用等导航受阻就放弃 | 试 `location.href` 直连等替代路径；仍不通则**如实记录局限** |
| 8 | 未跑自检就宣称达标 | Stage 4 五项自检 + 完成度自检（§七）**逐条给结论** |

## 七、完成度自检（交付前必答，不得含糊）

> 交付报告必须显式回答：

- **目标页 N / 本轮实采 M**（逐页列出，未采的给原因）；
- **缺场景补齐情况**（补了几个、还差几个）；
- **Token 覆盖**：哪些样本行挂了六项、哪些仅共用基线；
- **线框图覆盖**：每场景形态数、是否覆盖 EP 全分支；
- **未覆盖 / 待复核项**（`⚠️` 清单）；
- **EP 编号与锚点闭环**自检结论。

---

## 八、需用户拍板的节点（按时间顺序，**不是一次性**）

1. **触发时**：给 **目标域 + 专家经验原文**（没输入则不启 Stage 1）；
2. **Stage 1 之后**（Agent 返回三分类 + 补采页面提案后）：**冲突裁决 + 扩展取舍 + 扩页范围确认**——**此时用户才可能提供范围**；
3. 之后一路执行：**Stage 2 补采 ➔ Stage 3 全域重蒸馏 ➔ Stage 4 自检 ➔ Stage 5 回填 ➔ Stage 6 确认**。

> 🧭 **存量沿用页范围由 Agent 自动取**（环境备忘录）；重采深度 / 线框形态 / Token 粒度默认**一律对标 D-10**，不再逐项追问。

## 九、D-09/D-10 复盘要点（避坑备忘）

- **D-10 是标杆**：8/8 场景、EP 每子项可顺锚点落到「矩阵行（骨架＋Token）＋节末线框图」，可直接照抄其排版与颗粒度；
- **D-09 的坑**：① 首轮 5/11 覆盖、线框偏简；② 我曾把"14→17 页"说成"14 页只采 8 页"——**页数口径务必对齐**；③ 专家经验的编号与场景号易串位，**以场景内容语义为准**，不确定就回问；
- **SASE 侧栏不用 `<a>`、XDR 子应用（`apex-business`）`nav` 不可达**：改用 `eval location.href` 直连；
- **aES 表格为虚拟滚动**：`tbody tr` 读取常为空，取数用更稳的单元格选择器；排序触发件为 `.aesix-table-sortable-trigger`。
