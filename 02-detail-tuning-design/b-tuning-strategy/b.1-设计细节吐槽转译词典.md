# 微观细节转译词典：规划口语 ➔ 专业设计指令映射 (Detail Tuning Dictionary)

> 💡 **微观细节定位**：
> 本文档是织雨体验设计智脑针对 **微观细节吐槽、样式优化、间距排版、局部易用性** 的实战转译词典。
> 专门用于将规划人员的感性大白话（如“太挤了”、“好土”、“看不清”）精准映射为具体的 CSS/DOM 修复指令。

---

## 零、转译心法：三层穿透，不“按字面头痛医头” (Penetration Mindset)

> ⚠️ **使用前提**：本词典不是“关键词查表”。下笔前必须先做一次**语义穿透**，再对症查表。

```text
┌────────────────────────────────────────────────────────────────────────┐
│ 1. 表象层 (Symptom)   : 规划人员口语原话（如：“这个表格太丑、太乱了！”）   │
│         ↓ 语义转译与同理心还原                                         │
│ 2. 意图层 (Intent)    : 用户在当下任务中的心理受挫点与诉求（视线缺乏锚点，找字段累）│
│         ↓ 专业设计归因与代码映射                                       │
│ 3. 物理层 (Root Cause): DOM/CSS 真实病因（表头无区分底色、行高过挤、缺 Outfit 等宽）│
└────────────────────────────────────────────────────────────────────────┘
```

* **铁律**：绝不按字面意思直接改（用户说“太挤”≠“把字号调小”），必须先穿透到物理病因，再对症查表；
* **意图维度与分类导航（上下动态对齐，支持随业务经验灵活调整与扩充）**：
  在调优诊断时，先识别用户吐槽所属的意图维度，再直达对应章节对症施策：
  1. 📐 **一、空间、容器与信息密度类** ➔ 解决“太挤、太散、空洞撑开Bug、控件笨重、首屏信息过载”
  2. 🎨 **二、页面视觉层级、色彩与焦点类** ➔ 解决“花哨、土气、缺乏重点、三级字阶混乱、局部告警刺眼”
  3. 📊 **三、数据可视化与图表细节类** ➔ 解决“折线粗刷子、Tooltip缺失、散点无交互响应”
  4. 🧩 **四、表格、通用组件与一致性规范类** ➔ 解决“表格排版、数字右对齐、横滚冻结、组件长相各异/规范碎片化”
  5. 🏷️ **五、多状态并发与图标噪音控制类** ➔ 解决“图标随模式乱变色、多源厂商野图标、未读标记过重、状态颜色泛滥”
  6. ⚡ **六、交互反馈、状态机与文案语义类** ➔ 解决“技术代码直出、文案缺失、点击无反馈、流程死胡同、过度跳页”

### 转轨红线自检（查词典前先做）

细节调优只处理**局部**；若诊断发现满足以下任意一条，必须停下并**转轨到方案系统设计**（红线的权威定义见 [`triage-rules.md`](../../00-triage-and-routing/triage-rules.md)）：

1. **范围检查**：需修改 3 个以上独立模块，或涉及页面最外层骨架栅格；
2. **流程检查**：需新增页面状态、多步向导，或改变用户主任务链路；
3. **认知检查**：现有页面范式与用户业务本质完全错位。

### 调优诊断报告（输出结构）

```markdown
### 调优诊断报告
- **原始吐槽/指令**："[提取用户原话]"
- **意图维度归类**：[空间与密度 / 视觉层级与色彩 / 数据可视化 / 表格与组件规范 / 多状态与图标噪音 / 交互状态与文案 / 或自定义扩充分类]
- **真实设计病因**：[精准指出 DOM、样式、Token 或布局上的物理缺陷]
- **优化目标预定**：[明确微调后的预期视觉与可用性效果]
- **转轨红线自检**：[通过 / 触碰红线需转轨]
```

## 一、 空间、容器与信息密度类 (Layout & Spacing)

| 规划原始吐槽 | 真实设计病因诊断 | 织雨设计智脑专业设计决策 (Design Rationale) | 面向 Coding AI 的精确 Prompt 片段 |
| :--- | :--- | :--- | :--- |
| **“这里太挤了 / 密密麻麻的”** | 缺少 8px 网格留白，元素紧贴边缘，行高过低造成视觉压迫。 | 采用 8px 网格规范，加大父容器与卡片内边距，正文行高提升至 `1.5~1.6`，模块间增加留白。 | `主卡片内边距统一为 padding: 16px (p-4)；子项纵向间距使用 gap-3 (12px) 或 space-y-3；文字行高设为 leading-relaxed (1.625)；模块间增加 16px 留白。` |
| **“页面太散了 / 空荡荡的”** | 信息密度过低，字段缺乏业务内聚，栅格跨度过大导致视线游离。 | 将分散的独立字段按业务相关性聚合为结构化卡片；关键指标水平并排并配置浅色背景容器包裹。 | `将孤立展示的字段重构为 Inline 键值组 (flex items-center gap-2)；添加背景底色 bg-[#F8FAFC] 与 1px 细边框 border-[#E2E8F0] 进行视线包裹。` |
| **“小标题框在卡片里太碎了，好多线，不简洁”** | 外层大卡片套内层小卡片，造成多层无意义边框与分割线嵌套。 | 坚决去框线化：小标题从卡片内移出至外部上方，去除外层包裹大框及其内部 `border-b`，内部指标卡直接作为一级白底卡片平铺。 | `移除外层包裹卡片与内部 border-b；小标题独立置于外部上方 (flex items-center gap-2 mb-2 text-xs font-semibold)；指标卡直接作为一级卡片并排 (bg-white p-3 rounded-[2px] border border-[#EAEEF4] shadow-xs)。` |
| **“页面还有空间 / 页面显示的很空 / 间距拉得太开”** | 1. 间距定义过大造成视觉空洞；<br>2. 间距写法存在 CSS Bug（如容器被无意义的 `flex-1` / `justify-between` / `height: 100vh` 撑开，margin 穿透累加，实测像素远超 8px 网格标准的 12/16px）。 | 间距收敛与修复布局撑开 Bug：去除无意义的 `justify-between` / `flex-1` 纵向拉伸，容器设为内容自适应高度（`h-fit`）；模块级间距收敛为 `16px` (`gap-4`)，卡片内子项收敛为 `8~12px` (`gap-2 ~ gap-3`)。 | `排查并修复间距膨胀与空隙撑开 Bug：移除导致内容被动拉散的 flex-1 与 justify-between，容器改用 flex-col justify-start gap-4 (16px)；卡片内部子项间距收敛至 gap-3 (12px) 或 gap-2 (8px)；容器高度设为 h-fit，严格遵循 8px 网格规范收敛留白。` |
| **“搜索框怎么看着这么大 / 笨重”** | 控件高度超标（直出了 C 端 44px+ 输入框）或宽度占满整行。 | 紧凑化重构：收紧高度至 B 端标准 32px（`h-8`），宽度固定 240px，前置绝对定位放大镜微图标，Focus 时添加微蓝光圈。 | `外层 relative flex items-center w-60；前置图标 absolute left-2.5 w-3.5 h-3.5 text-[#94A3B8]；输入框 pl-8 pr-7 py-1 h-8 text-xs bg-[#F8FAFC] border border-[#CBD5E1] rounded-[2px] focus:ring-2 focus:ring-[#1C6EFF]/20 focus:border-[#1C6EFF]。` |
| **“按钮太大了 / 不像后台系统的按钮”** | 按钮高度过大，内边距过宽，使用了无约束的 C 端样式。 | 紧凑化重构：双字按钮固定 56px 宽度，高度 32px，字号 12px，圆角 2px，清除径向扩散阴影。 | `双字按钮设置 w-14 (56px) h-8 text-xs font-normal rounded-[2px]；主按钮使用 bg-[#1C6EFF] hover:bg-[#4FA1FF] active:bg-[#1458CC]；普通按钮使用 bg-white border border-[#D3D7DE] text-[#2F3540]。` |
| **“这里东西太多了 / 放了很多我用不到的”** | 所有功能项平权展示，无主次任务分层；低频配置项（如双语设置、高级参数、业务引流模块）侵占首屏主任务空间，造成视觉过载。 | 按「主任务优先」法则重构信息架构：首屏仅保留覆盖 80% 用户在当前页核心决策所需的字段；低频/高级选项通过「展开更多」/ 折叠面板 / Tab 收纳默认隐藏；装饰元素与业务引流模块归位到专属页面。 | `高频核心字段直接在首屏平铺；低频高级选项使用 <details> 或 Collapse 组件默认收起，标注「展开高级配置」；任何首屏新增字段须先回答：用户在本次核心任务决策的当下，需要这个字段做判断吗？` |
| **“从属配置项跟上面平级堆在一起，看不出是谁管谁 / 勾选之后出来的配置乱糟糟的”** | **层级混乱与视觉从属断裂**：多重嵌套或联动展开的从属表单项（如勾选复选框后展开的输入框与子表格）与父级控件顶格平级对齐，缺乏缩进与背景容器包裹，导致用户无法感知从属父子关系。 | 实施“视觉从属缩进与容器包裹法则”：所有因父级激活而展开的从属配置项，必须相对父级控件严格**左侧缩进 24px**（`ml-6`），并搭配左侧细竖线或浅色底板（`bg-[#F8FAFC]`）进行层级包裹；无从属关系的同级并列项保持顶格对齐。 | `从属联动配置容器配置缩进与层级包裹：外层添加 ml-6 pl-3 border-l-2 border-[#E2E8F0] space-y-3 bg-[#F8FAFC]/60 p-3 rounded-[2px]；子输入框与子表格严格处于缩进容器内，确保视觉从属关系一目了然。` |
| **“全局开关放在最底下，翻了半天没找到 / 怎么把总开关藏在翻页旁边”** | **全局配置沉底被淹没**：具有全局/全域影响力的核心总开关（如“开启自动同步”、“全局防御生效”），被错误地放置在列表底部、翻页器旁或折叠抽屉深处，严重违背用户的空间心理预期。 | 实施“全局配置强制置顶法则”：凡对当前业务域具备全局生效影响力的控制项，必须固定在页面/卡片的最顶部（Banner 下方或工具栏上方），配备醒目的全局状态容器与状态指示，绝对严禁沉在列表末尾或与分页混排。 | `全局配置项移至卡片顶部显要位置：构建顶置容器 flex items-center justify-between p-3.5 bg-[#F8FAFC] border-b border-[#EAEEF4] rounded-t-[2px] mb-3；左侧配全局状态标题与说明，右侧放 Switch 开关，严禁将全局开关沉底至列表下方。` |
| **“待处理告警展示没意义 / 没啥用 / 顶部的概览信息还能呈现什么有价值的内容”** | 顶部概览指标与下方表格 100% 重复（同样都是待处理条数），信息信噪比极低，浪费首屏黄金空间。 | **概览升维洞察法则（道）**：概览区坚决不摆放与下方明细重合的静态统计数字；应升级为具备时间演变维度的态势图（如近 7 天每日告警趋势），提供表格无法替代的宏观洞察；若无有效趋势数据则应果断移除概览，把高度留给核心内容。 | `概览区去废话升维重构（根据现场空间量体裁衣）：移除单纯的"待处理告警"静态数字卡片；空间充裕时替换为近 7 天告警态势折线图 (h-28 w-full)，左侧告警总数与今日增量，右侧双折线（紧急红线 + 重要橙线）；空间逼仄时直接精简移除该模块，将高度让给核心表格，外层留白保持 8px。` |

## 二、 页面视觉层级、色彩与焦点类 (Hierarchy & Colors)

| 规划原始吐槽 | 真实设计病因诊断 | 织雨设计智脑专业设计决策 (Design Rationale) | 面向 Coding AI 的精确 Prompt 片段 |
| :--- | :--- | :--- | :--- |
| **“界面太花哨了 / 颜色过多 / 不够轻量”** | 1. 视觉主次缺失：在大量非核心标签、文字、边框、图标上过度堆叠彩色与装饰线，缺乏视觉焦点；<br>2. 色彩厚重且饱和度过高：使用大面积深色背景或重色块，缺乏中性底色沉底和通透呼吸感，导致“元素多而杂、缺乏高级感与品质感”。 | 实施“视觉减负降噪法则 (Visual De-cluttering)”：遵循 60-30-10 配色定律（60% 基础浅底、30% 文本灰阶、10% 核心主题色）；坚决去装饰线与去重色块；非核心标签降阶为微浅底（如 `bg-blue-50 text-blue-600`）或中性灰（`#F1F5F9`），辅助图标统一中性灰化（`#64748B`）。 | `全面视觉降噪与轻量化重构：移除所有非必要的装饰性色彩背景与多余分割线；非核心状态标签统一降阶为超轻浅底 (如 bg-[#E8F4FF] text-[#1C6EFF] border-[#B3D8FF])；辅助图标统一降噪为 text-[#64748B]；卡片统一纯白底配合微边框 (#EAEEF4)；全屏确保仅保留 1 个核心主视觉焦点，提升通透感。` |
| **“重点不够突出 / 一眼看不到关键信息 / 啥都一样看不出重点”** | 字号字重全页均一（全是 12/14px 纯黑字），信息无梯度权重分配；所有文字、标签、描述处于同一视觉平面，缺少主次字阶阶梯与主题强调色。 | 建立清晰的**三级视觉梯度法则 (Visual Hierarchy Gradient)**：<br>1. **核心决策指标/标题**：20~28px Semibold，深色 `#1E293B`，搭配专用数字字体（Outfit/DIN）；<br>2. **主体内容/字段名**：14px Regular，次深色 `#2F3540`；<br>3. **辅助说明/时间戳/单位**：11~12px Regular，中性灰阶 `#64748B`；<br>核心卡片增加左侧 3px 品牌强调色条；三层之间严禁出现字号字重完全相同的情况。 | `主数值/核心标题升级为 text-2xl font-bold font-outfit text-[#1E293B]；主内容/字段设为 text-sm text-[#2F3540]；次级标签与辅助说明设为 text-xs text-[#64748B]；核心卡片增加左侧 3px 品牌强调条 (border-l-3 border-[#1C6EFF])；三层之间严禁出现字号相同且字重相同的情况。` |
| **“页面看起来很土 / 像老系统”** | 使用了高饱和原生红绿蓝、纯黑纯白硬切、缺乏阴影与圆角层次。 | 建立现代化 B 端色阶：区分页面底色（#F7F9FC）与卡片底色（#FFFFFF）；引入 2~4px 紧凑微圆角与浅微投影（shadow-xs）；状态色使用柔和语义色阶。 | `页面背景更换为 bg-[#F7F9FC]，卡片统一使用 bg-white rounded-[2px] border border-[#E1E5EB] shadow-xs；状态标签采用浅底+深字（bg-[#FFF1F0] text-[#D9363E] border-[#FFA39E]）。` |
| **“告警要红一点，一眼看出故障”** | 规划想突出警示，但容易做成大面积刺眼纯红背景，造成视觉疲劳与不可读。 | 采用“局部警示聚焦法”：卡片保持白底，仅在异常指标数值、状态徽标、拓扑节点边框施加红色高亮，并添加外圈脉冲光环（Pulse Halo）。 | `禁止大面积红底！卡片仅左侧添加 3px 红色条 border-l-[#D9363E]；异常数值标红 text-[#D9363E]；异常节点/散点增加微外环: absolute rounded-full border border-[#F52727]/40 animate-pulse。` |
| **“处处都是红的 / 满屏皆红 / 一眼看过去全是花的，处处都是重点”** | 告警指标过度染色，待处理、持续中、影响范围全用刺眼红底胶囊堆叠；已恢复事件未弱化，导致视觉信噪比崩塌。 | **去红降噪与状态分级法则（道）**：待处理全部采用石墨深灰文字（#475569），数量标签使用中性浅灰底（#F1F5F9 text-[#64748B]）；已恢复彻底剥离彩色标签，直接以纯文本弱化展示（正常无需关注）；告警信息去 Tag 化，改为项目符号列表排版。 | `全面实施告警去红降噪：待处理告警文字改为 text-slate-600 font-normal，对应数量标签改用 bg-[#F1F5F9] text-[#64748B] 无边框灰色胶囊（列宽狭窄时降阶为纯文本）；已恢复状态彻底移除彩色 tag，改用 text-slate-400 纯文本；告警信息移除彩色小标签，拆解为有序项目符号文本列表 (• 时延: 38ms • 丢包: 5.4%)。` |
| **“POP呼吸感动效过重 / 太夸张了 / 怎么圆圈里面还变色”** | AI 直出了整体背景颜色变红且由外向内收缩的剧烈动效，造成强烈的视觉眩晕感与不适。 | **轻量外圈扩散法则（Subtle Pulse Halo）**：圆圈内部必须恒定保持白底纯净，坚决不变红；仅使用绝对定位的伪元素在外层生成轻微向外扩散渐隐的光环，动效柔和克制。（注意载体适配：圆点用外圈扩散，长方形卡片改用左侧 2px 浅红呼吸条）。 | `重构告警动效为轻量外圈微脉冲：节点中心容器保持 bg-white border border-[#E2E8F0] 恒定不变色；仅在节点外部叠加绝对定位扩散环：absolute -inset-1 rounded-full border border-red-500/40 animate-ping pointer-events-none；长方形卡片载体则切换为 border-l-2 border-red-500 呼吸渐变；严禁整块背景闪烁或由外向内收缩。` |

| **“这文案完全看不懂 / 满屏代码 / 啥意思”** | 后端技术语言或工程术语直出 UI（如错误码 `ERR_CONN_TIMEOUT_504`、`rule_id=xxx`），未经设计侧翻译为业务自然语言；文案缺乏闭环：只说了发生了什么，没有说原因和下一步。 | 采用「结果 + 原因 + 闭环指引」三段式公式改写所有关键文案：① 用户最关心的结果 → ② 简短业务原因 → ③ 明确下一步操作引导；专业错误代码仅作括号辅助说明保留，不作主文案；所有上线文案须由设计侧版本校对把关，集中收集-校对-对齐研发。 | `所有状态/提示/报错文案使用三段式：结果文案 + 原因说明（括号辅助）+ 处理指引（文字链）；禁止将技术错误码、英文 key、null/undefined 作为主要展示文本，工程语言须翻译为业务自然语言。` |
| **“这里什么都没说 / 没有描述”** | 组件虽存在但文案 Token 为空（后端未返回）、被截断，或设计稿仅考虑了成功态，未定义异步进行中、部分失败、超时等关联提示文案。 | 建立「文案四要素」核查清单：对象（谁）+ 操作（做了什么）+ 结果（成功/失败/进行中）+ 可选指引（下一步）；设计稿交付前须逐字段确认文案来源（写死/后端返回/前端状态），并提供空值降级文案。 | `组件文案 fallback 策略：当后端字段为空时渲染占位降级文案（如「暂无描述」/ 「处理中，请稍候…」）；严禁渲染空白组件或裸露占位符（如 null、undefined、--）。` |
| **“点了没反应 / 不知道成没成功 / 一直转圈”** | 状态机设计缺失：UI 仅设计了正常提交态，未覆盖「提交中→处理中→结果」三阶段完整状态；按钮点击后无禁用保护，导致重复提交；成功/失败反馈未定义。 | 强制实施「三阶九态」完整状态覆盖：① 提交阶段（Loading 禁用态 / 冲突拦截 / 提交失败）→ ② 处理阶段（进度条 / 骨架屏 / 载入超时提示）→ ③ 结果阶段（成功 Toast + 刷新 / 失败 Modal + 重试引导 / 部分成功分项说明）；与研发对齐异常场景并要求研发场景反讲。 | `按钮点击后立即切换为 disabled + Spinner 状态（pointer-events-none opacity-60）；提交完成：成功用 Toast（duration 3s）+ 自动刷新；失败用 Modal 展示精确原因 + 重试/联系支持引导；禁止任何操作在点击后页面无任何视觉响应。` |
| **“做到一半做不下去了 / 点了没有下一步 / 回不去了”** | 任务流程设计只覆盖了主路径 Happy Path，未为失败分支、中断恢复、返回锚点设计出口；常见于「新建后才能创建关联任务」「预览设计漏掉了恢复默认配置」等多步骤流程。 | 以任务流程图为设计起点（先画流程图再开排版）：从起点到终点为每个分支标注成功/失败/超时出口；对照「CRUD 完整性」自检——对象支持的 ①增②删③改④查⑤恢复⑥导出⑦备份⑧排序 操作类型是否全覆盖；每步支持返回上一步与状态感知。 | `多步骤流程：每步提供「上一步」返回按钮和当前步骤进度指示；操作失败后在原地展示错误原因 + 重试入口，禁止跳到无关页面；任何「完成创建后需额外操作才能使用」的场景须在完成界面直接提供关联操作入口。` |
| **“点进去又跳了个新页面 / 太烦了 / 视线乱了”** | 过度依赖路由跳页处理「查看详情、编辑、二次操作」等中等信息量场景，打断用户任务连续性；仅因为「信息量大」就跳页，未评估是否可用抽屉/就地展开承载。 | 「非必要不跳页」决策树：① 信息量 ≤ 屏幕 60% → 就地 Modal/Drawer；② 信息量需要全屏但上下文无需保留 → 新页面可接受；③ 操作结果需回到来源列表 → 强制使用 Drawer 或侧边详情面板，关闭后原列表刷新不跳页。 | `详情/编辑场景优先使用 Drawer（width: 480px～720px）从右侧滑出；关闭 Drawer 后原列表自动刷新当前行数据；仅「独立工作台级功能（如全屏 IDE、大屏看板）」允许路由跳转新页面。` |
| **“这按钮怎么是灰的 / 点不了也不说为什么 / 这一堆小图标啥意思看不懂”** | **信息操作反馈缺失（说明缺失与禁用黑盒）**：控件直接置灰（`disabled`）但缺乏状态解释，用户不知道前置依赖条件；工具栏/表头放置单字孤立图标（如单独眼睛 `👁️`、喇叭），无文字无 Tooltip，产生认知困惑。 | 实施“状态透明化与图标自解释”：1. 禁用必有因：任何置灰不可点击的按钮/输入框，外层包裹容器必须在 Hover 时触发解释性 Tooltip（如“需拥有管理员权限”、“请先在下方勾选至少 1 项资产”），明确告知为什么被禁以及如何解锁；2. 图标拒绝盲盒：严禁裸露无文字说明的孤立图标，极度紧凑场景下的图标按钮必须强制绑定 Tooltip 说明具体功能。 | `禁用按钮与孤立图标反馈规范：disabled 按钮外层包裹 div 并绑定 Tooltip (如 cursor-not-allowed + 悬浮提示「需具备管理员权限方可执行」)；无文字图标按钮强制绑定 Tooltip (如 title="切换资产视图" 或自定义 Tooltip 组件)，严禁直出无说明单图标。` |
| **“点错了直接把数据删了 / 怎么点一下就直接生效了没个反悔”** | **缺少防错机制与破坏性操作裸奔**：高危破坏性操作（删除资产、解散集群、解绑租户）缺乏风险梯队防护，仅用简单单击或弱气泡确认；复杂资源配置缺乏提交前预览与计费明细。 | 建立“操作风险三级分层防御体系”：1. 低危（修改显示偏好/筛选）：直接生效无需确认；2. 中危（重命名/暂停实例）：Popconfirm 气泡或轻量 Modal 二次确认；3. 高危破坏性（不可逆删除/注销）：阻断式 Modal + **明确列出受影响对象清单**（如“将同步删除以下 3 个关联实例和 12 条策略”）+ **强制用户输入验证口令或登录密码**（如输入「确认删除」或操作密码）才高亮激活危险红按钮；4. 复杂多步骤资源配置末尾强制展示“配置预览与计费明细”。 | `高危破坏性操作防护：删除/解绑弹窗必须包含：1. 危险红色警示标题；2. 具体影响范围清单 (<ul class="list-disc pl-4 text-xs text-[#D9363E]">列出关联资源)；3. 验证输入框 (要求输入「确认删除」或密码后确认按钮才解除 disabled)；确认按钮使用 bg-[#D9363E] hover:bg-[#B3262E]。` |
| **“配完了弹个窗点关闭就没了，不知道下一步去哪 / 每次都要点进详情页才能处置，太麻烦了”** | **操作不连贯与链路冗长（死胡同与逐级下钻）**：1. 闭门死胡同弹窗：向导或核心操作完成后仅展示“成功”与“关闭”，中断业务流；2. 强迫逐级下钻：列表行操作仅有“详情”，逼迫用户必须进入三级详情页才能点击“处置/加白”，操作链路深度过大。 | 实施“操作闭环与就地快捷通道”：1. 完成态深链直达：向导/接入完成弹窗必须提供直达下一步主营业务场景的深链按钮（如“【完成并前往云资产管理】”、“【立即创建防护策略】”）；2. 高频核心动作列表就地释放：将最高频的动作（如“立即处置”、“加白名单”）直接外露在列表操作列第一优先级，点击右侧滑出处置抽屉就地闭环，严禁强迫用户必须跳入详情页才能执行常规处置。 | `操作链路闭环与高频快捷直达：向导完成弹窗主按钮设为深链跳转 (如「前往【云接入管理】查看详情」)；列表行操作外露高频直达动作 (如「立即处置」作为主操作，点击打开 Drawer 就地处置)，次要操作收纳至「更多 ···」下拉，避免强迫用户进入详情页。` |
| **“这选项为什么是灰的不能选 / 明明选了禁用了下面那一堆为什么还灰着摆在那里”** | **禁用与隐藏边界混淆（哑巴置灰与假性暴露）**：1. 表单内部互斥项未做条件隐藏（如勾选“禁止该用户登录”后，“应用授权”依然置灰留存，引发用户反复点击与困惑）；2. 外部受限项（缺权限/缺证书）直接置灰却无任何 Tooltip 说明。 | 严格执行**“禁用 vs 隐藏黄金法则”（铁律）**：<br>1. **条件隐藏**：凡是由当前表单内部其他字段联动决定的无效项，**必须直接隐藏**，不占用用户视线，消除视觉干扰；<br>2. **保留禁用 + Tooltip**：凡是因外部系统依赖、前置实体未创建、或权限不足导致的不可用项，**必须保留置灰展示**，并强制在 Hover 时显示 Tooltip：`[不可用根因] + [快捷开通/配置链接]`。 | `落实禁用与隐藏铁律：当前表单内联动控制的组件使用 v-if / 条件渲染直接销毁（如 isLoginDisabled ? null : <AppAuthSection />）；跨实体依赖受限的组件保留 disabled，并包裹 Tooltip 提示「当前节点尚未开通 HTTPS 证书，前往配置 ↗」。` |
| **“点了帮助文档跳去了一个大目录找半天 / 点开帮助链接直接 404”** | **帮助引导泛化未定向与死链**：点击配置项旁边的帮助问号图标，直接跳转到全系统泛目录首页，让用户在海量文档中手动检索；或外链因内网环境、路径失效导致 404/400 报错。 | 实施“深度链接定向锚点与就地帮助法则”：1. 深度链接直达（Deep Linking）：帮助外跳必须携带页面/段落锚点（`#section-corpid`），精准直达目标操作章节；2. 就地内嵌帮助抽屉：核心高频难题优先采用侧边轻量 Drawer 展示精简指引，避免跳出；3. 严格校验外链可达性与内网降级机制。 | `帮助图标交互优化：问号图标绑定精确锚点外链 (href="https://docs.corp.com/guide/auth#corpid" target="_blank")；高频关键配置项改用点击打开右侧简版指引抽屉 (Drawer width: 360px)，在当前视口内提供操作图解，无需离开主流程。` |
| **“已经开启了功能，顶部还一直挂着建议开启的横幅”** | **引导文案未与业务状态联动（静态僵尸横幅）**：引导横幅或通知条静态写死，在用户完成配置或功能开启后未实时感知业务状态变化，依然以刺眼的警示色悬挂在页面顶部。 | 实施“引导文案状态联动消隐机制”：所有提示性横幅必须与后端业务状态建立动态响应绑定；一旦检测到目标功能处于“已开启/已配置”状态，引导横幅必须**自动平滑消隐（Fade Out）**，或收敛为只读卡片内的“已保护”轻量绿色徽标。 | `引导横幅增加响应式状态判定：v-if="!isFeatureEnabled" 且添加过渡动画 transition-all duration-300；当检测到状态为 enabled 时自动销毁横幅组件，彻底清除页面上无意义的过期操作提示。` |
| **“填了半天表，不小心点了个链接/后退，填的二十个字段全没了”** | **未保存脏数据丢失（缺少防错守卫）**：复杂表单未建立脏数据（Dirty State）监听机制，用户误触外部链接、面包屑、侧边栏或浏览器后退时，页面直接静默卸载，导致输入内容蒸发。 | 实施“未保存脏数据导航守卫（Dirty State Guard）”：1. 表单录入时动态标记 `isDirty = true`；2. 用户触发页面离开、Tab 切换、弹窗关闭或浏览器后退时，**强制触发二次拦截 Modal**（“当前有未保存的修改，离开将丢失已填数据，确定离开吗？”）；3. 支持草稿本地自动暂存（LocalStorage Cache）。 | `表单增加离开守卫：监听 beforeunload 事件与路由钩子 beforeRouteLeave；若 formIsDirty 则弹出阻断确认框 (ElMessageBox.confirm)；关键长表单启用每 30 秒自动暂存草稿功能，防止意外数据清空。` |
| **“批量发了几百条，只弹了个‘成功’，到底有没有失败的、哪条失败了根本不知道”** | **批量操作黑盒与无溯源反馈**：批量异步操作（批量发送、批量下发策略、批量导入）处理完毕后，UI 仅弹出一个模糊的全局 Toast 报“操作成功”，对部分失败项未做分流统计与明细展示。 | 实施“批量操作溯源看板三要素”：所有批量操作结果必须提供看板级反馈：① **状态总量统计**（“共 100 项，成功 95 项，失败 5 项”）；② **失败原因明细抽屉**（表格列出失败项 ID、失败原因如“手机号格式非法”）；③ **一键重试入口**（支持仅对失败的 5 项一键重新下发）。 | `批量操作结果采用分项反馈组件 (Result / Drawer)：展示成功与失败计数饼图/胶囊；失败项渲染独立表格，包含字段：[条目标识]、[失败根因]、[重试按钮]；提供「一键重试全部失败项」按钮，严禁使用单行 Toast 覆盖批量操作。` |
| **“新建完一个用户，人呢？还要去五百个人的列表最后一页翻”** | **主干操作流程割裂与定位失锚**：新建对象成功后，系统仅关闭弹窗将用户抛回大列表，既没有提供“继续配置关联权限”的连贯通道，也没有在列表中高亮定位新对象（新条目默认沉在列表末尾）。 | 实施“连贯任务流与新建置顶高亮机制”：1. 任务连贯推进（Create & Configure）：向导/弹窗支持“保存并继续配置权限”按钮，避免链路断裂；2. 列表新建倒序置顶：从创建弹窗返回列表后，默认按创建时间倒序排列，**将最新生成的条目置顶并施加 3 秒浅黄微光高亮**（Fade highlight），确保用户即时定位。 | `新建成功回调机制优化：1. 弹窗提供「保存」与「保存并分配权限」双按钮；2. 成功后列表自动触发刷新并将排序重置为 createTime desc，最新行注入高亮动效 (bg-blue-50/50 transition-colors duration-3000) 确保视线锚定。` |
