# 资料投喂与经验蒸馏手册 (Distillation Guide)

> 💡 **核心定位：纯临时过程暂存区 (Inbox / Staging Area)**
> 
> 本目录 **不是** 长期索引的资料库，而是规划人员向织雨随时投喂原始资料的 **“过程暂存池 / 收件箱”**：
> 1. **零门槛随手扔**：无论是原始 PRD 片段、评审会议纪要、设计推演草稿、还是吐槽复盘，无需复杂分类，直接作为 `.md` 或 `.txt` 文件丢在此目录下；
> 2. **织雨深度蒸馏**：唤起织雨研读并提取背后的设计思维与规则，**将其永久沉淀到系统的 `01` 到 `04` 核心模块中**；
> 3. **随学随清**：一旦经验成功蒸馏并合入核心模块，**此目录下的过程文件即可随时删除清理**，保持工程轻量整洁。

## 📚 织雨蒸馏学习的具体维度大纲 (What Zhiyu Distills)

无论你扔进来的资料格式如何混乱，织雨在阅读时都会自发寻找以下 4 类“设计营养”，并将其标准化收敛：

### 1. 业务原语与标杆案例方案 ➔ 注入 `01-system-solution-design/`
* **识别点**：
  * 这个业务在解决什么问题？属于哪类高频需求？（对象管理？配置同步？监控驾驶舱？排障拓扑？）
  * 具备哪些专属业务上下文？针对该类型的通用设计场景是怎么落地的？为什么这么设计（Why 因果）？
* **蒸馏产物**：
  * 严格遵循 [`标杆方案案例蒸馏指南.md`](标杆方案案例蒸馏指南.md) 执行提纯，合入 `01-system-solution-design/②设计点思考/2.2-标杆案例库.md`。

### 2. 槽点病因与微观微调经验 ➔ 注入 `02-detail-tuning-design/`
* **识别点**：
  * 规划人员当时吐槽了什么？（“太挤”、“小标题碎”、“折线像刷子”、“操作列太乱”）
  * 资深设计师诊断出的**真实物理病因**是什么？（缺少 8px 网格？大框套小框？stroke 太粗？缺乏主次颜色？）
* **蒸馏产物**：
  * 形成一条新的 **“规划口语 ➔ 真实病因 ➔ 专业决策 ➔ AI 精准 Prompt 片段”** 映射，补充进 `02-detail-tuning-design/b-tuning-strategy/`；意图穿透心法注入 `b-tuning-strategy/b.1-设计细节吐槽转译词典.md` 引言。

### 3. 客观尺度与组件/套头硬指标 ➔ 注入 `03-design-assets/`
* **识别点**：
  * 推理过程中是否确立了新的尺寸约束或框架模板？（如：页面大盘套头骨架、树节点行高 36px、新场景下的状态浅底深字三元组色阶？）
* **蒸馏产物**：
  * 固化为客观的数字 Tokens、页面模板或组件级规则，更新进 `03-design-assets/page-templates/`、`tokens-cheatsheet.md` 或 `components/`。

### 4. 经典决策与前后对比 ➔ 注入 `04-workflows-and-cases/`
* **识别点**：
  * 这个案例是否具有极高的代表性？能否作为大模型“举一反三”的范例？
* **蒸馏产物**：
  * 抽象为包含“原始吐槽 ➔ 设计师诊断 ➔ 输出 A（面向规划） ➔ 输出 B（面向 Coding AI）”的标准 Demo，收录进 `04-workflows-and-cases/few-shots.md`。

## 🚀 投喂与蒸馏操作流水线 (Quick SOP)

1. **投喂**：将包含推演过程或项目经验的任意文件直接丢在 `learning-materials/` 下（如 `learning-materials/temp-demo-cases.md`）；
2. **指令**：在对话中对织雨说：
   > “织雨，请学习 `learning-materials/temp-demo-cases.md` 中的设计推演过程，按蒸馏大纲提取经验并更新到 01~04 模块中。”
3. **闭环**：织雨更新完核心文件并向你汇报后，你即可直接 `rm` 删除该暂存文件，零负担维护。
