## 二、逐项详情

### 1. 4 类工作类型的"设计拔高经验"补充

- **为什么**：突破点的**第二个入口**（按工作类型扫）需要经验底座。现在 1.3 第八节那张表"这类工作该追求什么"是空的，导致入口 2 只能靠 AI 自发判断，**必然缺漏**——GA 演练就漏掉了"结果可视化预览"。
- **要做**：为 ① 配置运维 ② 运营分析 ③ 排障闭环 ④ 价值感知 四类，各沉淀
  - 【**思考经验**】这类工作该往哪个方向拔高；
  - 【**解法经验**】这类工作里别人用过哪些招。
- **产出物**：1.3 第八节表格填实（或拆成独立经验文件后回链）。
- **验收**：拿 GA 配置需求能自动扫出"配置结果要可见、可预期"这类目标之外的机会点。

### 2. 突破点拆解演练扩到 10 个左右

- **为什么**：样本太少（现在 2 个），验证不出方法稳不稳。
- **要做**：按常见类型各跑几个，覆盖：可见性 / 降噪 / 信任 / 响应闭环 / 低摩擦 / 研判 / 防错 等。
- **现状**：2 个（含「GA 配置提效」）。
- **产出物**：演练案例集（放哪待定：并入 1.3 第五节，或独立案例文件）。
- **要求**：每个案例必须标出**哪些突破点来自目标、哪些来自工作类型经验**，方便看清缺口。

### 3. 突破点 → 草图 的衔接与执行规范

- **为什么**：[1.3 第七节](../01-system-solution-design/①需求理解与分析/1.3-体验目标突破点拆解.md) 目前只是**占位**，只写了"按档位成套出图"，草图画法、形态、交付规范都没定。
- **要做**：
  - 定义"突破点 + 分档点子"**如何传递**到草图；
  - 定义草图的**画法与形态**（关键框架与布局占位、设计点重点突出、不涉及设计细节、配一句思路简述）；
  - 定义"按档位成套输出"的**呈现形式**（基线 / 优化 / 创新 / 变革各一套）。
- **产出物**：草图执行规范 md（新建）。
- **关联**：1.3 第七节占位待替换。

### 4. 体验目标检视：避免低 level 目标

- **为什么**：**目标定得低，后面的突破点会跟着降智**（目标多大，天花板就多高）。现在缺少对体验目标的"检视 / 提级"动作。
- **要做**：给 1.2 补一层检视机制——判定目标是否够格（是不是只写了功能、有没有够到高层感受点），不合格就打回重写。
- **产出物**：1.2 里补检视清单 / 判据。
- **关联**：1.2 体验目标。

### 5. 相关报告 / 说明书调整优化

- **为什么**：1.3 是新增环节，说明书（5.0）与相关报告模板还没跟上，会割裂。
- **要做**：把 1.3 的产物（突破点 + 分档点子 + 草图）纳入说明书结构；核对现有模板与新增流程是否一致。
- **产出物**：更新后的说明书模板 / 相关报告。
- **关联**：5.0 设计说明书标准模板。
