# 1.4 草图发散与方向确认 (Sketch Divergence & Direction Confirmation)

> 💡 **中枢定位**：
> 本文档承接 [1.3 体验突破点拆解](1.3-体验突破点拆解.md)，是【方案系统设计主线】Part1 的**收尾环节，也是整条主线上唯一的分岔点**。
> * 1.3 定的是"**在哪破、怎么破，摆出几档打法**"；
> * 本步定的是"**画出来是几个样子、走哪一个**"。
>
> ⚠️ **这一步的性质是"出方向"，不是"出方案"。** 草图**整体**不是线框图（高保真区除外），它只回答一件事：**同一件任务，能走成几条不同的旅程，每条旅程里人被服务的方式差在哪。**

> 🛑 **阶段铁律**：
> 1. **精度分两档，不是一个精度**：**常规区**（筛选、工具栏、分页、输入框、选择框、按钮等约定俗成件）只画**关键框架与布局占位**；**高保真区**（每页主图 + 主清单、以及 1.3 承诺的创新点子所在区域）必须**做详细设计**——画到最好效果、图表与图标配色自由、**Token 写进图下说明**。细则仍不进草图（那是 4.1 的活），但"这块长什么样"必须在草图里看得见。
> 2. **一档一套、必须成套**：一个方向要**整套页面**（不只画一屏），否则看不出这个方向能不能站住——很多方向单屏好看，连起来就断了。
> 3. **非设计点允许占位**：不承载突破点的区域，用一个灰块 + 一句说明带过（"此处沿用现有列表页，本次不动"），**不许为了显得完整而随手画满**。
> 4. **每个方向必须能回答"它对应哪几处突破点"**：对不上的草图是自嗨，退回重画。
> 5. **两个方案必须真的岔开**：如果只是"把侧栏换成顶部栏"，那是一个方案的变体，不叫两个方案。
> 6. **到这里必须停（默认不可跳）**：草图出完即停在确认闸门，**未获方案选定，严禁进入页面清单、模板选型、线框图与任何代码**。**停下之前必须先过草图门禁**（`bash tools/gate-ex.sh 1.4 _output/<业务名>/草图-<业务名>.html _output/<业务名>/01-主场景-<业务名>.md` 拿到全绿：结构 6 条（含吸顶）+ 文案 7 条 + 能力位 1 条 + 占位可交接 1 条 + **页内 Tab 面板拆到块 1 条** + **场景链路可走通 1 条** + **页内视图清单闭合 1 条** + **交付面纯净 1 条（EX-1.4-21）** + **主图存在 1 条（EX-1.4-22）** + **框内解释禁令 1 条（EX-1.4-24，词表 + 结构双判据）** + **跨方案切换面板完整 1 条（EX-1.4-26，堵"方案二点开空白"）** + **三级导航与步骤齐 1 条（EX-1.4-34，堵"页面按编号罗列、步骤对不上 1.1"）** + **步骤-页面承接与闭环 1 条（EX-1.4-35，堵"入口在最后一页、页面不挂在步骤下"）** + **重复副本一致 1 条（EX-1.4-36，堵"改了这处漏了那处"）** + **覆盖 1 条（EX-1.4-37，堵"清单里有页、剧本里没有"）** + **两套对齐 1 条（EX-1.4-38，堵"两套剧本步名对不上"）** + **可视化布局 1 条（EX-1.4-39，堵"监控 / 概览页普通图表单块通栏凑版面"，核心主图 / KPI 允许 full）**，**机检不合格同样不许交付**），带着硬错给用户看，等于让他替你挑按钮位置。**唯一例外**：用户**明确说出**"跳过草图 / 不用给我看草图"时，可越过闸门并**默认以方案一执行**；用户只说"给我出说明书"不算跳过，见第七节铁律。
> 7. **能力必须满，精度分两档**：草图必须与线框**同源**——主按钮用主题蓝（`#1C6EFF`）、主按钮在左取消在右、抽屉/弹窗/表格不混用、页面分区骨架一致；**否则草图到线框会出现"我选的方案被改了"的断裂感**。**常规区**的精确像素、星号占位、图标、动效**可以不管**；**高保真区**反过来——图表、图标、动效、多色都可以画，只**不写组件名**（那是 4.1 的活），**色值与 Token 写在图下、不写图内**。**但"能力项"不是精度**：时间范围、筛选、排序、搜索、新增、编辑、启停、复制、批量、导出、分页、刷新、编辑态、**跨页入口与去向（`data-go` / `data-from`）**、**页内 Tab 的每一面内容**——**一个都不许丢**，画不出来就占一块色块 + 一句说明。
>
> 8. **四层剧本：方案 → 场景 → 步骤 → 页面，不按页面编号罗列**：`方案一/二` 两个 tab → 每条主场景一个**场景 tab**（两套下同组同序，默认 S1）→ 场景内按 1.1 旅程顺序排 **`Step N` 步骤头**（`Step N：【步名】` + 意图 + `关联界面 Px` + `看到：…`）→ 步骤下面是**完整页面块**。**每处出现都画全**：两套共性页各画一遍、跨场景各画一遍、同场景不同步骤/不同 Tab 也各画一遍，**不许用 `SAME` / `scene-ref` / "同上"省**。**页面编号 `P1..Pn` 是资产编号、跨方案跨场景恒定；每次出现另有 `data-occ` 实例号**。判据：**随便挑「方案 + 场景」，从 Step1 到末步末态不跳出去，旁边的人照着步骤头能听完。**
>
> 🛑 **两条轴分开判，别再混着用**：
> * **能力轴（必须满，缺一个就是功能缺失）**：每个能力都要在**它该在的位置**占一块 + 一句话说清"这是什么能力"；**位置本身也是结构**——列表页筛选区在页头右侧、工具栏在表格上方、排序挂在表头列上（`03-design-assets/page-templates/01-page-types.md`）。
> * **精度轴（分两支，不许用一句话概括）**：**常规区可以降**——精确像素、单元格字段值明细、组件样式、图标、动效、Token 都不管；**高保真区不许降**——主图与主清单要画到最好效果，图表 / 图标 / 配色自由，**Token 必须写、且写图下**。
> * **列名属于能力轴**：列名是用户核对"需求覆盖没覆盖"的凭据，按 PRD 列全；**单元格里的值**才是精度轴。
>
> 🛑 **能力项写在正文说明里＝没写**：用户和下游线框都只看图。图上没有那块位置，说明书第 7 节就不会有，功能就丢了。
>
> 🛑 **另一条边界**：线框图**不能因为"草图这样画的"就沿用草图的松散画法**——草图继承的是**分区与主结构**，不是它的精度。**继承结构，重做精度。**
> 🛑 **两个独立顺位任务的边界（与 5.0 铁律 25 配对，别互相越界）**：**草图**只对"思路、方向、内容"负责——分区、信息位置、动作落点、能力边界要对；**常规区的视觉与控件形态不对设计规范负责**（灰底斜体、单色灰阶、把"搜索 / 刷新"写成文字而不画控件，在这个阶段都属于允许的"还没细化"语汇）；**高保真区相反**——图表与图标按最优表达画，颜色不受三色限制，Token 写进图下说明。**说明书第 7 节线框**反过来——**内容不增不减，但样式必须按 `03-design-assets/` 重新设计**（时间日期用 `comp-date-picker` 复合日期筛选器、多条件按 `D09-EP02` 选壳、下拉按 `comp-select`、表单分区标题用 `design-form` §5.4 蓝竖条……）。**一句话记法：常规区可以不合规、线框必须重做；高保真区的表达必须继承、线框不许重画。**

## 零、这一步产出什么

| 项 | 内容 |
| :--- | :--- |
| **输入** | ① 主要场景清单 S1~Sn（1.1）② 各场景体验目标与指标（1.2）③ 各场景突破点 + 分档点子（1.3） |
| **产出** | ① **2 套方案草图**（方案一 / 方案二），每套 = **一条完整旅程（who / what / how / wow 四段）** + 整体设计说明 + 设计思考点 + 逐页草图与逐条说明<br>② **用户选定结果**（若该方案声明里含目标 / 指标变更，选定即同时授权；确认后留档，作为下游唯一入口） |
| **内部留档（不交给用户）** | 档位组合 / 突破点落点 / 动作覆盖表 / 五段代价 / 目标与指标变更 |

> 🛑 **交付面 / 校验面分开（先记住这一条，再往下读）**：用户打开草图文件，**从上到下只该读到 5 块**——① 页头一行 ② IA 树 + 页面清单 5 列 ③ 两套方案对比表 ④ **方案 tab + 场景 tab**（默认方案一 / S1）⑤ 场景内**按步骤串行**的页面（每屏含图下标号说明）。**其余全是校验面**：页内视图清单 `view-ledger`、场景链路表 `flow-ledger`、清单×草图覆盖矩阵、G-05 闭环覆盖、占位清单 `ph-ledger`、动作覆盖表、档位/代价/落点留档——**一律放文末单一 `<details class="handoff">` 折叠区，默认收起，不进正文**。
> 🛑 **为什么**：这些台账是给门禁和下游 4.1 / 5.0 读的交接件，不是给用户看的。把它们摆进正文，分析越严谨用户看到的越像审计底稿——**这是实测翻车点**（DEM 卡慢需求门禁全绿，用户仍判"不可用"）。机检 `EX-1.4-21` 会拦"台账泄漏进正文"。
> 📌 **一句话**：基于需求场景，把 1.3 的点子装进**两条未来旅程**，摆成两套，用**不懂业务的人也读得懂**的写法摆出来，让人一句话就能选。

### 🛑 四条输出铁律（最重要，先看这）

| # | 铁律 | 反面（实测犯过） |
| :---: | :--- | :--- |
| **1** | **只给 2 套**，两套的 **what / how 必须不同**（wow 也应不同）；两套都要过**实质自检**（每套 ≥2 段旅程质变含主战场、说得出"哪一段从什么变成什么"） | 一上来给 3 个方向 + 全量信息，**选择过多、信息过载**；或两套只是档位滑动，成了**拼盘**；或贴了"创新路线"却看不出质变在哪 |
| **2** | **不画常规版**，从**创新版 / 优化版**起画 | 把"最没设计含量"的那套也摆上台 |
| **3** | **图的框里只放内容，不放解释；解释一律写在草图正下方**——图上打标号，图下按标号逐条写"做法 + 为什么" | ①框里塞解释句挡着看结构；②**只有编号、图下没有说明**，用户看不懂这处在干嘛 |
| **4** | **所有文案必须站在用户视角**：说清"你会看到什么、你能做什么、做完会怎样"；**不写自造机制名、不写内部编号、不新造词；行业既有术语照用** | 用户读不懂、也讲不出去的，一律换掉 |

> 📌 **为什么是 2 套不是 3 套**：三套让用户进入"比较模式"，注意力耗在分辨差异上；两套进入"选择模式"，一句话就能定。**两套都各给一句实话：换来什么、要多付什么。**
> 📌 **为什么常规版不画**：常规版是"别人怎么做我们怎么做"，它**不需要被选择，只需要被满足**——它是优化版/创新版的地基，画出来只会稀释重点。**如果两套都还停在基线上，说明这需求没设计空间，直说。**
> 📌 **铁律 3 与铁律 4 的关系**：**框里不解释，但图下必须解释。** 标号是"图"与"说明"之间的钩子，不是装饰；没有图下说明的标号等于没说。
> 🛑 **"解释句"靠词表抓不全，按句式判（EX-1.4-24 词表 + 结构双判据）**：`做法/为什么/即可/当场` 这类固定词只是已知的一撮；图框内凡是成句的 **"操作 → 结论"口语式**（`按 X 筛一下就知道有没有…`、`点开就能看出…`）和 **"极值 + 持续"口语式**（`最久压了 3 小时…`、`最快等了…`）一律判解释句泄漏，搬进图下 notes。**判据是句式结构，不是背词表**——换个动词换个宾语照样拦得住。

### 交出去的是什么：一份单文件 HTML（页头 + 对比表 + 两个 tab）

**结论：`页头（页面总数 + 清单）→ 两套方案对比表 → [方案一 tab | 方案二 tab]`。**

| 内容 | 要不要 | 说明 |
| :--- | :---: | :--- |
| 场景名、体验目标、突破点清单、档位上限 | ❌ **不放顶部** | 这些**已经有共识**（1.1~1.3 都过过了），再摆一遍是重复劳动，还挡着看图 |
| 方案标题句（如"系统出草案，人只改差异"） | ❌ **不要** | **方案只叫「方案一」「方案二」**；这套方案是什么、解决什么，写进对比表的「整体设计说明」 |
| 推荐标 / 吸顶差异条 / 等级徽标 | ❌ **不要** | 两套的差异由对比表四段承担，不再靠徽标和"3 条差异" |
| **⓪ 页头标题 + 一行小字** | ✅ | `需求草图示意` + "关键设计点已给出设计表达，常规能力以占位交代；仅用于思路对齐。" |
| **① 有哪些页面 / 子页** | ✅ | **放最上面**；信息架构树 + 页面清单（见第三节） |
| **② 两套方案对比表** | ✅ | 整体设计说明（含代价）+ 各自的设计思考点，**表格形式** |
| **③ 切换条（吸顶）** | ✅ | 只有两个：`方案一` ｜ `方案二`，点击切换 |
| **④ 方案 tab 内：场景 tab + 步骤流** | ✅ | 每条 `Sx` 一个场景 tab（两套同组同序、默认 S1）；场景内 `Step N` 步骤头 + 该步的完整页面块；每处出现都画全 |

> 🛑 **不要前置一堆元信息**：用户点开文件，第一眼应该看到**页面规模和页面清单**，不是"场景 S1 / 体验目标 / 档位上限"这种台账。
> 🛑 **但对比表必须有**：两套方案的取舍要能并排读完；只给图、不给"两套各在想什么"，用户只能凭感觉选。
> 📌 **页面清单必须有**：否则用户不知道"这个需求一共几个页面、两个方案差在哪些页面"。

### 每一套方案的结构

```
方案一（tab）
├── P0 页面名（形态 · 主战场?）
│   ├── 草图：区块右上角打标号 ① ② ③（同一组内容只打一个）
│   └── 图下逐条：① 做法：…… 为什么：……
├── P1 页面名（形态）
│   └── …
└── P5 页面名（形态）
    └── 与方案一相同 → 一行交代，不重复画
```

> 📌 **设计说明必须回答"这个想法从哪来"**：每条思考点都要指回现状里的一个具体卡点（用户原话或 1.1 的卡点），**不写"因为这个方案更好"**。

> 🚫 **不设视觉样板、不设选型库**：草图长什么样**完全由执行时模型的能力上限决定**——越美观、越贴合需求场景越好。**不要去找、也不要写"参考视觉库 / 视觉手法表 / 风格母题 / 对着某样板选形态"这类指引**，这些库现在都不存在，写了也是空指引。本节只规定交付结构与可判下限（见 §五、§四-1），**不规定画面表现**。

## 一、先分清三张图（最容易混）

| 图 | 在哪一步 | 回答什么 | 精度 | 谁看 |
| :--- | :--- | :--- | :--- | :--- |
| **现状旅程图** | 1.1 | 现在人怎么干、卡在哪 | 流程级 | 内部 |
| **草图** | **1.4（本步）** | **同一任务能走成几条旅程，走哪条** | **混合精度：高保真区 = 设计级 / 常规区 = 布局占位级** | **规划人员（要选）** |
| **实现线框图** | 4.1 / 5.0 | 选定那种摆法，具体怎么落地 | 组件级 | 开发 / 评审 |

## 二、怎么出方案（先定未来旅程，再把点子装进去，最后成 2 套）

一套方案不是"挑一组点子拼起来"，也不是"挑两个页面骨架"——它是**一条完整的未来旅程**。

> 🧭 **为什么从旅程出发，而不是从"能怎么摆"的维度出发**：维度清单（谁先动 / 放哪儿 / 纵向还是横向）是**换壳清单**，挑两行组合出来的两套，必然是"摆法不同、做的事一样、感受一样"——用户看完会说"这不还是一个东西"。**旅程问的是另一件事：同一件任务，人被服务的方式是怎么不同的。**

### 思考顺序：选任务 → 画两条旅程 → 装点子 → 判是否真岔开

```text
① 选主任务：从 1.1 的 Sx 里挑这件事的主线（不是挑一个页面）
        ↓
② 画两条未来旅程：同一任务，两种"人被服务的方式"
   每条都写满 who / what / how / wow 四段（见 §二①）
        ↓
③ 把 1.3 的创新点子装进旅程的对应段（原料不变，见 §二②）
        ↓
④ 判两条是否真岔开：what、how 必须不同，wow 也应不同（见 §二③）
        ↓
⑤ 常规版不画（它只是这两套的地基）
```

### ① 未来旅程长什么样：四段（who → what → how → wow）

> 旅程不是"流程图"，是**一句一句能念出来的体验路径**。四段各回答一个问题，写法固定。

| 段 | 这一问答什么 | 写成什么样 | 两套方案是否必须不同 | 例（合规检测任务） |
| :---: | :--- | :--- | :---: | :--- |
| **who** | 谁来做？系统替他做了多少？（人机分工） | 一句话：人是"自己圈条件的人"还是"只处理 3 件事的人" | 可以相同 | 方案一：系统已判完，人只确认；方案二：人先说清范围，系统再判 |
| **what** | 通过什么方式 / 工具 / 手段办成？（承载形态） | 一句话：这件事靠在什么地方、什么形状的东西上办完 | **必须不同** | 方案一：一份"待处理 3 件"的清单；方案二：一张按部门铺开的合规水位图 |
| **how** | 人怎么使用与操作？（几步、要不要来回找） | 一句话：从进来到办完走几步、要不要跳页、要不要自己比 | **必须不同** | 方案一：进页即确认，两步办完；方案二：先看图定位、再点格进去处理，四步 |
| **wow** | 哪一刻超出预期？（峰值体验） | 一句话：**哪一刻 / 因为什么 / 意外在哪**（口径同 1.3 的 wow 判据） | **应当不同** | 方案一：点完"开始检测"2 秒后直接告诉你"这 38 台里 3 台会被拦下，先看这 3 台"；方案二：一眼看见哪片红，红格点开就是名单 |

> 🛑 **wow 不是可选项，也不是加装饰**：它必须来自 1.3 里已判过 wow 的创新点子，不能在 1.4 现编（1.3 的判据是"哪一刻 / 因为什么 / 意外在哪"三样齐）。给系统加一句"恭喜完成"、加个动效，不算 wow。
> 📌 **who 可以相同**：两种服务方式未必要换人机分工，换"系统怎么陪人做完"也算（例如 who 都是"人确认"，但 what 一个是清单、一个是分布图）。**但 what 和 how 不能相同**——那是同一件事换了个排版。

### ①-附 两条旅程怎么想出来：三条抓手（不是维度清单）

> 抓手是**产生差异的方法**，不是分方案的依据。**分方案看旅程四段，不看用了哪个抓手。**

| 抓手 | 变的是什么 | 问句 | 例 |
| :--- | :--- | :--- | :--- |
| **换分工** | 谁先动、系统替人做多少 | 这件事能不能不按"人先找、系统再答"来？能不能系统先判完，人只确认？ | 系统按资产画像出整套草案 vs 人自己圈范围 |
| **换载体** | 信息以什么形状被看见 | 现在人是在**读**一张表，还是能**看见**一条路径 / 一片分布 / 一条时间轴？ | 五段链路画成能看见卡在哪的路径 vs 一张写着五段用时的表 |
| **换时机** | 什么时候给、给到哪一步 | 提示能不能从"事后报告"挪到"提交前"？能不能边做边给？ | 巡检完出报告 vs 配置时就提示"这 3 台会离线" |

> 📌 **三条抓手可以混用，但两条旅程各自的取向要一致**：方案一若在 who 上"系统先判"、在 what 上又退回"给人一张全量表"，那就是自己跟自己打架，读起来像两个方案拼的。
> 📌 **视觉层面的创新同样算**：换载体让"第一眼看到的东西"变了（从表变成路径 / 分布），就是质变，不必非要换人机分工。
> 📌 **判一句（替掉旧的"形状和步子"）**：把两条旅程并排念一遍——**what 和 how 说的是同一件事、wow 也一样，就不是两个方案。**

### ② 把点子装进旅程：原料不变，装法变了

档位来自 1.3 的三档点子表（常规 / 优化 / 创新）。**1.4 拼方案只用创新档**——常规版与优化版是地基，不进方案（见 §零「不画基线版」）。

1.3 的创新点子**照取，仍然是两套方案的原料**。变的是**怎么用**：不是"每处挑一条取向"，而是"**每个点子装到旅程的某一段**"。

| 装法 | 硬要求 | 为什么 |
| :--- | :--- | :--- |
| **每个点子指到一段** | 写清 `点子 → 装在 who / what / how / wow 的哪一段 → 这一段从什么变成什么` | 指不到段的点子，说不出它服务哪一段，就没法进方案 |
| **不许逐处挑取向拼装** | 两套方案不能是"每处各挑一条点子"拼出来的，必须各自能念完整旅程 | 逐处拼装 = 机械组合，两套做着同样的事 |
| **同一段可以相同** | 差异不在这一段的，标「两段相同」，不重复画；但 **what、how 两段不许都相同** | 为了显得不同硬造差异，反而看不清真正不同的地方 |

> 🛑 **原料不变，不等于可以不用点子**：1.3 的创新点子该用的还是要用；区别只在于它们必须**落在同一条旅程上**，而不是散在各处各自成立。
> 🛑 **两条旅程各自的取向要一致**：方案一若在 who 上"系统先判"、在 what 上又退回"给人一张全量表"，就是自己跟自己打架，读起来像两个方案拼的。
> ⚠️ **创新档进方案，必须同时给两行**：`换掉了什么`（对象 / 载体 / 时机 / 分工）与 `防误伤怎么办`。两行缺一行，这处降回优化档——**这是防止把「追覆盖率→狂下发→断业务」这类风险藏在一个漂亮方案里。**

### ③ 判两条旅程是否真岔开

```text
① 两条旅程各写一遍：who → what → how → wow（写不出四段的，回 §二①）
        ↓
② 比 what：两套"靠什么办成"是同一种东西吗？
      相同 → 还没岔开，回 §二①-附 换抓手
        ↓
③ 比 how：两套从进来到办完，步数 / 是否跳页 / 要不要自己比，一样吗？
      相同 → 只是换了排版，回 §二①-附
        ↓
④ 比 wow：两套各自的"意外时刻"是同一处吗？
      相同 → 差异不够，至少让一条说出不同的峰值
        ↓
⑤ 都过了 → 这一对成立；what 或 how 相同 → 判机械组合，重画
```

| 位置 | 怎么写 | 在文里怎么表达 |
| :--- | :--- | :--- |
| **方案一 / 方案二** | 各写四段：who / what / how / wow | 对比表里四行对齐，让两套的差异一眼读完（见 §六·1） |
| **路线名怎么起** | 用「用户第一眼看到的东西」命名：待办 / 分布 / 时间轴 / 体检报告 | 名字要能让人不看图就知道这套长什么样；**不用"换对象 / 换载体"这类方法名当方案名** |
| **差异怎么写** | 一句人话，两头都在 | 例：`方案一：系统先判完，人只确认 3 件 ／ 方案二：人先说范围，再看哪片红`；不说"更智能 / 更高效" |

> 🛑 **两套都要写出代价**：都是创新级，不代表都免费。**谁都不许写成「全能方案」**——两套的代价必须不同，否则用户没有选择的理由。
> 🛑 **不凑第三个**：如果只能想出两套像样的，就给两套。**硬凑的第三套，一眼就看得出是凑的。**
> 🔎 **判「机械组合」只需一句**：两套的 what 与 how 说的是不是同一件事？是，就只是换了个排版。

### ④ 特例：某一段实在岔不出两种做法时

| 位置 | 要求 |
| :--- | :--- |
| **该段** | 该段降为优化档，并在方案声明里写明「这一段要不同，依赖 X 能力，本期不具备」 |
| **全案** | 降档段**不超过 1 段**；超过说明这套其实是「改良版」，不许再叫创新旅程 |
| **四段全同** | 那不是某段岔不开，是整个需求岔不开——按 §二⑤ 天花板低处置，改叫「上限版」 |

> 📌 **为什么允许这一条**：硬凑出来的第二段差异，用户一眼看得出是凑的。**如实标降档，比假装四段都不同更可信。**

### ⑤ 质变要看得见：判在哪一段、从什么变成什么

> 📌 **用户判断「这套有没有东西」，先看旅程四段，再看三个感知点。** 三个感知点是四段在界面上的投影：**第一眼 → what，步数 → how，结果呈现 → wow**。

| 感知点 | 创新级必须不同在哪 | 只是「精细一点」不算 | 对应旅程段 |
| :--- | :--- | :--- | :---: |
| **第一眼（首屏）** | 看到一个**原来这里没有的东西**：一份待办、一张分布、一条时间轴 | 同一屏里标签更全、按钮更顺 | what |
| **步数** | 少一次跳转 / 少一次判断 / 少一次自己去找去查 | 同一条路径上少点两下 | how |
| **结果呈现** | 给结论 + **可核验的依据形态**（能看见，不是能读到） | 原始数据摆得更整齐 | wow |

**两条硬要求（达不到就不是创新旅程）**：

1. **每套 ≥2 段旅程质变，且至少 1 段落在主战场**（用户花时间最多、操作最重的那一段）。只在边角发力（比如列表顶部加个统计条）不算。
2. **说得出「哪一段质变了、从什么变成什么」**：一句人话，两头都在——「从逐台看到只处理 3 件事」「从读表格到一眼看见哪片红」。**说不出这两头，就只是优化版换了张皮。**

> 🛑 **「高」不等于「多」**：创新档往往界面更空（系统把活接走了，见 §四）。**不许用「页面更多 / 组件更多 / 区块更多」来证高**，只许用「质变在哪一段」。

**天花板真的低时（需求小 / 目标只到优化版），三种正确处置**：

| 情况 | 正确处置 |
| :--- | :--- |
| **只有一段天花板低，其余能到创新** | 那一段降优化档并在声明里写明；全案仍算创新旅程 |
| **整案都到不了创新档** | **不许贴创新标签**：改叫 `方案一 · 上限版`，并在选择区写明「本需求最高到 [优化版]，原因是 [目标只要求… / 创新依赖的能力本期没有]」；此时方案二同样只能是上限版 |
| **两条旅程的 what、how、wow 全一样** | **不出两套**：只出一套 + 一页「备选路线」，并说明为什么岔不开——**硬造的第二条路线比只给一套更伤信任** |

> 🔁 **先回 1.3 找料，别先降低标准**：某一段没料时按顺序查三处——① 1.3 的创新档是不是只写了一条（回 1.3 补第二种做法）；② 入口 2（工作类型经验）是不是漏扫了；③ 某处创新档是不是因为「怕代价」被自己划掉了。**三处都查过仍无料，才按 ④ 降档。**

**三种「假创新」，一眼识破**：

| 假创新 | 长什么样 | 为什么假 |
| :--- | :--- | :--- |
| **换容器** | 抽屉改整页、列表改成分栏 | 人还得自己判断、自己找，只是换了个壳 |
| **加装饰** | 顶部加一排「智能概览」卡片 | 界面多了东西，人没少干活，也没多看见什么 |
| **档位虚标** | 优化版说成创新版 | 量级是标出来的，不是说出来的 |
| **机械组合** | 两套摆法不同（侧栏换顶栏、清单换卡片），但 what 与 how 是同一件事 | 用户做的事没变、感受没变，只是排版变了；**这是六维度拼装的典型产物** |

> 🔎 **一句话判据**：**两条旅程的 what、how 不同，且各自至少有一处质变说得清「从什么变成什么」，wow 各有一处真峰值。** 三条都给不出，就不是两套方案。

### ⑥ 旅程写在哪：进对比表，不新增交付块

> 🛑 **别把旅程单独做成一块"旅程图"塞进正文**：文件顶部已经因为台账进正文翻过三次车；再加一块，用户又要判断"我该读旅程还是读草图"。

| 旅程内容 | 写在哪 | 判据 |
| :--- | :--- | :--- |
| **四段差异（who / what / how / wow）** | §六·1 的**对比表**，两套各一列、四段各一行 | 只读对比表，就能说出两套差在哪四段 |
| **完整推演（含被否掉的备选、每段为什么这么定）** | 文末 `<details class="handoff">` 折叠区（给下游 4.1 / 5.0 读） | 正文里看不到这块；`EX-1.4-21` 仍绿 |
| **每段对应的页面落点** | 草图页头的页面名 + 交接区 flow-ledger | 指着任一段，能指到它落在哪一页 |

## 三之先、信息架构与页面清单（先做这几件，再动笔）

> 🛑 **这一节治两个实测病**：① 把需求条目翻译成页面（12 条能力 → 7 个页面，一个动作一页）；② 页面名写成口语或问句（「交给谁」「这一片还有谁」），传到说明书第 7 节时无法作为章节名与权限项落库。

### 1. 先给信息架构，再给页面清单（顺序不许反）

**四件套缺一即退回**（按顺序交）：

| # | 交付物 | 必须回答 | 长什么样 |
| :---: | :--- | :--- | :--- |
| **1** | **模块定位** | 新增一级模块还是挂在现有模块下？与哪些模块并列？只读消费谁？ | 3 行结论：模块归属 / 与现有模块关系 / 导航层级 |
| **2** | **信息架构树（导航级）** | 一级菜单 → 二级菜单 → 三级菜单 → 四级菜单（三级下**有多个页面内容**才拆四级）；**只到四级菜单** | 一棵树，节点 = 菜单名（≤6 字），**级别右对齐成独立一列**；**不写职责、不写括号说明、不标承载形态、不标方案差异**（职责进页面清单的「说明」列） |
| **3** | **页面清单** | 从需求触及层级往下拆全：四级菜单 + 页面内Tab + 下钻页 + 抽屉 + 弹窗；围绕主场景任务旅程拆分、串起来能闭环 | **5 列表**：编号 / 所属菜单 / 页面名称 / 类型 / 说明；**同菜单合并单元格、按菜单分组重排序号**；**不写承载形态、不写方案差异** |
| **4** | **页内视图清单（`view-ledger`）** | 每个页面内 Tab：这一面回答什么、主导图形、关键区块（≥2）、该面自己的能力位、空态与缺口 | 8 列表，一视图一行；**有页内 Tab 就必须有这张表**（见 §1.2） |

> 🛑 **信息架构与页面清单分离**：IA 只做"导航骨架"（到四级菜单），**页面内Tab / 下钻页 / 抽屉 / 弹窗全部进页面清单**；两者各自成节、各自成载体，禁止混排。
> 🛑 **删除「页面 × 对象 × 动作映射表」**：草图**不再展示**对象基数 / 匹配维度 / 主导图形 / 承载动作 / 两套差异；页面交付只看上面的 5 列页面清单。
> 🛑 **两份产物都是产品级资产，方案无关**：两套方案**共用同一份** IA 与页面清单，不写"两套差异"；方案差异只在后续方案说明与草图里表达。
> 🛑 **场景聚合**：二级菜单按主场景归并——一条主场景从进入到完成，**尽量在 1~2 个二级菜单内走完**；需跨 ≥3 个二级菜单，判"拆分过碎"，重新归并。判法与 1.1 的 `Sx` 主场景对账。
> 🛑 **主导图形并入草图**（不单列映射表列）：每页在草图里画出"人最先看、据以下判断的那件东西"（链路拓扑 / 时间轴 / 分布图 / 记分卡 / 工作台 / 表格）；画不出 = 这页没想清。
> 🛑 **动作覆盖表是内部校验**（不展示）：查"需求动作有没有落点"，不进页面清单、不进草图。

### 1.1 信息架构树：只到四级菜单

> 🛑 **实测病**：IA 只写到"功能域"三个字就停了；或一个能力名字独立就默认拆成一级菜单，结果菜单四层深、页面一堆空壳。**层级必须逐层写出来，不许停在中层。**

**拆解顺序（逐层写，不许跳层）**：

| 层 | 要回答什么 | 产物形态 |
| :---: | :--- | :--- |
| 一级菜单（模块） | 新增一级菜单，还是挂在现有模块下？ | 3 行结论 |
| 二级菜单 | 按主场景归并，3~5 个，各自只回答一个问题 | 树的第二层 |
| 三级菜单（页面） | 每页名词化 ≤6 字 | 树的第三层 |
| 四级菜单（子页面） | 三级下**有多个页面内容**才拆；只有一个内容 → **不设四级** | 树的第四层 |

> 页面内 Tab / 下钻页 / 抽屉 / 弹窗**不进 IA 树**，进页面清单（在「类型」列标注）。

**硬约束**：

1. **菜单层级 ≤4 级**（一级 → 二级 → 三级 → 四级）；不加深导航。
2. **四级是条件层级**：三级下只有一个页面内容 → 不设四级。
3. **页面内 Tab 不是四级菜单**：它是页面内部视图切换，归页面清单的「页面内Tab」类型。
4. **每个节点只写菜单名，不写职责、不写括号说明**：节点名 ≤6 字；"职责 / 这一层干什么"移到页面清单的「说明」列去写。**IA 树出现"（今天怎么样、谁最差）""· 一级菜单"这类括号与重复层级字样 = 干扰信息**，一律删（实测翻车点）。

**IA 树落盘格式（交付物里就长这样）**：

```text
数字体验                          一级菜单
├─ 体验观测                       二级菜单
│  ├─ 体验概览                    三级菜单
│  └─ 异常事件                    三级菜单
├─ 问题诊断                       二级菜单
│  └─ 访问诊断                    三级菜单
│     ├─ 分段证据                 四级菜单
│     └─ 影响范围                 四级菜单
└─ 监测配置                       二级菜单
   ├─ 监测策略                    三级菜单
   └─ 质量模型                    三级菜单
```

> 🛑 **级别右对齐、独立成列**：`一级菜单 / 二级菜单 / …` 统一顶到**最右侧**、彼此对齐成一列，不许写成 `数字体验（一级菜单）` 那样跟在名字后面。**必须用 flex 结构**：每行 `<div class="row"><span class="name">菜单名</span><span class="lv">三级菜单</span></div>`，`.lv` 用 `margin-left:auto` 顶到最右。
> 🚫 **禁止用等宽字体 + 空格填充对齐**——HTML 会折叠连续空格，源码里看着对齐、渲染出来参差（实测翻车点）。**节点名与级别字之间不加"（·）"等连接符。**

> 🛑 **只要有一个节点层级 / 归属写不清，IA 判未完成，不许进逐页草图。**
> 🛑 **IA 定稿即冻结**：这是全流程**唯一**的信息架构来源。4.1 只做继承对账与组件落地，5.0 只做投影引用，**都不许重拆、改名或新造菜单**；要改只能回本节改，改完重跑草图门禁并回填下游对账。

**页面清单的「类型」怎么判**（页面内Tab / 下钻页 / 抽屉 / 弹窗，先读 [`patterns/01-navigation-and-hierarchy.md`](../../03-design-assets/patterns/01-navigation-and-hierarchy.md)，按它判，不自己发明）：

| 情形 | 用什么（类型） | 判定要点 |
| :--- | :--- | :--- |
| 同一菜单下的独立页面 | **三级菜单页面** | 有独立入口价值，不是谁的附属 |
| 三级页面下有多个页面内容 | **四级菜单页面** | 有多个内容才拆；只有一个不拆 |
| 同一页面的不同内容面 | **页面内Tab** | 视图切换，不进 IA |
| 从列表挑一条看细节、保留上下文 | **抽屉** | 关掉后保留筛选与滚动位置 |
| 完整信息要持续浏览、内容多 | **下钻页** | 返回回原列表位置 |
| 临时查一批对象、选完就关 | **弹窗** | 不在主路径上 |
| 单条规则 / 少量字段的新增编辑 | **弹窗 / 抽屉表单** | 见 [`patterns/03-form-patterns.md`](../../03-design-assets/patterns/03-form-patterns.md) |

### 1.2 页内视图必须立账：一个页面里有几"面"，不看有没有 Tab 条

> 🚧 **归位**：本节产出的 `view-ledger` 是**交接件**——表格放文末 `<details class="handoff">` 折叠区，**不渲染进正文**。图上仍按本节要求给每个面板标 `data-view`，供机检闭合。

> 🛑 **实测病（最贵的一处断供）**：页面有 3 个 Tab，草图只画第一个，另两个写一句「切到「影响范围」时此处换成……」，或每个 Tab 只留一行字。**草图看着"交代过了"，下游 4.1 / 5.0 却拿不到内容，只能自己编或直接做成空白面板——方向层没定的东西，执行层就会替用户做设计。**

**根因有两层，第二层更要命。**

**第一层：视图没有账。** 页面有「管什么 / 主导图形 / 动作 / 能力位 / 差异」五列可填，页内视图只有树上的一行名字。**没有账，就没有内容可写；没内容可写，就只剩一句标签。**

**第二层：判定的入口被交给了控件。** 现行门禁只在页面出现 `class="tabbar"` 时才检查（`EX-1.4-18` / `EX-1.4-20`），**不画切换条就判"本项不适用"**——于是用分段按钮、左树右表、卡片↔表格切换、同页不同分组维度的页面，一面没画也是全绿。**这是"规则写了还是每次漏画"的机制根因**：检查的触发条件由被检查者自己提供。

#### 判据一句话（三问，替换原来的"≥2 个区块"）

**指任一个面，能回答三件事**：

1. **差分**：切换前后，**哪几块变了、变成什么**？指给我看——只能说"更详细 / 更全"，判没画。
2. **闭环**：这一面的判断链齐不齐？分析型：结论 → 依据 → 缺口 → 下一步；操作型：清单 → 状态 → 动作。缺段判没画。
3. **承接**：把这一面**单独**发给 5.0，他能不能**不问一句**就画成线框？要回来问"数从哪来 / 空态长什么样"，判没画。

> 📌 **"每面 ≥2 个命名区块"降为最低结构线**（保留在硬约束里），不再是主判据——它能被两个灰块凑过，这正是"判据太儿戏"的来源。
> 🛑 **判定标准是"判断能不能一次做完"，不是"有没有那条切换条"**：把标准交给控件形态，就变成"不画控件 = 不用画内容"。

#### 先判"这一页到底有几面"（三问，按顺序，不许跳步）

| 步 | 问什么 | 是 → | 否 → |
| :---: | :--- | :--- | :--- |
| 1 | 同一页面里，有没有**两批要分开判断**的信息？（"合在一起看还判断得清吗"） | 进第 2 问 | **单视图**，标 `data-single-view` 写原因（如"本页只有一个判断：这批任务该先做哪件"） |
| 2 | 它们看的是**同一个对象 / 同一段时间**吗？ | 进第 3 问 | **应该拆成两页**，不是同页两面 |
| 3 | 切换时，**承载判断的那块**变了吗？（只换排序 / 换列数不算） | **必须立账 + 必须画** | **同一视图**，不立账 |

**载体清单（都算视图，不只 Tab）**：页内 Tab / 分段切换 / 左树右表 / 卡片↔表格 / 同页不同分组维度（按应用看 / 按节点看）/ 抽屉内多段。

#### 两种线框案例：切换后画哪里（答案相反，两个都要看）

| | **案例 A · 整页重排型** | **案例 B · 局部替换型** |
| :--- | :--- | :--- |
| **典型** | 访问诊断：路径依据 / 影响范围 / 证据交接 | 同一条链路：按应用看 / 按节点看 |
| **切换后变什么** | 页头主信息以下**全换**：主图、结论、清单、该面能力位 | **只有中段换**：页头、筛选、主信息都不变 |
| **必须输出草图的位置** | **页头主信息之外的全部面板区**，每面按"主图 + 清单 + 能力位"画全 | **只画变化的那一块 + 上下文边界**：一条上边界标"以上不随切换变化"，并画出该块的新形态 |
| **不必画什么** | 页头主信息（画一次，标"各面共用"） | 不变区不必重画，但必须用边界表达"它没变" |
| **图上一句话标注** | `页头以下随切换整体变化` | `仅中段换维度，页头与筛选不变` |
| **不这么画的后果** | 另几面成空白面板，5.0 自己编内容 | 看不出"换的是什么"，或整页重画 3 遍、差异被稀释 |

> 🛑 **为什么必须两个案例**：两者对"画哪里"的答案**相反**（一个画全部、一个只画差异块）。只给一个，执行者会把它当通则——现在全篇默认"Tab = 整页重排"，就是只有一个隐含案例的结果。
> 🛑 **每页必须显式声明几面**：`本页 3 面` 或 `本页单视图：原因…`。**不声明 = 判未完成**——这是堵"不画切换条就不查"的唯一办法。

#### 硬约束（四条，缺一即判未完成）

| # | 约束 | 为什么 |
| :---: | :--- | :--- |
| **1** | **每个视图必须在 `view-ledger` 里占一行**（编号 `P2-V1` 形式），八列填满：视图编号 / 所属页面 / 视图名 / 这一面回答什么 / 主导图形 / 关键区块（≥2，`/` 分隔） / 该面能力位 / 两套差异。**"视图"不只 Tab**——分段切换 / 左树右表 / 卡片↔表格 / 同页不同分组维度 / 抽屉内多段，都按视图立账 | 视图成为和页面同级的承载单元，下游才能逐面落线框、逐面写说明书小节 |
| **2** | **面板里 ≥2 个命名区块（最低结构线）**，每块写成 `<b class="t">块名</b>　内容`（名词短语，见第五节第 6 条）；只有一个块的，必须在面板上标 `data-thin="sys"` 并写清"系统接管了什么，所以这面只剩 X"。**注意：凑够两块不等于过关**，主判据仍是上面的三问 | 两个块才构成"面"的最小结构（结论 / 依据、清单 / 分布）；一个块等于没拆；但只有数量没有差分，仍是空壳 |
| **3** | **能力位跟着面走**：这一面自己的筛选 / 搜索 / 排序 / 分页 / 导出，标在**这一面**里（`.cap` + `data-ph`），不许全堆在默认面；某面没有则写 `本面无筛选`，不写 = 没想 | 下游按面装配控件；堆在默认面会导致切到别的面时工具栏消失 |
| **4** | **数据缺口与空态在面内显性**：该面缺数写 `.ph data-ph="DATA"`，该面为空画空态块 | 面是最小判断单位，缺数写在页级等于没有 |

#### 禁止清单（出现任一条即判内容缺失）

| ❌ 不许写 | 为什么 |
| :--- | :--- |
| 「切到「X」时此处换成……」/「另两个 Tab 内容同上」/「此处略」 | 这是一句话替代一整面内容，`EX-1.4-18` 直接判死 |
| 面板里只有一行说明或一个灰块 | 拆到 0 个有条件的分支，下游无从落地 |
| Tab 名写成「视图①/②/③」 | 没说清承载形态，读起来像长页面的三块内容 |
| 把「全页共用」的筛选只画在默认面 | 切面后用户找不到筛选，下游会漏做 |
| **用分段按钮 / 左树右表 / 卡片切换承载多面，却当成"一页一面"不立账** | 这类页面没有 `tabbar`，门禁旧口径会判"不适用"，内容整块丢失（`EX-1.4-18` 已改为按载体识别） |
| **局部替换型页面把整页重画 3 遍** | 差异被稀释，读者看不出"换的到底是哪一块"；按案例 B 只画变化块 + 边界 |

> 📌 **"相同"不再省任何一块**：两套方案之间相同的页面、同一页在多个场景、同一场景内同一页的不同步骤/不同 Tab，**都各画一遍**。页内 Tab 更不用说——N 个面就是 N 块面板。**唯一允许"看起来重复"的理由，就是它是当前剧本里的这一步。**

### 1.3 场景链路必须立账：图上要有"边"，不能只在图下写入口

> 🛑 **实测病**：P2 是详情页，但 P1 列表上找不到"看详情"的入口，只能靠图下说明里一句"点这一行进详情"。**用户按草图走不完一条场景，新人第一句就是"我从哪点进去"。**

**判据一句话**：**每条主场景 `Sx` 摊开后，能在图上从第一屏点到末态屏，每一步都指得出"点的是图上哪个东西"。** 指不出触发元素，就是断点。

**必交与禁令（6 条，缺一即判未完成；机检 `EX-1.4-19`）**：

| # | 项 | 怎么写 |
| :---: | :--- | :--- |
| **1** | **去向锚点** | `<i class="go" data-go="P2">查看路径 →</i>`，画在**真实触发元素**上（行末操作 / 按钮 / 节点 / 卡片）；写进图下说明 = 没画 |
| **2** | **入口锚点（双向闭合）** | `<span class="from" data-from="P1">从「查看路径」进入</span>`，画在被进入页的对应位置（如抽屉标题左侧）；**两边必须互相指得到** |
| **3** | **场景链路表 `flow-ledger`** | 七列：场景 / 步骤 / 页面 / 触发元素 / 到哪 / 到这步看到什么 / 末态判定；每条 `Sx` 一条完整链路（进入 → 操作 → 看到结果）。**放文末 `<details class="handoff">`——"从哪来 / 到哪去"的文字只写这里** |
| **4** | **目标页存在** | 每个 `data-go` 指向的页面资产必须存在（对得上 `<span class="pid">P2</span>`）；原先是"每页有入边"，现在同页会多次出现，入边按实例算 |
| **5** | **场景内连通** | 每条场景内，从首步页面沿 `data-go` 能走到末步页面；**不再要求全篇 `E ≥ N-1`**（重复实例会让全篇拓扑失真） |
| **6** | 🚫 **页面上不许写动线行** | 不写 `进入：… ｜ 去向：…`、不写职责句（"看全部任务""定查什么"）——那是解释，不是图 |

**反例只留两条**（其余已在上面说过，不再重复）：

| ❌ | ✅ |
| :--- | :--- |
| 图下写"点节点可看对应路径清单" | 在节点右上角画 `查看 11 条 →`，清单区标 `data-from="P1"` |
| 只在方案一画链路，方案二靠"与方案一相同" | **两套各自画一套完整剧本**；同一页该出现在两套里就各出现一次 |

> 📌 **链路也要进说明书**：4.1 页面清单要带"进入 / 去向"，5.0 每页批注首句写清从哪来、办完去哪。**草图不立这条账，下游三处都补不回来。**

### 1.4 主场景剧本：方案 → 场景 → 步骤 → 页面

> 🛑 **两次实测病**：
> ① **按页面编号罗列**（P1 概览 → P2 监控 → … → P10 报障受理）：S1 的报障入口掉到最后一页，报障后去向看不到，用户"按图走不完一条场景"。
> ② **靠"相同页复用/占位"省篇幅**：切到场景 S3 或方案二时，当前剧本里缺屏，讲解必须跳出去找图——**省下来的是篇幅，丢掉的是剧本连续性。**
>
> **最终口径**：**一处出现就画一遍，页面可以在多个场景、两套方案里重复出现**；顺序只认 1.1 的任务旅程步骤。

**判据一句话**：**随便挑一个「方案 + 场景」，从 Step1 的第一屏一路点到末步的末态，中间不跳出去、不指别处；旁边的人照着步骤头就能听完。**

#### 四层结构（缺一层即判未完成）

| 层 | 是什么 | 谁在看 | 硬要求 |
| :---: | :--- | :--- | :--- |
| **1 方案** | `方案一 / 方案二` 两个分段 tab | 选方向的人 | 两套都是完整方案；切换后落到该方案的 **S1** |
| **2 场景** | 每条主场景一个 tab，**两套下同一组、同顺序** | 要按场景看的人 | 默认选中 **S1**；切场景只换段，不换方案 |
| **3 步骤** | 场景内按 1.1 旅程顺序排的 `Step N` 头 | 讲解的人 | 四要素齐：`Step N：【步名】` / 意图一句 / `关联界面 P1、P2` / `看到：…` |
| **4 页面** | 步骤下面的页面块 | 看结构的人 | **每次出现都画全**（主图 / Tab 面板 / 能力位 / 标号说明 / Token 一样不少） |

#### 重复展示规则（本次改造的核心）

| 情形 | 做法 | 为什么 |
| :--- | :--- | :--- |
| **两套方案的共性页** | 方案一画一遍、方案二再画一遍（`data-plan` 不同，`data-occ` 加 `B-` 前缀） | 用户切到方案二，当前剧本必须完整，不能让他"去方案一取图" |
| **同一页出现在多个场景** | 每个场景各画一遍 | 每个场景是一部独立剧本 |
| **同一场景内，同一页在不同步骤/不同 Tab** | **各画一遍**（`data-state` 或激活 Tab 不同） | 剧本要连续；DEM 的 S1 第 3、4 步都落在 P3，但看的是不同面 |
| **数据** | 所有副本的核心数据必须是同一批（同人数 / 同时间 / 同编号） | 换一批数就是两套事实，评审会当成两个需求 |
| **呈现状态** | 允许不同：`data-state="default / empty / filtered / no-permission / expired / detail"`，或不同 Tab 激活 | 进入场景时的上下文本来就不同 |

> 🛑 **不再有 `SAME`、不再有"与方案一相同"占位条、不再有 `scene-ref`**：这三样都会让"当前剧本"缺屏，全部退役。
> 🛑 **重复不等于复制垃圾**：同一个 `data-page` 的所有副本，**命名区块集合、视图集合、占位能力集合必须一致**；只允许状态与激活面不同。

#### 两套编号，别混

| 编号 | 长什么样 | 谁用 | 规则 |
| :--- | :--- | :--- | :--- |
| **页面资产编号** | `P3` | 页面清单 / 4.1 / 5.0 / 用户 | **全篇唯一、跨方案跨场景永不变**；页面上只显示这个 |
| **出现实例编号** | `data-occ="S1-3-P3"`、`B-S3-2-P3` | 门禁 / 定位"改哪一块" | 每次出现唯一；格式 `<方案前缀>-<场景>-<步骤>-<页面>` |

**台账按资产记，不按出现次数爆炸**：

| 台账 | 粒度 | 写法 |
| :--- | :--- | :--- |
| `view-ledger` | 页面级 | `P3-V1` 只有一行，不随出现次数复制 |
| `ph-ledger` | 页面 + 能力项 | 合并一行，新增「出现于」列（`S1-3 / S1-4 / S2-2`）；图上 `data-ph-id` 按实例唯一 |
| `flow-ledger` | 场景 × 步骤 | 一场景一行一步，与步骤头一一对应（交接件） |
| `dx-ledger` | 页面 + 区域 | 不变 |

#### 场景内必须首尾闭合（治"报障入口在最后一页"）

| # | 规则 | 判据 |
| :---: | :--- | :--- |
| **1** | **首步 = 触发所在承载页** | 首个 `step-hd` 的 `data-enter` 必须等于它 `data-pages` 的第一个页面；抽屉 / 弹窗不作首屏，必须露出背后承载页与触发元素 |
| **2** | **末步 = 末态** | 最后一个 `step-hd` 标 `data-close="Px"`，该步必须有 `class="scene-close"`（放在页面块之后，别落进 `.frame`），写清办成了什么 / 记录在哪 / 交给谁 |
| **3** | **每步有可点的前进锚点** | 步骤之间用 `data-go` 落在真实元素上；只在说明里写"点这一行"= 没画 |
| **4** | **入口多来源** | 工单 / 群消息 / 电话 / 口头，在首屏用一处「受理入口」区块列全，不拆成四条场景 |

#### 切换与默认态（写死）

| 动作 | 行为 |
| :--- | :--- |
| 打开文件 | 默认「方案一 + 场景 S1」 |
| 切方案 | 显示目标方案，**场景回到 S1**，视口滚到 **S1 的 Step1**（不是标题下、不是面板顶） |

#### 反例（全部实测）

| ❌ | 病 | ✅ |
| :--- | :--- | :--- |
| 页面按 `P1→P2→…→P10` 罗列，场景只在链路表里 | 读者翻到最后一页才看到报障入口 | 四个层：方案 → 场景 → 步骤 → 页面 |
| 报障后没有去处 | 场景跑到"生成诊断"就断 | 末步 `scene-close` 写清台账新记录 / 状态 / 交接对象 |
| 相同页留占位条 / 用 `scene-ref` | 当前剧本缺屏，讲解要跳出去找图 | 每次出现都画全 |
| 一页只画一次、其他场景靠"同上" | 用户切到 S3 看到空白或要回滚 | 每场景各画一遍 |
| 步骤内又按页面编号排序 | 步骤号与编号打架 | 顺序只认 `data-step` |
| 步骤头只写"Step 1" | 讲的时候不知道这步要干什么 | 四要素：步名 / 意图 / 关联界面 / 看到什么 |

> 📌 **与 §1.3 的分工**：**1.3 立"边"**（锚点存在），**1.4 立"剧本"**（每场景首尾闭合、每步页面齐）。**只有边是一张地图，有剧本才是一条能带着人走一遍的路。**

### 2. 页面命名五条（机器可判，见 EX-1.4-08）

| # | 规则 | 判据 | 反面 |
| :---: | :--- | :--- | :--- |
| **1** | **名词化** | 不写问句、不写动宾短语、不用指示代词（谁 / 哪 / 怎么 / 一次 / 这一片） | 「交给谁」「这一片还有谁」「一次卡慢的现场」 |
| **2** | **≤6 字** | 要能进左侧导航不被截断 | 「接入与对象圈定维护」 |
| **3** | **一页一功能域** | 不把两个动作或两个产物并列 | 「提醒与口径」「证据包与台账」 |
| **4** | **产物优先于动作** | 写「证据包 / 质量模型 / 处理记录」，不写「交接 / 配置 / 处理」 | 「配置页面」 |
| **5** | **可进目录** | 能被说明书直接引用为章节名、能被权限项命名 | 口语与缩写混写 |

**正反例（实测）**：

| ❌ 原写法 | 病在哪 | ✅ 改后 |
| :--- | :--- | :--- |
| 这一片还有谁 | 完整问句 | **影响范围** |
| 交给谁 | 完整问句 | **证据交接** |
| 一次卡慢的现场 | 指示代词 + 口语 | **访问诊断** |
| 提醒与口径 | 内部词「口径」+ 两个产物并列 | **监测策略** |
| 体验总览 | 非标准 IA 词 | **体验概览** |
| 接入与对象圈定 | 两个动作并列 | **采集配置** |

> 📌 **一句话**：页面名是**产品资产**，要进导航、进权限、进说明书目录、进测试用例；名字写坏，后面每一层都要跟着改。

### 3. 同一对象的多个视图，合并为一页

**判据只有一句**：这几个视图是否共用**同一核心对象**与**同一选择上下文**？

| 情况 | 处置 | 例 |
| :--- | :--- | :--- |
| 共用同一对象（同一个人 / 同一个事件 / 同一段时间） | **一页 + Tab 或抽屉**，不页化 | 现场 / 影响范围 / 证据交接 → 一个「访问诊断」页的三个视图 |
| 对象不同或需要重新选择上下文 | 分页 | 监测策略（对象 + 规则）与质量模型（口径） |

> 🛑 **页化同一对象 = 逼用户重新选一次对象**，最容易选错；而且页数会随流程步数膨胀。

### 4. 不线上化的能力，必须显式标注

| 要求 | 做法 |
| :--- | :--- |
| 页面清单 | 写 `❌ 否`，并在备注列写线下承接方式（邮件 / 群 / 人工台账） |
| 页面清单（对应条目） | 单列一行，写明「线下」，不许静默消失 |
| 交付话术 | 口头点一次，说明为什么本期不做 |

> 🛑 **两个极端都要避免**：静默删掉（用户以为漏做）与硬做空壳页（建一个没人维护的表单）。**线下承接方式必须一句话写清交给谁、用什么载体。**

### 5. 数据必须是**仿真数据**，不是随便编的示意

> 🛑 **示意 ≠ 仿真**：`深圳 · 某对象 · __ 人` 是示意，评审者无法判断结构是否成立；`VU-2041 张伟 · 研发部 · 接入节点-02 · 39.6 秒（基线 9.8 秒）` 是仿真，评审者能像看真实系统一样判断。

| # | 仿真要求 | 判据（自己能验） |
| :---: | :--- | :--- |
| **1** | **对象带标识** | 至少主要对象有编号或全名 + 归属（`VU-2041 张伟 · 研发部` / `APP-07 CRM` / `POP-02 接入节点-02 · 深圳`），不是「某人 / 某应用」 |
| **2** | **字段完整** | 时间戳到分秒（`2026-10-25 10:07:02.8`）、状态用枚举值（`处理中 / 已关闭`）、带来源与变更人（`来源：客户端探针 / 变更人：王敏`） |
| **3** | **量级自洽** | 总数 = 各分项之和（`1,240 = 1,082 + 121 + 37`），比例与人数能对上（`38/74 = 51%`） |
| **4** | **时间线不倒序** | 越线 → 报障 → 快照 → 处置，时间必须单调（`09:34 越线 → 10:07 报障 → 10:20 快照`），不许出现「快照早于越线」 |
| **5** | **跨页同一批数** | P1 说 38 人，P2 的事件行、P3 的名单、P5 的评分必须是同一批人、同一组数字 |
| **6** | **页头声明** | 示例环境 + 快照时间 + 规模 + 一句「仿真数据，不构成客户事实」 |
| **7** | **结论数字必须真值，`__` 空占位禁止** | 结论句里的数字（人数 / 占比 / 评分 / 时长 / 时间点）必须是仿真真值且可复算，否则判断不了「结论句是否成立」；**常规区**表格单元格的字段值可用灰条或示意值（那是精度，不是结论）；**高保真区**必须给真值 |

> 📌 与「不编造客户数据」不冲突：编的是**标注过的仿真样本**，用于判断结构是否成立；对外交付时声明必须保留，真实数据回来只换数值、不换结构。

### 6. 块标题必须是**名词短语**（机器可判，见 EX-1.4-11）

> 🛑 **先记住一件事：黑名单查不住口语。** 口语是无限组合——「盯谁」「通知到谁」「不是一个人」「按这次的证据，先问这一处」「一起交出去的材料」，每次换一句就漏一次。**所以判据不能是"禁用词表"，必须是"结构"：先规定格式，再按名词规则校验。**

**格式（强制）**：块标题写成 `<b class="t">标题</b>　内容`（后跟全角空格）。
* 只有 `class="t"` 的 `<b>` 才被当作标题校验；正文里的加粗强调不受影响，不会被误判。
* **标题里只放名字，不混内容**：`聚合规则：同一段链路上 ≥5 人同时越线` 是错的，应为 `聚合规则` + 全角空格 + 说明。

**五条机检判据（缺一条即不合格）**：

| # | 判据 | 为什么 | 反例 |
| :---: | :--- | :--- | :--- |
| **1** | **不含标点**（，。；？！） | 带标点的标题一定是句子 | 「按这次的证据，先问这一处」 |
| **2** | **不含口语词**（我 / 你 / 他 / 这 / 那 / 哪 / 谁 / 什么 / 怎么 / 为什么 / 吗 / 呢 / 吧） | 这些词把配置项写成了自问或对话 | 「不是一个人」「当前这批对象的分布」 |
| **3** | **不以动词短语开头**（不是 / 按 / 一起 / 先问 / 交给 / 导出 / 标记 / 看一下 / 打开 / 新增 / 发布新） | 标题是名字，不是动作 | 「一起交出去的材料」「发布新版本」 |
| **4** | **≤12 字** | 进导航、进表格列头、进说明书小节名都放得下 | 「接入形态与已接入探针」 |
| **5** | **命中名词词尾**（范围 / 对象 / 分组 / 条件 / 级别 / 通知 / 状态 / 记录 / 清单 / 模型 / 指标 / 阈值 / 权重 / 等级 / 分布 / 归因 / 结论 / 材料 / 方式 / 规则 / 版本 / 探针 / 分段 / 维度 / 评分 …） | 保证它是"一类东西的名字"，不是一句描述 | 「已划掉的跳」→ 已排除分段 |

**实测反例（全部栽过，直接背）**：

| ❌ 原写法 | 病 | ✅ 改后 |
| :--- | :--- | :--- |
| 盯谁 / 通知到谁 / 什么条件触发 | 疑问式 | 监测对象 / 通知配置 / 触发条件 |
| 不是一个人 | 句子 + 口语 | 群体判定结论 |
| 按这次的证据，先问这一处 | 带逗号的句子 | 责任方向建议 |
| 一起交出去的材料 | 动词开头 | 交接材料清单 |
| 按应用分布 / 按地区分布 | 动词开头 | 应用维度分布 / 地区与接入节点分布 |
| 当前这批对象的分布 | 口语词「这」 | 对象评分分布 |
| 一行一个对象，不做人群聚合 | 标题混内容 | 聚合方式 + 全角空格 + 说明 |
| 聚合规则：同一段链路上 ≥5 人… | 标题混内容 | 聚合规则 + 说明 |
| 主因跳：POP-02，等首包 1.8 秒 | 标题混内容 | 主因跳判定 + 说明 |
| 材料（按该团队模板已勾好） | 标题混括号说明 | 交接材料清单 |
| 已划掉的跳 | 无名词词尾 | 已排除分段 |
| 发布新版本 | 动词开头 | 版本发布 |
| 切维度看 / 筛与排 | 口语动补 | 维度切换 / 筛选与排序 |

> 🔎 **人工兜底判据**（机检之外）：把标题单独抄进一张清单，**只念标题、不看内容**——如果听的人能说出「这是一类配置 / 一类结论 / 一类材料」，合格；如果他以为你在跟他说话，就是口语。
> 🛑 **改一处必须全文扫**：发现一个口语标题，用同一套规则把**全篇所有 `class="t"` 标题**重过一遍，不许只改被指出的那一个。

### 7. 必要配置项不得隐藏或省略（机器可判，见 EX-1.4-12）

> 🛑 **配置类页面最常犯的错不是画错，是画少。** 草图省掉一项，到了线框与开发就被当作「不需要」，上线后实施只能反复追问。

**判据一句话**：**把这一页交给实施去配，他能不能不追问就配完？** 不能，就是漏项。

以「监测策略」为例，必备八项（每项在草图里都要有落点）：

| # | 配置项 | 省掉的后果 |
| :---: | :--- | :--- |
| 1 | **生效范围**（组织 / 租户 / 分支） | 不知道对谁生效，可能全租户误告警 |
| 2 | **监测对象与分组** | 不知道盯谁，全量即噪声 |
| 3 | **指标与阈值**（引用质量模型版本） | 不知道用什么判，改了模型对不上 |
| 4 | **触发条件**（持续时间 / 聚合规则） | 不知道何时响，单点抖动就叫人 |
| 5 | **通知配置**（收件人 / 渠道） | 不知道叫谁，响了没人管 |
| 6 | **合并与静默**（合并窗口 / 静默期 / 重复提醒） | 会被同一件事反复打扰，最后被关掉 |
| 7 | **生效时间与启停状态** | 不知道什么时候开始生效，改完不知道有没有生效 |
| 8 | **变更记录**（谁改了什么、何时） | 出问题查不出是哪次改动导致 |

> 📌 **不是每页都要这八项**：每类配置页要有一张自己的「必备项清单」，草图逐项有落点；分析类页面则要列全「判断所需的全部信息」（否则结论站不住）。
> 🛑 **不许用「后续再补」跳过**：本期不做的配置项，在图上写 `本期不做 + 原因`，不许静默省略。

### 8. 出图前逐页过一遍（不许"用户指哪改哪"）

> 🛑 **实测病**：用户截图指出 P4 三处口语，就只改 P4 这三处，其余五页同样的问题原样留着。**一次只改被指出的地方，等于把用户当质检员**，下一轮他还会发现新的。

**动作**：所有页面画完后，**按页逐块过一遍**，每页回答下表的问题；发现的问题**一次全部改掉**，再交给用户。

| 页面类型 | 必须逐项自查（缺一条就是漏检） |
| :--- | :--- |
| **所有页面** | ① 核心对象是什么（一句话说得出）② 图上有没有口语标题 ③ 数据与前后页对得上吗（同一对象、同一时间、同一批数）④ 有没有"必然被告知会被追问"的信息没画 |
| **分析 / 概览页** | 判断链是否完整：**结论 → 依据 → 缺口 → 下一步**；**时间范围是不是一个能点的位置**（今日 / 昨日 / 近 7 天 / 自定义 + 更新时刻）——只写一句"时间范围：今日"算漏能力；需要按时刻回看的，另有"时刻"入口；空态与"数据未就绪"是否交代 |
| **列表页** | 每一行的**状态字段**、**首次/最近时间**、**排序依据**；**筛选区在页头右侧、工具栏在表格上方**（新增 / 批量 / 导出 / 刷新），筛选能力覆盖真实追问（时间、对象、状态），排序挂在表头；空结果怎么显示；**能力项是否都在位置上——有没有塞到表格下方或只写在正文里** |
| **详情 / 诊断页** | 结论 + **把握程度** + 判定依据（引用了哪版标准）+ 证据完整度（几段有数据）+ 缺口说明；可执行动作是否指向下一跳；**多面信息有没有画出页内 Tab 条**（Tab 名 + 当前选中），**顺序是否是"主信息 → Tab 条 → 内容"**；标了抽屉的面是否真的画成抽屉 |
| **配置页** | 必备项清单（详见第 7 条）逐项有落点；**多实例对象有没有集合页**（列表 + 新增 / 复制 / 启停 / 优先级 / 最近变更）；**编辑态与"自定义口径"有没有入口**（改档数 / 区间 / 权重 / 匹配的主客体，而不是只展示结果）；**不做项写「本期不做 + 原因」**；生效范围 / 状态 / 变更记录是否给全 |
| **交接 / 输出页** | 交给谁、用什么方式、什么时候、对方是否已接收；导出件包含哪些内容、边界在哪 |

**两条硬要求**：

1. **同一问题全文扫**：发现"口语标题"这一处，就把全篇同类一次清完（用 grep 搜同义词，不靠眼睛）；
2. **数据自洽全文回算**：任何一个分数、比例、人数、时间，都要能被前后页复算出来（例：评分 57 分 → 权重与档位要能算出 57；38 人 → 与总人数 74 的比例要是 51%）。

> 🔎 **交付前的最后一问**：如果用户此刻只挑一页看，我还有哪一页会让他再发一次截图？

## 三、先定信息架构与页面清单，再画草图（本步交付的第一块）

> 🎯 **这是本步最容易卡住的一问**：不给页面清单，草图怎么知道画到哪个页面里？给了页面清单，不就等于结构已经定了、没得岔了？
>
> **答案：先有"页面草图清单"，后有"正式页面清单"。前者是本步产物，后者是 4.1 产物。**

| 谁定的 | 定的是什么 | 精度 | 能不能改 |
| :--- | :--- | :--- | :--- |
| **本步（1.4）★ 先做** | **页面草图清单**：本次涉及哪些页面 / 子页 / Tab / 下钻 / 抽屉 / 弹窗，各自叫什么、管什么 | 粗——只到"有这个东西、它管什么" | 随方案一起改 |
| **4.1 ★ 后做** | **正式页面清单**：页面编号 `Page-0x`、交互形态、模板 ID、承接主场景、来源草图 | 细——到组件与 Token | **原则上不改**；要改必须回本步重确认 |

### 页面清单：5 列，独立成表

> 📌 **清单摆在文件最开头**，一次回答三个问题：本次一共几个页面、每个干什么、各自属于哪个菜单。

**列固定 5 列**：

| 编号 | 所属菜单 | 页面名称 | 类型 | 说明 |
| :--- | :--- | :--- | :--- | :--- |
| ① | 系统配置 | 日期与时间计划 | 四级菜单页面 | 页面的用途 |
| ② | 日期与时间计划 | 日期时间服务器对接 | 弹窗 | 页面用途 |

- **所属菜单**：填该条目的**直接父级**菜单名（二级 / 三级 / 四级）。
- **页面名称**：页面或子页名称；编号可置于名称前（如 ①）。
- **类型**：`三级菜单页面 / 四级菜单页面 / 页面内Tab / 下钻页 / 抽屉 / 弹窗`。
- **说明**：这一页 / 子页的用途。
- **同一「所属菜单」的条目合并单元格，并按菜单分组重新排序号。**
- **不写承载形态、不写两套差异**——页面清单是产品级资产，与方案说明无关。
- **拆分依据 = 主场景任务旅程**：页面围绕 1.1 的 `Sx` 拆分，串起来必须能**闭环该主场景**；禁止脱离场景随性罗列。
- **每条页面都要在至少一条场景线路里出现**（§三之先·1.4）：出现在不了任何 `Sx` 段里的页，要么补进对应场景，要么删掉或标"本期不做 + 原因"。
- **编号不是展示顺序**：页面清单编号用于资产引用与下游对账，草图展示顺序由场景线路决定（`data-step`），两者不要求一致。
- **起点**：取需求实际触及的最深"页面级"层级（通常三级或四级；一级、二级是纯导航，不产生条目）。

> 🛑 **删除「页面 × 对象 × 动作映射表」**：草图不再展示对象基数 / 匹配维度 / 主导图形 / 承载动作 / 两套差异。

### 定清单前必做：内部校验（不展示）

> 以下两项是**内部推演 / 留档**，不进页面清单、不进草图，但**不做就会漏能力**。

**① 实例基数判定（防"只画单条详情"）**

> 🛑 **实测病**：监测策略只画了一条 `POL-014` 的详情，没有策略列表、没有新增——用户一问"我不同对象要求不一样，不能建多条策略吗"就露了。

| 判定 | 怎么问 | 内部推演里怎么体现 | 常见对象 |
| :--- | :--- | :--- | :--- |
| **多实例** | 客户环境里这玩意儿是一份还是很多份？ | **必须拆成集合页 + 详情页（或抽屉）** | 策略、质量模型、监测任务、规则模板、名单、探针、通知对象 |
| **单实例** | 全租户只有一份，或按"作用域"各一份 | 单页即可（可选作用域切换） | 概览、访问诊断、接入向导 |

> 🛑 **配置类对象还要判"匹配维度"**（主体 / 客体 / 端口 / 时段 / 组织），维度不全就画不出差异化策略；**判断记录进内部留档**。
> 🆕 **新模块必须单列 `P0` 接入页**：第一屏不是"空表格"，而是"怎么把对象弄进来"。
> ✅ **对齐检查**：1.3 的每一处 `Bx` 都要找到落点页面，一个都不能漏；漏了要么补页，要么写明"本期不做 + 原因"。

**② 动作覆盖表（防"只画了一条主线"）**

> 🛑 **实测病**：需求写了"安装升级 / 卸载 / 解绑 / 批量编辑 / 基础配置"五个动作域，草图只沿"安装升级"画，其余静默消失。**PRD 动作清单是验收项。**

| 业务对象 | 动作 / 状态 | 落在哪个页面 | 本期是否做 | 备注 |
| :--- | :--- | :--- | :---: | :--- |
| [终端] | 安装（底座 / 保护AI端 / Hook 分别安装） | P3 | 是 | 三类组件可分别选 |
| [终端] | 升级（同上三类） | P3 | 是 | — |
| [终端] | 卸载 | P2 / P3 | 是 | 高危，需影响确认 |
| [终端] | 解绑 | P2 / P3 | 是 | 高危，需影响确认 |
| [终端] | 批量编辑 | P1 | **否** | 原因：本期只做单条编辑 |
| [终端] | 基础配置（自启动 / 防卸载） | P2 | 是 | — |
| [终端] | 导入 | P5 | 是 | — |
| [终端] | 打标签 / 导出 | P1 | 是 | — |

> 🛑 **字段清单 ≠ 界面清单**：PRD 字段是信息备选池，哪些上主表 / 进详情 / 合并成一列，由"这页要办成什么事"决定；但每项要能说出它去了哪。
> 🛑 **表里出现"本期不做"的必须在交付时口头点一次**，不许埋在表里。

> 🛑 **红线**：页面清单**只写 5 列**；不写模板 ID（`page-form-drawer`）、组件名（`IxDrawer`）、字段清单、图形配色 / 线宽。**1.4 定"有几屏、各管什么"，4.1 定"每屏用什么模板、什么组件"。**

### 两套方案怎么摆：方案 tab → 场景 tab → 步骤 → 页面

> 🛑 **每一处出现都画全（2026-11-23 修正）**：上一版为了省篇幅让"相同页只画一次、另一套留占位条"。实测代价是**当前剧本缺屏**——用户切到场景 S3 或方案二，得跳出去找图才能讲。现规则：**同一页在几个地方出现，就画几遍**，每遍都完整。

```text
页头：需求草图示意 + 信息架构树 + 页面清单 + 示例数据声明

──────────────────────────────
## 草图思路发散              ← 分区标题：H2，字号 18~20，比正文标题大一号
```

> 🛑 **切换条是这块的主角，不是页脚的小链接**：方案 tab 选中项 `#1C6EFF` 实底白字；**整条左对齐、吸顶**；上方必须有「草图思路发散」标题。场景 tab 在方案 tab 下方一排，选中项同样实底。

| # | 铁律 | 为什么 |
| :---: | :--- | :--- |
| **1** | 结构固定四层：**方案 → 场景 → 步骤 → 页面**；**场景是互斥面板**（CSS `.scene{display:none}` + `.scene.on{display:block}`，一次只显示一个，**不许把一个方案的所有场景铺成无限长页**）；场景内只按步骤顺序排，不按页面编号 | 编号是资产号，不是操作顺序；无限长页会让切场景失去定位感 |

| **3** | **步骤头四要素齐**：`Step N：【步名】` / 意图一句 / `关联界面 Px、Py` / `看到：…`；步名与意图**逐字取自 1.1** | 讲解靠它；自编就与上游对不上 |
| **4** | 每个步骤下**按 `data-pages` 列出的顺序**放页面块；页面块 `data-page` 用资产编号，`data-occ` 用实例编号 | 门禁与下游都靠这两个键定位 |
| **5** | 两套的**场景集合、顺序、步骤号、步名一致**；页面集合可不同 | 左右切换时能对照同一场景 |
| **6** | 页面规模 + IA + 页面清单**只出现一次**（tab 之上）；顶部页面数按**资产**算 | 全貌属于"选之前"要看的；块数是内部概念 |
| **7** | 有差异的页，差异用**一句人话**写在图下说明里 | 两套差别常常只差"默认空还是满" |

| **9** | 默认态固定：**方案一 + 场景 S1**，场景 tab 与方案 tab 各自恰好一个选中 | 打开就能讲 |

> 🛑 **门禁口径（EX-1.4-34 ~ 38）**：34 查四层结构与步骤齐（步数/步名对 1.1），并查**每个方案恰好一个场景面板处于显示态、默认 S1**；35 查步骤头四要素、页面按 `data-pages` 承接、首步入口、末步末态，并查**场景互斥 CSS 与切换脚本（切方案回 S1 + 滚到 Step1、切场景换面板并定位 Step1）**；36 查同一 `data-page` 多副本的结构一致；37 查页面清单与剧本互相覆盖；38 查两套剧本的场景/步骤对齐。**五条中任一条红，不许交付。**
>

>
> 🛑 **切换定位（EX-1.4-33 / 35）**：跨方案切换显示目标面板后，先切到该方案 S1，再滚到 **S1 的 Step1**（`scrollTo` / `scrollIntoView`）；场景切换只换面板，再滚到该场景 **Step1**。页内 Tab 用按钮语义、无 `href="#"`、不改滚动。**场景必须互斥显示**（`.scene{display:none}` + `.scene.on{display:block}`），不许把一个方案的全部场景铺成一条长页。

## 四、每个方案要交什么

一个方案 = **四个必填件**，缺一个就算没交：

| # | 必填件 | 给谁看 |
| :---: | :--- | :--- |
| 1 | **对比表里的两段**：整体设计说明（含代价）+ 各自的设计思考点 | 看方向的人（30 秒） |
| 2 | **逐页草图**（按页面成套，带标号） | 想看清结构的人 |
| 3 | **图下标号说明**（每条标号一段：做法 + 为什么） | 要拿去讲给别人听的人 |
| 4 | **步骤流 + 重复页面**（每条 `Sx` 一个场景 tab，`Step N` 步骤头带意图与关联界面，每处出现都画全） | 要按场景讲一遍、或换人接手的人 |

> 档位组合、突破点落点、五段代价明细、动作覆盖表 → **进内部留档**，不占交付物版面。

### 1. 草图本体（按页面成套）

- **画法**：**不设视觉选型、不设参考库**——用什么图形、什么风格、好不好看，完全由执行时模型能力决定，越美观、越贴合需求场景越好。本节只管结构与下限，不规定画面表现（见 §五·1）；
- **必须画出来的**：页面整体分区、**主内容区必须有一个数据主图**（用 `<div class="hero viz" data-hero>` 圈住，区内 ≥2 个数据单元 + ≥2 处真实数字）——**主图必须呈现真实数据，不许用一句文字或一张文字表格代替**。
- **高保真区还要多两件事**：① 主图与主清单**画到最好效果**（图表用色、图标、层级、留白都按成品要求，不设上限）；② **图下写 Token**（`主色 #1C6EFF ｜ 风险 #FA8C16 ｜ 圆角 8 ｜ 正文 14px`），**图框内一个色值都不许出现**。
  - **语法不限、质量优先**：HTML/CSS 组件、SVG、Canvas、动态 demo 都行，选哪种由执行时模型能力决定，**不规定画法**。关键价值 / 创新点那一页要**高质量还原**，别用示意色块糊弄（机检 `EX-1.4-22` 会拦空壳）。
  - 🛑 **字体必须继承页面体系**：主图里的文字**不许写死 `font-size="…"` 或内联绝对字号**——用 CSS class 继承正文的 font-family / 字号阶梯（正文 14 / 标题 14 / 辅助 11~13）。实测翻车点：SVG 内写死 10~13px，缩放后与正文不一致、字体回退成 serif，整张图"和页面样式不搭"。**优先用 HTML/CSS 画**（天然继承字体），用 SVG 时必须显式继承 `font-family:inherit` 且字号用相对单位。
  - **创新档只剩一行状态的极简页可标 `data-thin="sys"` 豁免**；还要画出关键操作位置、**跨页的入口与去向锚点**（`data-go` / `data-from`，见 §1.3——这是结构，不是精度）；
- **必须标出来的**：**设计点**——用**标号**（①②③…）标在区块**右上角**，**同一组内容用虚线框圈住、只打一个标号**；标号必须与图下说明一一对应；
- **能力项一个不许掉**（画法可简化，功能不可省）：

| 类别 | 举例 | 草图里怎么处理 |
| :--- | :--- | :--- |
| **能力（必须满）** | 时间范围切换 / 时刻回看、筛选区、排序、搜索、新增、编辑、启停、复制、删除、批量、导入导出、分页、刷新、编辑态与保存、**页内 Tab 切换条** | **在它该在的位置画一块占位区 + 一句能力说明**（`筛选区：时间范围 / 对象 / 状态`、`工具栏：新增 / 批量 / 导出`、`排序：按影响人数 ↓`、`页内 Tab：分段证据 ｜ 影响范围`）；不画组件样式、不画下拉选项 |
| **跨页动线（必须满）** | 进详情 / 下钻 / 打开抽屉 / 返回 / 下一跳 | **画在真实触发元素的位置**：行末操作、按钮、节点、Tab、卡片；写法 `<i class="go" data-go="P2">查看路径 →</i>`；被进入页写 `<span class="from" data-from="P1">从「查看路径」进入</span>`。**只在图下说明里写"点这一行进详情"= 没画** |
| **数据（常规区可简 / 高保真区必须真）** | 单元格字段值、行内明细 | **常规区**：1~2 行示意值或灰条；**高保真区**：真值；**结论句里的数字一律必须仿真真值**（人数 / 占比 / 评分 / 时长） |
| **样式（常规区不画）** | 常规件的组件名、像素、图标、动效、Token | 一律不画 |
| **样式（高保真区要画）** | 图表用色、图标、动效、层级、间距 | **画到最好效果**；**Token 与色值只写图下，图内不写**；组件名（`Ix*`）仍不写 |

- **可以不画的（仅限常规区）**：字段值明细、组件样式、颜色、间距、图标（**列名要留**——列名是用户核对"覆盖没覆盖"的凭据）；**高保真区不在此列**——主图与主清单的配色、图标、间距都要按最优表达画出来。

#### 按页面类型对一遍能力位（缺一个就是漏功能，位置错了线框会跟着错）

| 页面类型 | 必须有的能力位 | 正确位置 |
| :--- | :--- | :--- |
| **概览 / 分析页** | 时间范围切换（今日 / 昨日 / 近 7 天 / 自定义）、数据更新时刻、（要看单次时）时刻回看、下钻入口 | 页头右侧或内容区首行；**不能只在标题里写"今日"** |
| **列表页** | 筛选区（时间 / 对象 / 状态）、搜索、排序、刷新、新增（主按钮）、批量、导入导出、分页、空态 | 页头右侧（筛选）→ 表格工具栏（新增 / 批量 / 导出 / 搜索 / 刷新）→ 表头（排序）→ 表尾（分页） |
| **详情 / 诊断页** | ① **顶部主信息区**（对象 / 事件名 + 关键状态 + 主操作，**不放进 Tab**）② **页内 Tab 条**（≤3 个，标出当前选中）③ 当前 Tab 的内容（结论 / 证据 / 明细）④ 底部动作（导出 / 标记已交接 / 下一跳） | **自上而下：标题栏 → 主信息 → Tab 条 → 内容 → 操作区**；Tab 条压在内容区首行，**不许顶到页头，也不许把主信息塞进某个 Tab** |
| **配置类 · 集合页** | 列表、状态、新增（主）、复制、启停、删除、优先级、最近变更、搜索 | 页头 + 工具栏 + 表格 |
| **配置类 · 详情页** | 编辑态、保存 / 取消（主左取右）、启停、变更记录、影响预演、**自定义项入口**（档数 / 区间 / 权重 / 匹配的主客体） | 表单分区 + 页脚 |
| **抽屉 / 弹窗** | 标题、关闭、主体、页脚主次按钮（抽屉贴左 / 弹窗贴右） | 按容器规范 |

> 🛑 **"不画"只针对常规区样式，不针对能力**：常规件可以不画按钮长什么样，但必须画"这里有一个新增按钮"；可以不给下拉里的选项，但必须写"这里能按时间 / 对象 / 状态筛"。**高保真区相反**：图表与配色要画，但**图内仍不写色值**。**图上看不到这个位置，下游就不会有这项功能。**

> 🛑 **一个页面有多面信息时，必须画出页内 Tab 切换条**（这是能力，不是装饰）：
> 1. **画出切换条**：一条横向的 Tab 区，写全 N 个 Tab 名，**标出当前选中的那个**。
> 2. **N 个 Tab = N 个面板，一个都不许省**（门禁 `EX-1.4-18`，与 5.0 的 `SP-W-09` 同一条判据，上下游成对）：切换条下面**每一块面板都要画出自己的内容**。写法固定，供机检认：切换条 `<div class="tabbar"><span class="tabx on">当前 Tab 名</span><span class="tabx">另一个 Tab 名</span></div>`；面板 `<div class="pane" data-pane="<Tab 名>" data-view="<视图编号>">…</div>`，`data-pane` 与 Tab 名**逐字一致**、`data-view` 与 `view-ledger` 编号一致。
>    * 🛑 **禁止用一句话代替面板**：「切到「影响范围」时此处换成…」「另两个 Tab 内容同上」「此处略」这类写法**一律判内容缺失**——草图是下游线框唯一的内容来源，占位这一句话，线框就会把这两个 Tab 做成空白页。
>    * **判据一句话**：指着任一个 Tab 名，能在同一页里指到它切换后的**≥2 个有名字的区块**。指不到、或只指到一句说明 = 这个面没画。
>    * **面板结构按 §1.2 的四条硬约束**：视图在 `view-ledger` 占一行；面板内 ≥2 个 `<b class="t">块名</b>`；该面自己的能力位标在面内；面内数据缺口用 `.ph data-ph="DATA"` 显性画出。**只有一个块的面必须标 `data-thin="sys"` 并写清系统接管了什么**。
>    * **允许留白的唯一情况**：创新档下系统把活接走了，面板只剩一行状态或一个结果——但那时**仍要把这块面板画出来、标 `data-thin="sys"`**并写清"系统接管了什么，所以这屏只剩 X"（见 §四·1「创新档的区域可以画得很空」）。
> 3. **位置固定**：`标题栏 → 顶部主信息（对象名 / 关键状态 / 主操作，不进 Tab）→ Tab 条 → 各 Tab 面板（按 Tab 顺序依次排，每块标出对应的 Tab 名）→ 底部操作`。**Tab 条不许顶到页头**，也不许把主信息塞进某个 Tab —— 否则每切一次 Tab 就丢一次"我在看谁"。
> 4. **术语只许写类型**：写 `页内 Tab：分段证据 ｜ 影响范围`、`抽屉：证据交接`。**禁用「视图①/②/③」这类自造词**——它既没说清是 Tab 还是抽屉，又容易被读成"一个长页面的三块内容"。
> 5. **抽屉不是 Tab**：标了抽屉的面，必须画抽屉形态（右侧浮层 + 露出背后页），不许和 Tab 内容平铺在同一列里。
> 6. 🛑 **同页的 Tab 面必须逐个画**：同一页面里的 N 个 Tab 就是 N 块面板，**没有"另一套有就行"、也没有"切到时此处换成"**。跨方案/跨场景重复的是整页，页内各面在每一处出现里也要画全（实测：`影响范围` / `交接材料` 两个 Tab 只写一行，到线框直接消失）。
- **非设计点区域**：灰块 + 一句 `此处沿用现有 XX，本次不动`。

> 🛑 **不许出现 `B1 / B2` 这类经验编号**：那是 1.3 的内部指针，用户看不懂。编号只用于"图 ↔ 图下说明"的对应，**图下说明里也不写 Bx**。

#### 点子怎么变成图上的一个块（从 1.3 到草图元素的转译）

> 🎯 **这是最容易断的一环**：1.3 给的是"提交前给影响预览"，这是个**句子**；草图上要出现的是个**方块**。中间缺一步转译，结果就是"点子表很漂亮，草图上看不出用没用"。

转译只有一条规则：**问这句点子在界面上"让人多看见了什么 / 少做了什么"，那个东西就是一个占位块。**

| 1.3 的点子（句子） | 问：界面上多了什么？ | 草图里画成 | 标号 |
| :--- | :--- | :--- | :--- |
| 提交前给影响预览：哪些会被命中、哪些会被自动阻断 | 多了一个"后果说明区" | 抽屉底部一个区块：三个数字（将受检 / 离线 / 可检）+ 一行提示 | `①` |
| 按"防病毒 / 防泄密 / 防外联"分组预置，勾选即填完 | 多了"一组可勾的项" | 一个区块：三行标签 + 展开入口 | `②` |
| 系统按资产画像自动出整套基线 | 多了"系统已填好的内容" | 同上区块，但**默认是满的**，并带"已预置 12 项"字样 | `②`（同一组，共用标号） |
| 规则组独立成模板，可命名 | 多了"来源与保存"入口 | 表单顶部一行：来源标签 + "保存为新模板"链接 | `③` |
| 三态进度 + 失败终端可查 | 多了"三个数字并排" | 详情页顶部三栏数字卡 | `④` |

> 📌 **同一处点子在不同档位下，画出来的差别就在"是空的还是满的""是人填还是系统填"**——这是草图上唯一要表达的档位差异，不靠颜色、不靠组件。
> 🛑 **转译不出来 = 这条点子是"感觉"不是"做法"**，退回 1.3 重写：说不出它在界面上让人多看见什么，它就落不了地。

#### 创新档的区域可以画得很空（唯一允许"留白"的情况）

系统把活接走了，界面上本来就只剩"确认 / 状态 / 结果"。**这是对的，不要因为"怕看起来没设计"就把内容填满——一填就退回优化版。**

| 做法 | 具体要求 |
| :--- | :--- |
| 区域形态 | 极简态 / 空态即可（一行状态 + 一个确认 / 一个结果列表） |
| 框里写什么 | 内容标题照写（如 `系统自动判定结果` / `本轮到期待确认`），不写解释 |
| 必须交代 | 在**图下标号说明**里写明"**因为系统接管了 X，此屏只剩确认**"——否则用户会以为这页没做完 |

> 🛑 **不要用"填满"来证明设计存在**：创新档的价值在于人少干活，图上看起来"没东西"恰恰是它的证据。**空得有理，比填得满更好看。**

### 1.5 每一页出现的顺序与入口，要能读出"人怎么走"

一套草图不只是几张图，**图的排列顺序本身就是设计**，但**顺序不等于链路**——页与页之间必须有图上锚点，否则只是"按顺序摆好的几张图"。**展示顺序 = 场景顺序**（不是页面编号顺序）：

```
S1 段：P1 概览（右上「受理报障」）→ P10 报障受理（弹窗）→ P3 诊断 · 路径依据 → P3 · 影响范围（ref）→ 末态：P4 台账新增 RG-0231（已交接）
S2 段：P1（ref）→ P2 监控 → P3 诊断 → 末态：……
```

**每页三件事必须齐**（缺一即判断点）：

| # | 要交的 | 判据 |
| :---: | :--- | :--- |
| **1** | **图上入口锚点** | 被进入页标 `<span class="from" data-from="P1">从「查看路径」进入</span>`，位置在该页真实入口处（抽屉标题左侧 / 页面标题下） |
| **2** | **图上去向锚点** | `<i class="go" data-go="P2">查看路径 →</i>` 落在真实触发元素上（行末操作列 / 按钮 / 节点 / Tab / 卡片） |
| **3** | **场景链路表 `flow-ledger`**（交接区） | 每条 `Sx` 至少一条完整链路：进入 → 操作 → 看到结果，每步都指得出触发元素与目标页。"从哪来到哪去"的文字只写在这张表里 |

> 🚫 **页面上不许写「进入：… ｜ 去向：…」动线行、职责句**（如"看全部任务""定查什么"）——那是解释，不是图；一律移到交接区或图下 notes。

- 排列要能回答一句：**"用户第一步看到什么、第二步做什么、什么时候知道自己成了"**；
- 如果两个方向的排列顺序一样，**它们大概率不是两个方向**（回第二节第一层重岔）；
- 抽屉 / 弹窗类页面，**必须露出背后的承载页轮廓**（灰化处理），并在**背后页上画出触发它的那个锚点**——否则"就地闭环、不跳页"这个最大的卖点在图上既看不出来、也走不进去。

### 2. 图下标号说明（每条标号一段，最重要）

固定两段，**缺任一段都不算交**：

```
① 做法：这处长什么样（一句话）
   为什么：针对现状里的哪个问题（一句话，指回 1.1 的卡点或用户原话）
```

- 好例子：*"② 做法：四类问题各占一格，格子里写明判定标准。为什么：这四种状态容易混，混了就会把'已安装'当成'已经在管'。"*
- 坏例子：*"② 做法：使用四象限布局，提升信息密度。"*（没有为什么，也没有取舍）

**判据**：把这段念给没看过需求的人，他能说出"**这处让我多看见什么 / 少做什么**"。说不出，重写。

> 🛑 **不许写**：`B1 / B2` 等经验编号、机制名（如"最小处理集合""四态并列"——要用人的话说"先做哪几件""四种状态分开写"）、"提升体验 / 更清晰 / 更高效"这类形容词。
> 🛑 **不许图和说明对不上**：图上有几个标号，图下就必须有几段；标号不许只当装饰。

### 3. 整体设计说明（对比表第一行，每套一段）

格式固定：**`把「<现在怎么做>」变成「<改成怎么做>」。代价：<谁要跟着变、每轮多花/省多少>。`**

- 3~4 句，≤120 字，一段说完；
- **代价必须写在同一段末尾**，不许另起一块、不许用小字灰色带过；
- 「现在怎么做」用用户的原话或 1.1 的卡点原文，不写"现状存在一定问题"。

> 🛑 **没有代价那一句，"创新路线"就成了"高级版"**：用户会默认它更好，闭眼选，上线才发现要改流程、改指标。**路线差必须折成代价差。**

### 4. 设计思考点（对比表格，两套各列各的）

| 要求 | 说明 |
| :--- | :--- |
| 条数 | **不要求两套一致**，各说各的；硬凑维度会让话说得别扭 |
| 每条内容 | 思考点（用户视角一句话）+ 为什么这么想（指回具体卡点） |
| 取舍怎么标 | 属于取舍的（如"不改分工，所以不派单"）**写明"取舍"**，不许包装成优点 |
| 来源怎么标 | 「为什么」一栏必须落到 1.1 的卡点或用户原话上，**不写"因为这样更好"** |

### 5. 成立前提与代价明细（内部留档，不交给用户）

一句话说清"这个方案成立要靠什么"：*要靠资产画像准确 / 要靠后端能给出影响面预估 / 要靠预置库有人维护*。**前提不成立的方案，不能当作可选项摆给用户。**

代价明细固定五段（对比表里只留一句总述，明细留档备查）：

| 段 | 写什么 |
| :--- | :--- |
| 改动范围 | 动几个页面 / 要不要动流程与角色 |
| 影响面 | 谁要跟着变（运维习惯、下游系统、口径） |
| 上线风险 | 主要靠什么兜底（先小范围试、可回滚） |
| 工作量档 | 大 / 中 / 小（粗估即可，不给人天） |
| **每轮多花多少人工** | **每次/每轮要多几步操作、多花多少时间**。**这一行最容易被漏，也最影响用户选择** |

> 🛑 **只算"项目成本"、不算"用户的日常成本"**：走"换载体"那条路往往改动小、风险低，但活儿还留在人身上。**不写这一行，等于把最大的代价藏起来。**

## 五、草图的画法标准（答疑：画成什么样算合格）

> 📌 **为什么要标准化**：不标准就会出现两种失控——**画太细**（用户开始挑颜色和间距，方向讨论变成细节讨论）和**画太粗**（用户看不出差异，只能说"都行"）。标准的作用是**把草图钉在"刚好看得出结构差异、又看不出实现细节"那一格**。

### 1. 视觉规格（常规区走灰块语汇，**高保真区按最优表达画**）

草图可以借用 `.wf-*` 里的**灰块 / 容器轮廓 / 占位条**这几个视觉语汇（省得另造一套观感）。但借用分两种，必须分清：

| 借用类型 | 例子 | 草图能不能用 | 原因 |
| :--- | :--- | :---: | :--- |
| **面块语汇**（只表达"这里有一块内容"） | `wf-card` `wf-row` `wf-shell` `wf-label` `wf-table` | ✅ 用 | 与规范无关，纯粹是画法 |
| **规范结构件**（自带规范语义） | `wf-form-item` `wf-form-label` `req` 星号占位 | ❌ 不用 | 一旦用了就得接受整套表单规范检查，草图会变线框 |

| 变量 | 线框图（第 7 节） | **草图·常规区** | **草图·高保真区** | 为什么这么分 |
| :--- | :--- | :--- | :--- | :--- |
| **信息密度** | 真实字段名、真实按钮文案、真实数值 | 3~7 字内容标题 + 灰条表示"这里有一批内容" | **真实数据 + 内容标题 + 状态**（主图与主清单要看得见内容） | 常规区写字段名会把讨论带到字段；高保真区不写就看不出点子兑现 |
| **组件精度** | 真组件（`IxTable` / `IxDrawer`）、真实宽度 | 灰块、虚线框，不标像素 | 图表 / 图标 / 动效按成品画，**清晰度不设上限** | 组件名两区都不写（那是 4.1 的活）；能不能画细是两回事 |
| **结构规范** | 全项必检 | **跟 5 条**：主按钮用主题蓝 `#1C6EFF` / 主左取右 / 抽屉页脚贴左、弹窗页脚贴右 / 抽屉·弹窗·整页不混用 / 页面分区骨架一致 | **同左，一条不减** | 这 5 条变了，线框就得变形，用户会觉得"方案被改了" |

> 🚫 **主图判定：与形态无关的四条不变量 + 五步选形程序（2026-11-20 修订）**
>
> 上一版写成「链路→轨道、分布→格」的形态对照表，是头疼医头：换成拓扑、桑基、概览条、机理插图就又不会了。**形态是结果，不是判据**。判据只有一条内核：**主图必须把「数据之间的关系」编码到「同一个承载空间」里，让人能指出来。** 任何形态（链路轨道 / 热力格 / 拓扑 / 桑基 / 概览条 / 构成条 / 排名榜 / 机理插图）只要满足下面四条，就是图；不满足，长得多像图都不是。
>
> **① 共享承载空间**：所有数据落在**同一个**空间里——一条轴、一张网格、一幅节点-边画布、一棵树、一条流带、一条堆叠条、一条时间轴、一条因果链。判据：被比较的两样东西，在图上能否用**同一把尺子**量（同一条轴上的位置、同一张网格的色阶、同一条流带的粗细）。**每个数各占一个私有框 = 没有共享空间 = 卡片墙。**
>
> **② 有编码通道**：主量必须落到**可排序的视觉变量**上，优先级：位置 ＞ 长度 ＞ 面积 ＞ 色阶/密度；连接关系用**边**（粗细 = 量，虚实 = 有没有数据）；状态用**色 + 形双重编码**（正常 / 异常 / 缺数据各有一种形状语言）。判据：把数字抹掉，图还看得出高低/长短/疏密/连断。**数字抹掉图就没了 = 只是把表格装进盒子。**
>
> **③ 关系可指认**：看完能说出一句**带关系的话**——「X 比 Y 慢 6 倍」「这 38 人都连到 CON-11」「这片是断点」「这分是被首包拉低的」「请求先卡在排队这一段」，并且**手指能落到图上的具体位置**（哪一段 / 哪一格 / 哪条边 / 哪个节点 / 哪一截刻度）。指不出位置、或只能说「有 5 个数」，判没画。
>
> **④ 落点可承接**：要接着查、接着改的实体（节点 / 格 / 段 / 边 / 刻度区间）在图上**本身可点**，不必回到下方清单再找一次。这条是加分项，但缺了通常说明图与下一步动作脱节。
>
> **五步选形程序（任何形态都走这五步，不许跳到样式）**
>
> | 步 | 做什么 | 反例（跳过会怎样） |
> | :---: | :--- | :--- |
> | 1 | **一句话问题**：这屏回答哪一个判断（断在哪段 / 今天哪片最差 / 这分怎么来的 / 请求卡在哪个环节） | 先想「放几张卡」，问题就被拆成了几个孤立数字 |
> | 2 | **指出主关系**：序列连接 / 同维分布 / 构成拆解 / 高低对比 / 层级包含 / 流向来源去向 / 时间变化 / **机理因果**（解释性插图用这一条） | 关系没定，形态只能靠感觉挑 |
> | 3 | **定承载空间**（骨架，不是样式）：连接→节点-边；分布→网格；构成→堆叠；对比→轴；层级→树；流向→流带；时间→时间轴；机理→因果链（部件 + 流向 + 前后对比） | 跳过骨架直接画框，必然回到卡片墙 |
> | 4 | **分通道**：主量给位置/长度，次量给面积/色阶/密度，状态给色+形，连接给边 | 全部信息都写成文字，图只剩装饰 |
> | 5 | **反向验收**：缩略图 + 一句关系话 + 手指落点，三样齐才算过 | 只验收「有图」，交出去的是空壳 |
>
> **形态可以是什么（举例只为说明覆盖面，不是清单）**：链路轨道、分支×应用热力格、节点-边拓扑、桑基状流向带、顶部概览条（总量 + 分段 + 变化率）、构成条 + 刻度、排名榜（长度编码）、时序分解图、机理插图（请求—排队—响应三段，标出卡在哪一段）。**共同点是四条不变量，不是长得像。**
>
> **卡片不是禁用，是降级**：卡片可以做**副图/指标条**（一屏顶部的 3 个 KPI），但**不许占主图位**；主图位必须同时出现「承载空间 + 编码通道」。一屏可以有卡片，但卡片不能是这一屏唯一的东西。
>
> **四类假图（一眼识别，治的是不同病）**：**卡片墙**——每数一私有框，缺 ①②；**数字表**——有行列没通道，缺 ②；**装饰图**——图形与数据无关（图标墙、渐变、插画底），缺 ②③；**空壳图**——有坐标没数据，缺 ③。
>
> 🚫 **监控 / 概览页：普通图表与局部可视化禁"单块通栏"，但核心主图 / KPI 可全宽**：柱状 / 饼 / 趋势 / 词云 / 排名摘要 / 分布图等**普通图表与局部件**，须**横向并排 2–3 块**或把 2–3 块**合并进同一横向容器**，各答一个**不同**的"3 秒问题"；单块拉满横向全宽 = 思考不足、用拉满凑版面。**全宽只给两类**：顶部概览统计卡 / KPI 条，以及需要大空间的核心主图视觉（拓扑 `topo`、桑基 `sankey`、热力 `mx`、散点 `scatter`）。**核心原则**：按对象的重要程度 × 页面信息密度灵活布局——重要且需空间的给全宽，次要 / 局部的横向组合；同一横向容器内多块须**上下等高对齐**（不得一块高一块矮、基线参差）。判据：指着普通图表问"旁边还能不能并一块？"能并没并 = 没拆；指着核心主图问"缩窄会不会看不清关系？"会 = 该给全宽。

**五条硬要求**：

1. **一份占位在台账里一行，图上按实例唯一**：图上编号写成 `<台账编号>@<实例>`（如 `PH-A-P2-01@S1-4-P2`）；去 `@` 后缀后必须等于台账编号。**图上编号集合 = 台账编号集合**（多一个少一个都判不合格），图上全编号唯一（机检）。
2. **「位置」必须写到"哪页、哪一块、哪一行"**：写 `页面上` 等于没写——线框要据此判断"展开后放哪、会不会挤掉别的东西"。
3. **CAP 必填「能力项」，一项一个词，用 `/` 分隔**：这是**唯一被机器对账的清单**——4.1 在映射清单里逐词占行，`SP-W-07` 拿这列去说明书里逐词找，缺一个报一条。写选项值（今日 / 昨日）不算能力项，写控件名（下拉框）也不算，要写**能力名**（时间范围 / 对象 / 状态 / 搜索 / 刷新）。
4. **「下游动作」用人话，不写组件名 / 模板 ID**：写"展开成什么能力、留在哪、沿用谁、不做什么"。组件与 Token 是 4.1 的事，写进来就跑到下一环了。**「出现于」列列出该能力所在的所有实例**，供讲解与对账。
5. **OFF 与 CAP 不许混**：本期不做的，图上不许出现可点控件；该做却标 OFF 的，等于静默砍需求。**判据一句话：指着这个占位问"线框里它变成了什么"，答不出具体控件 / 具体异常态的，就是没交接。**

> 🎨 **再强调一次：常规区的视觉不是设计，高保真区的表达才是。** 灰底斜体只是"这里还没细化"的语汇，不是配色、字号、间距或控件形态。**判据（分两区看）**：把草图与线框并排——**常规区**除"分区与信息位置"一致外，控件形态、字号、色阶、间距都应不同（完全一样判"没做设计"，5.0 铁律 24 / `SP-W-06`）；**高保真区**的图表形态、配色、层级、主图结构应与草图一致，线框只补字段、异常态与状态（被重画判"改掉了用户选的那块"）。　（视觉硬指标以 V 组为准：`V-03` 容器嵌套 / `V-08` 间距 / `V-10` 字阶 / `V-19` 圆角阴影 / `V-25` 行内对齐；本段只定"两区精度分界"，不重复取值）

> 🔗 **为什么这一步不能省**：下游拿到的是 HTML，不是你脑子里的打算。它读得懂 `class` 和 `data-ph`，读不懂"我本来想在这儿放个筛选"。**占位清单就是草图对下游说的最后一句话**——4.1 按它逐条落线框（§1.9），5.0 按它逐条核能力（铁律 23 / `SP-W-06`）。

#### 1.1.1 高保真区的标记与清单（`dx-ledger`）

> 🛑 **占位清单只说"这里该展开"，没说"这里已经画完了、下游该继承"。** 没有正向标记，4.1 会把高保真区当占位重画一遍——用户选的那块就白画了。

**标记写法（图上必须有，供机检认）**：

```html
<!-- 高保真区：一个区域一个编号，全篇唯一 -->
<div class="dx" data-dx="DX-A-P2-01">
  <div class="hero viz" data-hero>…主图…</div>
  <b class="t">受影响对象清单</b>　真实数据 + 状态
</div>
```

**三条硬规则**：

1. **同一块只能有一种身份**：`.dx`（已做设计）与 `.ph` / `.cap` / `.same`（未做 / 占位）**互斥**，同一元素不许同时带 `data-dx` 和 `data-ph`。判据：指着任一块问"下游该重画还是该继承"，答案必须唯一。
2. **高保真区必须指得出来源**：要么对到 1.3 的某条创新点子，要么是"本页主体内容（主图 + 主清单）"。**指不出来源的 `.dx` 判越界**（执行时自行扩大的高保真区）。
3. **Token 写在图下，不进图内**：`.dx` 区里只放内容与图表；色值 / 字号 / 间距写在图下 notes 的 Token 行（F-6）。`dx-ledger` 只登记"有没有 Token"，不重复记值。

| 编号 | 方案 | 页面 | 区域（哪一块） | 来源（1.3 点子 / 主体内容） | 图下 Token | 下游动作 |
| :---: | :---: | :---: | :--- | :--- | :---: | :--- |

### 1.6 浮层页与版面三条硬约束（机检 `EX-1.4-27` / `EX-1.4-28` / `EX-1.4-29`）

> 🛑 **治两类实测翻车**：① 抽屉页把内容画在浮层外，读者看成「页面里又套了一个抽屉」，上下半截不知什么关系；② 5 段链路被挤成 4+1 两排，链路读不出先后。这两类不是「草图精度不够」，是**结构错**，草图阶段就要拦。

**浮层页（抽屉 / 弹窗）三件事，缺一即判不合格**：

| # | 必须 | 怎么写 | 判错后的实测后果 |
| :---: | :--- | :--- | :--- |
| 1 | **灰化背景页** | `.ghost` 包住承载页轮廓（只放骨架线条，不放内容块），并标「背后页：Px（本次不改）」 | 读者看不出这个浮层压在哪，以为是一张独立页面 |
| 2 | **触发锚点** | 背景页里点出来的那一行 / 那个按钮加 `.trig` 并写明「行末『查看路径』」 | 读者问「我从哪点进来的」，链路断在浮层之外 |
| 3 | **内容全在浮层内** | `.blk` / `.sec` / `hero` 一律放进 `.wf-drawer` / `.wf-modal`；浮层之前只许有 `.ghost` | 出现「页面里又套一个抽屉」，上下两块谁也不属于谁 |

**版面三条（与「主图四不变量」配套）**：

| # | 约束 | 判据 | 反例 |
| :---: | :--- | :--- | :--- |
| 1 | **序列关系一条轴** | ≥4 段的链路 / 流程只用 `.chain`（`flex-wrap:nowrap` + 子项 `min-width:0`）；`.steps` 只用于 ≤3 段 | 5 段用等宽卡排，挤成 4+1 两排 |
| 2 | **主图必须有共享承载空间** | 一条轴 / 一张网格 / 一条链路 / 一条构成条；纯卡片与数字堆不算图 | 顶部四个数字卡当主图 |
| 3 | **指标不堆卡片墙** | 页内同类指标 ≥4 个，改成一排**指标条**（label + 数字 + 一行注释，无独立边框），不做独立卡 | 一屏 6 个指标各占一个卡片 |

> 📌 **这三条是「画法」，不是「风格」**：换任何视觉风格都成立，因此可以机检。风格好坏仍由人判，但「两个抽屉」「链路折成两排」「卡片墙当主图」属于结构错，**不放过草图闸门**。

### 2. 🛑 框里写"是什么"，不写"为什么"；为什么写进图下说明

> **先分清两种文字，别一刀切**（实测纠正过两次）：

| 文字类型 | 长什么样 | 写在哪 | 原因 |
| :--- | :--- | :---: | :--- |
| **内容信息**（是什么） | 「检测项」「下发范围与影响」「最近一轮检测」 | ✅ **框里** | 全是灰块，别人根本不知道这块是什么内容 |
| **解释信息**（为什么这么设计） | 「系统已按研发机画像出草案」「动手前就知道影响面」 | ❌ 框里 / ✅ **图下标号说明** | 框里写解释挡着看结构；但直接删掉，用户就看不懂——**必须搬到图下** |
| **规格值**（色值 / 字号 / 间距 / 圆角） | `#1C6EFF`、`14px`、`圆角 8` | ❌ 框里 / ✅ **图下 Token 行** | 图内写值会把画面弄脏，还会让人误以为这是定稿尺寸 |

**判据一句话**：**框里告诉人"这是什么"；图下告诉人"为什么这么设计" + "用了什么值"（Token）。三样各有位置。**

| ❌ 框里别写 | ✅ 框里该写 | ✅ 图下该写 |
| :--- | :--- | :--- |
| 「① 查什么 · 系统已按研发机画像出草案」 | `检测项 · 已按「研发机」预置 12 项` | ① 做法：系统按机器画像先填好……为什么：不用先懂规则、先选范围 |
| 「注：父部门以后新增终端也会被纳入」 | 不写在框里 | ① 为什么：父部门新增终端也要覆盖，否则新机器漏检 |

> 🛑 **每个区块要有一个 3~7 字的内容小标题，但不要带解释**：`检测项`（✅）／`① 查什么 · 系统已按画像出草案`（❌）。
> 🛑 **图框内不许出现色值与尺寸值**（`#1C6EFF`、`rgba(...)`、`14px`、`圆角 8`、`24px/600`）：它们统一进图下 Token 行。**判据**：把图框单独截出来，图上应该一个"值"都没有——只有内容、数字和状态词。
> 🛑 **图上不要写"第几步"式的序号叙事**：标号只用于"图 ↔ 图下说明"对应，不代表操作顺序。

### 3. 标号与区域的画法

| 规则 | 具体要求 |
| :--- | :--- |
| **位置** | 标号一律吸附在区块**右上角**（绝对定位，向外偏 8px），**不许占用正文位置、不许把文字推开** |
| **数量** | **同一组内容只打一个标号**：多个卡片/多行属于同一个设计点时，用**蓝色虚线框整体圈住**，标号打在框的右上角 |
| **形态** | 圆形实心徽标 + 阿拉伯数字（①②③ 与徽标二选一，全篇统一）；不用字母、不用 `Bx` |

| **非设计点但必须存在** | 虚线灰框 + 保留内容标题与大致体量（如 `任务列表` + 3 行灰条） |
| **未定的空白** | 留白，不要填"待定" |

## 六、怎么摆给用户看（呈现形式）

> 三次纠偏都发生过，记住这三条：
> * 第一版：3 个方向 + 对比表 + 顶部台账 → **"太复杂了，全是字，好累"**；
> * 第二版：删得太狠，清单也删了、框里只剩灰块 → **"看不到全貌，也不知道这块是什么内容"**；
> * 第三版：加了"方案标题句 + 3 条差异 + 方案依据 → **"根本看不懂，给其他人讲也讲不了"**。
>
> ✅ **现行结构：清单打底 → 对比表选方向 → 方案 tab → 场景 tab → 步骤流 → 每步下面的完整页面。**

```text
① 文件头：标题「需求草图示意」+ 一行小字
② 信息架构树 + 页面清单（全局，只出现一次）
③ 两套方案对比表：整体设计说明（含代价）+ 各自的设计思考点
④ 方案切换条（吸顶）：[ 方案一 ]  [ 方案二 ]   ← 切换后回到该方案 S1
⑤ 场景切换条：[ 场景 S1 ] [ 场景 S2 ] [ 场景 S3 ] [ 场景 S4 ]   ← 两套同一组，默认 S1
   ├ 场景 S1
   │   ├ Step 1：【步名】意图… ｜ 关联界面 P2 ｜ 看到：…
   │   │    P2 页面（完整画一遍）
   │   ├ Step 2：…
   │   │    P2 页面（另一种状态/另一面，仍画全）
   │   └ Step 3：…（末步含末态块）
   ├ 场景 S2：……
   └ 场景 Sn：……
```

> 🛑 **不要"请选择一个方案"这一块**：两个选项各配一段五段代价，用户得读完两段才能比；改成对比表，一眼并排。
> 🛑 **不要方案标题句**：`方案一：系统出草案，人只改差异` 这种压缩句，没读过 1.1~1.3 的人解不出来。**方案是什么，写在「整体设计说明」里。**
> 🛑 **不要"与另一方案的 3 条差异"**：三条差异说不清取舍，也不成体系；差异由对比表逐条对齐。
> 📌 **为什么对比表要放在 tab 之前**：用户先要知道两套各在想什么，再决定往哪套里钻。放在 tab 里，等于逼他先看一套再回来看另一套。

### 0. 页头与措辞规范

| 位置 | 内容 |
| :--- | :--- |
| 大标题 | **`需求草图示意`** |
| 小字说明 | **`基于需求理解之后进行的设计思考草图：关键设计点已给出设计表达，常规能力以占位交代；用于思路对齐，不替代说明书里的详细设计。`**（原"不涉及详细设计"已废止：高保真区就是设计表达） |
| 第三行 | 信息架构树 + 页面清单 |

> 🛑 **这行小字不是客套**：它提前把预期钉死——**用户不会拿它当设计稿挑间距和颜色**，也就不会把方向讨论带偏成细节讨论。这句话必须原样出现，不要改写。

> **交付话术不在这里写**：顿点话术见 §七「顿点话术（固化）」那四句，本节只管文件页头怎么写。

| 别写 | 该写 | 为什么 |
| :--- | :--- | :--- |
| 继续出**正式线框图** | 继续出**正式**说明书 | 线框图只是说明书里的一节，用户关心的是最终交付物 |
| 继续**进入下一环节** | 继续出正式说明书 | 用户不知道"环节"是什么，他只知道最后要拿到什么 |
| 请选择一个方案（+五段代价） | 两套方案的草图都在下面 | 选择区要读两段长文字才能比；对比表能一眼并排 |

> 🛑 **措辞要对齐用户的预期产物**：用户对接的是"说明书 + 代码"这两样东西；"线框图""页面清单"都是我们的中间件，**不要拿来跟用户对话**。

### 1. 对比表怎么写（本步的核心交付物）

固定两段，**都用表格**：

**第一段：整体对比**（两列并排，一眼读完）

| 对比项 | 方案一 | 方案二 |
| :--- | :--- | :--- |
| 整体设计说明 | `把「<现在怎么做>」变成「<改成怎么做>」。代价：<谁要跟着变、每轮多花/省多少>。` | 同左结构 |
| **who · 谁来做** | `<系统替他做了多少；一句话>` | （可相同，写"同上"） |
| **what · 靠什么办成** | `<承载形态：清单 / 分布 / 时间轴 / 工作台…>` | `<必须与方案一不同>` |
| **how · 人怎么操作** | `<几步、要不要跳页、要不要自己比>` | `<必须与方案一不同>` |
| **wow · 哪一刻意外** | `<哪一刻 / 因为什么 / 意外在哪>` | `<应当与方案一不同>` |
| 一句话区别 | `<两套最根本的分歧，一句话>` | 同左 |
| 本期不做 | `<动作清单>` | 同左 |

> 🛑 **中间四行是两套差异的主体**：`一句话区别` 只是给没耐心的人看的总结，不能代替四行。**what 与 how 两行写成同一件事，就判机械组合**（见 §二③）。
> 🛑 **代价必须写进「整体设计说明」的末尾**，不许另起一块、不许灰色小字带过。**没有代价那一行，"创新路线"就成了"高级版"**，用户会默认它更好，闭眼选，上线才发现要改流程、改指标。

**第二段：各自的设计思考点**（列：方案 | 编号 | 思考点 | 为什么这么想）

| 方案 | 编号 | 思考点 | 为什么这么想（对应现状里的哪个卡点） |
| :--- | :---: | :--- | :--- |
| 方案一 | 1 | `<用户视角一句话：会看到什么 / 能做什么>` | `<1.1 的卡点原文或用户原话>` |
| 方案二 | 1 | `<……>` | `<……>` |

- **两套条数不要求一致、维度不要求对齐**：硬凑会让话说得别扭；
- **每条必须带「为什么这么想」**，且落在具体卡点上，不写"因为这样更好"；
- **属于取舍的（如"不改分工，所以不派单"）必须写明"取舍"**，不许包装成优点；
- 思考点里**不出现** `Bx`、机制名、形容词（"更清晰""更高效"）。

**命名必须过三关**（思考点、整体说明都要过）：

| 关 | 判据 | 反面（实测犯过） |
| :---: | :--- | :--- |
| **对象** | 有没有**具体的业务对象**（终端 / 客户端 / 任务 / 策略） | `一进来就是没装好的终端`——哪个东西没装好？ |
| **动作** | 有没有**一个能做的动作**，不是"处理""补齐""搞定" | `点一下批量补装`——补装什么？ |
| **条件** | 有没有说清**按什么来选**（清单 / 标签 / 版本差 / 人工勾选） | `系统先判`——判什么、按什么判，全无 |

> 🛑 **禁用词**：`没装好 / 补齐 / 到位 / 闭环 / 收口 / 先判 / 赋能 / 极致 / 最小处理集合 / 采信 / 回执 / 留痕 / 处置 / 裁决 / 认领`。
> 🛑 **自检一句话**：把这句话念给没看过需求的人听，他能复述出"**对这个对象、按这个条件、做这个动作**"，才算过。
> 🛑 **不写"推荐 / 次选"**：一旦标了，用户跳过代价直接选；哪套更合适在交付话术里说一句即可。

### 2. 图下标号说明的固定句式

> **`① 做法：<这处长什么样> 为什么：<针对现状里的哪个问题>`**

- 「为什么」必须指出来源：**来自体验目标，还是来自这类工作的固有毛病**（写成用户的话，不写编号）；
- **代价不用在这里写**：代价在对比表的「整体设计说明」里已经写过一次，图下重复会显得啰嗦；
- 一段一条，**不超过两行**；超过两行说明这条设计点还没想清楚。

### 3. 内部留档要写清"想法从哪来"（不交给用户）

| 行 | 写什么 | 例 |
| :--- | :--- | :--- |
| 突破点落点 | 1.3 的每个 `Bx` 落在哪页哪块 | B1 → P2 顶部来源标签 |
| 档位组合 | 逐个突破点标档，一行读完 | B1 创新版 / B2 创新版 / B3 优化版 / B4 不在本套 |
| 代价五段 | 改动范围 / 影响面 / 上线风险 / 工作量档 / **每轮多花多少人工** | 改 4 页新增 2 页；运维要改习惯；先小范围试 5%；大；每轮多花约 20 分钟 |
| 动作覆盖表 | PRD 的每个动作落在哪页 | 见 §三 |

> 🛑 **不要写"亮点""优势""价值"**：那是营销词。写"为什么这么想"和"代价是什么"，用户自己会判断好不好。

### 4. 图的排布规矩

- **载体是一份单文件 HTML，两级 tab + 步骤流**：顶部（页头 / 页面总数 / 清单 / 对比表）固定；方案 tab 吸顶；场景 tab 在其下；tab 用原生 `radio + label` 或极简 JS 均可，**必须离线可用**；
- **场景是互斥面板**：一个方案下同时只显示一个场景（`.scene{display:none}` + `.scene.on{display:block}`），切场景是整块替换，**不是在一整页里往下滚**；
- **结构顺序固定**：方案 → 场景 → 步骤 → 页面。**不要按页面编号平铺**，也不要把两套的同类页面交叉排（见 §三之先·1.4）；
- 两套的**场景集合、顺序、步骤号、步名必须一致**（S1→S2→…；`Sx-1`→`Sx-2`…）；页面编号只作资产引用；
- 每个步骤头一行四段：`Step N：【步名】` ｜ 意图 ｜ `关联界面 Px、Py` ｜ `看到：…`；紧接着放该步的页面块；
- 每个页面块固定三段：**页面标题行（只放 `P1 页面名 · 形态`）→ 草图 → 图下标号说明**；说明紧跟草图，**中间不许插别的内容**；
- **每一处出现都画全**：同页在两个方案、多个场景、同场景多步/多 Tab 时都各自完整呈现，**不留占位条、不写"同上"**；
- 每张图配 `P1 / P2` 编号 + `页面名 · 形态`（如「终端详情 · 右侧抽屉」），方便用户指着说"这个第二屏不要"；**实例号 `data-occ` 不显示给用户**；
- 文件命名：`草图-<业务名>.html`，与说明书的 `design-spec-<业务名>.html` 区分开。

## 七、确认闸门（顿点话术固化，只发这一段）

> 🚦 **这是主线上第一个必须停下来等的闸门**，比 5.0 说明书后的确认更早、更关键——**方向错了，后面越细越浪费**。
>
> 🛑 **也是"需求进来之后唯一一次停顿"**：从 1.1 到本步交付，中间**不许停下来提问**（缺什么自己补 `【假设】`，随交付物一起给出）。

### 顿点话术（固化 · 照抄，只改 `< >` 里的填空）

```text
我已经对需求文档做了 <痛点穿透 / 场景与任务旅程 / 突破点拆解> 分析，梳理了需求的信息架构（<N> 个功能域 / <N> 个页面）以及两套草图思路。
请您查看 `_output/<业务名>/草图-<业务名>.html`，确认哪套思路更优。
确认后我将基于此方向做更进一步的设计与物料装配（逐页线框 → 设计说明书）——结构和高保真区的表达会保留，常规控件与配色会按设计规范重画。
若两种思路均不合您的预期，可以随时指出其中问题，或邀请我一起做思路共创。
```

> 🛑 **就发这四句，不许加料**：不列推荐理由、不铺五段代价、不贴 `【假设】` 清单、不复述页面清单、不说"我准备先做 A 再做 B"。这些**都已经在草图文件里**（对比表有整体说明与代价、图下有做法与为什么），用户点开就看得到，**问了再答**。
> 🛑 **第一句要落到实处**：写清做了哪几类分析（痛点穿透 / 场景旅程 / 突破点拆解）与梳理出的规模（功能域数 / 页面数）；不许写"我认真分析了需求"这类空话。
> 🛑 **路径必须能直接点开**：给真实路径，不许写"见附件"。
> 🛑 **总长 ≤6 行**（四句 + 空行），超了就是又铺开了。

### 用户追问时才补（一次补一层，不主动展开）

| 用户问 | 回什么 |
| :--- | :--- |
| "你推荐哪套？" | 一句：建议方案 X + 它让你不用再干 `<那件具体的事>`（不许用"更完整 / 更智能"带过） |
| "要付什么代价？" | 五段代价各一句（改动范围 / 数据 / 研发 / 每轮人工 / 组织），含**每轮多花多少人工** |
| "还有哪些没定？" | `【假设】` ≤3 条，每条一行 |
| "两套差在哪？" | 一句说 what 与 how 的差别（靠什么办成、人怎么操作），不展开页面清单与编号 |

> 🛑 **不追问就不主动铺**：顿点的任务是"让他点开文件、回一句话"，不是"让他读完一份方案"。

### 不符合预期时：共创改这一版，不重头画

| 用户说 | 我怎么接 | 产物 |
| :--- | :--- | :--- |
| 页多了 / 页少了 / 某页不该独立成页 | 在**同一份草图**上增删页、重排序号，两套同步改 | 改版草图（沿用原文件名，页头标 `v2 · 改了什么`） |
| 旅程不对（"这不是我要的做法"） | 回 §二① 重画两条旅程，档位沿用 | 新草图（仍叫方案一 / 方案二） |
| 某几屏对、某几屏不对 | **只改不对的那几屏**，其余原样保留，改动屏加标注 | 局部改版 |
| 档位不对（"太激进 / 太保守"） | 回 1.3 换档位点子，旅程不动 | 改档版 |
| 说不出哪不对，只说"感觉不对" | **给 1~2 个具体改法让他挑**（"P3 拆两页 / 留在 P3 用 Tab"），不许把题推回去 | 二选一后改版 |

> 🛑 **单点问题必须走「缺陷类」，不许「改这一处」**（`EX-1.4-27~29` 就是这么长出来的）：
> 用户指出一处（如「这页看不懂」「这段怎么换行了」），先把它归到一个**可判的结构类**——层级（谁压在谁上面）/ 排布（序列有没有折行）/ 主图（有没有承载空间）/ 占位（有没有身份证）/ 文案（是不是解释句），然后按三步走：
> ① **全篇扫同类**：同一类缺陷不许只改被指的那一页，改完重跑 `gate.js ex 1.4`，新增项必须全绿；
> ② **拦不住就先补门禁**：现有门禁拦不住这一类，先加机检（编号进《准出门禁总表》），再改产物；
> ③ **补完必须回归**：造一个坏例（只犯这一类）→ 坏例必须红，现有好例必须绿，两条都过才叫补完。
> **只改产物不改门禁 = 换一个需求原样复现**；这也是判断「这次是真的修了系统，还是又打了补丁」的唯一口径。

> 🛑 **共创回合上限 2 轮**：改两轮还对不上，说明问题不在草图——回 1.3 查突破点、回 1.1 查卡点，说明原因再重来，**不许在第 3 轮继续磨图**。
> 🛑 **每轮改版必须列出"改了什么"（≤5 条，写在页头）**：用户要能看出自己那句话落在哪，否则会觉得没被听见。
> 🛑 **共创不是开放式提问**：不给"你觉得该怎么改"这种题；要么让用户指屏，要么给 1~2 个改法让他挑。
> 🛑 **改版后同样要过 `tools/sketch-selfcheck.sh`**，并重发本节那段固化话术（只把"确认哪套"换成"看看这版改对没有"），不许改完直接往下跑。

### 用户可能给的答复，对应怎么走

| 用户答复 | 该怎么处理 |
| :--- | :--- |
| **选一个** | 记录选定结果；**若该方案声明里含"目标与指标变更"，选定即同时授权，并把新目标一起留档**（见下方铁律），再进 4.1 |
| **选一个但要改** | **先改、再确认、后进线框**——改动如果动到结构（换主结构 / 加减页面），退回本步重出草图，不许直接带去线框 |
| **先说"不太对 / 不是我想要的"** | **先进入共创，不追问选哪套**：按上文「不符合预期时」那张表处理；改完重发 §七那段固化话术（把"确认哪套"换成"看看这版改对没有"） |
| **都不满意** | 不许硬推，也不许直接进线框。问清"是旅程不对还是档位不对"：旅程不对 → 回 §二① 重画两条旅程；档位不对 → 回 1.3 补档位点子 |
| **要合并两个方案** | 允许，但必须让用户明确"以哪个为主结构、吸收另一个的哪一处、合并后档位取高的还是低的"，并留档；**防止最后变成四不像** |
| **明确说跳过草图** | 按"方案一直接执行"处理，见下方铁律；跳过只免掉"停下来等"，不免掉草图本身 |

> 🛑 **闸门铁律（默认必停）**：方案未定，不得输出正式页面清单、模板 ID、组件名。**只要用户没有明确说"跳过草图 / 不用草图 / 直接按方案一"，就必须先交草图、停下来等一句选定**——哪怕他这一轮的指令是"给我出设计说明书"、"你直接做吧"，也先出草图再问一句；"要说明书"不等于"授权你替他定方向"。
> 🛑 **明示跳过 = 默认方案一**：仅当用户**明确说出**跳过草图确认（如"跳过草图"、"不用给我看草图"、"别确认了，按方案一直接做"）时，才可越过闸门；此时**默认以草图方案一执行**，并在下游交付物开头用一行写明`方案来源：用户明示跳过草图，按方案一执行`。用户只说了跳过、没说哪套的，不再追问，直接取方案一。
> 🛑 **方案声明含目标变更 = 同时授权改目标**：必须当场把 1.2 的目标句与指标改成方案声明的那版并留档。**否则下游说明书还写着旧目标，新方案拿旧验收线验收，必然打架**——这是创新路线方案最容易埋的雷。

## 八、下游怎么接（1.4 → 4.1 的交接契约）

本步交给 4.1 的东西，只有六样，多一样都是负担：

| # | 交接物 | 下游怎么用 | 缺了会怎样 |
| :---: | :--- | :--- | :--- |
| 1 | **选定方案的全套草图** | 4.1 画线框时**按草图的分区与主结构继承**，不许另起炉灶 | 线框和草图对不上，用户会觉得"我选的不是你画的" |
| 2 | **突破点 → 档位 → 页面区域**对照（在本步是"方案依据"里的档位行） | 4.1 逐页核对"这处突破点有没有落点"，并作为经验采纳的靶子 | 突破点做了却没落地，或落地了却没人知道为什么 |
| 3 | **设计说明（含五段代价）** | **只在本步留档，不进说明书**（5.0 已取消「方案取舍 / 档位组合与授权记录」两节）；评审追问时回本步查 | 说明书变长、读者被方案复盘干扰 |
| 4 | **未采纳方案的一句话结论** | 进 5.0，回答"考虑过别的旅程吗" | 被质疑"是不是只想到一种" |
| 5 | **档位组合 + 目标/指标变更记录** | 4.1 逐页核"档位有没有降级"；5.0 用**改后的**目标与指标写第一、三节 | 拿旧目标验收新方案，说明书自相矛盾 |
| 6 | **占位清单（`ph-ledger`）** | 4.1 逐条填"展开成什么 / 沿用谁 / 不做 / 补什么异常态"（对账表见 4.1 §1.9）；5.0 按它逐条核线框能力 | 草图上画着的能力位在线框里凭空消失，用户上线才发现少功能 |
| 7 | **页内视图清单（`view-ledger`）** | 4.1 把每个视图当作独立装配单元登记（页面清单里一页带 N 个视图行）；5.0 第 7 节每页线框里逐面落 `wf-pane-label` 与该面自己的映射行 | 视图只剩一个标签，线框里变成空白面板，下游只能自己编 |
| 8 | **场景链路表（`flow-ledger`）+ 图上锚点（`data-go` / `data-from`）** | 4.1 页面清单带「进入 / 去向」并按锚点对账（§1.5）；5.0 每页批注首句写清从哪来、办完去哪 | 用户拿着说明书走不完一条场景，评审第一句就是"我怎么点进去" |
| 9 | **高保真区清单（`dx-ledger`）+ 图下 Token** | 4.1 按"**继承**"处理：图表形态、配色、层级、主图结构照草图落，只补字段与异常态；5.0 第 7 节对应页按此对账 | 高保真区被当占位重画，用户觉得"我选的那块被改了" |
| 10 | **剧本结构（`data-plan` / `data-scene` / `data-step` / `data-page` / `data-occ`）+ 步骤头四要素** | 4.1 页面清单仍是**资产级一页一行**，新增「出现位置」列（`S1-1 / S1-4 / S2-2 …`），「进入 / 去向」按出现列多值；5.0 第 7 节一页一节，批注首句列多动线。**步骤头不进说明书**，只作讲解底稿 | 4.1 按块数当页面数、5.0 只写一条动线，一页多次出现时丢上下文 |

### 继承校验（4.1 必做，回填到本步）

线框画完后必须回头对一次：

| 校验 | 判定 |
| :--- | :--- |
| 主结构是否一致 | 草图是"一屏工作台"，线框不能变成"列表 + 详情两页"——**要变必须先回本步改方向** |
| 页面数量是否一致 | 草图 3 个页面，线框多了 2 个 → 说明草图漏了页面，或线框私自扩张，两者都要回查 |
| 突破点落点是否都在 | 1.3 的每条方向（`Bx`，条数 = 1.1 旅程步骤数）在草图里圈的每一处，线框里必须都找得到；少了就是降级，要有理由 |
| 档位是否被偷偷降级 | 草图定的"创新版/创新版"，线框做成了"优化版" → 判定为执行降级，必须改回或说明原因 |
| 目标是否被悄悄改动 | 方案不得反向修改 1.2 的目标句；若点子确实做到了目标没写到的那一步，**回 1.2 把目标句补到方案实际做到的位置并留痕**（同步，不是授权），不许说明书与目标两套说法 |
| **结构级规范是否继承** | 草图上主按钮在左、用主题蓝、抽屉形态、分区位置——线框必须一致。**这 4 项在草图阶段已定死，线框阶段不许再改** |
| **占位是否逐条闭合** | 清单里每条 `CAP` 在线框里都能指到具体控件与位置；`KEEP` 写明复用谁；`OFF` 只进实现边界、不出现可点入口；`DATA` 落成显性异常态。**一条没处置 = 一处能力丢**（`SAME` 已退役，不存在"从另一套取图") |
| **Tab 面板是否逐块画出且拆到块** | 草图有 N 个 Tab 就必须有 N 块 `data-pane` 面板，且每面 ≥2 个命名区块、`view-ledger` 一视图一行；线框按每块面板逐一落 `wf-pane-label` 与该面自己的映射行。**出现"草图这里只写了一句、线框自己编内容"就是方向层失职**——内容没在方向层定下来，执行层就在替用户做设计（`EX-1.4-18` / `EX-1.4-20` / `SP-W-09`） |
| **高保真区是否被继承（不是被重画）** | 清单里每条 `DX` 在线框里都要能指到"同一个图表形态、同一套配色、同一层级"；线框只许补字段、异常态与状态。**被重画 = 用户在草图阶段选的那块被改掉了**（`SP-W-06` 的反向判据） |
| **动线是否闭合** | 图上 `data-go` / `data-from` 锚点与交接区 flow-ledger 的"进入 / 去向"，在 4.1 页面清单的「进入 / 去向」列与 5.0 每页批注首句里都要对得上（**草图页面上不写动线说明行**）；**目标页必须存在**，不许"点进去没有这页"或"这页没有入口"（`EX-1.4-19` / `SP-W-11`） |

> 📌 **一句话概括这张表**：**结构继承，常规区重做，高保真区继承，占位展开。** 分区、页面数、按钮位置与主次、容器形态一律照搬；**常规区**没定的字段、列名、像素、图标、动效全部补齐并按规范检查；**高保真区**的图表形态与配色照草图落，不重画；**草图上占着的每一块，线框里都要有归属**——变成控件、变成沿用、变成异常态，或者明确不做的口径。
>
> 🛑 **数据也要重做精度（不做就是失败）**：草图上为守"不编数字"而留的 `__`，**线框里一律不许带过去**。线框必须用一套**跨页自洽的示例数据**（对象名 / 数量 / 状态 / 时间 / 证据来源）填满，并补上**草图没展示全的字段与异常态**（长文本截断、空值、无权限、过期、超限降级）；同时在说明书第 7 节开头声明这是示例样本、不构成客户事实。**注意：高保真区在草图阶段就已用真实数据，"重做"指的是补全字段与异常态，不是换一批数**——换了数，跨页就对不上了。

## 九、常见跑偏（反面样本）

| 跑偏写法 | 为什么错 | 改法 |
| :--- | :--- | :--- |
| 给了 3 个方案 + 对比表 + 顶部台账 | **信息过载，用户没耐心看**（第一版实录） | 砍到 2 套，删前置信息与对比表 |
| 把常规版也画出来 | 常规版不需要被选择，只需要被满足 | 删；只在优化版/创新版里体现 |
| 框里带解释句（"查什么 · 系统已按…出草案"） | 干扰信息，挡着看结构 | 搬到图下标号说明里 |
| **框里只剩灰块、没有内容标题** | 别人**不知道这块是什么内容**（第二版实录，矫枉过正） | 补 3~7 字内容标题 |
| **没有页面清单，只按场景切两段** | 用户看不到全貌、不知道本次一共几个页面 | 开头补清单；页面在每个场景里各画一遍 |
| **共性页只在其中一套里画** | 另一套链路断裂，用户切过去找不到这一屏 | 两套都画，右上角标灰底 `两方案相同`（**重复画是对的，别省**） |
| 两个方案只是侧栏位置不同 | 结构没岔，是同一个方案的变体 | 回第二节①，从"谁先动 / 任务放在哪"重岔 |
| **常规区**里画了完整的表格列、写了字段名 | 精度跑到线框去了，用户会在细节上挑 | 退成灰条；**高保真区不适用**（那里就该有真实数据与列名） |
| 只画了首页 | 旅程站不站得住要连起来看 | 补成整套（进入 → 操作 → 结果） |
| 页内有 3 个 Tab，只画默认面、其余各留一句"切到时换成…" | 下游拿不到内容，线框只能编或做成空白面板 | 逐面画全：`data-pane` + `data-view` + ≥2 个命名区块 + 该面能力位（§1.2） |
| 页面之间只靠"排列顺序"表达先后，图上没有入口 | 顺序不是链路，用户走不进去（"我从哪点详情"） | 图上补 `data-go` / `data-from` 锚点，交接区补 `flow-ledger`（§1.3）；**页头不写「进入 / 去向」行** |
| 设计说明只写好话，不写代价 | 没取舍等于没判断 | 按"代价是…"强制补全 |
| **两套摆法不同、做的事一样（机械组合）** | what 与 how 是同一件事，用户做的事没变，只是排版变了 | 回 §二① 重画两条旅程（换分工 / 换载体 / 换时机），不要靠改容器制造差异 |
| **两套旅程四段全同，只有视觉不同** | 视觉差异不构成两条体验路径；用户看两套会问"这不还是一个东西" | 至少让 what 与 how 不同；视觉差异只能作为同一条旅程内的加分项 |
| **方案一写满创新档，却不写目标与指标怎么变** | 把"改前提"藏进漂亮方案里，上线才发现要改流程、改验收线 | 创新档必带"目标改哪句 / 指标换哪个 / 怎么防误伤"三行 |
| 用户说"都不满意"，我加第三个硬凑 | 没搞清是旅程问题还是档位问题 | 先问一句，再决定重画旅程还是回 1.3 补档位 |
