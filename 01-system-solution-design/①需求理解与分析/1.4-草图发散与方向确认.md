# 1.4 草图发散与方向确认 (Sketch Divergence & Direction Confirmation)

> 💡 **中枢定位**：
> 本文档承接 [1.3 体验突破点拆解](1.3-体验突破点拆解.md)，是【方案系统设计主线】Part1 的**收尾环节，也是整条主线上唯一的分岔点**。
> * 1.3 定的是"**在哪破、怎么破，摆出几档打法**"；
> * 本步定的是"**画出来是几个样子、走哪一个**"。
>
> ⚠️ **这一步的性质是"出方向"，不是"出方案"。** 草图不是线框图，它只回答一件事：**同一批突破点，能摆成几种结构完全不同的页面形态，每种形态里人还出多少力。**

> 🛑 **阶段铁律**：
> 1. **草图不是线框图**：只画**关键框架与布局占位**，不排字段、不调间距、不定组件、不写 Token。细则进不了草图，进了就变线框（那是 4.1 的活）。
> 2. **一档一套、必须成套**：一个方向要**整套页面**（不只画一屏），否则看不出这个方向能不能站住——很多方向单屏好看，连起来就断了。
> 3. **非设计点允许占位**：不承载突破点的区域，用一个灰块 + 一句说明带过（"此处沿用现有列表页，本次不动"），**不许为了显得完整而随手画满**。
> 4. **每个方向必须能回答"它对应哪几处突破点"**：对不上的草图是自嗨，退回重画。
> 5. **两个方案必须真的岔开**：如果只是"把侧栏换成顶部栏"，那是一个方案的变体，不叫两个方案。
> 6. **到这里必须停（默认不可跳）**：草图出完即停在确认闸门，**未获方案选定，严禁进入页面清单、模板选型、线框图与任何代码**。**停下之前必须先过草图门禁**（`bash tools/gate-ex.sh 1.4 _output/<业务名>/草图-<业务名>.html` 拿到全绿：结构 5 条 + 文案 7 条 + 能力位 1 条 + 占位可交接 1 条，**机检不合格同样不许交付**），带着硬错给用户看，等于让他替你挑按钮位置。**唯一例外**：用户**明确说出**"跳过草图 / 不用给我看草图"时，可越过闸门并**默认以方案一（高水位）执行**；用户只说"给我出说明书"不算跳过，见第七节铁律。
> 7. **能力必须满，精度可以降**：草图必须与线框**同源**——主按钮用主题蓝、主按钮在左取消在右、抽屉/弹窗/表格不混用、页面分区骨架一致；**否则草图到线框会出现"我选的方案被改了"的断裂感**。精确像素、星号占位、图标、动效**一律不管**（管了草图就变线框）。**但"能力项"不是精度**：时间范围、筛选、排序、搜索、新增、编辑、启停、复制、批量、导出、分页、刷新、编辑态——**一个都不许丢**，画不出来就占一块色块 + 一句说明。
>
> 🛑 **两条轴分开判，别再混着用**：
> * **能力轴（必须满，缺一个就是功能缺失）**：每个能力都要在**它该在的位置**占一块 + 一句话说清"这是什么能力"；**位置本身也是结构**——列表页筛选区在页头右侧、工具栏在表格上方、排序挂在表头列上（`03-design-assets/page-templates/01-page-types.md`）。
> * **精度轴（可以降，降了不影响判断）**：精确像素、单元格字段值明细、组件样式、图标、动效、Token。
> * **列名属于能力轴**：列名是用户核对"需求覆盖没覆盖"的凭据，按 PRD 列全；**单元格里的值**才是精度轴。
>
> 🛑 **能力项写在正文说明里＝没写**：用户和下游线框都只看图。图上没有那块位置，说明书第 7 节就不会有，功能就丢了。
>
> 🛑 **另一条边界**：线框图**不能因为"草图这样画的"就沿用草图的松散画法**——草图继承的是**分区与主结构**，不是它的精度。**继承结构，重做精度。**

## 零、这一步产出什么

| 项 | 内容 |
| :--- | :--- |
| **输入** | ① 主要场景清单 S1~Sn（1.1）② 各场景体验目标与指标（1.2）③ 各场景突破点 + 分档点子（1.3） |
| **产出** | ① **2 套方案草图**（方案一 / 方案二），每套 = **一条走法 × 一组档位** + 整体设计说明 + 设计思考点 + 逐页草图与逐条说明<br>② **用户选定结果**（选高水位时含目标/指标变更授权；确认后留档，作为下游唯一入口） |
| **内部留档（不交给用户）** | 档位组合 / 突破点落点 / 动作覆盖表 / 五段代价 / 目标与指标变更 |

> 📌 **一句话**：基于需求场景，把 1.3 的点子按**走法 × 档位**拼成两套，用**不懂业务的人也读得懂**的写法摆出来，让人一句话就能选。

### 🛑 四条输出铁律（最重要，先看这）

| # | 铁律 | 反面（实测犯过） |
| :---: | :--- | :--- |
| **1** | **只给 2 套**，两套的**走法与档位都要不同**；高水位还要过**实质自检**（≥2 处档位差含主战场页、说得出"人少干了哪件事"） | 一上来给 3 个方向 + 全量信息，**选择过多、信息过载**；或两套只是档位滑动，成了**拼盘**；或贴了"高水位"却看不出强在哪 |
| **2** | **不画常规版**，从**创新版 / 优化版**起画 | 把"最没设计含量"的那套也摆上台 |
| **3** | **图的框里只放内容，不放解释；解释一律写在草图正下方**——图上打标号，图下按标号逐条写"做法 + 为什么" | ①框里塞解释句挡着看结构；②**只有编号、图下没有说明**，用户看不懂这处在干嘛 |
| **4** | **所有文案必须站在用户视角**：说清"你会看到什么、你能做什么、做完会怎样"；**不写机制名、不写内部编号、不造词** | 「最小处理集合」「采信」「回执」「四组队列」「B2」——用户读不懂，也讲不出去 |

> 📌 **为什么是 2 套不是 3 套**：三套让用户进入"比较模式"，注意力耗在分辨差异上；两套进入"选择模式"，一句话就能定。**高水位那套放第一个，用一句实话说明它多解决什么、要多付什么。**
> 📌 **为什么常规版不画**：常规版是"别人怎么做我们怎么做"，它**不需要被选择，只需要被满足**——它是优化版/创新版的地基，画出来只会稀释重点。**如果两套都还停在基线上，说明这需求没设计空间，直说。**
> 📌 **铁律 3 与铁律 4 的关系**：**框里不解释，但图下必须解释。** 标号是"图"与"说明"之间的钩子，不是装饰；没有图下说明的标号等于没说。

### 交出去的是什么：一份单文件 HTML（页头 + 对比表 + 两个 tab）

**结论：`页头（页面总数 + 清单）→ 两套方案对比表 → [方案一 tab | 方案二 tab]`。**

| 内容 | 要不要 | 说明 |
| :--- | :---: | :--- |
| 场景名、体验目标、突破点清单、档位上限 | ❌ **不放顶部** | 这些**已经有共识**（1.1~1.3 都过过了），再摆一遍是重复劳动，还挡着看图 |
| 方案标题句（如"系统出草案，人只改差异"） | ❌ **不要** | **方案只叫「方案一」「方案二」**；这套方案是什么、解决什么，写进对比表的「整体设计说明」 |
| 水位徽标 / 推荐标 / 吸顶差异条 | ❌ **不要** | 水位差与差异由对比表承担，不再靠徽标和"3 条差异" |
| **⓪ 页头标题 + 一行小字** | ✅ | `需求草图示意` + "仅用于思路对齐，不涉及详细设计" |
| **① 本次需求一共 N 个页面** | ✅ | **放最上面**；紧跟功能域树与映射表（见第三节） |
| **② 两套方案对比表** | ✅ | 整体设计说明（含代价）+ 各自的设计思考点，**表格形式** |
| **③ 切换条（吸顶）** | ✅ | 只有两个：`方案一` ｜ `方案二`，点击切换 |
| **④ tab 内：按页面分块** | ✅ | 每页 = 草图（带标号）+ 图下逐条说明（做法 + 为什么） |

> 🛑 **不要前置一堆元信息**：用户点开文件，第一眼应该看到**页面规模和页面清单**，不是"场景 S1 / 体验目标 / 档位上限"这种台账。
> 🛑 **但对比表必须有**：两套方案的取舍要能并排读完；只给图、不给"两套各在想什么"，用户只能凭感觉选。
> 📌 **页面清单必须有**：否则用户不知道"这个需求一共几个页面、两个方案差在哪些页面"。

### 每一套方案的结构

```
方案一（tab）
├── P0 页面名（形态 · 主战场?）
│   ├── 草图：区块右上角打标号 ① ② ③（同一组内容只打一个）
│   └── 图下逐条：① 做法：…… 为什么：……
├── P1 页面名（形态）
│   └── …
└── P5 页面名（形态）
    └── 与方案一相同 → 一行交代，不重复画
```

> 📌 **设计说明必须回答"这个想法从哪来"**：每条思考点都要指回现状里的一个具体卡点（用户原话或 1.1 的卡点），**不写"因为这个方案更好"**。

| 图 | 在哪一步 | 回答什么 | 精度 | 谁看 |
| :--- | :--- | :--- | :--- | :--- |

## 二、怎么出方案（先岔走法、再配档位、最后拼成 2 套）

一套方案不是凭空想的，也不是"挑一组点子"——它是**一条走法 × 一组档位**。

> 🧭 **为什么要把这根轴说清**：只按走法分两套（两套水位一样高），最值钱的创新级点子永远进不了方案主体，只能被降档成一行注记；只按水位分两套（走法一样），得到的是两套精细度不同的**拼盘**，用户看的还是同一件事。**两维都得有差，才是两套方案。**

### 思考顺序：先岔走法，再给每条走法配档位，最后按二维挑两套

```text
① 按场景找岔口（同一件事，页面骨架/分工可以怎么歪）
        ↓ 一般能想出 3~4 种
② 给每条走法配一组档位（越高越要付代价，见后文"档位构成硬要求"）
        ↓
③ 按二维挑两套：走法不同 + 水位不同
        ↓
④ 常规版不画（它只是这两套的地基）
```

### ① 岔口在哪：五个维度（够用了，不必更多）

| 分岔维度 | 可以怎么摆 | 举例（合规检测任务） |
| :--- | :--- | :--- |
| **谁先动** | 人找对象 / 系统推出该处理的 / 系统判完人只确认 | 人自己选范围圈条件 vs 系统按资产画像出草案 |
| **任务放在哪** | 独立页 / 抽屉 / 弹窗 / 内嵌在原页 | 新建任务独立成页 vs 抽屉内配完即走 |
| **主线纵向还是横向** | 列表 → 详情 → 操作（纵向）／ 工作台一屏办完（横向） | 先选任务再看结果 vs 直接进"待处理"工作台 |
| **一屏管几件事** | 单任务单屏 / 多任务合屏 / 一屏管一类对象 | 一个任务一页 vs 一屏管所有任务 + 结果 |
| **改动落在哪里** | 改现有页面 / 新增页 / 重构导航 | 在现有列表上加能力 vs 新开一个运营工作台 |

> 📌 **最常出创新版的是第一个维度（谁先动）**。其他四个维度多半只能变"摆法"，变不了"分工"。
> 📌 **判一句**：把两个方案并排念一遍"用户第一步看到什么、第二步做什么"——**两步都一样，就不是两个方案**。

### ② 配档位：给每条走法配"一组"档位，不是逐处随手取一档

档位来自 1.3 的三档点子表（常规 / 优化 / 创新），但**取法不是逐处自由挑**，而是按水位成套配：

| 位置 | 档位构成硬要求 | 为什么这么定 |
| :--- | :--- | :--- |
| **方案一 · 高水位** | **≥2 处创新版**，其余不得低于优化版；**不许出现常规版** | 创新档才是"换人机分工"；没有它，这套只是"做得更好的优化版" |
| **方案二 · 稳水位** | **全部落在优化版**，最多允许 1 处创新版（该处方案一须是另一种更彻底的形态）；**不许出现常规版** | 优化版是"同一个做法做到最好"，不是没设计；但判断仍由人下，所以不给创新 |
| **同一处突破点** | 两套**不得同档**；同档的标"两案相同"，不再画 | 同档不贡献差异，摆上去只增篇幅 |

> 🛑 **档位差的背后是代价差**：同一处从常规版走到优化版，通常只是信息组织与路径的重排；从优化版走到创新版，通常意味着后端要能算、系统要能自动判，或者人机分工要改。**水位差如果对不上代价差，说明档位是硬凑的。**
> ⚠️ **创新档进方案，必须同时给两行**：`换掉了哪一步人机分工` / `防误伤怎么办`。两行缺一行，这处降回优化版——**这是防止把"追覆盖率→狂下发→断业务"这类风险藏在一个漂亮方案里。**

### ③ 拼成 2 套：走法与档位，两维都要有差

```text
① 五岔口出 3~4 条走法
② 每条走法配一组档位（按上面②的硬要求）
        ↓
③ 挑两条：走法不同 + 水位不同
      走法不同、水位相同 → 其中一条重新配档，或砍掉
      走法相同、水位不同 → 判为拼盘，退回 ① 重想走法
        ↓
④ 同一处 Bx 两套同档 → 标"两案相同"，不画
⑤ 每套出一行档位组合：B1 创新 / B2 创新 / B3 优化 …
```

| 位置 | 怎么挑 | 在文里怎么表达 |
| :--- | :--- | :--- |
| **方案一（高水位）** | 走法上敢动人机分工，档位上至少 2 处创新 | 标题缀 `高水位`，紧跟一句"多解决什么、要多付什么" |
| **方案二（稳水位）** | 走法上阻力最小、改动最少，档位全部落在优化版 | 标题缀 `稳水位`，多写一句"适合什么情况下选它" |

> 🛑 **不凑第三个**：如果只能想出两套像样的，就给两套。**硬凑的第三套，一眼就看得出是凑的，反而降低可信度。**
> 🛑 **两个都不满意怎么办**：那就是回第二节①重岔走法，不是往回收一个常规版垫底。
> 🔎 **判"拼盘"只需一句**：把两套的"第一步看到什么、第二步做什么"各念一遍——**两步都一样、只是精细度不同，就是拼盘，不是两套方案。**

### ④ 特例：走法真的岔不开时

如果需求很实、走法没什么可岔的（比如"给现有列表加个批量处置"），允许**两套共用同一条走法，只在档位上分**：

| 位置 | 要求 |
| :--- | :--- |
| 方案一 | 至少 2 处创新版，并在依据里写明"走法无分岔，本套靠档位拉开" |
| 方案二 | 全部优化版 |
| 必须补一句 | **"这件事在创新档下会变成什么样"**——哪怕不画，也要写 |

> 📌 **为什么要补那一句**：**"结构只有一屏"不等于"分工不能变"**。批量处置做得再顺，也可能本来就该由系统自动执行——把这条特例当成"这需求没有创新空间"的免死牌，就会漏掉真正的创新档。
> **这时更要严格不画常规版**——否则整份文件就只剩一张谁都想到的图。

### ⑤ 高水位的"高"要看得见，不能只是个标签

> 📌 **用户判断"这套有没有东西"，不看档位名，只看三个地方。**

| 感知点 | 高水位必须不同在哪 | 只是"精细一点"不算 |
| :--- | :--- | :--- |
| **第一眼（首屏）** | 多一个"结论 / 该办什么"区，或少一个"先选条件"的动作 | 同一屏里标签更全、按钮更顺 |
| **步数** | 少一次跳转 / 少一次判断 / 少一次自己去找去查 | 同一条路径上少点两下 |
| **结果呈现** | 直接给结论 + 依据 + 下一步 | 原始数据摆得更整齐 |

**两条硬要求（达不到就不是高水位）**：

1. **≥2 处 `Bx` 与方案二不同档，且至少 1 处落在主战场页**（用户花时间最多、操作最重的那一页）。只在边角页发力（比如列表顶部加个统计条）不算。
2. **说得出"用户少干了哪一件具体的事"**：一句话、动词在手——"不用自己圈范围""不用逐个看哪台不合规""不用等跑完再回来看"。**说不出这件具体的事，这套就只是优化版换了张皮。**

> 🛑 **"高"不等于"多"**：创新档往往界面更空（系统把活接走了，见 §四）。**不许用"页面更多 / 组件更多 / 区块更多"来证高**，只许用"人少干了什么"。

**天花板真的低时（需求小 / 目标只到优化版），两种正确处置**：

| 情况 | 正确处置 |
| :--- | :--- |
| **天花板低，但仍有档位空间** | **方案一取"顶格档"、方案二取"顶格下一档"**，不要两套都停在中段。水位差可以只有 1 档，但必须是**最高的相邻两档**——这是"尽量拉开"的底线 |
| 创新档在本需求里不成立，或代价明显大于收益 | **不许贴"高水位"标签**：改叫 `方案一 · 上限版`，并在选择区写明"本需求最高到 [优化版]，原因是 [目标只要求… / 创新依赖的能力本期没有]" |
| 两套在第一眼、步数、结果三处都一样 | **不出两套**：只出一套 + 一页"备选档位"，并说明为什么岔不开——**硬造的高水位比只给一套更伤信任** |

> 🔁 **先回 1.3 找料，别先降低标准**：高水位没料时，按顺序查三处——① 点子是不是只摊到了优化档（回 1.3 第 3 步换维度重摊）；② 入口 2（工作类型经验）是不是漏扫了；③ 某处创新档是不是因为"怕代价"被自己划掉了。**三处都查过仍无料，才认定天花板低。**

**三种"假高"，一眼识破**：

| 假高 | 长什么样 | 为什么假 |
| :--- | :--- | :--- |
| **换容器** | 抽屉改整页、列表改成分栏 | 人还得自己判断、自己找，只是换了个壳 |
| **加装饰** | 顶部加一排"智能概览"卡片 | 界面多了东西，人没少干活 |
| **档位虚标** | 两处优化版合并说成一处创新版 | 档位是标出来的，不是做出来的 |

> 🔎 **一句话判据**：**高水位 = 用户少干了一件具体的事。** 说不出这件具体的事，就不是高。

## 三之先、信息架构与页面命名（先做这五件，再动笔）

> 🛑 **这一节治两个实测病**：① 把需求条目翻译成页面（12 条能力 → 7 个页面，一个动作一页）；② 页面名写成口语或问句（「交给谁」「这一片还有谁」），传到说明书第 7 节时无法作为章节名与权限项落库。

### 1. 先给信息架构，再给页面映射（顺序不许反）

**三件套缺一即退回**（按顺序交）：

| # | 交付物 | 必须回答 | 长什么样 |
| :---: | :--- | :--- | :--- |
| **1** | **模块定位** | 新增一级模块还是挂在现有模块下？与哪些模块并列？只读消费谁？ | 3 行结论：模块归属 / 与现有模块关系 / 导航层级 |
| **2** | **功能域树** | 一级模块 → 功能域（3~5 个）→ 页面 → 页面内视图；**每个节点都要标"承载形态"（菜单 / Tab / 整页 / 下钻页 / 抽屉 / 弹窗）**，判据见下节 | 一棵树，每层标名字 + 职责 + 承载形态 |
| **3** | **页面 × 对象 × 动作映射** | 每页属于哪个功能域、核心对象与**实例基数**（一份 / 多份）、**匹配维度**（主体 / 客体 / 时段 / 组织）、承载形态、承载哪些动作、**不在这页做什么**、两套差异 | 7 列表（一张表同时回答"谁、什么对象、做什么、哪里不一样"） |

> 🛑 **不再单列「核心对象模型」与「页面清单」两张表**：对象信息并进映射表（实例基数 / 匹配维度两列），页面信息并进功能域树与映射表（页面名 + 两套差异列）。**同一件事只在一处定义**——多一张表，就多一次对不齐。

> 🛑 **动作覆盖表是校验工具，不是拆页依据**：它的用途是「查有没有动作没落点」，不是「每个动作给一个页面」。**先有 IA → 再定页面 → 最后用覆盖表校验**；顺序反了就会一步一页，页数永远等于流程步数。

### 1.1 层级必须拆到叶子，每层都要判"用什么承载"

> 🛑 **实测病**：IA 只写到"功能域"三个字就停了；或一个能力名字独立就默认拆成一级菜单，结果菜单四层深、页面一堆空壳。**"拆到第几层、这一层用什么接"必须逐层写出来，不许停在功能域名上。**

**拆解顺序（逐层写，不许跳层）**：

| 层 | 要回答什么 | 产物形态 |
| :---: | :--- | :--- |
| 一级模块 | 新增一级菜单，还是挂在现有模块下？ | 3 行结论 |
| 二级（功能域 / 菜单） | 3~5 个，各自只回答一个问题；**是"菜单"还是"页面组"** | 树的第二层 |
| 三级（页面 / 叶子） | 每页名词化 ≤6 字；**是独立菜单项、菜单下 Tab，还是上级页的下钻页** | 页面清单 |
| 页面内（视图 / 浮层） | 同一对象的多面信息用 **Tab** 还是 **抽屉 / 弹窗**；谁能点开谁 | 视图清单（挂到页面下） |

**承载形态怎么判**（先读 [`patterns/01-navigation-and-hierarchy.md`](../../03-design-assets/patterns/01-navigation-and-hierarchy.md)，按它判，不自己发明）：

| 情形 | 用什么承载 | 判定要点 |
| :--- | :--- | :--- |
| 独立业务旅程、要反复进出、要独立权限 | **一级 / 二级菜单 + 整页** | 有独立入口价值，不是谁的附属 |
| 同一菜单下的子任务 / 同一对象的不同内容面 | **菜单下 Tab 页面**（不再开子菜单） | 避免 Tab 套 Tab |
| 从列表挑一条看细节、要保留当前上下文 | **抽屉详情页** | 关掉后保留筛选与滚动位置 |
| 完整信息要持续浏览、内容多 | **下钻详情页** | 返回回原列表位置 |
| 临时查一批对象、选完就关 | **弹窗列表页**（<20 项）/ **抽屉列表页**（≥20 项） | 不在主路径上 |
| 单条规则 / 少量字段的新增编辑 | **弹窗表单页**（默认）/ 抽屉表单页（仅特别说明）/ 配置表单页（字段多、需稳定 URL） | 见 [`patterns/03-form-patterns.md`](../../03-design-assets/patterns/03-form-patterns.md) |
| 名字很独立、但只是辅助配置 | **挂在相关对象页里的入口**，不单独成菜单或页面 | 不因名字独立就拆页 |

**硬约束**（与规则库冲突时以规则库为准）：

1. **菜单层级 ≤3 级**（一级 → 二级 → 三级 / 叶子）；超了优先收敛成 Tab 或分组标题，**不加深导航**；
2. **收敛顺序固定**：独立菜单页 → 菜单下 Tab 页 → 页面内入口 / 轻量入口；**不许一上来就拆新菜单**；
3. **下钻顺序 ≤4 层**：页面 → 抽屉 → 弹窗；**不许"抽屉打开页面"、"弹窗打开抽屉"**；
4. **每个节点都写"承载形态 + 一句依据"**：只写名字不写形态 = IA 没做完。

**IA 树落盘格式（交付物里就长这样，不是只写功能域名）**：

```text
数字体验（一级菜单）
├─ 体验观测 · 菜单（二级）              ← 承载：菜单下 2 个页面
│  ├─ 体验概览 · 整页（叶子）
│  └─ 异常事件 · 整页 · 列表（叶子）
├─ 问题诊断 · 菜单（二级）              ← 承载：1 个页面 + 3 个页内视图
│  └─ 访问诊断 · 整页（叶子）
│     ├─ 分段证据 · 页内 Tab
│     ├─ 影响范围 · 页内 Tab
│     └─ 证据交接 · 抽屉
└─ 监测配置 · 菜单（二级）
   ├─ 监测策略 · 整页 · 列表（多实例 → 集合页）
   │  └─ 策略详情 · 抽屉表单（新增 / 编辑）
   └─ 质量模型 · 整页 · 列表（多实例 → 集合页）
      └─ 模型编辑 · 整页表单（改档数 / 区间 / 权重）
```

> 🛑 **只要有一个节点写不出承载形态，或形态冲突（4 级菜单 / 抽屉开页面 / 弹窗开抽屉），IA 判未完成，不许进逐页草图。**
> 🛑 **IA 定稿即冻结**：这是全流程**唯一**的信息架构来源。4.1 只做继承对账与组件落地，5.0 只做投影引用，**都不许重拆、改名或新造功能域**；要改只能回本节改，改完重跑草图门禁并回填下游对账。

### 2. 页面命名五条（机器可判，见 EX-1.4-08）

| # | 规则 | 判据 | 反面 |
| :---: | :--- | :--- | :--- |
| **1** | **名词化** | 不写问句、不写动宾短语、不用指示代词（谁 / 哪 / 怎么 / 一次 / 这一片） | 「交给谁」「这一片还有谁」「一次卡慢的现场」 |
| **2** | **≤6 字** | 要能进左侧导航不被截断 | 「接入与对象圈定维护」 |
| **3** | **一页一功能域** | 不把两个动作或两个产物并列 | 「提醒与口径」「证据包与台账」 |
| **4** | **产物优先于动作** | 写「证据包 / 质量模型 / 处理记录」，不写「交接 / 配置 / 处理」 | 「配置页面」 |
| **5** | **可进目录** | 能被说明书直接引用为章节名、能被权限项命名 | 口语与缩写混写 |

**正反例（实测）**：

| ❌ 原写法 | 病在哪 | ✅ 改后 |
| :--- | :--- | :--- |
| 这一片还有谁 | 完整问句 | **影响范围** |
| 交给谁 | 完整问句 | **证据交接** |
| 一次卡慢的现场 | 指示代词 + 口语 | **访问诊断** |
| 提醒与口径 | 内部词「口径」+ 两个产物并列 | **监测策略** |
| 体验总览 | 非标准 IA 词 | **体验概览** |
| 接入与对象圈定 | 两个动作并列 | **采集配置** |

> 📌 **一句话**：页面名是**产品资产**，要进导航、进权限、进说明书目录、进测试用例；名字写坏，后面每一层都要跟着改。

### 3. 同一对象的多个视图，合并为一页

**判据只有一句**：这几个视图是否共用**同一核心对象**与**同一选择上下文**？

| 情况 | 处置 | 例 |
| :--- | :--- | :--- |
| 共用同一对象（同一个人 / 同一个事件 / 同一段时间） | **一页 + Tab 或抽屉**，不页化 | 现场 / 影响范围 / 证据交接 → 一个「访问诊断」页的三个视图 |
| 对象不同或需要重新选择上下文 | 分页 | 监测策略（对象 + 规则）与质量模型（口径） |

> 🛑 **页化同一对象 = 逼用户重新选一次对象**，最容易选错；而且页数会随流程步数膨胀。

### 4. 不线上化的能力，必须显式标注

| 要求 | 做法 |
| :--- | :--- |
| 页面清单 | 写 `❌ 否`，并在备注列写线下承接方式（邮件 / 群 / 人工台账） |
| 页面 × 动作映射表 | 单列一行，写明「线下」，不许静默消失 |
| 交付话术 | 口头点一次，说明为什么本期不做 |

> 🛑 **两个极端都要避免**：静默删掉（用户以为漏做）与硬做空壳页（建一个没人维护的表单）。**线下承接方式必须一句话写清交给谁、用什么载体。**

### 5. 数据必须是**仿真数据**，不是随便编的示意

> 🛑 **示意 ≠ 仿真**：`深圳 · 某对象 · __ 人` 是示意，评审者无法判断结构是否成立；`VU-2041 张伟 · 研发部 · 接入节点-02 · 39.6 秒（基线 9.8 秒）` 是仿真，评审者能像看真实系统一样判断。

| # | 仿真要求 | 判据（自己能验） |
| :---: | :--- | :--- |
| **1** | **对象带标识** | 至少主要对象有编号或全名 + 归属（`VU-2041 张伟 · 研发部` / `APP-07 CRM` / `POP-02 接入节点-02 · 深圳`），不是「某人 / 某应用」 |
| **2** | **字段完整** | 时间戳到分秒（`2026-10-25 10:07:02.8`）、状态用枚举值（`处理中 / 已关闭`）、带来源与变更人（`来源：客户端探针 / 变更人：王敏`） |
| **3** | **量级自洽** | 总数 = 各分项之和（`1,240 = 1,082 + 121 + 37`），比例与人数能对上（`38/74 = 51%`） |
| **4** | **时间线不倒序** | 越线 → 报障 → 快照 → 处置，时间必须单调（`09:34 越线 → 10:07 报障 → 10:20 快照`），不许出现「快照早于越线」 |
| **5** | **跨页同一批数** | P1 说 38 人，P2 的事件行、P3 的名单、P5 的评分必须是同一批人、同一组数字 |
| **6** | **页头声明** | 示例环境 + 快照时间 + 规模 + 一句「仿真数据，不构成客户事实」 |
| **7** | **结论数字必须真值，`__` 空占位禁止** | 结论句里的数字（人数 / 占比 / 评分 / 时长 / 时间点）必须是仿真真值且可复算，否则判断不了「结论句是否成立」；**表格单元格的字段值可用灰条或示意值**（那是精度，不是结论） |

> 📌 与「不编造客户数据」不冲突：编的是**标注过的仿真样本**，用于判断结构是否成立；对外交付时声明必须保留，真实数据回来只换数值、不换结构。

### 6. 块标题必须是**名词短语**（机器可判，见 EX-1.4-11）

> 🛑 **先记住一件事：黑名单查不住口语。** 口语是无限组合——「盯谁」「通知到谁」「不是一个人」「按这次的证据，先问这一处」「一起交出去的材料」，每次换一句就漏一次。**所以判据不能是"禁用词表"，必须是"结构"：先规定格式，再按名词规则校验。**

**格式（强制）**：块标题写成 `<b class="t">标题</b>　内容`（后跟全角空格）。
* 只有 `class="t"` 的 `<b>` 才被当作标题校验；正文里的加粗强调不受影响，不会被误判。
* **标题里只放名字，不混内容**：`聚合规则：同一段链路上 ≥5 人同时越线` 是错的，应为 `聚合规则` + 全角空格 + 说明。

**五条机检判据（缺一条即不合格）**：

| # | 判据 | 为什么 | 反例 |
| :---: | :--- | :--- | :--- |
| **1** | **不含标点**（，。；？！） | 带标点的标题一定是句子 | 「按这次的证据，先问这一处」 |
| **2** | **不含口语词**（我 / 你 / 他 / 这 / 那 / 哪 / 谁 / 什么 / 怎么 / 为什么 / 吗 / 呢 / 吧） | 这些词把配置项写成了自问或对话 | 「不是一个人」「当前这批对象的分布」 |
| **3** | **不以动词短语开头**（不是 / 按 / 一起 / 先问 / 交给 / 导出 / 标记 / 看一下 / 打开 / 新增 / 发布新） | 标题是名字，不是动作 | 「一起交出去的材料」「发布新版本」 |
| **4** | **≤12 字** | 进导航、进表格列头、进说明书小节名都放得下 | 「接入形态与已接入探针」 |
| **5** | **命中名词词尾**（范围 / 对象 / 分组 / 条件 / 级别 / 通知 / 状态 / 记录 / 清单 / 模型 / 指标 / 阈值 / 权重 / 等级 / 分布 / 归因 / 结论 / 材料 / 方式 / 规则 / 版本 / 探针 / 分段 / 维度 / 评分 …） | 保证它是"一类东西的名字"，不是一句描述 | 「已划掉的跳」→ 已排除分段 |

**实测反例（全部栽过，直接背）**：

| ❌ 原写法 | 病 | ✅ 改后 |
| :--- | :--- | :--- |
| 盯谁 / 通知到谁 / 什么条件触发 | 疑问式 | 监测对象 / 通知配置 / 触发条件 |
| 不是一个人 | 句子 + 口语 | 群体判定结论 |
| 按这次的证据，先问这一处 | 带逗号的句子 | 责任方向建议 |
| 一起交出去的材料 | 动词开头 | 交接材料清单 |
| 按应用分布 / 按地区分布 | 动词开头 | 应用维度分布 / 地区与接入节点分布 |
| 当前这批对象的分布 | 口语词「这」 | 对象评分分布 |
| 一行一个对象，不做人群聚合 | 标题混内容 | 聚合方式 + 全角空格 + 说明 |
| 聚合规则：同一段链路上 ≥5 人… | 标题混内容 | 聚合规则 + 说明 |
| 主因跳：POP-02，等首包 1.8 秒 | 标题混内容 | 主因跳判定 + 说明 |
| 材料（按该团队模板已勾好） | 标题混括号说明 | 交接材料清单 |
| 已划掉的跳 | 无名词词尾 | 已排除分段 |
| 发布新版本 | 动词开头 | 版本发布 |
| 切维度看 / 筛与排 | 口语动补 | 维度切换 / 筛选与排序 |

> 🔎 **人工兜底判据**（机检之外）：把标题单独抄进一张清单，**只念标题、不看内容**——如果听的人能说出「这是一类配置 / 一类结论 / 一类材料」，合格；如果他以为你在跟他说话，就是口语。
> 🛑 **改一处必须全文扫**：发现一个口语标题，用同一套规则把**全篇所有 `class="t"` 标题**重过一遍，不许只改被指出的那一个。

### 7. 必要配置项不得隐藏或省略（机器可判，见 EX-1.4-12）

> 🛑 **配置类页面最常犯的错不是画错，是画少。** 草图省掉一项，到了线框与开发就被当作「不需要」，上线后实施只能反复追问。

**判据一句话**：**把这一页交给实施去配，他能不能不追问就配完？** 不能，就是漏项。

以「监测策略」为例，必备八项（每项在草图里都要有落点）：

| # | 配置项 | 省掉的后果 |
| :---: | :--- | :--- |
| 1 | **生效范围**（组织 / 租户 / 分支） | 不知道对谁生效，可能全租户误告警 |
| 2 | **监测对象与分组** | 不知道盯谁，全量即噪声 |
| 3 | **指标与阈值**（引用质量模型版本） | 不知道用什么判，改了模型对不上 |
| 4 | **触发条件**（持续时间 / 聚合规则） | 不知道何时响，单点抖动就叫人 |
| 5 | **通知配置**（收件人 / 渠道） | 不知道叫谁，响了没人管 |
| 6 | **合并与静默**（合并窗口 / 静默期 / 重复提醒） | 会被同一件事反复打扰，最后被关掉 |
| 7 | **生效时间与启停状态** | 不知道什么时候开始生效，改完不知道有没有生效 |
| 8 | **变更记录**（谁改了什么、何时） | 出问题查不出是哪次改动导致 |

> 📌 **不是每页都要这八项**：每类配置页要有一张自己的「必备项清单」，草图逐项有落点；分析类页面则要列全「判断所需的全部信息」（否则结论站不住）。
> 🛑 **不许用「后续再补」跳过**：本期不做的配置项，在图上写 `本期不做 + 原因`，不许静默省略。

### 8. 出图前逐页过一遍（不许"用户指哪改哪"）

> 🛑 **实测病**：用户截图指出 P4 三处口语，就只改 P4 这三处，其余五页同样的问题原样留着。**一次只改被指出的地方，等于把用户当质检员**，下一轮他还会发现新的。

**动作**：所有页面画完后，**按页逐块过一遍**，每页回答下表的问题；发现的问题**一次全部改掉**，再交给用户。

| 页面类型 | 必须逐项自查（缺一条就是漏检） |
| :--- | :--- |
| **所有页面** | ① 核心对象是什么（一句话说得出）② 图上有没有口语标题 ③ 数据与前后页对得上吗（同一对象、同一时间、同一批数）④ 有没有"必然被告知会被追问"的信息没画 |
| **分析 / 概览页** | 判断链是否完整：**结论 → 依据 → 缺口 → 下一步**；**时间范围是不是一个能点的位置**（今日 / 昨日 / 近 7 天 / 自定义 + 更新时刻）——只写一句"时间范围：今日"算漏能力；需要按时刻回看的，另有"时刻"入口；空态与"数据未就绪"是否交代 |
| **列表页** | 每一行的**状态字段**、**首次/最近时间**、**排序依据**；**筛选区在页头右侧、工具栏在表格上方**（新增 / 批量 / 导出 / 刷新），筛选能力覆盖真实追问（时间、对象、状态），排序挂在表头；空结果怎么显示；**能力项是否都在位置上——有没有塞到表格下方或只写在正文里** |
| **详情 / 诊断页** | 结论 + **把握程度** + 判定依据（引用了哪版标准）+ 证据完整度（几段有数据）+ 缺口说明；可执行动作是否指向下一跳；**多面信息有没有画出页内 Tab 条**（Tab 名 + 当前选中），**顺序是否是"主信息 → Tab 条 → 内容"**；标了抽屉的面是否真的画成抽屉 |
| **配置页** | 必备项清单（详见第 7 条）逐项有落点；**多实例对象有没有集合页**（列表 + 新增 / 复制 / 启停 / 优先级 / 最近变更）；**编辑态与"自定义口径"有没有入口**（改档数 / 区间 / 权重 / 匹配的主客体，而不是只展示结果）；**不做项写「本期不做 + 原因」**；生效范围 / 状态 / 变更记录是否给全 |
| **交接 / 输出页** | 交给谁、用什么方式、什么时候、对方是否已接收；导出件包含哪些内容、边界在哪 |

**两条硬要求**：

1. **同一问题全文扫**：发现"口语标题"这一处，就把全篇同类一次清完（用 grep 搜同义词，不靠眼睛）；
2. **数据自洽全文回算**：任何一个分数、比例、人数、时间，都要能被前后页复算出来（例：评分 57 分 → 权重与档位要能算出 57；38 人 → 与总人数 74 的比例要是 51%）。

> 🔎 **交付前的最后一问**：如果用户此刻只挑一页看，我还有哪一页会让他再发一次截图？

## 三、先定信息架构与页面映射，再画草图（本步交付的第一块）

> 🎯 **这是本步最容易卡住的一问**：不给页面清单，草图怎么知道画到哪个页面里？给了页面清单，不就等于结构已经定了、没得岔了？
>
> **答案：先有"页面草图清单"，后有"正式页面清单"。前者是本步产物，后者是 4.1 产物。**

| 谁定的 | 定的是什么 | 精度 | 能不能改 |
| :--- | :--- | :--- | :--- |
| **本步（1.4）★ 先做** | **页面草图清单**：这个需求一共涉及哪几个页面 / 视图 / 弹层、各自叫什么、管什么、在两个方案里有没有差异 | 粗——只到"有这么个页面、它管什么" | 随方案一起改 |
| **4.1 ★ 后做** | **正式页面清单**：页面编号 `Page-0x`、交互形态、模板 ID、承接主场景、来源草图 | 细——到组件与 Token | **原则上不改**；要改必须回本步重确认 |

### 为什么清单要给用户看（实测修正）

> 📌 **第一版把清单当内部台账藏起来了，这是错的。** 用户的原话：**"用户看到全貌会更清晰——原来是有两种方案、差异是什么，以及本次我的需求大概有多少个页面。"**

清单摆在文件最开头，一次回答三个问题：

| 用户想知道 | 清单里哪一列回答 |
| :--- | :--- |
| 本次需求一共几个页面 | 第一列，整个表有几行 |
| 每个页面干什么的 | 「这一页管什么」列 |
| 两个方案差在哪 | 「两套方案」列（**有差异 / 差异最大 / 两套相同**）——这一列直接决定后面要不要重复画 |

### 页面规模与页面信息怎么放（不再单列页面清单表）

页头只写一行 `本次需求一共 N 个页面（M 个功能域 / K 个页内 Tab）`，紧跟功能域树；**每页的所属功能域、名称、承载形态、职责、两套差异，都在映射表里各占一列**——两张表写同一件事，必然对不齐。

| 用户想知道 | 映射表里哪一列回答 |
| :--- | :--- |
| 本次需求一共几个页面 | 页头那一行 + 映射表的 P 行数 |
| 每个页面干什么的 | 「这一页管什么」列 |
| 两个方案差在哪 | 「两套差异」列（**有差异 / 差异最大 / 两套相同**） |
| 这页属于哪个功能域 | 「所属功能域」列（与功能域树逐字一致） |

#### 定映射表前必判：这个对象是"一份"还是"很多份"（防"只画单条详情"）

> 🛑 **实测病**：监测策略只画了一条 `POL-014` 的详情，没有策略列表、没有新增——用户一问"我不同对象要求不一样，不能建多条策略吗"就露了。**根子在定清单时没判实例基数，到画图阶段就只能画一条。**

| 判定 | 怎么问 | 映射表里怎么体现 | 常见对象 |
| :--- | :--- | :--- | :--- |
| **多实例** | 客户环境里这玩意儿是一份还是很多份？ | **必须拆成集合页 + 详情页（或抽屉）**：集合页承载列表、状态、优先级、最近变更 + 新增 / 复制 / 启停 / 删除；详情页承载编辑态与生效 | 策略、质量模型、监测任务、规则模板、名单、探针、通知对象 |
| **单实例** | 全租户只有一份，或按"作用域"各一份 | 单页即可（可选作用域切换） | 概览、访问诊断、接入向导 |

> 🛑 **配置类对象还要判"匹配条件能不能表达业务差异"**：先列它的匹配维度（**主体**：用户 / 用户组 / 终端；**客体**：应用 / 站点 / 域名 / IP；再加端口、时段、组织），维度不全就画不出差异化策略。**维度在 IA 阶段定死，不许留到线框再补**。
> 🛑 **判断记录进内部留档**（对象 | 实例基数 | 匹配维度 | 拆分后的页面），交付时不用念给用户听，但**映射表里少了集合页就是漏能力**。

> 🆕 **新模块必须单列 `P0` 接入页**：从 0 台开始的产品，第一屏不是"空表格"，而是"怎么把对象弄进来"。**接入途径按实际情况列**（很多产品只有普通导入，不要凭空补扫描/同步/分发）；`P0` 通常两套相同。
> ✅ **对齐检查（内部留档里做，不写在映射表上）**：映射表必须把 1.3 的每一处 `Bx` 都找到落点页面，**一个都不能漏**。漏了就是"这处突破点无处落地"——要么补页面，要么写明"本期不做 + 原因"。

#### 定稿清单前必交：动作覆盖表（防"只画了一条主线"）

> 🛑 **实测病**：需求写了"安装升级（三类组件）/ 卸载 / 解绑 / 批量编辑 / 基础配置"五个动作域，草图上只沿着"安装升级"画，其余四个动作**静默消失**。规划人员一看就知道"这不是我要的"。
> 📌 **PRD 里的"动作清单"不是示意，是验收项。** 每一个动作都要有页面落点，落不了的必须写"本期不做 + 原因"。

| 业务对象 | 动作 / 状态 | 落在哪个页面 | 本期是否做 | 备注 |
| :--- | :--- | :--- | :---: | :--- |
| [终端] | 安装（底座 / 保护AI端 / Hook 分别安装） | P3 | 是 | 三类组件可分别选 |
| [终端] | 升级（同上三类） | P3 | 是 | — |
| [终端] | 卸载 | P2 / P3 | 是 | 高危，需影响确认 |
| [终端] | 解绑 | P2 / P3 | 是 | 高危，需影响确认 |
| [终端] | 批量编辑 | P1 | **否** | 原因：本期只做单条编辑 |
| [终端] | 基础配置（自启动 / 防卸载） | P2 | 是 | — |
| [终端] | 导入 | P5 | 是 | — |
| [终端] | 打标签 / 导出 | P1 | 是 | — |

> 🛑 **字段清单 ≠ 界面清单**：PRD 给的字段是**信息备选池**，不是列清单。哪些上主表、哪些进详情、哪些合并成一列，由"这页要办成什么事"决定；但**每一项都要能说出它去了哪**（主表 / 详情 / 不展示 + 原因）。
> 🛑 **表里出现"本期不做"的，必须在交付时向规划人员口头点一次**，不许埋在表里。
> 🛑 **红线**：本步清单**只写"名称 + 形态 + 职责 + 差异类型 + 档位名"**。一旦开始写模板 ID（`page-form-drawer`）、组件名（`IxDrawer`）、字段清单，就已经跑到 4.1 去了，**回退**。
> 📌 **一句话**：**1.4 定"有几屏、各管什么、哪里不一样"，4.1 定"每屏用什么模板、什么组件"。**

### 两套方案怎么摆：一条醒目的分段切换条，上方给「草图思路发散」标题

> 🛑 **相同页不再重复画（2026-10-23 修正）**：旧规则要求"共性页照画、标两方案相同"。实测代价是**近一半篇幅在重复**，用户反而找不到重点。现规则：**相同页在各自的 tab 里留一个占位条**，一行写"P5 ×××：与方案一相同"，保留页面编号与名称，**不画图**。

```text
页头：需求草图示意 + 本次需求一共 N 个页面（+ 功能域树 + 映射表）
对比表：方案一 / 方案二 的整体设计说明（含代价）+ 各自的设计思考点
──────────────────────────────
## 草图思路发散              ← 分区标题：H2，字号 18~20，比正文标题大一号
[ 方案一 ][ 方案二 ]            ← 分段控件：左对齐、吸顶、下方不加分割线；选中蓝底白字
──────────────────────────────
  ├─ 方案一 tab：P1 → P2 → …（每页：草图 + 图下标号说明）
  └─ 方案二 tab：同上，页面顺序与方案一一致
```

> 🛑 **切换条是这块的主角，不是页脚的小链接**：做成左右两个分段按钮，选中项 `#1C6EFF` 实底白字、未选中白底灰字带边框；**整条左对齐、吸顶、下方不加分割线**（那条线会把标题和内容割开）；**上方必须有「草图思路发散」标题**，让人一眼看出"下面是两种思路，不是两页文档"。

| # | 铁律 | 为什么 |
| :---: | :--- | :--- |
| **1** | 每个 tab 内按页面顺序排**完整链路**（进入 → 操作 → 看到结果），不许"见共用页面"跳转 | 跳转就是断裂：用户看到"见下方"就得滚出去，回来还得重新定位 |
| **2** | **每页草图下必须有标号说明**，一个标号一段，写"做法 + 为什么" | 只有图、没有说明，用户只能猜；这是本次最核心的修正 |
| **3** | 相同页用**占位条**交代（页面编号 + 名称 + 一句"与方案一相同"），**不重复画** | 重复画占篇幅、稀释重点；一句话就能交代清楚 |
| **4** | 页面规模 + 功能域树 + 映射表**只出现一次**（切换条之上），每行标 `有差异 / 差异最大 / 两套相同` | 全局全貌属于"选之前"要看的 |
| **5** | 两套的页面**顺序与编号一致**，同一页在两套里位置相同 | 左右切换时视线不跳，才能对照 |
| **6** | 新模块的两态（刚接入 / 有内容）**两套都要有交代** | 只给一套画两态，另一套显得薄，对比不公平 |
| **7** | 有差异的页，差异用**一句人话**写清（`方案一：系统先给建议，人只确认` / `方案二：人自己选范围`） | 水位差常常只差"默认空的还是满的"，不写字看不出来 |

> 📌 **优先级**：**能看懂 > 能对比 > 省篇幅。** 前两者冲突时，宁可文件变长。
> 🛑 **不许用"相同页"当省事的借口**：占位条必须带页面编号和名称，让用户知道"这一页存在、只是两套一样"，不许整块消失。

## 四、每个方案要交什么

一个方案 = **三个必填件**，缺一个就算没交：

| # | 必填件 | 给谁看 |
| :---: | :--- | :--- |
| 1 | **对比表里的两段**：整体设计说明（含代价）+ 各自的设计思考点 | 看方向的人（30 秒） |
| 2 | **逐页草图**（按页面成套，带标号） | 想看清结构的人 |
| 3 | **图下标号说明**（每条标号一段：做法 + 为什么） | 要拿去讲给别人听的人 |

> 档位组合、突破点落点、五段代价明细、动作覆盖表 → **进内部留档**，不占交付物版面。

### 1. 草图本体（按页面成套）

- **画法**：用与现有系统一致的**线框原语**（灰块 / 灰线 / 占位条），保持"骨架感"；
- **必须画出来的**：页面整体分区、主内容区放什么类型的东西（列表 / 卡片流 / 拓扑 / 表单 / 结论区）、关键操作位置、跨页的入口关系；
- **必须标出来的**：**设计点**——用**标号**（①②③…）标在区块**右上角**，**同一组内容用虚线框圈住、只打一个标号**；标号必须与图下说明一一对应；
- **能力项一个不许掉**（画法可简化，功能不可省）：

| 类别 | 举例 | 草图里怎么处理 |
| :--- | :--- | :--- |
| **能力（必须满）** | 时间范围切换 / 时刻回看、筛选区、排序、搜索、新增、编辑、启停、复制、删除、批量、导入导出、分页、刷新、编辑态与保存、**页内 Tab 切换条** | **在它该在的位置画一块占位区 + 一句能力说明**（`筛选区：时间范围 / 对象 / 状态`、`工具栏：新增 / 批量 / 导出`、`排序：按影响人数 ↓`、`页内 Tab：分段证据 ｜ 影响范围`）；不画组件样式、不画下拉选项 |
| **数据（可以简）** | 单元格字段值、行内明细 | 1~2 行示意值或灰条；**结论句里的数字必须仿真真值**（人数 / 占比 / 评分 / 时长） |
| **样式（不画）** | 组件名、像素、图标、动效、Token | 一律不画 |

- **可以不画的**：字段值明细、组件样式、颜色、间距、图标（**列名要留**——列名是用户核对"覆盖没覆盖"的凭据）；

#### 按页面类型对一遍能力位（缺一个就是漏功能，位置错了线框会跟着错）

| 页面类型 | 必须有的能力位 | 正确位置 |
| :--- | :--- | :--- |
| **概览 / 分析页** | 时间范围切换（今日 / 昨日 / 近 7 天 / 自定义）、数据更新时刻、（要看单次时）时刻回看、下钻入口 | 页头右侧或内容区首行；**不能只在标题里写"今日"** |
| **列表页** | 筛选区（时间 / 对象 / 状态）、搜索、排序、刷新、新增（主按钮）、批量、导入导出、分页、空态 | 页头右侧（筛选）→ 表格工具栏（新增 / 批量 / 导出 / 搜索 / 刷新）→ 表头（排序）→ 表尾（分页） |
| **详情 / 诊断页** | ① **顶部主信息区**（对象 / 事件名 + 关键状态 + 主操作，**不放进 Tab**）② **页内 Tab 条**（≤3 个，标出当前选中）③ 当前 Tab 的内容（结论 / 证据 / 明细）④ 底部动作（导出 / 标记已交接 / 下一跳） | **自上而下：标题栏 → 主信息 → Tab 条 → 内容 → 操作区**；Tab 条压在内容区首行，**不许顶到页头，也不许把主信息塞进某个 Tab** |
| **配置类 · 集合页** | 列表、状态、新增（主）、复制、启停、删除、优先级、最近变更、搜索 | 页头 + 工具栏 + 表格 |
| **配置类 · 详情页** | 编辑态、保存 / 取消（主左取右）、启停、变更记录、影响预演、**自定义项入口**（档数 / 区间 / 权重 / 匹配的主客体） | 表单分区 + 页脚 |
| **抽屉 / 弹窗** | 标题、关闭、主体、页脚主次按钮（抽屉贴左 / 弹窗贴右） | 按容器规范 |

> 🛑 **"不画"只针对样式，不针对能力**：可以不画按钮长什么样，但必须画"这里有一个新增按钮"；可以不给下拉里的选项，但必须写"这里能按时间 / 对象 / 状态筛"。**图上看不到这个位置，下游就不会有这项功能。**

> 🛑 **一个页面有多面信息时，必须画出页内 Tab 切换条**（这是能力，不是装饰）：
> 1. **画出切换条**：一条横向的 Tab 区，写全 N 个 Tab 名，**标出当前选中的那个**；每个 Tab 只画它自己的内容，不画的面用一行 `切到「影响范围」时此处换成：…` 带过。
> 2. **位置固定**：`标题栏 → 顶部主信息（对象名 / 关键状态 / 主操作，不进 Tab）→ Tab 条 → 当前 Tab 内容 → 底部操作`。**Tab 条不许顶到页头**，也不许把主信息塞进某个 Tab —— 否则每切一次 Tab 就丢一次"我在看谁"。
> 3. **术语只许写承载形态**：写 `页内 Tab：分段证据 ｜ 影响范围`、`抽屉：证据交接`。**禁用「视图①/②/③」这类自造词**——它既没说清是 Tab 还是抽屉，又容易被读成"一个长页面的三块内容"。
> 4. **抽屉不是 Tab**：标了抽屉的面，必须画抽屉形态（右侧浮层 + 露出背后页），不许和 Tab 内容平铺在同一列里。
- **非设计点区域**：灰块 + 一句 `此处沿用现有 XX，本次不动`。

> 🛑 **不许出现 `B1 / B2` 这类经验编号**：那是 1.3 的内部指针，用户看不懂。编号只用于"图 ↔ 图下说明"的对应，**图下说明里也不写 Bx**。

#### 点子怎么变成图上的一个块（从 1.3 到草图元素的转译）

> 🎯 **这是最容易断的一环**：1.3 给的是"提交前给影响预览"，这是个**句子**；草图上要出现的是个**方块**。中间缺一步转译，结果就是"点子表很漂亮，草图上看不出用没用"。

转译只有一条规则：**问这句点子在界面上"让人多看见了什么 / 少做了什么"，那个东西就是一个占位块。**

| 1.3 的点子（句子） | 问：界面上多了什么？ | 草图里画成 | 标号 |
| :--- | :--- | :--- | :--- |
| 提交前给影响预览：哪些会被命中、哪些会被自动阻断 | 多了一个"后果说明区" | 抽屉底部一个区块：三个数字（将受检 / 离线 / 可检）+ 一行提示 | `①` |
| 按"防病毒 / 防泄密 / 防外联"分组预置，勾选即填完 | 多了"一组可勾的项" | 一个区块：三行标签 + 展开入口 | `②` |
| 系统按资产画像自动出整套基线 | 多了"系统已填好的内容" | 同上区块，但**默认是满的**，并带"已预置 12 项"字样 | `②`（同一组，共用标号） |
| 规则组独立成模板，可命名 | 多了"来源与保存"入口 | 表单顶部一行：来源标签 + "保存为新模板"链接 | `③` |
| 三态进度 + 失败终端可查 | 多了"三个数字并排" | 详情页顶部三栏数字卡 | `④` |

> 📌 **同一处点子在不同档位下，画出来的差别就在"是空的还是满的""是人填还是系统填"**——这是草图上唯一要表达的档位差异，不靠颜色、不靠组件。
> 🛑 **转译不出来 = 这条点子是"感觉"不是"做法"**，退回 1.3 重写：说不出它在界面上让人多看见什么，它就落不了地。

#### 创新档的区域可以画得很空（唯一允许"留白"的情况）

系统把活接走了，界面上本来就只剩"确认 / 状态 / 结果"。**这是对的，不要因为"怕看起来没设计"就把内容填满——一填就退回优化版。**

| 做法 | 具体要求 |
| :--- | :--- |
| 区域形态 | 极简态 / 空态即可（一行状态 + 一个确认 / 一个结果列表） |
| 框里写什么 | 内容标题照写（如 `系统自动判定结果` / `本轮到期待确认`），不写解释 |
| 必须交代 | 在**图下标号说明**里写明"**因为系统接管了 X，此屏只剩确认**"——否则用户会以为这页没做完 |

> 🛑 **不要用"填满"来证明设计存在**：创新档的价值在于人少干活，图上看起来"没东西"恰恰是它的证据。**空得有理，比填得满更好看。**

### 1.5 每一页出现的顺序，要能读出"人怎么走"

一套草图不只是几张图，**图的排列顺序本身就是设计**：

```
P1 列表（人从这进） → P2 抽屉（就地配，不跳页） → 回 P1（看到状态变了） → P3 详情（点进去看结果）
```

- 排列要能回答一句：**"用户第一步看到什么、第二步做什么、什么时候知道自己成了"**；
- 如果两个方向的排列顺序一样，**它们大概率不是两个方向**（回第二节第一层重岔）；
- 抽屉 / 弹窗类页面，**必须露出背后的承载页轮廓**（灰化处理），否则"就地闭环、不跳页"这个最大的卖点在图上是看不出来的。

### 2. 图下标号说明（每条标号一段，最重要）

固定两段，**缺任一段都不算交**：

```
① 做法：这处长什么样（一句话）
   为什么：针对现状里的哪个问题（一句话，指回 1.1 的卡点或用户原话）
```

- 好例子：*"② 做法：四类问题各占一格，格子里写明判定标准。为什么：这四种状态容易混，混了就会把'已安装'当成'已经在管'。"*
- 坏例子：*"② 做法：使用四象限布局，提升信息密度。"*（没有为什么，也没有取舍）

**判据**：把这段念给没看过需求的人，他能说出"**这处让我多看见什么 / 少做什么**"。说不出，重写。

> 🛑 **不许写**：`B1 / B2` 等经验编号、机制名（如"最小处理集合""四态并列"——要用人的话说"先做哪几件""四种状态分开写"）、"提升体验 / 更清晰 / 更高效"这类形容词。
> 🛑 **不许图和说明对不上**：图上有几个标号，图下就必须有几段；标号不许只当装饰。

### 3. 整体设计说明（对比表第一行，每套一段）

格式固定：**`把「<现在怎么做>」变成「<改成怎么做>」。代价：<谁要跟着变、每轮多花/省多少>。`**

- 3~4 句，≤120 字，一段说完；
- **代价必须写在同一段末尾**，不许另起一块、不许用小字灰色带过；
- 「现在怎么做」用用户的原话或 1.1 的卡点原文，不写"现状存在一定问题"。

> 🛑 **没有代价那一句，"高水位"就成了"高级版"**：用户会默认它更好，闭眼选，上线才发现要改流程、改指标。**水位差必须折成代价差。**

### 4. 设计思考点（对比表格，两套各列各的）

| 要求 | 说明 |
| :--- | :--- |
| 条数 | **不要求两套一致**，各说各的；硬凑维度会让话说得别扭 |
| 每条内容 | 思考点（用户视角一句话）+ 为什么这么想（指回具体卡点） |
| 取舍怎么标 | 属于取舍的（如"不改分工，所以不派单"）**写明"取舍"**，不许包装成优点 |
| 来源怎么标 | 「为什么」一栏必须落到 1.1 的卡点或用户原话上，**不写"因为这样更好"** |

### 5. 成立前提与代价明细（内部留档，不交给用户）

一句话说清"这个方案成立要靠什么"：*要靠资产画像准确 / 要靠后端能给出影响面预估 / 要靠预置库有人维护*。**前提不成立的方案，不能当作可选项摆给用户。**

代价明细固定五段（对比表里只留一句总述，明细留档备查）：

| 段 | 写什么 |
| :--- | :--- |
| 改动范围 | 动几个页面 / 要不要动流程与角色 |
| 影响面 | 谁要跟着变（运维习惯、下游系统、口径） |
| 上线风险 | 主要靠什么兜底（先小范围试、可回滚） |
| 工作量档 | 大 / 中 / 小（粗估即可，不给人天） |
| **每轮多花多少人工** | **每次/每轮要多几步操作、多花多少时间**。**这一行最容易被漏，也最影响用户选择** |

> 🛑 **只算"项目成本"、不算"用户的日常成本"**：稳水位方案往往改动小、风险低，但把活儿留给了人。**不写这一行，等于把最大的代价藏起来。**

## 五、草图的画法标准（答疑：画成什么样算合格）

> 📌 **为什么要标准化**：不标准就会出现两种失控——**画太细**（用户开始挑颜色和间距，方向讨论变成细节讨论）和**画太粗**（用户看不出差异，只能说"都行"）。标准的作用是**把草图钉在"刚好看得出结构差异、又看不出实现细节"那一格**。

### 1. 视觉规格（同一套灰块语汇，**结构级规范跟随、精度级不管**）

草图可以借用 `.wf-*` 里的**灰块 / 容器轮廓 / 占位条**这几个视觉语汇（省得另造一套观感）。但借用分两种，必须分清：

| 借用类型 | 例子 | 草图能不能用 | 原因 |
| :--- | :--- | :---: | :--- |
| **面块语汇**（只表达"这里有一块内容"） | `wf-card` `wf-row` `wf-shell` `wf-label` `wf-table` | ✅ 用 | 与规范无关，纯粹是画法 |
| **规范结构件**（自带规范语义） | `wf-form-item` `wf-form-label` `req` 星号占位 | ❌ 不用 | 一旦用了就得接受整套表单规范检查，草图会变线框 |

| 变量 | 线框图（第 7 节） | **草图（1.4）** | 为什么 |
| :--- | :--- | :--- | :--- |
| **信息密度** | 真实字段名、真实按钮文案、真实数值 | 3~7 字内容标题 + 灰条表示"这里有一批内容"；只留 1~2 个关键数字做示意 | 写了字段名，用户就会开始讨论字段 |
| **组件精度** | 真组件（`IxTable` / `IxDrawer`）、真实宽度 | 灰块、虚线框，不标像素、不标组件名 | 标了像素，就被当成承诺 |
| **结构规范** | 全项必检 | **只跟 5 条**：主按钮用主题蓝 / 主左取右 / **抽屉页脚贴左、弹窗页脚贴右** / 抽屉·弹窗·整页不混用 / 页面分区骨架一致 | 这 4 条变了，线框就得变形，用户会觉得"方案被改了" |
| **精度规范** | 全项必检 | **一律不管**：精确像素 / 字段名 / 星号占位 / 图标 / 动效 / Token | 跟了这些，草图就被当成成品挑细节 |
| **强调方式** | 靠布局与层级 | 靠**一圈蓝框 + 编号徽标** | 草图只有一件事要强调：**这里是我在发力** |

**允许使用**：页面分区、容器轮廓、占位条 / 占位块、按钮块（**区分主次：主动作用主题蓝实心，次要操作用描边**）、关键数字。
**禁止使用**：真实组件名、像素尺寸、字段名清单、图标、动效、超过三种的颜色。

> 🎨 **颜色只许三种**：灰阶做骨架、`#1C6EFF` 标设计点与主按钮、`#FA8C16` 标风险。**草图上出现第四种颜色，说明有人在表达"好看"，而不是"结构"。**
>
> 🛑 **主按钮必须用主题蓝，这条别省**：草图上主按钮是灰的，用户就分不出"这页的主操作是什么"；到了线框突然变成蓝的，他会问"为什么改了"。**结构级的视觉信号，从草图就要给对。**
>
> 🎨 **页面编号徽标统一用主题蓝**：`P1 / P2` 徽标用 `#1C6EFF` 底 + 白字（不要深灰或黑），与设计点标号同色——同一份文件里"编号"只有一种颜色，扫起来才不费劲。
>
> 🧱 **占位只有一套样式，能力位也算占位**：凡是"这里不做详细设计、到线框再细化"的地方（**筛选区 / 时间范围 / 工具栏 / 排序 / 分页 / 编辑入口 / 沿用现有页 / 本期不做**），一律同一套样式——**灰底 `#F2F4F7`、12px、斜体、常规字重（不加粗）、字色 `#6F7785`**。**不许**用"白底 + 虚线框 + 正常字重"冒充占位（那看着像已完成的控件）。
>
> ✂️ **占位文案 ≤1 行、≤20 字，只写"这是什么能力"**：如 `筛选区：时间 / 对象 / 状态`、`工具栏：新增 / 复制 / 启停`。**禁止写"到线框再补"、"将来会怎样"、"本页不展开"这类解释**——草图只回答"这里有什么"，不解释"以后怎么做"。
>
> 🧩 **占位不只是灰块，还是交接件**：一套灰底斜体只说得出"这里没细化"，说不出"下游该不该做、做成什么"。**每个占位必须带类型与唯一编号**（`data-ph="CAP|KEEP|SAME|OFF|DATA"` + `data-ph-id`），并在文件里交一张「占位清单」。**没有身份证的占位，下游（4.1 / 5.0 / Coding AI）只能当"这处不用做"——功能就此丢掉，且没人发现**。五类语义、标记写法与清单格式见本节 **1.1**。
>
> 🚫 **图上有控件，就不要再配一行文字复述**：已经画了页内 Tab 切换条，就不再写"页内 Tab：A｜B（当前选中：A）"；已经有工具栏按钮，就不再配一行"以下是工具栏"。**同一件事只表达一次**，复述即干扰。
>
> 🔠 **表格内不加粗**（表头除外）：加粗是营销式强调，草图靠位置、分组、留白表达重点；`差异最大` 这类判断写成文字即可，不用 `<b>`。
>
> 🖱️ **页内 Tab 切换不许改变页面滚动位置**：Tab 用按钮语义（`role="button"` / `<button>`），**禁止 `href="#"` 锚点**——一点就跳回页首，用户还得重新滚下来找刚才那一屏。
>
> 📄 **图下说明默认只展开 2 条**：第 3 条起折叠进「展开更多（N 条）」，点击展开。折叠只影响渲染，**源码必须保留全部说明**（下游与门禁都按源码读）。
>
> 🚫 **草图容器内不许出现竖向滚动条**：草图框、抽屉示意、页内 Tab 内容一律**按内容全高展开**（容器不用 `overflow:auto/scroll`，抽屉不要用绝对定位切死高度）；判据：任何一块内容都不需要在小框里滚动才能看完。
>
> ⚠️ **脚本口径说明**：自检脚本第 4 项（色值）与第 10 项（线框规范）**已跳过草图折叠区**，因为草图要到精确像素与完整表单规范这一级才是错的。草图那 4 条结构级规范，**靠第五节自检表人工把关，不掉给脚本**。

#### 1.1 占位的五类语义、机读标记与交接清单（下游唯一识别口径）

> 🛑 **这一节治的是"草图看着有、线框里没了"这条最贵的漏损链**：草图用一套灰底斜体表达"这里还没细化"，但它同时承载了**五种完全相反的下游动作**——该展开的、该沿用的、该去另一套取图的、该**不**做的、只是没数的。**混在一套样式里，下游只能靠猜；猜错的代价是功能消失或空壳入口。**

| 类型码 | 语义（一句话） | 草图怎么写 | 线框（4.1 → 5.0 第 7 节）必须怎么处理 | 判错后的实测后果 |
| :---: | :--- | :--- | :--- | :--- |
| **CAP**<br>能力位 | 这处**有功能**，只是没画控件 | 灰底斜体一行，写能力名 + 位置：`筛选区：时间 / 对象 / 状态`、`工具栏：新增 / 复制 / 启停` | **必须展开成真实控件并留在原位**：筛选 → 一组下拉 / 输入；时间范围 → 时间控件 + 当前取值；排序 → 表头可点排序态（含升降序与当前列）；分页 → 页码条（总数 + 页码 + 每页条数）；搜索 / 刷新 → 输入框 + 图标按钮 | 「筛选区」只活在草图里，线框没做 → 上线后用户问"怎么按对象筛" |
| **KEEP**<br>沿用 | 这块**沿用现有页面 / 组件**，本次不动 | `此处沿用现有 XX，本次不动`（写出沿用的是哪个页 / 哪块） | 允许保留简化块，但**必须写清复用哪个现成页 / 组件**，并在映射清单里登记"沿用"；**不许重画成新设计**，也不许当空白跳过 | 线框把它当空白区跳过，交付时才发现少一块 |
| **SAME**<br>相同页 | 这一页两套一样，**本 tab 不重复画** | `〔占位〕P5 ××× 与方案一相同`（保留编号 + 名称） | **不等于"这页不做"**：线框必须**去另一套取该页的完整草图**再设计；无论用户选定哪套，这一页都要出全 | 用户选了方案二，下游只看到占位条 → P5 整页丢失 |
| **OFF**<br>本期不做 | 本期不做 / 线下承接 | `❌ 否 + 线下（邮件 / 群 / 人工台账）` | **不许画成可点控件**；只进第 7 节 **⑥ 实现边界**（不做清单）与验收说明；交付时口头点一次 | 线框画了"派单 / 催办"按钮，后端没有 → 上线是空壳入口 |
| **DATA**<br>数据缺口 | 这块**没数 / 没采到 / 无权限**，不是没功能 | `—`、`缺数据`、`未采到`、`无权限`（写清缺口范围与时段） | 必须落成**显性异常态**：未采到（斜纹 / 灰字 + 不参与判定）、空值（明确"无数据"而不是 0）、无权限（只读 + 说明原因）；并进 §2.2 状态七态 | 缺数据的跳被画成 0 秒或空白 → 结论失真，评审看不出证据缺口 |

**标记写法（图上必须有，供机检 `EX-1.4-17`）**：

```html
<!-- CAP 能力位：类型 + 全篇唯一编号，编号必须进占位清单 -->
<p class="cap" data-ph="CAP" data-ph-id="PH-A-P2-01">筛选区：时间 / 对象 / 状态</p>

<!-- SAME 相同页占位条：保留页面编号与名称 -->
<div class="same" data-ph="SAME" data-ph-id="PH-B-P5-01">〔占位〕P5 策略详情与方案一相同</div>

<!-- DATA 数据缺口：把"没采到"本身画出来，也登记 -->
<span class="ph" data-ph="DATA" data-ph-id="PH-A-P3-01">连接器段 10:06—10:09 未采到</span>

<!-- OFF 本期不做：标在动作覆盖表那一行，不进图 -->
<tr data-ph="OFF" data-ph-id="PH-OFF-01">…处理流转…<td>❌ 否</td><td>线下通知（邮件 / 群）</td></tr>
```

> 📌 **只认三种载体类名**：`.ph`（数据缺口 / 单点占位）、`.cap`（能力位条）、`.same`（相同页占位条）。**凡是这三个类名出现的元素，都必须同时带 `data-ph` 与 `data-ph-id`**；没带的一律判"占位没身份证"。

**占位清单（`ph-ledger`，2 套共用一张，放**文末交接区**并默认折叠）**：

> 🚧 **位置规则：它是交接件，不是正文。** 一律放文件**最后**，用 `<details class="handoff">` 折叠，摘要写「📦 交接件：占位清单（N 条 · 给下游 4.1 / 5.0 读，不参与方案阅读）」。**不许夹在页面清单与方案之间**——用户打开草图是来选方案的，不是来读交接表的；放前面既打断阅读，又容易被当成"设计说明"。

| 占位编号 | 方案 | 页面 | 类型 | 位置（图上锚点） | 占位文案（逐字） | 能力项（`/` 分隔） | 下游动作（线框怎么落） |
| :---: | :---: | :---: | :---: | :--- | :--- | :--- | :--- |
| PH-A-P2-01 | 方案一 | P2 | CAP | 表格上方首行 | `筛选区：时间 / 对象 / 状态 · 搜索 · 刷新` | `时间范围 / 对象 / 状态 / 搜索 / 刷新` | 展开为三个可点筛选 + 搜索 + 刷新，位置在表格上方 |
| PH-A-P2-02 | 方案一 | P2 | CAP | 表头「事件 ↓」 | `按影响人数排序` | `影响人数排序` | 表头做成可点排序，默认影响人数降序 |
| PH-B-P5-01 | 方案二 | P5 | SAME | 页内占位条 | `〔占位〕P5 策略详情与方案一相同` | — | 从方案一 P5 取完整抽屉表单设计，不许当"这页不做" |
| PH-A-P3-01 | 方案一 | P3 | DATA | 分段证据 · 分段条第 4 段 | `连接器 缺数据 10:06—10:09 未采到` | — | 落成"未采到"异常态，不参与判定，不许填 0 秒 |
| PH-OFF-01 | 两套 | — | OFF | 动作覆盖表「处理流转」 | `责任方接手 / 对方回话 / 催办` | — | 不画入口；只进第 7 节 ⑥ 实现边界 |

**五条硬要求**：

1. **一个占位 = 一行，编号全篇唯一**：图上 `data-ph-id` 的集合 = 清单里编号的集合，多一个少一个都判不合格（机检）。
2. **「位置」必须写到"哪页、哪一块、哪一行"**：写 `页面上` 等于没写——线框要据此判断"展开后放哪、会不会挤掉别的东西"。
3. **CAP 必填「能力项」，一项一个词，用 `/` 分隔**：这是**唯一被机器对账的清单**——4.1 在映射清单里逐词占行，`SP-W-07` 拿这列去说明书里逐词找，缺一个报一条。写选项值（今日 / 昨日）不算能力项，写控件名（下拉框）也不算，要写**能力名**（时间范围 / 对象 / 状态 / 搜索 / 刷新）。
4. **「下游动作」用人话，不写组件名 / 模板 ID**：写"展开成什么能力、留在哪、沿用谁、不做什么"。组件与 Token 是 4.1 的事，写进来就跑到下一环了。
5. **OFF 与 CAP 不许混**：本期不做的，图上不许出现可点控件；该做却标 OFF 的，等于静默砍需求。**判据一句话：指着这个占位问"线框里它变成了什么"，答不出具体控件 / 具体异常态的，就是没交接。**

> 🎨 **再强调一次：草图的视觉不是设计，线框要重新设计。** 灰底斜体只是"这里还没细化"的语汇，**不是配色、不是字号、不是间距、更不是控件形态**。线框必须按组件规范、Token 与命中的经验重新出图；**判据是把草图与线框并排放，除"分区与信息位置"必须一致外，控件形态、字号、色阶、间距、状态表现都应不同**——两张看起来像同一张图，判"没做设计"（5.0 铁律 24 / `SP-W-06`）。

> 🔗 **为什么这一步不能省**：下游拿到的是 HTML，不是你脑子里的打算。它读得懂 `class` 和 `data-ph`，读不懂"我本来想在这儿放个筛选"。**占位清单就是草图对下游说的最后一句话**——4.1 按它逐条落线框（§1.9），5.0 按它逐条核能力（铁律 23 / `SP-W-06`）。

### 2. 🛑 框里写"是什么"，不写"为什么"；为什么写进图下说明

> **先分清两种文字，别一刀切**（实测纠正过两次）：

| 文字类型 | 长什么样 | 写在哪 | 原因 |
| :--- | :--- | :---: | :--- |
| **内容信息**（是什么） | 「检测项」「下发范围与影响」「最近一轮检测」 | ✅ **框里** | 全是灰块，别人根本不知道这块是什么内容 |
| **解释信息**（为什么这么设计） | 「系统已按研发机画像出草案」「动手前就知道影响面」 | ❌ 框里 / ✅ **图下标号说明** | 框里写解释挡着看结构；但直接删掉，用户就看不懂——**必须搬到图下** |

**判据一句话**：**框里告诉人"这是什么"；图下告诉人"为什么这么设计"。两边都缺一不可。**

| ❌ 框里别写 | ✅ 框里该写 | ✅ 图下该写 |
| :--- | :--- | :--- |
| 「① 查什么 · 系统已按研发机画像出草案」 | `检测项 · 已按「研发机」预置 12 项` | ① 做法：系统按机器画像先填好……为什么：不用先懂规则、先选范围 |
| 「注：父部门以后新增终端也会被纳入」 | 不写在框里 | ① 为什么：父部门新增终端也要覆盖，否则新机器漏检 |

> 🛑 **每个区块要有一个 3~7 字的内容小标题，但不要带解释**：`检测项`（✅）／`① 查什么 · 系统已按画像出草案`（❌）。
> 🛑 **图上不要写"第几步"式的序号叙事**：标号只用于"图 ↔ 图下说明"对应，不代表操作顺序。

### 3. 标号与区域的画法

| 规则 | 具体要求 |
| :--- | :--- |
| **位置** | 标号一律吸附在区块**右上角**（绝对定位，向外偏 8px），**不许占用正文位置、不许把文字推开** |
| **数量** | **同一组内容只打一个标号**：多个卡片/多行属于同一个设计点时，用**蓝色虚线框整体圈住**，标号打在框的右上角 |
| **形态** | 圆形实心徽标 + 阿拉伯数字（①②③ 与徽标二选一，全篇统一）；不用字母、不用 `Bx` |
| **对应** | 图上有 N 个标号，图下就必须有 N 段说明，编号一致、顺序一致 |
| **设计点区域** | 蓝虚线框圈住；框内正常写内容 |
| **非设计点但必须存在** | 虚线灰框 + 保留内容标题与大致体量（如 `任务列表` + 3 行灰条） |
| **未定的空白** | 留白，不要填"待定" |

> 📌 **相同页不再重复画**：在各自的 tab 里留一个占位条（`P5 规则模板库（抽屉）· 与方案一相同`），保留编号与名称即可。旧规则"共性页照画"已废弃——一半篇幅在重复，用户反而找不到重点。

> ⚠️ **14.1 是最容易被做错的一条**，因为两种容器规则确实相反（原始规范见 `comp-drawer.md` 与 `comp-modal.md`）：
>
> | 容器 | 按钮组对齐 | 内部顺序 | CSS |
> | :--- | :--- | :--- | :--- |
> | **抽屉 `IxDrawer`** | **左对齐**（主按钮左间距 16px） | 主按钮在最左，取消在其右 | `justify-content: flex-start` |
> | **弹窗 `IxModal`** | **右对齐** | 主按钮在左，取消在右（组内仍是主左取右） | `justify-content: flex-end` |
>
> 📌 **记法**：**抽屉"靠边站"（贴左），弹窗"按老规矩"（贴右）；两边的内部顺序都是主在左、取消在右。**

> 🔎 **13~16 是"结构级规范"，与 1~12、17~26 不同**：1~12 管的是"草图作为一份沟通材料合不合用"，17~20 管的是"两套方案的差异成不成立、档位有没有真拉开"，21~23 管的是"**图上说的话规划人员信不信、看不看得懂、有没有从 0 讲起**"，24~26 管的是"**PRD 的动作有没有漏、清单与图对不对得上、两套能不能对比**"，13~16 管的是"**草图与线框能不能接上**"。
> 🔎 **为什么这几条不能等到线框再改**：按钮左右反了、抽屉画成弹窗、分区挪了位——这些在用户眼里都是"**我选的方案被改了**"。**结构级的东西，草图就要给对；精度级的，线框再补。**

### 4.1 交付前跑草图门禁（机器把关：结构 5 条 + 文案 7 条 + 能力位 1 条 + 占位可交接 1 条）

> 🛑 **1~12 与 17~26 靠人眼，13~16 靠脚本。** 人工自检会漏——**实测就漏过页脚对齐**（抽屉页脚做成了右对齐，肉眼看不出，一跑脚本就报）；**也漏过能力位**（筛选与排序被塞到表格下方，脚本一跑就报 `EX-1.4-14`）。

```bash
# 退出码 0 = 本环准出，可交给用户选；1 = 修完再交
```

脚本只查这 5 条结构级规范，**不查精度**（像素、字段名、图标、星号占位一律不管）：

| # | 检查项 | 判据 |
| :---: | :--- | :--- |

**文案表达机检（EX-1.4-05 / 07，由 `gate.js` 判，不靠自觉）**：

| 子项 | 判据 | 命中后怎么改 |
| :--- | :--- | :--- |
| 内部词与编号 | 不出现 `采信 / 回执 / 留痕 / 处置 / 裁决 / 认领` 与 `B1~B5` | 按 §4.2 对照表换成用户话 |
| 空洞词 | 不出现 `提升体验 / 优化体验 / 更清晰 / 更高效 / 更智能 / 更省心 / 大幅提升 / 赋能 / 极致 / 闭环 / 收口 / 影响面 / 态势` | 换成"能看见什么、能做什么" |

> 🔎 **最关键的是第 1、2、5、11 条**：第 1 条决定"看不看得进去"，第 2 条决定"认不认得内容"，第 5 条决定"有没有全貌"，第 11 条决定"要不要做选择"。
> 🔎 **第 9 条是底线**：两个方案要靠读文字才能区分，说明图没起作用，这套草图白画了。

## 六、怎么摆给用户看（呈现形式）

> 三次纠偏都发生过，记住这三条：
> * 第一版：3 个方向 + 对比表 + 顶部台账 → **"太复杂了，全是字，好累"**；
> * 第二版：删得太狠，清单也删了、框里只剩灰块 → **"看不到全貌，也不知道这块是什么内容"**；
> * 第三版：加了"方案标题句 + 3 条差异 + 方案依据 → **"根本看不懂，给其他人讲也讲不了"**。
>
> ✅ **现行结构：清单打底 → 对比表选方向 → tab 内逐页看图读说明。**

```text
① 文件头：标题「需求草图示意」+ 一行小字
② 本次需求一共 N 个页面 + 功能域树 + 映射表（全局，只出现一次）
③ 两套方案对比表：整体设计说明（含代价）+ 各自的设计思考点
④ 切换条（吸顶）：[ 方案一 ]  [ 方案二 ]
   ├ tab 一：P0 → P1 → …（每页 = 草图 + 图下标号说明）；相同页用占位条
   └ tab 二：同上，页面顺序与编号与 tab 一一致
```

> 🛑 **不要"请选择一个方案"这一块**：两个选项各配一段五段代价，用户得读完两段才能比；改成对比表，一眼并排。
> 🛑 **不要方案标题句**：`方案一：系统出草案，人只改差异` 这种压缩句，没读过 1.1~1.3 的人解不出来。**方案是什么，写在「整体设计说明」里。**
> 🛑 **不要"与另一方案的 3 条差异"**：三条差异说不清取舍，也不成体系；差异由对比表逐条对齐。
> 📌 **为什么对比表要放在 tab 之前**：用户先要知道两套各在想什么，再决定往哪套里钻。放在 tab 里，等于逼他先看一套再回来看另一套。

### 0. 页头与措辞规范

| 位置 | 内容 |
| :--- | :--- |
| 大标题 | **`需求草图示意`** |
| 小字说明 | **`基于需求理解之后进行的设计思考草图，仅用于思路对齐，不涉及详细设计。`** |
| 第三行 | **`本次需求一共 N 个页面`** 一行 + 功能域树 |

> 🛑 **这行小字不是客套**：它提前把预期钉死——**用户不会拿它当设计稿挑间距和颜色**，也就不会把方向讨论带偏成细节讨论。这句话必须原样出现，不要改写。

> **交付话术不在这里写**：顿点话术见 §七「顿点话术（固化）」那四句，本节只管文件页头怎么写。

| 别写 | 该写 | 为什么 |
| :--- | :--- | :--- |
| 继续出**正式线框图** | 继续出**正式**说明书 | 线框图只是说明书里的一节，用户关心的是最终交付物 |
| 继续**进入下一环节** | 继续出正式说明书 | 用户不知道"环节"是什么，他只知道最后要拿到什么 |
| 请选择一个方案（+五段代价） | 两套方案的草图都在下面 | 选择区要读两段长文字才能比；对比表能一眼并排 |

> 🛑 **措辞要对齐用户的预期产物**：用户对接的是"说明书 + 代码"这两样东西；"线框图""页面清单"都是我们的中间件，**不要拿来跟用户对话**。

### 1. 对比表怎么写（本步的核心交付物）

固定两段，**都用表格**：

**第一段：整体对比**（两列并排，一眼读完）

| 对比项 | 方案一 | 方案二 |
| :--- | :--- | :--- |
| 整体设计说明 | `把「<现在怎么做>」变成「<改成怎么做>」。代价：<谁要跟着变、每轮多花/省多少>。` | 同左结构 |
| 一句话区别 | `<两套最根本的分歧，一句话>` | 同左 |
| 本期不做 | `<动作清单>` | 同左 |

> 🛑 **代价必须写进「整体设计说明」的末尾**，不许另起一块、不许灰色小字带过。**没有代价那一行，"高水位"就成了"高级版"**，用户会默认它更好，闭眼选，上线才发现要改流程、改指标。

**第二段：各自的设计思考点**（列：方案 | 编号 | 思考点 | 为什么这么想）

| 方案 | 编号 | 思考点 | 为什么这么想（对应现状里的哪个卡点） |
| :--- | :---: | :--- | :--- |
| 方案一 | 1 | `<用户视角一句话：会看到什么 / 能做什么>` | `<1.1 的卡点原文或用户原话>` |
| 方案二 | 1 | `<……>` | `<……>` |

- **两套条数不要求一致、维度不要求对齐**：硬凑会让话说得别扭；
- **每条必须带「为什么这么想」**，且落在具体卡点上，不写"因为这样更好"；
- **属于取舍的（如"不改分工，所以不派单"）必须写明"取舍"**，不许包装成优点；
- 思考点里**不出现** `Bx`、机制名、形容词（"更清晰""更高效"）。

**命名必须过三关**（思考点、整体说明都要过）：

| 关 | 判据 | 反面（实测犯过） |
| :---: | :--- | :--- |
| **对象** | 有没有**具体的业务对象**（终端 / 客户端 / 任务 / 策略） | `一进来就是没装好的终端`——哪个东西没装好？ |
| **动作** | 有没有**一个能做的动作**，不是"处理""补齐""搞定" | `点一下批量补装`——补装什么？ |
| **条件** | 有没有说清**按什么来选**（清单 / 标签 / 版本差 / 人工勾选） | `系统先判`——判什么、按什么判，全无 |

> 🛑 **禁用词**：`没装好 / 补齐 / 到位 / 闭环 / 收口 / 先判 / 赋能 / 极致 / 最小处理集合 / 采信 / 回执 / 留痕 / 处置 / 裁决 / 认领`。
> 🛑 **自检一句话**：把这句话念给没看过需求的人听，他能复述出"**对这个对象、按这个条件、做这个动作**"，才算过。
> 🛑 **不写"推荐 / 次选"**：一旦标了，用户跳过代价直接选；哪套更合适在交付话术里说一句即可。

### 2. 图下标号说明的固定句式

> **`① 做法：<这处长什么样> 为什么：<针对现状里的哪个问题>`**

- 「为什么」必须指出来源：**来自体验目标，还是来自这类工作的固有毛病**（写成用户的话，不写编号）；
- **代价不用在这里写**：代价在对比表的「整体设计说明」里已经写过一次，图下重复会显得啰嗦；
- 一段一条，**不超过两行**；超过两行说明这条设计点还没想清楚。

### 3. 内部留档要写清"想法从哪来"（不交给用户）

| 行 | 写什么 | 例 |
| :--- | :--- | :--- |
| 突破点落点 | 1.3 的每个 `Bx` 落在哪页哪块 | B1 → P2 顶部来源标签 |
| 档位组合 | 逐个突破点标档，一行读完 | B1 创新版 / B2 创新版 / B3 优化版 / B4 不在本套 |
| 代价五段 | 改动范围 / 影响面 / 上线风险 / 工作量档 / **每轮多花多少人工** | 改 4 页新增 2 页；运维要改习惯；先小范围试 5%；大；每轮多花约 20 分钟 |
| 动作覆盖表 | PRD 的每个动作落在哪页 | 见 §三 |

> 🛑 **不要写"亮点""优势""价值"**：那是营销词。写"为什么这么想"和"代价是什么"，用户自己会判断好不好。

### 4. 图的排布规矩

- **载体是一份单文件 HTML，带 tab 切换**：顶部（页头 / 页面总数 / 清单 / 对比表）固定，下面两个 tab 左右切换；tab 用原生 `radio + label` 或极简 JS 均可，**必须离线可用**；
- 每个 tab 内**按"人怎么走"的顺序排**（进入 → 操作 → 看到结果），**不要在 tab 内把两套的同类页面交叉排**；
- 两套的页面顺序、编号**必须一致**（P0、P1、P2… 同位置），切换时视线不跳；
- 每个页面块固定三段：**页面标题行（`P1 页面名 · 形态 · 这一页管什么`）→ 草图 → 图下标号说明**；说明必须紧跟在它的草图下面，**中间不许插别的内容**；
- 相同页用一行占位条（`P5 规则模板库（抽屉）· 与方案一相同`）带过；
- 每张图配 `P1 / P2` 编号 + `页面名 · 形态`（如「终端详情 · 右侧抽屉」），方便用户指着说"这个第二屏不要"；
- 文件命名：`草图-<业务名>.html`，与说明书的 `design-spec-<业务名>.html` 区分开。

## 七、确认闸门（顿点话术固化，只发这一段）

> 🚦 **这是主线上第一个必须停下来等的闸门**，比 5.0 说明书后的确认更早、更关键——**方向错了，后面越细越浪费**。
>
> 🛑 **也是"需求进来之后唯一一次停顿"**：从 1.1 到本步交付，中间**不许停下来提问**（缺什么自己补 `【假设】`，随交付物一起给出）。

### 顿点话术（固化 · 照抄，只改 `< >` 里的填空）

```text
我已经对需求文档做了 <痛点穿透 / 场景与任务旅程 / 突破点拆解> 分析，梳理了需求的信息架构（<N> 个功能域 / <N> 个页面）以及两套草图思路。
请您查看 `_output/<业务名>/草图-<业务名>.html`，确认哪套思路更优。
确认后我将基于此方向做更进一步的设计与物料装配（逐页线框 → 设计说明书）。
若两种思路均不合您的预期，可以随时指出其中问题，或邀请我一起做思路共创。
```

> 🛑 **就发这四句，不许加料**：不列推荐理由、不铺五段代价、不贴 `【假设】` 清单、不复述页面清单、不说"我准备先做 A 再做 B"。这些**都已经在草图文件里**（对比表有整体说明与代价、图下有做法与为什么），用户点开就看得到，**问了再答**。
> 🛑 **第一句要落到实处**：写清做了哪几类分析（痛点穿透 / 场景旅程 / 突破点拆解）与梳理出的规模（功能域数 / 页面数）；不许写"我认真分析了需求"这类空话。
> 🛑 **路径必须能直接点开**：给真实路径，不许写"见附件"。
> 🛑 **总长 ≤6 行**（四句 + 空行），超了就是又铺开了。

### 用户追问时才补（一次补一层，不主动展开）

| 用户问 | 回什么 |
| :--- | :--- |
| "你推荐哪套？" | 一句：建议方案 X + 它让你不用再干 `<那件具体的事>`（不许用"更完整 / 更智能"带过） |
| "要付什么代价？" | 五段代价各一句（改动范围 / 数据 / 研发 / 每轮人工 / 组织），含**每轮多花多少人工** |
| "还有哪些没定？" | `【假设】` ≤3 条，每条一行 |
| "两套差在哪？" | 一句说走法差（核心对象、首屏给什么不同），不展开页面清单与编号 |

> 🛑 **不追问就不主动铺**：顿点的任务是"让他点开文件、回一句话"，不是"让他读完一份方案"。

### 不符合预期时：共创改这一版，不重头画

| 用户说 | 我怎么接 | 产物 |
| :--- | :--- | :--- |
| 页多了 / 页少了 / 某页不该独立成页 | 在**同一份草图**上增删页、重排序号，两套同步改 | 改版草图（沿用原文件名，页头标 `v2 · 改了什么`） |
| 走法不对（"这不是我要的做法"） | 回 §二① 重岔走法，档位沿用 | 新草图（仍叫方案一 / 方案二） |
| 某几屏对、某几屏不对 | **只改不对的那几屏**，其余原样保留，改动屏加标注 | 局部改版 |
| 水位不对（"太激进 / 太保守"） | 回 1.3 换档位点子，走法不动 | 改档版 |
| 说不出哪不对，只说"感觉不对" | **给 1~2 个具体改法让他挑**（"P3 拆两页 / 留在 P3 用 Tab"），不许把题推回去 | 二选一后改版 |

> 🛑 **共创回合上限 2 轮**：改两轮还对不上，说明问题不在草图——回 1.3 查突破点、回 1.1 查卡点，说明原因再重来，**不许在第 3 轮继续磨图**。
> 🛑 **每轮改版必须列出"改了什么"（≤5 条，写在页头）**：用户要能看出自己那句话落在哪，否则会觉得没被听见。
> 🛑 **共创不是开放式提问**：不给"你觉得该怎么改"这种题；要么让用户指屏，要么给 1~2 个改法让他挑。
> 🛑 **改版后同样要过 `tools/sketch-selfcheck.sh`**，并重发本节那段固化话术（只把"确认哪套"换成"看看这版改对没有"），不许改完直接往下跑。

### 用户可能给的答复，对应怎么走

| 用户答复 | 该怎么处理 |
| :--- | :--- |
| **选一个** | 记录选定结果；**若选的是高水位，同时把"目标与指标变更"一起留档**（见下方铁律），再进 4.1 |
| **选一个但要改** | **先改、再确认、后进线框**——改动如果动到结构（换主结构 / 加减页面），退回本步重出草图，不许直接带去线框 |
| **先说"不太对 / 不是我想要的"** | **先进入共创，不追问选哪套**：按上文「不符合预期时」那张表处理；改完重发 §七那段固化话术（把"确认哪套"换成"看看这版改对没有"） |
| **都不满意** | 不许硬推，也不许直接进线框。问清"是走法不对还是水位不对"：走法不对 → 回第二节①重新想；水位不对 → 回 1.3 补档位点子 |
| **要合并两个方案** | 允许，但必须让用户明确"以哪个为主结构、吸收另一个的哪一处、合并后档位取高的还是低的"，并留档；**防止最后变成四不像** |
| **明确说跳过草图** | 按"方案一直接执行"处理，见下方铁律；跳过只免掉"停下来等"，不免掉草图本身 |

> 🛑 **闸门铁律（默认必停）**：方案未定，不得输出正式页面清单、模板 ID、组件名。**只要用户没有明确说"跳过草图 / 不用草图 / 直接按方案一"，就必须先交草图、停下来等一句选定**——哪怕他这一轮的指令是"给我出设计说明书"、"你直接做吧"，也先出草图再问一句；"要说明书"不等于"授权你替他定方向"。
> 🛑 **明示跳过 = 默认方案一**：仅当用户**明确说出**跳过草图确认（如"跳过草图"、"不用给我看草图"、"别确认了，按方案一直接做"）时，才可越过闸门；此时**默认以草图方案一（高水位）执行**，并在下游交付物开头用一行写明`方案来源：用户明示跳过草图，按方案一执行`。用户只说了跳过、没说哪套的，不再追问，直接取方案一。
> 🛑 **选高水位 = 同时授权改目标**：必须当场把 1.2 的目标句与指标改成方案声明的那版并留档。**否则下游说明书还写着旧目标，新方案拿旧验收线验收，必然打架**——这是高水位方案最容易埋的雷。

## 八、下游怎么接（1.4 → 4.1 的交接契约）

本步交给 4.1 的东西，只有六样，多一样都是负担：

| # | 交接物 | 下游怎么用 | 缺了会怎样 |
| :---: | :--- | :--- | :--- |
| 1 | **选定方案的全套草图** | 4.1 画线框时**按草图的分区与主结构继承**，不许另起炉灶 | 线框和草图对不上，用户会觉得"我选的不是你画的" |
| 2 | **突破点 → 档位 → 页面区域**对照（在本步是"方案依据"里的档位行） | 4.1 逐页核对"这处突破点有没有落点"，并作为经验采纳的靶子 | 突破点做了却没落地，或落地了却没人知道为什么 |
| 3 | **设计说明（含五段代价）** | **只在本步留档，不进说明书**（5.0 已取消「方案取舍 / 档位组合与授权记录」两节）；评审追问时回本步查 | 说明书变长、读者被方案复盘干扰 |
| 4 | **未采纳方案的一句话结论** | 进 5.0，回答"考虑过别的走法吗" | 被质疑"是不是只想到一种" |
| 5 | **档位组合 + 目标/指标变更记录** | 4.1 逐页核"档位有没有降级"；5.0 用**改后的**目标与指标写第一、三节 | 拿旧目标验收新方案，说明书自相矛盾 |
| 6 | **占位清单（`ph-ledger`）** | 4.1 逐条填"展开成什么 / 沿用谁 / 不做 / 补什么异常态"（对账表见 4.1 §1.9）；5.0 按它逐条核线框能力 | 草图上画着的能力位在线框里凭空消失，用户上线才发现少功能 |

> 📌 **再交一段 HTML 注释当"交接清单"**（不渲染、不打扰用户）：草图 `<body>` 之后写清三件事——① 占位清单在哪张表、共几条；② 突破点 / 档位 / 代价明细在哪个留档文件；③ 选定方案待用户确认。**下游只拿到这一个 HTML 时，靠这段注释就能找齐全部上游依据**，不用猜、不用回头问。

### 继承校验（4.1 必做，回填到本步）

线框画完后必须回头对一次：

| 校验 | 判定 |
| :--- | :--- |
| 主结构是否一致 | 草图是"一屏工作台"，线框不能变成"列表 + 详情两页"——**要变必须先回本步改方向** |
| 页面数量是否一致 | 草图 3 个页面，线框多了 2 个 → 说明草图漏了页面，或线框私自扩张，两者都要回查 |
| 突破点落点是否都在 | 草图里圈的每一处（上限 5 处），线框里必须都找得到；少了就是降级，要有理由 |
| 档位是否被偷偷降级 | 草图定的"创新版/创新版"，线框做成了"优化版" → 判定为执行降级，必须改回或说明原因 |
| 目标是否被悄悄改动 | 方案不得反向修改 1.2 的目标句；若点子确实做到了目标没写到的那一步，**回 1.2 把目标句补到方案实际做到的位置并留痕**（同步，不是授权），不许说明书与目标两套说法 |
| **结构级规范是否继承** | 草图上主按钮在左、用主题蓝、抽屉形态、分区位置——线框必须一致。**这 4 项在草图阶段已定死，线框阶段不许再改** |
| **占位是否逐条闭合** | 清单里每条 `CAP` 在线框里都能指到具体控件与位置；`KEEP` 写明复用谁；`SAME` 从另一套取完整页；`OFF` 只进实现边界、不出现可点入口；`DATA` 落成显性异常态。**一条没处置 = 一处能力丢** |

> 📌 **一句话概括这张表**：**结构继承，精度重做，占位展开。** 草图定的分区、页面数、按钮位置与主次、容器形态，线框一律照搬；草图没定的字段、列名、像素、图标、动效，线框全部补齐并按规范检查；**草图上占着的每一块，线框里都要有归属——变成控件、变成沿用、变成异常态，或者明确不做的口径**。
>
> 🛑 **数据也要重做精度（不做就是失败）**：草图上为守"不编数字"而留的 `__`，**线框里一律不许带过去**。线框必须用一套**跨页自洽的示例数据**（对象名 / 数量 / 状态 / 时间 / 证据来源）填满，并补上**草图没展示全的字段与异常态**（长文本截断、空值、无权限、过期、超限降级）；同时在说明书第 7 节开头声明这是示例样本、不构成客户事实。**草图守"结构级"可以空，线框守"落地级"必须满。**

## 九、常见跑偏（反面样本）

| 跑偏写法 | 为什么错 | 改法 |
| :--- | :--- | :--- |
| 给了 3 个方案 + 对比表 + 顶部台账 | **信息过载，用户没耐心看**（第一版实录） | 砍到 2 套，删前置信息与对比表 |
| 把常规版也画出来 | 常规版不需要被选择，只需要被满足 | 删；只在优化版/创新版里体现 |
| 框里带解释句（"查什么 · 系统已按…出草案"） | 干扰信息，挡着看结构 | 搬到图下标号说明里 |
| **框里只剩灰块、没有内容标题** | 别人**不知道这块是什么内容**（第二版实录，矫枉过正） | 补 3~7 字内容标题 |
| **没有页面清单，只按场景切两段** | 用户看不到全貌、不知道本次一共几个页面 | 开头补清单 + 相同页做共用区 |
| **共性页只在其中一套里画** | 另一套链路断裂，用户切过去找不到这一屏 | 两套都画，右上角标灰底 `两方案相同`（**重复画是对的，别省**） |
| 两个方案只是侧栏位置不同 | 结构没岔，是同一个方案的变体 | 回第二节①，从"谁先动 / 任务放在哪"重岔 |
| 草图里画了完整的表格列、写了字段名 | 精度跑到线框去了，用户会在细节上挑 | 退成灰条 |
| 只画了首页 | 走法站不站得住要连起来看 | 补成整套（进入 → 操作 → 结果） |
| 设计说明只写好话，不写代价 | 没取舍等于没判断 | 按"代价是…"强制补全 |
| **两套走法一样、只是档位不同（拼盘）** | 用户选的还是同一件事，只是精细度；创新没变成可选项 | 回第二节①重岔走法；真岔不开，按 §二④ 特例显式声明并补"创新档会变成什么样" |
| **两套水位一样高** | 高水位点子进不了方案主体，只能降档成一行注记 | 按 §二② 配档：方案一 ≥2 处创新，方案二全部优化版 |
| **方案一写满创新档，却不写目标与指标怎么变** | 把"改前提"藏进漂亮方案里，上线才发现要改流程、改验收线 | 创新档必带"目标改哪句 / 指标换哪个 / 怎么防误伤"三行 |
| 用户说"都不满意"，我加第三个硬凑 | 没搞清是走法问题还是水位问题 | 先问一句，再决定回岔还是回 1.3 补档位 |

## 十、交付模板

```markdown
# 需求草图示意
> 基于需求理解之后进行的设计思考草图，仅用于思路对齐，不涉及详细设计。
```

## 十一、与其余环节的边界

| 易混环节 | 分工 |
| :--- | :--- |
| **1.3 突破点拆解** | 1.3 出"打法点子"，本步出"页面形态"。**1.3 的档位表是原料，本步的草图是组装结果**——同一个突破点在两个方案里可以取不同档 |
| **本步的页面草图清单 vs 4.1 的正式页面清单** | 本步定"几屏、各管什么、两个方案哪里不一样"（粗）；4.1 定"编号、模板 ID、组件、Token"（细）。**见第三节** |
| **4.1 线框图** | 本步只定"分区与主结构"，4.1 定"分区里放什么组件、多少列、多宽"。**精度差别见第一节** |
| **5.0 说明书** | 选定方案的设计说明与未采纳方案的一句话结论，进说明书；草图本体**默认不进说明书**（避免和线框图混）。**确需留回溯入口时**，只许以"存档"形态放进 5.0 §5.2 的 `<details class="sketch-fold" data-purpose="archive">`，摘要写「📦 存档：…（实现以第 7 节线框为准）」，区内首行声明"含占位、不得复制样式、不得作为实现依据"；**存档区不算"占位已展开"**，线框仍须按占位清单逐条落控件（5.0 铁律 15.1 / 23） |

> 📌 **一句话记法**：**1.3 说怎么破，1.4 说长什么样、走哪套，4.1 说具体怎么摆，5.0 说清为什么这么摆。**
