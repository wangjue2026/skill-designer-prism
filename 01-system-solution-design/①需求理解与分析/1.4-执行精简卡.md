## 一、核心产出与硬边界（7 条铁律）

1. **只出 2 套真分岔方案（「方案一」「方案二」）**：不画常规版、不标推荐/水位徽标、不写方案标题句。两套方案必须在**未来旅程四段（`who / what / how / wow`）**中做到 **`what` 与 `how` 均不同、`wow` 峰值不同**，且每套 ≥2 段质变（含主战场页），说得出“从 X 变成 Y”。
2. **导航 IA 共用，页面/浮层形态允许分岔**：
   - **信息架构树（导航级，≤4 级菜单）**：两套共用，只写菜单名（≤6 字）+ 右对齐级别列，不写括号说明。
   - **页面清单（5 列：编号 / 所属菜单 / 页面名称 / 类型 / 说明）**：允许方案一与方案二在同一导航菜单下拥有**不同的页面/浮层组合**（如方案一含独立节点抽屉 `P3`，方案二将其内联进主画布从而取消 `P3`，在说明/清单中注明所属方案即可）。
3. **步骤驱动的可交互原型（告别重复静态长卷）**：
   - 顶层结构：`方案一 / 方案二` 吸顶切换条 → `场景 Tab`（1 条场景时可省略切换条）→ **顶部交互式「步骤剧本条」（`Step 1 → Step N`，步名逐字取自 1.1）** → **单一高保真可交互产品画布**。
   - 点击步骤条或画布内触发点（如点击列表行、点击左栏规则、点击 Tab、点击轮次轨），**真实切换画布状态 / 打开抽屉 / 联动高亮**，让评审者直接“点着体验”创新交互。**不再同一页重复画 3 遍、不再把所有 Tab 面板同时纵向摊开。**
4. **视觉上限放开 + 严守 7 条底线红线**：
   - **Part1 视觉上限不设限（决策 A）**：概念高保真原型的高保真核心区与可视化图形**放宽 `V-14` 色板白名单与 `V-19` 2px 圆角限制**——允许柔和层次色、微阴影、精致圆角与丰富 SVG/Canvas 配色（Part2 线框与说明书再收敛回 idux Token）。
   - **严守 7 条人工实证底线红线（不可破）**：`V-05` 无大面积空洞留白、`V-06` 工具栏左右分区有序、`V-07` 同类动作不散落多区、`V-20` 语义色不错用（如排名不用告警红）、`V-23` ≥3 个并列统计数字用规范 KPI 条、`V-24` 同类卡片主操作位置一致、`V-25` 数值列右对齐且标签纵线对齐。
   - **结构级规范必守**：主按钮 `#1C6EFF`、主左取右、抽屉页脚贴左 / 弹窗页脚贴右、无 `Ix*` 组件名、图框内不出现 `#RRGGBB`/`px` 规格值。
5. **真可视化，禁敷衍主图**：
   - 核心分析/主战场页必须有 `data-hero` 数据主图，且必须满足**真实视觉编码**（位置 / 长度 / 面积 / 色阶 / SVG 节点-边 / 流带）——**禁止用“3~4 个等大白底文字框 + `→` 箭头”冒充高保真主图**；
   - 轻量确认弹窗 / 简单表单页**豁免 `data-hero`**，禁止为了过门禁强行塞图表。
6. **去框线化 + 标注层解耦 + 路径信息置顶**：
   - 画布内部遵循织雨哲学第 1 条（`#F7F9FC` 超浅底色 + `#FFFFFF` 纯白卡片，最多 2 层可见容器，禁止 5~6 层套娃边框）；
   - **来源路径锚点置顶规则（2026-11-27 固化）**：`<span class="from" data-from="Px">从「xxx」打开</span>` 一律放在页面标题顶部栏 `.page-hd` 内（紧跟形态说明之后），**不塞进抽屉/弹窗内部标题栏污染真实产品界面**；字色采用深黑 `#1F232B`、`font-weight: 600` 保持清晰醒目；
   - 所有工程解释（`做法 / 为什么`、`Token:`）、`.dx` 虚线框与标号徽标默认隐藏，点击「显示设计标注」Toggle 后叠加呈现；画面内禁止出现 `进入：/去向：`、`当前激活视图：xxx` 等工程噪音字样。
7. **台账沉底 + 仿真数据**：
   - `view-ledger`、`flow-ledger`、`ph-ledger`、`dx-ledger` 统一收入文末 `<details class="handoff">` 折叠区，不进正文；
   - 数据必须仿真自洽（页头声明环境/快照时间/规模，跨页数字可复算，无 `__` 空占位）。

## 二、执行工作流（5 步出稿）

1. **定两套未来旅程（`who / what / how / wow`）**：消费 1.3 创新点子，确认两套在 `what`（承载形态）与 `how`（操作路径）上真正岔开，并各写清 1 句真实代价。
2. **定导航 IA 与分方案页面清单**：先画导航树（≤4 级），再列 5 列页面清单（标注方案差异页），内部核对 PRD 动作覆盖（不展示覆盖表）。
3. **基于 `tools/prototype-shell.js` 装配可交互概念原型**：
   - 交付页结构（从上到下 4 块）：① 页头（标题 + 仿真数据声明）→ ② IA 树 + 页面清单 → ③ 两套方案对比表（整体说明含代价 + `who/what/how/wow` 四段 + 各自思考点）→ ④ 吸顶控制栏（`方案一 | 方案二` + `显示设计标注` Toggle）+ 场景步骤剧本条 + **整屏高保真可交互画布** → 文末折叠交接区 `<details class="handoff">`。
   - 为每处核心创新区标记 `data-dx="DX-..."` 与图下标注（Toggle 打开时可见），常规未细化能力位标记 `data-ph="CAP|KEEP|OFF|DATA"` + `data-ph-id`。
4. **过准出门禁 + 真实看图**：
   - 运行：`bash tools/gate-ex.sh 1.4 _output/<业务名>/草图-<业务名>.html _output/<业务名>/01-主场景-<业务名>.md`
   - 用无头浏览器截图自检：确认默认态干净无噪音、主图有真实视觉编码、打开「设计标注」后标号与说明清晰可读。
5. **停在方向确认闸门（固化四句话术，≤6 行）**：
   > 我已经对需求文档做了 [X 分析]，梳理了信息架构（N 个功能域 / N 个页面）以及两套概念高保真原型方案；
   > 请您打开 [`_output/<业务名>/草图-<业务名>.html`] 体验交互并确认哪套方向更优（右上角可开关「显示设计标注」查看设计思考）；
   > 确认后我将基于此方向进入 Part2 的详细设计与物料装配（逐页线框 → 设计说明书）；
   > 若两套思路均不合预期，可随时指出问题，或邀请我一起共创调整。
