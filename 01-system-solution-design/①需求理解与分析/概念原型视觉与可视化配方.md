# 概念高保真原型 · 视觉工艺基准与 1 对 N 视觉形态矩阵（Part1 必读）

> 💡 **核心原则（反千篇一律 · 工艺与形态解耦）**：
> 本文档**绝不是**“照抄的 5 套固定页面模板”——固化模板会导致所有需求长得一模一样、杀死创新。
> 我们把视觉能力拆成两层：
> 1. **工艺层（下沉到工具引擎，保高级感与精准度）**：去框线表面体系（[`tools/prototype-shell.js`](../../tools/prototype-shell.js)）+ 纯数学 SVG/时间轴精密绘图引擎（[`tools/viz-engine.js`](../../tools/viz-engine.js)）+ **1 轮无头截图自审精修**；
> 2. **形态层（保持 1 对 N 开放，保创新多样性）**：同一类业务问题有多种完全不同的视觉文法，**硬约束：方案一与方案二禁止选用同一种视觉形态**。

---

## 一、视觉质感工艺基准（不限形态，只定高级感）

1. **三层微底色去框线化**：画布 `#F5F7FA` → 独立内容面 `#FFFFFF`（轻投影代替硬边框）→ 面内次级区 `#F7F9FC`（零边框）。**严禁出现 5~6 层套娃细线框。**
2. **强字阶与空间节奏**：主指标 `22~26px / 600 / tabular-nums`、区块标题 `14~15px / 600`、正文 `13px`、元数据 `12px` 浅灰；拒绝“大段 12px 黑字平铺”，AI 研判、摘要、证据必须有视觉重心与结构化分块。
3. **语义色克制（决策 A + 严守 V-20 红线）**：Part1 概念原型放开高级配色与微渐变，但**非风险类排名/进度绝对禁用红色（V-20）**；≥3 个并列统计数字须落 `wf-kpi--strip`（V-23）。

## 二、1 对 N 视觉形态发散矩阵（禁止方案一 / 二撞形）

> 🛑 **使用规则**：先从 1.1 识别核心数据的**主关系**，再从下表为**方案一、方案二各挑一种不同形态**，自由发挥视觉创意——**绝不把任何一种形态当成唯一标准答案**。

| 核心业务/数据问题 | 可选视觉形态方向（1 对 N，不限于此） | 复杂图形精密绘制支持 |
| :--- | :--- | :--- |
| **多轮交互 / 链路调用 / 排障定位** | ① **比例瀑布 Trace 轨**（共享毫秒轴 + 耗时条）<br>② **双轨同步对照台**（左对话/规则 ↔ 右实时调用树联动）<br>③ **横向能量脉冲时间轴**（柱高/面积编码风险密度）<br>④ **节点-边因果拓扑图**（高亮异常攻击/卡慢路径） | `VizEngine.renderWaterfallHTML()`<br>`VizEngine.renderLayeredTopoSVG()` |
| **AI 能力演绎 / 机理展示 / 价值感知** | ① **黑盒白盒化机理透视图**（输入 → 引擎命中模块 → 拦截结果）<br>② **防护前后对比沙盘**（无防护波及面 vs 拦截后 0 扩散）<br>③ **流向桑基图**（来源 → 风险类型 → 阻断/脱敏/放行占比）<br>④ **ROI / 价值归因故事卡**（关键数字 + 支撑证据微图） | `VizEngine.renderLayeredTopoSVG()`<br>`VizEngine.renderSankeySVG()` |
| **全局态势 / 多维分布 / 批量分诊** | ① **多维热力覆盖矩阵**（部门 × 应用 / 规则 × 时段色阶格）<br>② **行内微型可视化入表**（Sparkline / 轮次风险微柱）<br>③ **分层占比树图 / 气泡聚类**（面积编码体量、色相编码风险）<br>④ **优先级分诊队列条 + 聚焦主工作台** | `VizEngine.renderSankeySVG()`<br>CSS Grid 色阶矩阵 / 内联 SVG |
| **AI 研判结论 / 摘要信息呈现** | ① **结构化要点微卡**（一句话主结论 + 3 维无框浅底拆解）<br>② **实体高亮叙事条 + 右侧依据锚点**（结论句内嵌可点实体）<br>③ **置信度仪表 + 关键证据胶囊组** | 自由排版（**禁止浅蓝框内倒一整坨黑字**） |

## 三、复杂图形为什么不用“纯文字手算 SVG”？

- **原则**：凡涉及**全局拓扑、攻击路径、桑基流转、精确比例瀑布 Trace**，优先通过 [`tools/viz-engine.js`](../../tools/viz-engine.js) 的数学布局函数生成无重叠、精确贝塞尔曲线的静态 SVG/HTML，再叠加业务图标、徽标与点击联动（`data-go`）——**让代码算坐标、让模型做创意**，彻底告别“文字重叠、曲线歪斜”和“4 个等大文字框 + `→` 箭头”的敷衍画法。

## 四、出稿必做：1 轮「渲染 → 截图 → 视觉精修」闭环

单次盲写代码很难稳定达到高视觉完成度。交付前必须执行 1 轮视觉自审：
1. **无头截图**：用 Chrome headless 渲染出图，肉眼检视默认态（标注 Toggle 关闭时）的真实画面；
2. **四问精修**：
   - **抹掉数字还能看懂高低/长短/流向/断点吗？**（否则立刻重做视觉编码）
   - **有没有拥挤、文字截断、一坨黑字或套娃边框？**（立刻调间距、删冗余框线）
   - **方案一和方案二的视觉形态是不是一眼不同？**（撞形则换矩阵里的另一种形态）
   - **是否至少有 1 处让人愿意截屏发群的“产品力画面”？**
