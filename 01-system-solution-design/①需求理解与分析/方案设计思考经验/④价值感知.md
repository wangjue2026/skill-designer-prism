# ④ 价值感知

> 💡 **用途**：作为 [1.3 体验突破点拆解](../1.3-体验突破点拆解.md) 第八节「入口 2：按用户工作类型扫」的经验底座。
>
> 🧠 **这是一份"怎么想"的经验，不是"怎么做"的答案库。**
> 用法顺序固定：**先按原则定症结 → 再想办法变出别的做法 → 最后拿参考解法对照补充**。参考解法只用于打开思路和查漏，不是匹配源。
>
> 📌 **边界**：这是**方案设计阶段的思考经验**，只管"往哪个方向想、变成什么形态"，不管"用什么手段实现"。落地技法走 Type-01~07 等执行侧经验。
>
> 🚧 **状态**：初稿，未验证。四类初稿已齐。

## 一、这类工作在干什么

看态势、要汇报、对上负责——用户的产出不是"操作完成"，而是**一个能说出口的判断**：现在安不安全、这套东西帮到了什么、钱花得值不值、下一步该往哪使劲。

共同点是：**用户要拿这里的结论，去跟别人交代。**

扫之前先自问一句（问的是**当前这个场景 / 页面**，不是整个需求）：

> 这块界面上的结论，最后要拿去跟谁交代？

- 说不清 → 拿不到预算、争取不到人。
- 说不准 → 对上汇报出错，比数字难看严重得多。
- 只报喜 → 真问题被掩盖，下一次更被动。

所以这类工作里，**"说得清"比"说得好"重要**。

---

## 二、拔高方向（一句话）

> 别只让用户"自己从大屏里找数字"，要让他"**一眼看到价值和状况、数字经得起追问、要汇报时能直接拿走、回头看说得清成效**"。

---

## 三、原则（判据）

扫需求时，逐条问右边的扫描问句。**发现"有问题"还不够，要定到具体是哪一种病**。

| # | 原则 | 什么意思 | 常见症结 | 扫描问句 |
| :---: | :--- | :--- | :--- | :--- |
| 1 | **一眼看到价值和状况** | 一进来既知道"现在怎么样"，也知道"这套东西帮到了什么" | ① 大屏全是数字和图，没有判断<br>② 只报当前状态，说不出挡了什么、省了什么<br>③ 重要的事混在次要的事里 | 领导站这屏前 30 秒，能不能说出"现在怎么样、帮到了什么"？ |
| 2 | **数字经得起追** | 每个数都能追到来源、口径、时间范围，被问到能当场答 | ① 不知道数从哪来<br>② 同一指标在不同页面对不上<br>③ 口径改过，没标注 | 有人追问"这个数怎么算的"，他能当场答上来吗？ |
| 3 | **好坏要有参照** | 数字旁边有基线、目标或同业，不然数字没有意义 | ① 只给当前值<br>② 没有目标值<br>③ 不知道同业什么水平 | 这个数算好还是差，他凭什么判断？ |
| 4 | **能往下钻，不跳不断** | 从总览能一路看到明细，位置、筛选、时间都还在 | ① 想看明细得跳页<br>② 跳过去筛选和时间丢了<br>③ 看完明细回不到原来的位置 | 他想看某条数据的细节，要跳几次、丢多少上下文？ |
| 5 | **问题带优先级和下一步** | 不只指出哪块弱，还说清谁负责、先改哪个、怎么改 | ① 只展示不指问题<br>② 指了问题没有责任方<br>③ 弱项并列，不知道先改哪个 | 从这屏能直接得出"先干什么、谁来干"吗？ |
| 6 | **汇报能直接拿走** | 从"看到"到"能讲"，不用再截图拼材料 | ① 材料靠手工截图整理<br>② 时间范围一改就得重做<br>③ 讲的时候说不清口径 | 他要向上汇报，还得再做多少加工？ |
| 7 | **成效看得出、说得出** | 措施上线后带来了什么变化、投入换回了什么，能说得清是哪件事起的作用 | ① 只有当前快照<br>② 有趋势，但说不清是不是这项措施带来的<br>③ 只讲投入，不讲产出 | 半年后回看，能说清"哪件事起了作用、值不值"吗？ |

> 🛑 **别七条全上**：做日常态势的场景，第 1、3 条是主角；做月度汇报的场景，主角是第 2、6 条；做年度复盘，主角是第 7 条。

> ⚠️ **例外**：如果这个页面是"总部给下级看的总览、同时要往上汇报"（一张屏两头都要交差），七条常同时成立。这时按"被追问时答不上来最丢人"排优先级——第 2（数字经得起追）、第 6（汇报能直接拿走）优先，其余作基线补齐。
> 📐 **演练已暴露的偏科**：现有案例只触到第 1、3 条，第 2、6、7 条几乎没被扫出来过。走 ④ 时**专门为这三条各问一遍**，别被"一屏看清"吸走全部注意力。

### 基线下限（缺了直接补，不用发散）

| 对应原则 | 基线该有什么 |
| :--- | :--- |
| 一眼看到价值和状况 | 关键指标和趋势看得到，有一句状态概述 |
| 数字经得起追 | 指标带口径说明和时间范围 |
| 好坏要有参照 | 关键指标有目标值或上期对比 |
| 能往下钻，不跳不断 | 总览点得进明细，返回能回到原处 |
| 问题带优先级和下一步 | 有弱项清单 |
| 汇报能直接拿走 | 数据能导出 |
| 成效看得出、说得出 | 有同比或环比 |

## 四、怎么往上想：换个做法

定了症结之后，**先别去看第六节的参考解法**。问一句：**这件事还能从哪儿变？**

> 🔗 **和 1.3 变维表的关系**：这八处是把 1.3 的通用六维换成本域说法，另加四处本域专用的——**能钻多深**、**给谁看**、**怎么带走**、**成效怎么算**。

| 能变的地方 | 可以变成 | 变完大概到哪档 |
| :--- | :--- | :---: |
| 先给什么 | 数字 / 趋势 / 一句话判断 / 判断带价值 | 基线~优化 |
| 跟什么比 | 不跟 / 上期 / 目标 / 同业 / 历史最好 | 优化~创新 |
| 看多长时间 | 当前 / 今天 / 本周 / 季度 / 年度 | 优化 |
| 能钻多深 | 只看总览 / 到分类 / 到单条明细 / 明细可回到原处 | 优化~创新 |
| 给谁看 | 一线 / 主管 / 老板 / 客户 | 创新 |
| 怎么带走 | 截图 / 导出 / 一页报告 / 可分享的链接 | 优化~创新 |
| 落在哪 | 大屏 / 报告 / 邮件 / 会议材料 | 优化 |
| 成效怎么算 | 只看趋势 / 措施前后对比 / 按措施归因 / 投入产出一笔账 | 优化~变革 |

两条用法：

1. **至少动两个地方，才算一条新做法。** 只换图表类型、只把卡片排得更整齐，不算。
2. **变完校验一句**：这条做法替用户省了哪份力——找、读、判断、重复、返工。说不出来，退回重想。

> 「给谁看」是这类工作最容易忽略的一处：同一个数字，老板要看价值，主管要看弱项，一线要看明细。不分角色的结果是谁都不满意。

## 五、走一遍示例（示意走法，不是答案）

拿原则 1 的症结①"大屏全是数字和地图，没有结论"走一遍。**不用八处都动，动两处就够一条**：

| 变的地方 | 变出来的做法 | 怎么解决"没有结论" | 档位 |
| :--- | :--- | :--- | :---: |
| 先给什么 → 一句话判断 | 顶部一句"本周整体平稳，两处需要关注" | 不用自己从图里总结 | 优化 |
| 跟什么比 → 上期 / 目标 | 关键数字都带对比和趋势 | 判断有了参照 | 优化 |
| 给谁看 → 分角色 | 老板看价值、主管看弱项、一线看明细 | 每类人拿到自己那层判断 | 创新 |
| 能钻多深 → 到单条明细 | 点数字就地展开，返回还在原处 | 想看细节不用跳走 | 优化~创新 |
| 怎么带走 → 一页报告 | 一键生成可分享的一页：结论、三条支撑、一张图 | 判断能直接带走 | 创新 |
| 成效怎么算 → 按措施归因 | 季度视角，标出措施上线点，说清哪项起了作用 | 判断能回答"值不值" | 创新~变革 |

> 🛑 这些不是答案，是走法示范。换个症结要重新变，**不要回来抄**。

## 六、参考解法（只做参考，不是匹配源）

> ⚠️ **使用顺序**：先按第四节自己想一轮，再回来对照，用来打开思路、查漏。
> 这里不是匹配表；真用了，要能说出"这个需求为什么是它"。
> 📊 表内按档位从低到高排，只从优化档挑，做出来一定"不落后但不出彩"。

### 对应 1 · 一眼看到价值和状况

| 参考做法 | 档位 | 省哪份力 | 适用 / 慎用 |
| :--- | :--- | :---: | :--- |
| 顶部一句判断，后面再跟图 | 优化 | 判断 | 全类通用 |
| 判断下面挂一条"最近帮到了什么"：挡了多少、恢复多快、省了多少 | 优化~创新 | 判断 | 价值没人看见时最值 |
| 判断 + 三条支撑：哪块恶化、哪块改善、影响谁 | 创新 | 判断 | 有人要拿去做决策时 |
| 按角色自动生成"你该知道的三件事"，里面带价值结论 | 变革 | 判断 | 角色分工明确的团队 |

### 对应 2 · 数字经得起追

| 参考做法 | 档位 | 省哪份力 | 适用 / 慎用 |
| :--- | :--- | :---: | :--- |
| 每个数都能点开看明细和算法 | 优化 | 读 | 有人会追问口径时 |
| 同一指标全局一个口径，跨页面一致 | 优化~创新 | 判断 | 多页面并存的产品，先解决对不上 |
| 数字变化能自动解释"因为什么变的" | 变革 | 判断 | 波动大、容易被误解的场景 |

### 对应 3 · 好坏要有参照

| 参考做法 | 档位 | 省哪份力 | 适用 / 慎用 |
| :--- | :--- | :---: | :--- |
| 给上期对比和趋势 | 优化 | 判断 | 全类通用 |
| 给同业或产线水位 | 创新 | 判断 | 有可比的样本时 |
| 给出"做到什么程度算好"的建议目标 | 变革 | 判断 | 目标本身没定、需要引导时 |

### 对应 4 · 能往下钻，不跳不断

| 参考做法 | 档位 | 省哪份力 | 适用 / 慎用 |
| :--- | :--- | :---: | :--- |
| 总览上的数字可点，点了就地展开明细 | 优化 | 找 | 有明细数据的场景 |
| 下钻时保留筛选和时间窗，返回回到原处 | 优化 | 重复 | 多页面联查时 |
| 总览、分类、单条同屏分层展开，不换页 | 创新 | 找 | 需要来回对照时 |
| 从异常数字直接跳到"这个数背后是哪些对象" | 创新 | 判断 | 数字异常但看不出原因时 |
| 钻到底能指到具体对象，并直接转给处理人 | 创新~变革 | 返工 | 要接处置流程时 |

### 对应 5 · 问题带优先级和下一步

| 参考做法 | 档位 | 省哪份力 | 适用 / 慎用 |
| :--- | :--- | :---: | :--- |
| 弱项清单带责任方和建议动作 | 优化 | 判断 | 有明确责任划分时 |
| 每项标出影响面和优先级 | 优化~创新 | 判断 | 弱项多于三五条时 |
| 按"改了能带来多少改善"排序，而不是按严重度排 | 创新 | 判断 | 资源有限、只能先改几处时 |
| 措施执行后自动回看效果，优先级跟着调整 | 变革 | 判断 | 改进周期长、需要追踪时 |

### 对应 6 · 汇报能直接拿走

| 参考做法 | 档位 | 省哪份力 | 适用 / 慎用 |
| :--- | :--- | :---: | :--- |
| 一键生成一页报告：结论、三条支撑、一张图 | 创新 | 重复 | 周期性汇报的场景 |
| 按对象和时间范围生成，改范围自动重算 | 创新 | 返工 | 每次汇报范围都不一样时 |
| 材料随数据自动更新，链接直接发出去 | 变革 | 重复 | 汇报频率高、数据天天变时 |

### 对应 7 · 成效看得出、说得出

| 参考做法 | 档位 | 省哪份力 | 适用 / 慎用 |
| :--- | :--- | :---: | :--- |
| 关键指标给同比、环比 | 优化 | 判断 | 全类通用 |
| 趋势线上标出措施上线的时间点，能看出拐点 | 创新 | 判断 | 想证明"措施有用"时 |
| 按措施归因：这项措施让哪几个指标变了、变了多少 | 创新 | 判断 | 同时上了多项措施、要分清功劳时 |
| 价值账本：投入多少、风险下降多少、少损失多少 | 变革 | 判断 | 要预算、要编制时 |
| 年度成效一页纸：今年做了什么、换回了什么 | 创新~变革 | 重复 | 年度复盘 |

### 全类通用 · 具象化（把抽象变成看得见的）

| 参考做法 | 档位 | 省哪份力 | 适用 / 慎用 |
| :--- | :--- | :---: | :--- |
| 安全态势 = 体检报告：总体结论、各项指标、建议三条 | 创新 | 判断 | 非专业受众也要看懂时 |
| 汇报 = 一页纸：结论、三条支撑、一张图 | 创新 | 重复 | 对上汇报 |
| 价值 = 账本：花了多少、挡了多少、少损失多少 | 创新~变革 | 判断 | 要预算、要编制时 |
| 下钻 = 漏斗：总览 → 分类 → 单条，逐层收窄 | 优化~创新 | 找 | 层级多、数据量大时 |
| 长期 = 时间轴上的折线，拐点标着做了什么 | 变革 | 判断 | 年度复盘 |

> 🛑 **具象化不是画得花哨**：形态要跟用户脑子里那件事的过程对得上；对不上，就只是装饰。

## 七、怎么用（三步）

> 📐 **扫描粒度：场景 / 页面 / 任务，不是"需求"**。
> 一个需求里可能有态势大屏、专题分析、月报导出几个页面，**逐个场景判断**，一个需求可以同时命中多类经验。

> 🧩 **原则不是每个页面的验收单**：一条原则通常只在一两个页面上是主角。

| 链路段 | 主要原则 |
| :--- | :--- |
| 日常看态势 | 一眼看到价值和状况 + 好坏要有参照 |
| 追问 / 核对 | 数字经得起追 |
| 细看某一块 | 能往下钻，不跳不断 |
| 定下一步 | 问题带优先级和下一步 |
| 向上汇报 | 汇报能直接拿走 |
| 长期复盘 | 成效看得出、说得出 |

> 反查用：如果「数字经得起追」没有任何页面承接，汇报时一定被问住；如果「能往下钻」没有，用户看完总览只能靠猜。

1. **先问交代给谁**：给老板看 → 第 1、7 条是主角；给主管定动作 → 第 5 条；对外或对上、数字会被追问 → 第 2 条必答，数字不准比不好看严重。
2. **逐条扫，定症结**：用扫描问句一条条问，记到具体症结（①②③），别只写"大屏不好看"。
3. **变出做法，再对照**：拿症结对照第四节的八处地方，变出几条结构不同的做法；想完再看第六节，缺的补、重的删。还原成一句"让人……"，和入口 1 的结果**合并去重**，回到 1.3 第 3 步分档。

> ⚠️ 只走入口 1 的时候，第 2、4、7 条几乎不会被触发——目标里写的多是"看得清、看得全"，很少写"数要对得上""要能钻到明细""这项措施值不值"，但恰恰是这三条决定这份东西能不能拿去交代。

## 八、扫描示例：安全运营价值汇报

> 示例只演示扫法，场景细节以实际需求为准。

| 原则 | 扫到的答案 | 症结 | 目标里有没有提 | 转成的突破点 |
| :--- | :--- | :---: | :---: | :--- |
| 一眼看到价值和状况 | 大屏全是指标和地图，得自己总结；也看不出挡住了什么 | ①② | 没提 | 让人一眼知道整体怎么样、帮到了什么 |
| 数字经得起追 | 被问"这个数怎么来的"答不上，各页面对不上 | ①② | 没提 | 让每个数都能追到口径 |
| 好坏要有参照 | 只给本月数值，没有目标和上期 | ②③ | 没提 | 让人看得出好还是差 |
| 能往下钻，不跳不断 | 想看成明细要跳三个页面，回来筛选没了 | ①② | 没提 | 让人能一路看到明细，回来还在原处 |
| 问题带优先级和下一步 | 指出问题，但没责任方、没先后 | ②③ | 没提 | 让弱项落到人和先后顺序 |
| **汇报能直接拿走** | 每月手工截图拼 PPT，做一两天 | ①② | **提了（汇报）** | 让人一键生成能直接讲的材料 |
| 成效看得出、说得出 | 只有月度快照，说不清哪项措施有用 | ②③ | 没提 | 让人说清哪件事起了作用 |

结论：目标只覆盖了「汇报」；「价值可见」「口径可追」「能下钻」「落到人和优先级」「成效归因」都是入口 2 补的。
