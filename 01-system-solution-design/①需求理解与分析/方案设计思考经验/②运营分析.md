## 一、这类工作在干什么

研判告警、查日志、做分析、挖威胁——这四件事不是四类工作，是**一条链上的四段**：发现信号 → 查证真假 → 分析影响 → 往深处挖。

共同点是：**用户在从一堆信号里，下一个能拿去行动的判断**。

扫之前先自问一句（问的是**当前这个场景 / 页面**，不是整个需求）：

> 这块界面上，用户要下的是什么判断？判错了会怎样？

- 漏判 → 真威胁被放过去，代价在安全侧。
- 误判 → 白花人力，甚至误处置打断业务。

两头都有代价，所以「给结论快」不能拿「依据看不见」去换。

## 二、拔高方向（往哪几个方向拔）

> 🎯 **这一节的作用**：定"这类工作值得往哪几个方向使劲"，**不是定页面长什么样**。它给第三节的五维原则定调子，不给设计方案下指令。
> 🛑 **最常见的误读**：把一句话读成"结论放顶部"。照这么读，所有分析类需求都会做成同一个模板——顶栏一句结论 + 下面一堆图，**除了这一招再没有别的**。同质化不是从原则开始的，是从这一句开始的。

**成本结构**：这类工作最贵的不是操作时间，是**注意力**——一天看几千条，人的判断力会被磨钝。所以拔高不是"把信息搬得更靠前"，而是**让注意力只花在该花的地方**。

**五个方向**（每个方向对着一条原则，只说要拿到什么，不指定形态）：

| # | 方向 | 从 → 到 | 对着哪条原则 | 判据 |
| :---: | :--- | :--- | :---: | :--- |
| 1 | **给判断，不给原料** | 给人一堆数据 → 给人能拿去行动的判断 | 1 结果易感知 | 他还要不要自己先算一遍？ |
| 2 | **让结论站得住** | 给结论 → 给能被验证的结论 | 2 结果可验证 | 他不信的时候，能不能就地验？ |
| 3 | **分配注意力** | 信息平铺 → 按价值分配视线 | 3 信息主次区分明显 | 他第一眼看的那条，对不对？ |
| 4 | **把路走通** | 一串独立页面 → 一条不打断的路 | 4 研判旅程顺畅 | 中间断几次、重来几次？ |
| 5 | **让判断看得见** | 用文字和表格讲 → 用形态和视觉讲 | 5 可读性强 | 他是在扫，还是在读？ |

> 📌 **方向是"往哪使劲"，不是"做哪个控件"**。方向 1 可以由顶部结论条实现，也可以由一张按风险排好的分诊图、一条带阈值的信号条、一张按状态着色的覆盖矩阵实现——**同一个方向，形态可以完全不同**。做得好不好，回第三节按五维判，不看"有没有照一句话做"。
> 📌 **方向 5 最容易被漏**：前四个方向做出来都还是"页面 + 文字"，只有它管"判断有没有被画出来"。具体招法见第四节末的「视觉与表达手法」表——**没有这一层，方案就只能靠加内容卡撑场面**。

## 三、原则（判据）

> 🛑 **原则写的是维度，不是举措**：同一维可以由完全不同的做法满足，做法随场景变；把做法当原则写，任何需求都只能扫出同一套方案。

| # | 原则 | 说明与要求 | 扫描问句 | 常见反例 | 常见举措（参考，不限于此） |
| :---: | :--- | :--- | :--- | :--- | :--- |
| 1 | **结果易感知** | 不用先读数据、先做计算，打开就拿到三件事：**整体怎么样、这一轮得出什么结论、先处理哪个**。管结论"有没有、够不够拿去行动"，不管写得好不好读（那是 5） | 他打开这一屏，是先拿到结论，还是先开始算？ | ① 首屏是指标和图，没有结论<br>② 有数据，没有"这一轮的分析结论"<br>③ 有结论，没有"先做哪个"<br>④ 结论散在各分区，拼不出全局 | ① 顶部结论条：今天有几件事要判，按轻重排好<br>② 概览卡 + 三条支撑（哪块恶化 / 哪块改善 / 影响谁）<br>③ 事件卡三段式：发生了什么 / 影响谁 / 建议怎么做<br>④ 默认视图只给"待研判"，已闭环的折叠<br>⑤ 结论带置信度，按置信度分档给建议 |
| 2 | **结果可验证** | 结论旁边就是能撑住它的**证据链**：命中依据、原始记录、相关对象、以及反证；顺着能走完一次复核，不切系统、不靠经验补 | 他不信这个结论时，能在原地走完一次验证吗？ | ① 只给分数 / 等级，黑盒<br>② 证据散在多个系统<br>③ 只给原始日志，要自己解读<br>④ 只有支持证据，没有反证 | ① 结论旁挂证据：命中规则 / 日志片段 / 实体画像<br>② 每条证据标注它支持或排除哪个原因<br>③ 标出证据是否同源，同源派生的只算一条<br>④ 摆出反证："为什么没报"<br>⑤ 说清"还差什么才能定"，把确认成本摆出来 |
| 3 | **信息主次区分明显** | 层级把"必须看的"顶上来、"可略过的"压下去，人一眼知道**关注点在哪、下一步往哪走**。管"谁在前、谁可见"，不管"长得好不好看"（那是 5） | 这一屏里，他第一眼该看的那条，现在排第几？ | ① 高危与低危平铺<br>② 重复项各占一行<br>③ 关键信息埋在长列表里<br>④ 看不到哪些被系统自动忽略了 | ① 同一实体 / 规则 / 时间窗合并成一条事件<br>② 按影响面 × 置信度分级，低价值自动折叠<br>③ 默认按"需要我判的"组织视图，而不是按数据源<br>④ 视觉重心跟风险走：高危占更大位置，不是只加红标签<br>⑤ 把"被自动忽略的"也摆出来，可查可申诉 |
| 4 | **研判旅程顺畅** | 从看到 → 查证 → 下结论 → 交出结论，是一条不打断的路：上下文不丢、条件跟随、结论有地方落、复核不用重来 | 他从"看到"走到"结论交出去"，中间断几次、重来几次？ | ① 换页丢掉筛选和时间窗<br>② 查到一半要跳系统<br>③ 结论没处落，靠截图和嘴说<br>④ 复核要重走一遍前面的步骤 | ① 就地展开到日志、到处置，不跳页<br>② 筛选条件、时间窗跟人走，换页不丢<br>③ 结论就地落：标记 / 转工单 / 加备注<br>④ 复核走和首次研判同一条路<br>⑤ 交接带上已研判结论和待确认点 |
| 5 | **可读性强** | 关键信息以"扫一眼就能捞到"的形式出现：分组、层级、可视化、短句；**避免大面积文字平铺**，界面轻量简约 | 他是在"扫"，还是在"读"？ | ① 结论是一大段话<br>② 证据是整段原始日志<br>③ 多条证据并排，看不出先后因果<br>④ 信息密度均匀，没有视觉重心 | ① 结论压成一句：谁 / 做了什么 / 影响什么<br>② 分组归类替代平铺字段，组内按重要性排<br>③ 关系、分布、时序交给可视化，文字只留判断和结论<br>④ 关键行高亮，别让人逐行找<br>⑤ 长文本先摘要，点开看全文<br>⑥ 一屏只留这一轮要判的，次要信息收进二级 |

> 📌 **「常见举措」只是起步点，不是候选清单**：一维给 3~6 个，**不等于只能从里面挑**，且这里列的多是**信息层面**的做法。定稿前要按第四节两张表各摊一轮（结构 / 交互一张，视觉表达一张）；分档与适用条件见第六节。
> 📌 **五维里只有「2 结果可验证」是本域独有**，其余四维跨域都成立——只能当基线补齐，别占亮点位。判亮的依据一句话：**这条换到别的域还成立吗？成立就不是亮点。**

> 🛑 **别五条全上**：五维是扫描方向，不是验收项。做告警降噪的需求，3 是主角；做威胁狩猎的需求，主角多半是 2 和 5；做统一研判台，1 与 4 是主角。

> ⚠️ **例外**：同一个页面里如果用户的任务是"判完就要定结论并交出去"（如多场景研判台的统一研判单），五维可能同时成立。这时不必砍，按"结论判错的代价"排优先级——2（可验证）、3（主次）优先，其余作基线补齐。

### 五维的边界（同一件事别记两遍）

| 现象 | 归到 | 为什么 |
| :--- | :---: | :--- |
| 没有结论 / 结论太笼统，不能拿去行动 | 1 | 缺的是结论本身 |
| 结论是一大段话，读完才知道说啥 | 5 | 结论有，形态不行 |
| 缺证据 / 证据在别的系统 | 2 | 缺的是内容与来源 |
| 证据齐全，但关键行要自己找 | 5 | 证据有，形态不行 |
| 高危低危平铺、重复项不合并 | 3 | 分配问题 |
| 排版乱、信息密度均匀、没有重心 | 5 | 形式问题 |
| 跳页、丢筛选、结论没处落 | 4 | 旅程问题 |

> 📐 **1 和 3 的分界**：1 问"有没有一个能拿走的结论"，3 问"这一屏里先看到哪一条"。可以结论很清楚、主次却很乱。
> 📐 **3 和 5 的分界**：3 管"谁排前面、谁被收起"（信息分配），5 管"露出来的东西长什么样"（呈现形式）。

### 基线下限（缺了直接补，不用发散）

| 对应维度 | 基线该有什么 |
| :--- | :--- |
| 结果易感知 | 首屏有状态概览 + 一句本轮结论 |
| 结果可验证 | 详情里看得到命中规则和原始记录 |
| 信息主次区分明显 | 能按风险 / 优先级排，能筛，重复项能合并 |

## 四、怎么往上想：换个做法

定了症结之后，**先别去看第六节的参考解法**。问一句：**这件事还能从哪儿变？**

下面这张表管"信息怎么摆、谁来干"；本节末还有第二张表管"判断怎么画出来"。两张表各摊一轮，出来的东西才不在同一个层面上打转。

> 🔗 **和 1.3 变维表的关系**：**这不是 1.3 通用六维的翻译，是本域自己的一张变维表。** 和通用六维（信息在哪层 / 走几步 / 上下文丢不丢 / 谁先动 / 什么时候给 / 默认状态）只是部分重叠——"谁来筛"对"谁先动"，"在哪判断"对"信息在哪层 / 走几步"；**"判断委托到哪一层""确认成本""证据独立性"是本域独有的**（体现在下面"谁来筛"与证据类变维里）。**直接用这张，不用回套通用六维**；这张发散不够，再拿通用六维补。

| 能变的地方 | 可以变成 | 变完大概到哪档 |
| :--- | :--- | :---: |
| 先给什么 | 原始数据 / 指标图 / 一句话结论 / 结论带依据 / 结论 + 待办优先级 | 基线~优化 |
| 谁来筛 | 人逐条看 / 系统聚合去重 / 系统先给判断、人只确认或推翻 / 按置信度分层委托 | 优化~创新 |
| 判断的粒度 | 单条告警 / 一个事件 / 一个实体（资产、账号、域名） / 一类行为 | 优化~创新 |
| 时间视角 | 当前快照 / 一段时间的变化 / 与历史同期比 | 优化~创新 |
| 在哪判断 | 列表里 / 详情页 / 图上 / 对话里 | 优化~创新 |
| 结论怎么落 | 就地标记 / 转工单 / 写成规则 / 什么都不落 | 优化~创新 |
| 证据怎么取信 | 单条证据 / 多源并列 / 独立多源（标出是否同源）/ 证据链 + 反证 | 优化~创新 |

两条用法：

1. **至少动两个地方，才算一条新做法。** 只改图表样式、只把列表换成卡片，不算。
2. **变完校验一句**：这条做法替用户省了哪份力——找、读、判断、重复、返工。说不出来，退回重想。

> 「判断的粒度」是这类工作最容易出彩的一处：单条告警永远判不完，但**一个实体**可以被持续观察，**一类行为**可以被总结成模式。粒度一换，工作量会掉一个量级。

### 第二张摊法表：视觉与表达手法（把判断画出来）

> 上面的变维表变的是"信息摆在哪、谁来干"，出来的多是**结构与交互层**做法。**视觉层还有一整类没被用起来的招**：用位置、大小、色彩、密度、形态、动效，把判断直接表达出来。这类做法常常比"再加一块内容"更省注意力，也更少撞车。

| 手法 | 怎么用 | 替用户省哪一步 | 适用 / 慎用 |
| :--- | :--- | :---: | :--- |
| **去色降噪** | 只让高危有色，其余降为灰阶；一屏不超过三种强调色 | 找 | 信息多、必须一眼分主次时最有效；慎用：颜色已被业务语义占用时，先统一色义 |
| **视觉重心** | 按风险给面积 / 位置 / 留白差异，危险项占更大块，而不是只描红边 | 找 | 高危少、低危多时最有效；慎用：重心一旦平均，就退化成平铺 |
| **微型可视化入表** | 表格单元格里嵌 sparkline、迷你柱、覆盖率条 | 重复 | 列表要顺带判趋势；慎用：列宽不够时宁可另起一行 |
| **信号条代替分数** | 风险分换成"条 + 阈值刻度 + 档位"，让人看到离红线多远 | 判断 | 有明确阈值时；慎用：没有阈值，条就是装饰 |
| **差异高亮** | 两期数据只标变化部分，其余压平 | 读 | 复盘、对比；慎用：差异太多时退化成全彩 |
| **时间带 + 变更竖线** | 一条时间轴上叠"事件"与"变更"，把因果摊开 | 判断 | 排障、归因；慎用：时钟不同源时先校时，否则线是错的 |
| **覆盖矩阵 / 方块图** | 分支×租户、资产×策略铺成格，按状态着色 | 找 | 对象多、要看覆盖与缺口；慎用：格子过小看不清时改用聚合 |
| **分层嵌套（treemap）** | 按"分支 → 部门 → 终端"面积分解，体量一目了然 | 找 | 层级与占比要同时表达时 |
| **证据卡片 + 连线** | 证据做成卡片，用线连出"谁先谁后、谁支撑谁" | 判断 | 多步攻击、多源取证；慎用：超过 8 条线就糊，改成分段 |
| **结论句 + 实体高亮** | 一句结论里把实体、动作、影响面高亮，而不是写一段话 | 读 | 结论要被人转述时最值；慎用：高亮超过三处就没有重点 |
| **渐进披露** | 首层只给判断 + 三条依据，其余逐层展开 | 读 | 信息量大、受众分层；慎用：藏得太深等于没有 |
| **动效表达变化** | 只对"刚刚变了"的东西做一次轻动效，其余不动 | 找 | 实时态、轮询页；慎用：常驻动画会持续抢注意力 |

> 🛑 **视觉手法不是装饰**：判据只有一条——它替用户省了「找 / 读 / 判断 / 重复」里的哪一步？说不出来就是装饰。
> 📌 **视觉手法要落到五维里的一维**（多数落在 3 信息主次区分 与 5 可读性强 上）。**既说不出落到哪一维、又只是"更好看"的，不进方案**。
> 📌 **和"具象化"的分工**：具象化是**借一个现实过程造隐喻**（法庭、分诊、行程）；这一张是**用视觉变量把判断直接画出来**（色、位、形、密度、时序）。两者可以叠加：先定隐喻，再挑手法实现。

## 五、走一遍示例（示意走法，不是答案）

拿「结果可验证」的症结②"证据散在多个系统里"走一遍：

| 变的地方 | 变出来的做法 | 怎么解决"散" | 档位 |
| :--- | :--- | :--- | :---: |
| 先给什么 → 结论带依据 | 结论旁直接挂三类证据：命中规则、日志片段、实体画像 | 证据跟着结论走，不用自己去找 | 优化 |
| 在哪判断 → 同屏 | 三类证据在详情页分区摆放，不跳系统 | 还是在一个页面里看 | 优化 |
| 判断的粒度 → 事件 | 同一实体的多条告警合成一个事件，证据自动归到同一个案卷 | 来源再多，也归到一个案卷 | 优化 |
| 时间视角 → 一段时间 | 跨系统的事实按发生顺序并到一条时间线上 | 散在各处的事实变成一条链 | 创新 |
| 谁来筛 → 系统先判断 | 系统先把跨系统证据对齐，给建议结论，人只核对 | 对齐由系统做，人不用拼 | 创新 |
| 证据怎么取信 → 独立多源 + 反证 | 标出哪几条同源派生、再补一条反证，"凭什么不是它"也有答案 | 散不是问题，来源不明才是 | 创新~变革 |

> 🛑 这六条不是答案，是走法示范。换个需求，要重新拿症结从六处地方变，**不要回来抄**。

## 六、参考解法（只做参考，不是匹配源）

> ⚠️ **使用顺序**：先按第四节自己想一轮，再回来对照，用来打开思路、查漏。
> 这里不是匹配表；真用了，要能说出"这个需求为什么是它"。
> 📊 **表内按档位从低到高排**：只从优化档挑，做出来一定"不落后但不出彩"，至少往创新档想一条。
> 🧮 **档位后面那句"还得出力"就是这档的依据**：创新档及以上的条目都跟了一句"用户还得自己出什么力"。**这句话写不出来，说明这条实际只到优化档，别往上报**；往 1.4 报水位时，直接用它答"人少干了哪件事、还剩哪件事"。
> 🛑 **每条都只是"这个维度的一种做法"**：同一维换个场景就该换做法，**照着往下挑 = 又是同一套方案**。挑之前先问：本场景的症结是①②③④里的哪一种病，这条是不是冲着那种病去的？对不上就回第四节变，别硬套。
> 📌 **每维至少要看两条不同形态的条目**：一条"信息摆法"，一条"人机分工"或"形态替换"。只看一条，等于把维度又降回举措。

### 对应 1 · 结果易感知

| 参考做法 | 档位 | 省哪份力 | 适用 / 慎用 |
| :--- | :--- | :---: | :--- |
| 三件事齐不齐：整体状况 / 本轮结论 / 待办优先级 | 优化 | 找 | 有结论但缺"先做哪个"时 |
| 顶部结论条：今天有几件事需要你判断，按轻重排好 | 优化 | 找 | 事件量大的场景 |
| 列表顶部概览卡：待研判多少、高危多少、和昨天比怎么样，先给全貌 | 优化 | 找 | 告警列表页，量大时最有用 |
| 事件卡片三段式：发生了什么、影响谁、建议怎么做 | 优化 | 判断 | 单条告警信息不全时 |
| 默认视图只给"待研判"，已闭环的折叠 | 创新｜还得出力：判断已闭环的要不要回看 | 找 | 有明确闭环流程的产品 |
| 结论带置信度：高置信直接给处置建议，中置信标"建议复核"，低置信只做提示 | 创新｜还得出力：中低置信仍要自己判 | 判断 | 误判代价高的场景 |
| 高置信事件自动闭环，人只抽检；抽检发现问题再回退 | 变革｜还得出力：抽检发现问题要退得回去 | 判断 | 误报率已经压得很低时 |

### 对应 2 · 结果可验证

| 参考做法 | 档位 | 省哪份力 | 适用 / 慎用 |
| :--- | :--- | :---: | :--- |
| 结论旁挂证据：命中规则、原始日志片段、相关实体 | 优化 | 读 | 全类通用 |
| 每条证据标注它支持或排除哪个原因 | 优化 | 判断 | 原因有多种可能时 |
| 证据串成时间线，按发生顺序讲一遍 | 创新｜还得出力：自己把时间线读成因果 | 判断 | 有多步行为的攻击 |
| 标出证据是否同源（同一条规则派生的只算一条） | 创新｜还得出力：判断剩下几条够不够 | 判断 | 证据条数多、来源单一 |
| 也能看"为什么没报"：把反证摆出来 | 创新｜还得出力：判断反证够不够 | 判断 | 用户常质疑漏报的场景 |
| 说清"还差什么才能定"：把确认成本摆出来 | 创新｜还得出力：按提示去补那一条 | 判断 | 结论只能到"疑似"时 |

### 对应 3 · 信息主次区分明显

| 参考做法 | 档位 | 省哪份力 | 适用 / 慎用 |
| :--- | :--- | :---: | :--- |
| 同一实体、同一规则、时间窗内合并成一条事件 | 优化 | 重复 | 告警量大时最值 |
| 按影响面和置信度分级，低价值的自动折叠 | 优化 | 判断 | 有分级依据才可信，乱分级反而更乱 |
| 默认按"需要我判的"组织视图，而不是按数据源组织 | 优化~创新｜还得出力：判断被折叠掉的有没有漏 | 找 | 多数据源并存时 |
| 视觉重心跟风险走：高危占更大的位置，不是只加个红标签 | 优化~创新｜还得出力：确认重心没被别的元素抢走 | 找 | 一屏信息多、平铺时 |
| 把"被自动忽略的"也摆出来，可查可申诉 | 创新｜还得出力：偶尔翻一下漏没漏 | 判断 | 降噪做得越狠，这条越必要 |

### 对应 4 · 研判旅程顺畅

| 参考做法 | 档位 | 省哪份力 | 适用 / 慎用 |
| :--- | :--- | :---: | :--- |
| 就地从列表展开到日志、到处置，不跳页 | 优化 | 找 | 全类通用 |
| 筛选条件、时间窗跟人走，换页不丢 | 优化 | 重复 | 多页联查的场景 |
| 结论就地落：标记、转工单、加备注 | 优化 | 返工 | 有处置流程的产品 |
| 复核走和首次研判同一条路，不重来一遍 | 优化~创新｜还得出力：判断复核结论是否推翻原判 | 重复 | 有复核环节的团队 |
| 交接时带上已研判结论和待确认点 | 创新｜还得出力：判断交接信息够不够 | 重复 | 多人轮班、跨团队复核时 |

### 对应 5 · 可读性强

| 参考做法 | 档位 | 省哪份力 | 适用 / 慎用 |
| :--- | :--- | :---: | :--- |
| 结论前置成一句，后面跟三个点：谁、做了什么、影响什么 | 优化 | 读 | 全类通用 |
| 分组归类替代一长串平铺字段，组内再按重要性排 | 优化 | 读 | 字段多、信息密度高时 |
| 该用图的地方用图：关系、分布、时序交给可视化，文字只留判断和结论 | 优化 | 读 | 除了数值还要看结构时 |
| 原始日志里把关键字段高亮，别让人逐行找 | 优化 | 读 | 日志类证据 |
| 证据按时间或因果排成链，标出哪一环是判定依据 | 创新｜还得出力：自己确认哪一环说了算 | 判断 | 多步行为、多条证据时 |
| 长文本先给摘要，点开再看全文 | 优化 | 读 | 报告、情报类内容 |
| 关键数字给对比基线（失败率 92%，平时 2%） | 优化 | 判断 | 单看数字没感觉的场景 |
| 界面轻量：一屏只留这一轮要判的，次要信息收进二级 | 优化 | 读 | 信息长期堆叠时 |

### 五维之外 · 跨会话沉淀（不参与五维扫描，需要时单列突破点）

> 原「判过的能留下」移出五维：它跨会话、跨单次研判，不是这一屏的体验质量。但确实是净增量来源——遇到"研判量大、结论稳定"的需求，作为独立突破点提，**别混进上面五维当维度用**。

| 参考做法 | 档位 | 省哪份力 | 适用 / 慎用 |
| :--- | :--- | :---: | :--- |
| 研判记录可查可搜：谁、依据什么、判成什么 | 优化 | 找 | 多人轮班的团队 |
| 相似事件推荐：这类告警上次怎么判的 | 创新｜还得出力：判断这次和上次是不是同一回事 | 判断 | 历史积累足够多时 |
| 结论回写规则：确认误报的，一键变成抑制条件 | 创新~变革｜还得出力：确认抑制不会把真攻击一起压掉 | 返工 | 误报反复出现的场景 |
| 研判经验自动固化成检测 / 抑制规则，系统自己迭代，人只审规则 | 变革｜还得出力：审规则、担规则的责任 | 重复 | 研判量大、结论稳定的场景 |

### 全类通用 · 具象化（把抽象变成看得见的）

| 参考做法 | 档位 | 省哪份力 | 适用 / 慎用 |
| :--- | :--- | :---: | :--- |
| 研判 = 法庭：结论、证据、反证三样摆齐 | 创新｜还得出力：把三样摆全并下判断 | 判断 | 结论容易引起争议的场景 |
| 一次攻击 = 一条故事线：从哪进来、做了什么、影响了谁 | 创新｜还得出力：自己把步骤连起来核一遍 | 判断 | 多步攻击、跨实体关联时 |
| 一堆告警 = 分诊台：先分轻重，再送不同的人 | 优化~创新｜还得出力：定分级标准 | 找 | 告警量大、多人分工的团队 |
| 分析 = 关系图：人、资产、行为之间的连线 | 创新｜还得出力：自己从连线里读关系 | 判断 | 关系比数值更重要时 |
| 研判结论 = 一页摘要 + 附卷：主结论一页看完，证据作为附件逐层展开 | 创新｜还得出力：判断摘要够不够用 | 读 | 结论和证据都很长时 |

> 🛑 **具象化不是画得花哨**：形态要跟用户脑子里那件事的过程对得上；对不上，就只是装饰。

## 七、怎么用（三步）

> 📐 **扫描粒度：场景 / 页面 / 任务，不是"需求"**。
> 一个需求里可能有告警列表、事件详情、日志查询、威胁狩猎几个页面，**逐个场景判断**，一个需求可以同时命中多类经验。

> 🧩 **原则不是每个页面的验收单**：一个页面通常只承接其中两三条，剩下交给链路上的其他页面。判断依据不是"这是什么页面"，而是"它在链路上承担哪一段"。

| 链路段 | 主要维度 |
| :--- | :--- |
| 发现 / 浏览（如告警列表） | 结果易感知 + 信息主次区分明显 |
| 查证 / 研判（如告警详情） | 结果可验证 + 可读性强 + 研判旅程顺畅 |
| 复核 / 交接 | 研判旅程顺畅 |
| 沉淀 / 复盘 | 五维不覆盖，走「跨会话沉淀」单列 |

> 反查用：哪一维在所有页面上都没人承接，说明流程缺了一段，不是页面没做好。

1. **先问代价**：这块界面上下的是什么判断，判错了是漏还是误？漏判为主 → 第 2、3 条是主角；误判为主 → 第 1、2 条更关键；处置或交接容易跑偏 → 第 4 条。
2. **逐条扫，定症结**：用扫描问句一条条问，记到具体症结（①②③④），别只写"信息太多"。
3. **变出做法，再对照**：拿症结对照第四节的七处地方，变出几条结构不同的做法；想完再看第六节，缺的补、重的删。还原成一句"让人……"，和入口 1 的结果**合并去重**，回到 1.3 第 3 步分档。

> ⚠️ 只走入口 1 的时候，第 1 条（结果易感知）和第 5 条（可读性强）几乎必然被漏——目标里很少会写"先给结论""别让我通读"，但这两条恰恰最耗人。

## 八、扫描示例：告警降噪与研判提效

> 示例只演示扫法，场景细节以实际需求为准。

| 维度 | 扫到的答案 | 症结 | 目标里有没有提 | 转成的突破点 |
| :--- | :--- | :---: | :---: | :--- |
| 结果易感知 | 首页是一堆趋势图，人自己找哪里不对；也没有"本轮结论" | ①② | 没提 | 让人一进来就拿到全貌 + 本轮结论 + 先处理哪几条 |
| 结果可验证 | 详情只有一句"命中规则 X"，日志要跳去另一个系统查 | ①② | 提了（研判提效） | 让人在原地顺着证据走完一次验证 |
| **信息主次区分明显** | 同一条告警一天报几百次；高危低危平铺 | ①② | **提了（降噪）** | 让重复的自动合并，高危占住视线 |
| 研判旅程顺畅 | 判完切到工单系统再写一遍 | ②③ | 没提 | 让人判完就地落结论，不用二次搬 |
| 可读性强 | 研判页是一大段系统结论 + 全量日志，关键几行靠人自己摘 | ①② | 没提 | 让人扫一眼就抓住关键几行 |

结论：目标只覆盖了「降噪」和一部分「研判提效」；「易感知」「可验证」「主次」「旅程」「可读」都是入口 2 补的。

## 九、待补

- **四类初稿已齐**：①配置运维 ②运营分析 ③排障闭环 ④价值感知。
- **五维改造后的验证（新增，未跑）**：拿两个不同的运营分析需求（如告警降噪 vs 威胁狩猎）各跑一遍，**扫出的举措应当不一样**。若两份还是同一套（结论前置 + 证据挂旁 + 聚合去重 + 高亮），说明维度仍没起到发散作用——回第四节改变维表，**不要往第六节加做法**。
- **待演练验证**：拿真实运营分析需求跑，扫不出目标之外的东西，就改维度或改症结。
- **参考解法可长，但不追求穷举**：遇到新做法补进对应维度下，标档位、省哪份力、适用 / 慎用；**补的时候必须写清它冲着哪种症结**，否则它只是又一条通用举措。
