## <a id="p1"></a>一、需求类型认知

> 🔗 **类型识别与边界判定**（是否属于 Type-07、与相邻类型的区别）已**统一收敛到门户** → [类型识别判据与边界](../2.2-标杆案例库.md)。**本分册不再重复该内容。**

### 1.1 这是什么类型 / 解决什么问题

* **一句话定义**：以「任务」为主键，把分散的检测/扫描/巡检能力编排成一次**可周期调度、可复用、可追溯多轮历史**的作业，并通过任务清单持续暴露执行态与失败面。
* **它解决什么问题**：让"对一批对象施加一次检测动作"这件事**有载体、有归档、有追溯**。

### 1.2 产品形态谱系

| 维度 | 谱系 |
| :--- | :--- |
| **任务量级** | 十几条（人工逐个关注）～ 数千条（需批量与检索）→ **直接决定呈现架构选型** |
| **结果规模** | 每任务几条 ～ 每任务十几万条明细 → 决定是否需分页/虚拟滚动/异步导出 |
| **目标对象数** | 几十 ～ 百万级 → 决定目标选择控件形态 |
| **使用角色** | 一线运维（高频执行）/ 安全运营（看结果与趋势）/ 合规审计（查历史留痕） |
| **调度形态** | 一次性 / 周期（日/周/月）→ 影响状态机与并发约束 |

## <a id="p2"></a>二、设计要素清单（本类型的思考骨架）

> **什么是设计要素**：不是"页面类型"，而是**资深设计师在这个类型下必须思考和考量的维度**。
> 📌 本表是后续「案例 × 要素」差异性对比的**行基准**（对比产出见 [第三节经验库](#p3)）；某要素若无案例覆盖，在对比表中标注「⚠️ 未覆盖」，**严禁虚构填补**。

| 编号 | 设计要素 | 考量什么 | 自检问句 | 可选解法空间 |
| :---: | :--- | :--- | :--- | :--- |
| **E1** | 呈现架构 | 任务清单的承载容器与字段排布 | ① 字段是否对称？② 量级多少？③ 逐条细读还是扫视找异常？④ 一屏要能看几条？ | `卡片流`（字段不对称 / 量级小）／`高密度表格+抽屉`（字段规整 / 量级大）／`看板分组`（有明确流程阶段） |
| **E2** | 编排与新建 | 必填要素组织、大规模目标选择、调度定义 | ① 编排维度是否 ≥4？② 目标量级？③ 是否有多组织维度？④ 是否需"保存复用 + 立即执行"双出口？⑤ 是否有可复用内容库？ | `弹窗向导`（≤3 维度）／`整页向导`（≥4 维度含大列表）／`左树右选穿梭`（大规模 + 多组织维度） |
| **E3** | 调度与执行态 | 状态机设计、状态可视化、调度冲突与并发 | ① 状态是否 ≤5 种？② "完成"是否需细分有风险 / 无风险？③ 失败能否当场看原因？④ 周期任务能否手动重跑？⑤ 并发资源争抢如何处理？ | `小圆点+纯文本`（海量行降噪）／`语义色标签`（量级小需醒目）／`整卡底色`（失败须一眼锁定） |
| **E4** | 结果与证据 | 产出呈现、下钻取证、导出交付 | ① 结果量级？② 需哪些下钻维度？③ 筛选项是否 ≥6？④ 导出范围？⑤ 是否需列配置与排序？ | `概览条 + 明细表 + 就地抽屉`／`概览 + 图表 + 下钻表`／`分级视图` |
| **E5** | 历史与复测 | 多轮执行的组织、切换与对比 | ① 是否可重跑 / 周期？② 同主键还是各自独立？③ 如何切换、默认看哪轮？④ 是否需跨轮对比？ | `父任务主键 + 轮次下拉`／`子任务列表 + 独立详情`／`时间轴 + 差异对比` |
| **E6** | 批量管控与高危防呆 | 破坏性操作的确认机制与状态约束 | ① 哪些操作不可逆？② 是否回显对象名？③ 是否受状态机约束？④ 是否需影响面提示？⑤ 是否需审计留痕？ | `重确认弹窗 + 回显`（删除级）／`popconfirm 气泡`（重跑级）／`状态置灰`（约束级） |

> 💡 **候选补充要素（待确认，暂不编号）**：`执行资源与并发保护`（同时跑多少任务、限速防压垮、配额与调度冲突）／`权限与可见范围`（多租户 / 多业务线隔离）／`通知与订阅`（完成或失败如何触达负责人）

## <a id="p4"></a>四、案例导入蒸馏（证据层）

### 案例 A：XDR 检测任务（深信服可扩展威胁检测响应平台 风险管理 ➔ 检测任务）

#### 4.0 案例来源声明
* **物料来源**：线上系统实访（深信服 XDR 控制台，经本地反向代理访问），含列表页 / 新建向导 / 模板管理 / 详情页实拍与 DOM/样式级取证
* **蒸馏日期**：2026-09-17
* **案例独立性**：⚠️ **单产品**（深信服 XDR），归纳时不可直接等同于行业共性
* **覆盖局限（未拍到的深水区）**：检测中运行态与取消任务的交互、删除确认弹窗真实样式、失败原因弹窗结构、有数据的结果明细表、目标选择的数量上限与熔断、导出的大数据量异步策略、新建模板向导

#### 4.1 需求场景简述
* **解决什么问题**：平台要对 **14 万+ 资产**做漏洞体检，但"检测"这一**动作本身没有载体** —— 无法表达"用哪套模板、对哪些设备、扫哪些资产、多久扫一次"；结果无处归档追溯；执行失败静默无声。
* **Before ➔ After**：逐台手点 / 临时扫描、结果不落档、失败无从追查 ➔ 一次编排、周期复用、每轮沉淀为可追溯的多轮历史。

#### 4.2 业务上下文
* **所属类型**：Type-07 ｜ **产品线**：XDR 可扩展威胁检测响应平台 / 安全运营
* **管理对象特征**：14 万+ 资产；中低频变化；多数据源、多检测设备
* **目标角色与压力**：安全运营 / 资产运维；核心心智 = 怕漏扫、怕任务静默失败、怕结果无法交付与复盘

#### 4.3 页面族与信息架构

| 路由 | 页面 | 定位与职责 |
| :--- | :--- | :--- |
| `/xdr/fragile/detect_task` | 检测任务列表 | **枢纽页**，所有入口的起点与返回点 |
| `/xdr/fragile/detect_task/:parentID` | 检测任务详情 | 结果概览 + 明细证据 + 多轮历史 |
| `/xdr/fragile/create_detect_task` | 新增检测任务 | 整页编排向导 |
| `/xdr/fragile/detect_task_template` | 模板管理 | 检测内容的可复用资产库 |

* **导航与返回契约**：子页统一挂 `backBtn + breadList 面包屑 + backUrl` 返回列表，权限继承父级 `detectTask`。**任务类模块的导航是"树状进出"，不是平级跳转。**
* **主键传递规则**：详情页取 `parent_id ?? task_id`，承载同一任务族的多轮历史。

#### 4.4 按设计要素逐项做法

* 关键机制：单选切换**驱动控件形态**（按模板→单选下拉 / 从漏洞列表→多选标签输入框）

**▸ E3 调度与执行态**
* 状态枚举：`检测中 RUNNING` / `已检测 COMPLETED` / `检测失败 FAILED` / `未检测 INIT(-)`
* **COMPLETED 继续二分**：检出风险（danger）vs 未检出风险（normal）
* 列表用**修饰类**表达状态（正常不加类、异常加 `.failed`），驱动整卡底色
* **仅 FAILED** 时出现"失败原因"按钮 ➔ 失败原因弹窗
* 周期任务禁止手动重测：`isDetectable = 非 RUNNING && 非周期任务 && 非复测任务`
* ⚠️ **未覆盖**：并发/资源保护

* **复用组件**：`useRiskLevelTableColumn`、`useDataSourceTableColumn` —— 列级能力组件化
* 风险资产列自带 ⓘ 提示，可**就地打开资产详情抽屉**（不跳页）
* **导出 = 导出当前查询条件**（取 tableParams，而非仅 task_id）

**▸ E5 历史与复测**
* 详情页路由参数取 `parent_id ?? task_id` —— 复测子任务**指回父任务**，故"查看结果"永远打开**同一任务族的历史**
* 多轮时出现"检测历史"下拉：`{key: task_id, label: 格式化开始时间}`，**默认选中最新一轮**；仅 1 轮时不出现（`hasMultipleTask = subTasks.length > 1`）
* ⚠️ **未覆盖**：跨轮对比

**▸ E6 批量管控与高危防呆**
* 行内动作枚举：`ViewResult / CancelTask / ReScan / Delete / Start / Export`
* **删除**：confirm 弹窗且**回显任务名**；**重新检测**：popconfirm 气泡确认 + `disabled` 受 `isDetectable` 约束；**取消任务**：独立动作项；**重命名**：就地行内编辑
* ⚠️ **未覆盖**：影响面提示、审计留痕

#### 4.5 本案例的贡献与局限
* **贡献**：完整呈现了「任务族页面枢纽 + 五要素编排 + 三栏穿梭选目标 + 状态机 + 多轮历史主键」这一整套骨架，并提供了全部 Token 硬指标
* **局限**：单产品；执行中/失败/导出等深水区未覆盖；「执行资源与并发保护」要素完全缺失
