3. 核心体验改进目标

  • 多源整理：四类来源分散整理（不同入口、不同口径）➔ 统一入池、一次识别。可观察判据：任一首期来源结果到达或文件导入完成后即形成服务器或终端资产，通用字段完整率 ≥ 95%。
  • 身份连续性：人工比对（易重复、易错归）➔ 规则化归并、连续可追溯。可观察判据：同一 Agent 标识的资产 IP 变化后，平台仍引用同一内部资产标识，并更新当前 IP、保留历史 IP。
  • 台账维护：字段缺失、口径不一 ➔ 完整字段 + 与 WEB 应用资产同口径的就地查看与维护。可观察判据：服务器 / 终端可获取全部通用字段与专属字段；10 万级资产可查询、可查看。

🚫 本期不承诺：识别与入库失败的状态机、重试与幂等；风险数量 / 摘要 / 跳转；第三方资产平台与 CMDB 自动同步；影子资产、主机漏洞、主动渗透与风险处置；国际化与 NFV。以上不派生为前台能力。

Part2　需求解决方案全景

6. 设计决策经验匹配与采纳

6.1 需求类型分析

  • 需求定性：配置运维 | 资产管理台账（Type-01）。判据：主键是实体，对象长期存在并带台账属性，需按类型批量维护且有生命周期。
  • 业务属性与严肃度：企业统一资产治理，中等严肃度。资产是下游安全运营的引用基础，字段口径要求稳定准确，但单条操作多为可逆维护。
  • 色彩基调：现代扁平 / 高效规整。超浅底 #F7F9FC 划分区域、卡片白底、去框线化、线条 1px；状态用"浅底 + 深字 + 浅边框"三元组；只有品牌蓝主按钮，不用红色实心按钮。
  • 页面职责分工：台账页只管"查 / 筛 / 看 / 维护 / 盘点"；资产识别与入库是后台统一链路，本期不新增前台识别页。
