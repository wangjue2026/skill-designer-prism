# 织雨设计智脑：标准设计说明书模板 (Design Specification Template)

> 💡 **中枢定位**：
> 本文档是织雨在执行 **【方案系统设计主线】** 步骤 5 的核心交付物模板。
> 它是资深设计师在动工写代码前，向业务规划人员呈递的**“高维方案共识协议”**。
>
> 📄 **交付格式（强制）**：
> 设计说明书以 **单个自包含 HTML 文件** 交付（内联 CSS、无外部依赖），**可直接在浏览器打开或通过本地预览服务在线查看**，不再以纯 Markdown 文本交付。
> * **文件名建议**：`design-spec-[业务名].html`；
> * **视觉规范**：严格遵循 [`tokens-cheatsheet.md`](../../03-design-assets/tokens-cheatsheet.md)（页面底色 `#F7F9FC`、卡片 `#FFFFFF`、边框 `#E1E5EB`、品牌蓝 `#1C6EFF`、状态浅底深字三元组）；
> * **流程图**：第三章的旅程图使用 Mermaid 渲染（CDN 引入），保证在线查看时可缩放、可读；
> * **查看方式**：浏览器直接打开该 `.html` 即可；如需以 `http://` 在线地址查看，可在文件所在目录起本地服务（如 `python3 -m http.server`）后访问。
>
> 🛑 **强制规则**：输出本说明书后，Agent 必须停下来等待规划人员审阅确认，严禁未经确认直接跳到步骤 6 生成前端代码！

---

## 一、章节内容结构（内容骨架，六章固定）

HTML 只是交付形态，**内容仍须完整覆盖以下六章**（分别对应步骤 1~4 的推演产物）：

| 章节 | 标题 |
| :---: | :--- |
| 一 | 需求洞察与体验目标 |
| 二 | 业务定性与设计选型 |
| 三 | 优化后各场景任务旅程 |
| 四 | 页面布局结构与组件清单 |
| 五 | 关键界面布局与交互细节说明 |
| 六 | 页面体验与异常保护规则 |

> 📌 第一章的「体验目标」须按 [`1.2-体验目标.md`](../①需求理解与分析/1.2-体验目标.md) 的**务实版**规则推演：固定语序「产品改造动作 ➔ 用户操作变化 ➔ 解决历史痛点 ➔ 体验收益度量」，采用 A ➔ B 对比跨越、去口号化，并锚定主场景痛点旗帜（🚩 Sx-Py）；**不得写成笼统的“收益目标”**。
