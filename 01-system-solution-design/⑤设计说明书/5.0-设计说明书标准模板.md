# 织雨设计智脑：标准设计说明书模板 (Design Specification Template)

> 💡 **中枢定位**：
> 本文档是织雨在执行 **【方案系统设计主线】** 步骤 4 的核心交付物模板。
> 它是资深设计师在动工写代码前，向业务规划人员呈递的**“端到端最终解决方案全景共识协议”**。
>
> 🛑 **系统化整合铁律（拒绝碎片化与机械堆叠）**：
> 设计说明书绝不是把 1~3 步推演产物机械、孤零零地各放一块内容！
> 它必须是将每一步的信息（业务痛点、标杆经验、场景旅程、组件选型）**全面汇流、整理并结构化映射到最终的解决方案中**：
> 明确回答本次需求**最终包含哪几个页面、各页面的界面结构线框图如何、每个页面融合承载了哪些标杆设计经验、以及具体采用了哪些页面模板和 idux 真实组件与 Token 样式**。
>
> 📐 **排版顺序与表达核心铁律（防退化硬规则）**：
> 1. **两段式结构**：全篇固定为 **Part1 需求分析与思考（1~5 节）** + **Part2 需求解决方案全景（6~8 节）**，评审共识关卡作为末尾 `<div class="checkpoint">` 浮层，不设第九章。旧“五章”结构的说明书仍可被自检脚本识别，不做强制迁移。
> 2. **经验只在两处出现（去冗余）**：第 6.2 节「业务场景 → 经验匹配与承接突破点」用**单表穿透**（6 列，强制保留「自行设计补充」列）；**具体机制与采纳结论落在第 7 节每页的「设计经验与组件选型映射清单」里**。原「经验采纳明细」独立小节已取消——每页清单已说清"用了哪条、用在哪"，再单列一节属重复登记。
> 3. **第 7 节严格“先线框、后清单”**：每个分页面小节固定四段：`① 页面定位与核心任务 + 选用页面模板（各一行） ➔ ② 结构线框图 ➔ ③ 设计经验与组件选型映射清单（排在线框下方） ➔ ④ 设计批注 (wf-annotation)`；含可视化件的页面再追加第 ⑤ 段《可视化件声明》。**批注三行标题固定为「💡 为什么这样布局」「🧭 这页能做什么」「🛡️ 哪些做不了、拦下后怎么提示」，一行为一句大白话**；严禁再出现「架构定位与 Why 依据 / 业务动作落点 (CRUD 闭环) / 状态机与异常规则」这类需要专业人士翻译的黑话标题。**线框是审阅主体，必须排在映射表之前**；页面头部**只留这两行**，不写「承接突破点」「档位达成证据」「与草图的一致性」等解释性条目——用户看的是线框质量，不是推导过程。
> 4. **双轨制归因标注**：映射清单中，标杆复用必须使用 `<span class="tag-exp">EP-xx</span>`（绿底实线），标杆未覆盖的自研推导必须使用 `<span class="deriv">业务独立推导</span>`（灰底虚线），血统泾渭分明。
> 5. **EP 经验与真实 UI 文本彻底解耦**：线框图中的按钮、标签、表头文字必须是 **100% 干净真实的业务语言**，**严禁**在 UI 文案中写入 `(EP-xx)`（如禁止写 `立即执行 (EP-05)`），EP 编号只允许出现在代码注释、映射表与底部批注中。
> 6. **文风去 AI 套话与黑话**：拒绝“极速赋能”、“零心智负担”、“立体感知”等无物虚词，拒绝虚拟人设吹嘘；采用简约、清晰、克制的设计师直白表达与量化对比（如“30 分钟 ➔ 30 秒”、“首页管任务、详情管终端”）。
> 7. **模板借用规范**：若 [`01-page-types.md`](../../03-design-assets/page-templates/01-page-types.md) 暂无专属模板，严禁杜撰不存在的 template ID，必须借用相近模板并显式注明参考案例（如：`套头借用 page-table-overview + 自定义主从分栏，参考 XDR 模板管理案例`）。
> 8. **表单书写必须严格参考设计资产规范输出（左右结构铁律）**：所有线框图中的表单书写**必须严格参考设计资产规范 [`03-design-assets/components/design-form.md`](../../03-design-assets/components/design-form.md) 输出**。所有表单片段必须遵循**左右结构**（左文本标题 Label、右组件内容 Control），**严禁出现 Ant Design 默认的上标题下组件（Vertical）布局**（严禁在 Label 文本后使用 `<br/>` 断行堆叠表单项）。非必填项左侧必须留星号占位空间确保文字像素级垂直对齐。
> 9. **顶部概要只留四项、且不写状态**：方案制定者 / **产线（仅产线名）** / **需求定性（上层工作类型可多列：主角标「主」排在最前，其余标「条件命中」，再接具体需求类别）** / **需求输入（需求文件名）**。**多列只列真正扫过并出了突破点的类型，没扫的不写、不凑数；主角只能有一个**（判法见 1.3 第八节）。**禁止出现「当前状态」「协同状态」「⏳ 交付完成 / 待评审」等状态行与状态徽标**——进度只在文末 checkpoint 说一次；也去掉「面向对象」，产线不写模块路径。
> 10. **角色只写主次两个**：Part1 第 1 节用 `.role-grid` 卡片（**不用 `<ul>`**），固定 **2 张：主角色 1 + 次角色 1**，只判定"谁主用、谁被牵动"。**不列审计、旁观、领导等凑数角色**——角色多时合并进次角色，或只写主角色一张。
> 11. **编号体系不外泄**：症状编号 `Sx-Py`、原始需求号 `REQ-xxx` 一律不进正文（详见 1.1 第四节「编号体系」）。
> 12. **正文不写“写法说明”**：说明书是交付物，不是模板教学。**任何“本节回答什么 / 为什么这么排 / 规则是什么 / 与哪一步对应”的解释性段落一律不写进成品**——那些是生成时的规矩，属于本铁律区与各节结构约束，不属于读者要看的内容。读者只该看到**结论、表、图**。
> 13. **场景表固定四列**：`场景（编号. 名称）` / 主要角色 / 用户 Job / 现状卡点（**不再设「触发情境」列**——时机是场景内的细节，单列一列既占宽、又诱使按"什么时候发生"切场景）。编号与名称合并一列；痛点格用项目符号分行，**不写 `🚩` 前缀、不写 `REQ-xxx`**（详见 1.1 第四节「编号体系」）。**用户 Job 一栏写"这个场景要维护／交付的那份东西 + 覆盖的工作内容"（如：维护一份清晰可用的资产台账，含入库、分类、打标、出库），不写"从 A 到 B"的改善句——那是第 3 节体验目标的活，提前写进 Job 会把目标挤到比 Job 更小。场景按责任域切，A 的终态若是 B 的触发情境必须合并；成品场景数 2~5 条、名称不含阶段词，此项由自检第 1 项硬校验。**
> 14. **内容预算（超了就是没收敛）**：主场景 ≤5 行 · 体验目标 ≤5 条（每条一句，= 主场景数）· 突破点 ≤5 条 · 角色 2 张 · 每页映射清单 ≤8 行。**任何表都不许为"显得完整"加说明性列**（如「本方案取档」「落点页面」「备注」）；一列如果删掉以后读法不变，就是该删的列。
> 15. **不写方案取舍复盘**：说明书**不设**「方案取舍」「档位组合与授权记录」两节——这些留在 1.4 草图闸门的留档里，说明书只呈现选定结果对应的页面与组件。第 5 节只保留 **页面清单** 与 **草图** 两块。
> 16. **弹窗与提示条按组件规范画线框**：弹窗严格按 [`comp-modal.md`](../../03-design-assets/components/comp-modal.md)——标题栏 `48px`（标题 `16px/600`、左边距 `16px`、**无底部分割线**）、内容区左右 `32px`（上下不加 padding）、按钮栏 `56px`（**无顶部分割线**、按钮 `32px`/`14px`、间距 `8px`、**按钮组右对齐且主按钮在左、取消在右**）；提示条严格按 [`comp-alert.md`](../../03-design-assets/components/comp-alert.md)——**一律无边框**，普通条 `#F7F7F8`/`#6F7785`、告警条 `#FFFAF2`/`#A35F40`（图标 `16px`、与正文间距 `8px`）。**红色三元组 `#FFF1F0`/`#D9363E`/`#FFA39E` 不得用作 Alert 底色或边框**——comp-alert 只有普通与告警两档，没有红色档；标杆样例里出现的红底警示块属于偏离规范的样本，禁止照抄（逐条反例见 [`comp-modal.md`](../../03-design-assets/components/comp-modal.md) 与 [`comp-alert.md`](../../03-design-assets/components/comp-alert.md) 末节「反例」，与内部调优文档或外部截图冲突时一律以组件规范为准）。
> 17. **映射清单默认只露前 3 行**：每页映射清单超过 4 行时（即至少 2 行要收），第 4 行起加 `class="rows-extra"`，第 3 行后插入 `<tr class="rows-toggle-row">` 折叠按钮（模板已内置 CSS/JS，无需另写脚本）；只有 4 行的清单不折叠，直接全显。**折叠只是渲染，严禁删行、严禁把行搬出 `<tbody>`、严禁省略组件名与 Token 数值**——Step 6 的 Coding AI 按源码全量读取，折叠态不影响还原精度。
> 18. **线框必须贴合真实页面数据，不得沿用草图标准**：第 7 节线框图**禁止出现 `__` 之类占位符**，必须用一套**跨页自洽的真实示例数据**（对象名、数量、状态、时间、证据来源）填满；草图上为守"不编数字"而留空的量、以及**草图没展示全的字段与异常态**（长文本截断、空值、无权限、过期、超限降级），线框里要**尽量补全并显性表达**。示例数据的口径在第七节开头用一行声明（示例环境 + 快照时间 + 规模），**明确它是示例样本、不构成客户事实**。判据一句话：**草图守"结构级"可以留占位，线框守"落地级"必须给真值——两份精度必须拉开**；没值的线框等于把"放不放得下、会不会截断"的判断成本退回给评审人。
> 19. **说明书必须"完本自包含"，能脱离对话交给他人或其他工具编码**：除 Part1 与逐页线框外，第 7 节尾部必须补齐**六节编码契约**——① 交互逻辑与状态机（逐页：元素 / 触发 / 系统响应 / 状态变化 / 不可用边界 ＋ 前端状态字段 ＋ 页面与浮层关系）；② 数据口径与演示数据集（每个数字的定义与真源 ＋ 可整节替换的 mock 数据 ＋ 一致性铁律）；③ 组件、Token 与全局样式契约（尺寸栅格 / 颜色白名单 / 组件选型与禁止替换 / 动效）；④ 固定文案与状态词表（逐字照抄的责任边界句 ＋ 状态标签映射 ＋ 空态文案 ＋ 禁用词与格式）；⑤ 验收清单（页面级 / 交互异常级 / 账实边界 ＋ 手工自测步骤）；⑥ 实现边界（不做清单 ＋ 只读约束 ＋ 禁令）。**判据：把文件单独发给一个没参与对话的人或另一个 AI，他不问一句就能做出同款页面。** 缺任一节即判"未完本"，不得标记交付。
> 🛡️ **交付前自检铁律（强制 · 未过不得汇报）**：
> 出稿后**必须**运行 `bash tools/gate-sp.sh _output/<业务名>/design-spec-<业务名>.html`——SP-S/A/W/C/D 五组全过，方可进入「🚦 人机共识确认闸门」。门禁编号与判据见 [`准出门禁总表.md`](../../04-workflows-and-cases/准出门禁总表.md)；单跑 `design-spec-selfcheck.sh`（11 项）只覆盖 SP-A / SP-W，**不算过闸门**。

## 一、章节内容结构（两段式骨架：Part1 思考 / Part2 方案）

```mermaid
graph TD
  subgraph Input ["上游推演要素输入 (Steps 1~2)"]
    S1["Step 1: 角色痛点 P1..Pn / JTBD / 务实体验目标"]
    S2["Step 2: 标杆经验 EP-xx / 样式规则 / 专家范式 / 自研补充"]
  end

  subgraph Integration ["设计说明书核心主体：最终解决方案示意与分页面深度推导"]
    C1["Part1-1 目标用户与核心任务 (卡片)"]
    C2["Part1-2 主场景清单与现状痛点"]
    C3["Part1-3~4 体验目标 / 体验突破点思考"]
    C4["Part1-5 草图发散 (方案取舍 + 页面清单 + 草图)"]
    C5["Part2-6~7 经验匹配 / 逐页线框 / 异常保护"]
  end

  Input --> C1 --> C2 --> C3 --> C4 --> C5
```

```html
      rows.forEach(function (r) { r.style.display = expanded ? 'none' : 'table-row'; });
      btn.setAttribute('aria-expanded', String(!expanded));
      btn.textContent = expanded ? ('展开其余 ' + rows.length + ' 行') : ('收起，只看前 3 行');
    });
  });
</script>
</body>
</html>
```

## 三、生成与交付前自检铁律 (Self-Check Gateways)

为确保产出的设计说明书达到**资深设计师基准水平**，全流程必须严格遵守以下工程纪律与机器自检闸门：

### 1. 单文件自包含与资产合规
* **纯自包含**：CSS 必须内嵌在 HTML 的 `<style>` 中，严禁外链本地 CSS 文件；除 Mermaid CDN 脚本外不依赖任何第三方运行时，离线双击即可完整浏览。
* **零随机值与色值合规**：全篇所有色值必须取自 [`tokens-cheatsheet.md`](../../03-design-assets/tokens-cheatsheet.md) 白名单，严禁 AI 自由发挥发明新色值（如 `#15803D`, `#1E40AF` 均属违规，必须使用规范中的 `#12A679`, `#1C6EFF`）。
* **按钮用色绝对安全带**：全系统仅允许品牌蓝主按钮（<code>#1C6EFF</code>）与普通描边按钮，**绝对禁止红色实心按钮**。

### 2. SP 准出闸门（11 项机检是其中一段）
出稿后、向业务规划人员汇报前，**必须在终端执行准出闸门**：
```bash
bash tools/gate-sp.sh _output/<业务名>/design-spec-<业务名>.html
# 串行两段，任一 FAIL 即整体 FAIL：
#   node tools/gate.js sp                 → SP-S 结构规模 / SP-W-04 数据完整 / SP-C 内容一致 / SP-D 六节契约
#   bash tools/design-spec-selfcheck.sh   → SP-A 资产真实性 / SP-W 线框规范（下表 11 项）
# 退出码 0 = SP-S/A/W/C/D 全绿（方可进入共识确认）；退出码 1 = 按报出编号退回
```
> ⚠️ 下表 11 项由 `design-spec-selfcheck.sh` 承载，**只覆盖 `SP-A` / `SP-W`**；单跑 11/11 不等于过 SP，`SP-C` 与 `SP-D` 必须由 `gate.js sp` 跑到。

| # | 检查项 | 判定标准 | 拦截的历史退化 |
| :---: | :--- | :--- | :--- |
| **1** | **结构完整性** | Part1 / Part2 两段式（2 个 `h2.part`）齐备，且包含具体的分页面小节（第 7 节 `h4 7.x`）。**另校验场景切分：主场景 2~5 条，场景名不含「定位 / 追踪 / 查看 / 结果 / 下发 / 配置 / 新建」等阶段词**（串行旅程必须合并，判据见 1.1）。旧五章结构亦可识别。 | 章节缺失或擅自增设 / 场景按动作阶段切碎 |

| **5** | **按钮用色铁律** | 严格扫描不存在“危险型”按钮文本，不存在任何红色背景实心按钮。 | 红色警示按钮误用 |

### 3. 未通过自检时的自愈与处理流程
* **严禁带病汇报**：`gate-sp.sh` 未达 SP 五组全绿之前（含 11/11 未满），**严禁进入人机共识确认关卡**，严禁向规划人员汇报“已完成”，更严禁偷跑 Step 6 生成 Demo 代码。
* **按项靶向修复**：
