> **本清单定位**：这是从「信息密度」这一交互矛盾自顶向下推导出的**前置客观思考母尺**，不依赖任何特定产品的已有实现。面对任何需求，均以本表决策场景与分析维度为统一准绳逐条读数。

| 决策场景 | 分析维度 | 候选答案空间 |
| :--- | :--- | :--- |
| ① 上千条列表该用**分页、虚拟滚动还是"加载更多"**？ | 量级、是否需定位到具体行、是否需跨页比对、列表是否内嵌于表单 | 分页 / 虚拟滚动 / 加载更多 / 固定高度局部滚动 / 前 N 条 + 加载更多 |

| ⑧ **卡片流 / 网格**该单列还是多列、一屏承载多少张？ | 字段对称度、卡片内容宽度需求、量级、可用空间 | 单列 / 两列 / 三列 / 自适应网格 |

## 二、设计经验库 ★ 本决策域最终沉淀物（按决策场景归纳）

### 2.1 设计经验 (EP-01 ~ EP-11)

> 编号 `EP-xx` 按决策场景 `①~⑪` 顺序编（本决策域内独立序号，不跨域连编）；**跨域引用**（如《设计说明书》）时加域前缀简写，写作 `D03-EP01`。

| 编号 | 归属决策场景 | 设计经验项（统一基线 / 推荐体验 / 形态分流 / 例外场景） | 备注（特殊场景 / 体验权衡 / 避坑红线） | 来源 |
| :---: | :--- | :--- | :--- | :---: |
| **EP-01** | 【D-03 ① 上千条列表该用分页、虚拟滚动还是"加载更多"？】 | **【统一基线】** 台账 / 检索类列表**一律用分页**承载，页脚固定为「共 N 项 ＋ 页码 ＋ 每页条数切换 ＋ 前往第 N 页」；量级从**个位到 92 万**均不分流虚拟滚动，**也不因量小而改用"加载更多"** `` `XDR · 日志检索 ▸ D-03 ①` `` ・ `` `SASE · 应用管理 ▸ D-03 ①` `` ・ `` `aES · 病毒防护 ▸ D-03 ①` ``。<br><br>**【形态分流】**<br>① **台账 / 检索列表** → 分页，页大小分档 **XDR 10 / 20（运营规则 10）；SASE 20；aES 50** `` `XDR · 运营规则 ▸ D-03 ①` ``；<br>② **列表内嵌于表单 / 详情（局部列表）** 且量级小（不过百）→ **固定高度局部滚动**：容器内滚动、不撑高表单，底部操作栏固定 `` `aTrust · 用户与角色·编辑用户（授权设置） ▸ D-03 ①` ``。<br><br>**【例外场景】** 结果集超出引擎可检索上限 → 在分页之上叠加**显式护栏文案**「共 17,936 项，**仅展示前 10,000 条**匹配结果」 `` `aES · 日志调查 ▸ D-03 ①` ``。<br><br>**【零例声明】** 三产线台账**未见虚拟滚动，也未见"加载更多"**（"加载更多"分支已移入 **EQ-01** 待复核）。 | **【选型依据】** 台账需**精确定位到具体行并可回到原位置**，分页天然满足；无限滚动会丢失位置感。<br>**【形状判据】** 独立台账 vs 表单内局部列表是分流分水岭：前者用分页、后者用固定高度局部滚动。<br>**【阈值】** 量级无分水岭（10⁰~10⁶ 通用）；局部滚动适用"不过百"；页大小档 `10 / 20 / 50`；超大结果护栏 `10,000`。 | 🤖 推理 ＋ 👤 人工 |
| **EP-02** | 【D-03 ② 列 / 字段很多时该冻结哪几列、是否横向滚动？】 | **【统一基线】** 列超出视口 → **横向滚动 ＋ 冻结首末列**：**列首冻结勾选、序号、对象名称 / 编号等身份识别字段**；**列尾冻结操作列**；**中间业务数据列原则上不冻结**，靠横向滚动承载 `` `SASE · 用户管理 ▸ D-03 ②` `` ・ `` `SASE · 应用管理 ▸ D-03 ②` `` ・ `` `XDR · 智能对抗 ▸ D-03 ②` `` ・ `` `aES · 安全策略 ▸ D-03 ②` ``。<br><br>**【避坑红线】** **冻结列的总宽度应适当控制**，避免固定区域挤压主要数据 —— 冻结集合按需收敛：aES 安全策略仅冻结「勾选列（左）＋ 操作列（右）」，身份列（策略名称）仍随中间列滚动 `` `aES · 安全策略 ▸ D-03 ②` ``。 | **【选型依据】** 对象主标识与行内操作是滚动中最不该丢失的两端，故冻结首末；中间业务列冻结越多，横向可视数据越少。<br>**【实测】** SASE 以 `fixed-left-line ＋ fixed-right-line` 明确划出左右冻结边界；XDR/aES 以 `*-table-fix-start / -fix-end` 类标记冻结单元格。<br>**【触发条件】** aES 安全策略（12 列）已检出左右冻结，说明"列超视口即冻结首末"为普遍机制（推翻了旧"aES 宽表零冻结"的存疑）。 | 🤖 推理 ＋ 👤 人工 |
| **EP-03** | 【D-03 ③ 对象的信息什么时候该平铺、分组还是拆局部 Tab？】 | **【形态分流】**<br>① **同页平铺** —— 满足以下多条时优先：信息主要为**基础描述字段**、结构简单、**字段数较少（如 30 以内）**、用户需**快速浏览或同时比较多个字段**、模块间**关联强**（拆分增加切换与记忆成本）、属**同一阅读任务** `` `aES · 任务详情 ▸ D-03 ③` ``。平铺可用页面内分组，但**避免过度切分**（分组基于明确业务语义如"基础信息 / 状态信息 / 配置参数"，每组含若干相关字段，不出现只有一两个字段的碎片分组）；<br>② **局部 Tab** —— 同一对象下存在**多个相对独立的信息面**、用户通常**不同时阅读**、各面**内容结构或交互方式差异明显**（基础描述 / 左树右表 / 图表 / 日志）、继续平铺会使**页面过长**、模块间**无需频繁对照** → 拆 Tab `` `SASE · 敏感对象定义 ▸ D-03 ③` ``。Tab 使用规则：**数量克制（通常 3 个左右）**、每 Tab 代表清晰稳定的信息主题、**标题直接表达内容**（禁用"其他 / 更多"）、Tab 内可再用分组 / 平铺 / 折叠。 | **【选型依据】** 平铺省一次切换、利于同屏比对；Tab 降单屏纵向长度，但增加切换与记忆成本。<br>**【避坑红线】** 若用户需**同时比较两个模块或频繁来回切换**，慎用 Tab（改同页分组 / 左右分栏 / 上下布局）。<br>**【阈值（专家经验）】** 字段数 ≲30 且属同一阅读任务 → 平铺；多信息面且相互独立 → Tab。**本域产线样本各仅 1 例，判据主据专家经验，标 ⚠️ 待多产线验证。** | 🤖 推理 ＋ 👤 人工 |
| **EP-04** | 【D-03 ④ 概览与明细何时该上下切分，何时左右分屏？】 | **【形态分流】**<br>① **总分结构、顶部概览 ＋ 下方明细** → **默认上下布局** `` `SASE · 上网行为分析 ▸ D-03 ④` `` ・ `` `XDR · 资产体检 ▸ D-03 ④` `` ・ `` `aES · 任务中心 ▸ D-03 ④` ``；<br>② **多分类的从属关系、需切换对象查看详情**（左清单 ＋ 右明细，两级**各自独立滚动与筛选**）→ **左右分屏** `` `XDR · 指纹清点 ▸ D-03 ④` ``。 | **【选型依据】** 左右分屏用横向空间换"对象 ↔ 明细"的切换效率，仅在"左清单是多分类、需逐个点开看详情"时值得；纯指标概览用上下卡片更省宽度。<br>**【阈值】** 概览为少量指标（≤6 格）→ 上下；左清单为多分类从属 + 需切换对象看详情 → 左右。 | 🤖 推理 ＋ 👤 人工 |
| **EP-05** | 【D-03 ⑤ 单元格内的多值 / 长文本该截断悬浮、就地展开还是计数下钻？】 | **【统一基线】** 超长单元格文本**一律截断、不换行撑高行**（行高固定是整表扫视节奏的前提） `` `SASE · 应用管理 ▸ D-03 ⑤` `` ・ `` `aES · 病毒防护 / 文件隔离区 ▸ D-03 ⑤` `` ・ `` `XDR · 高风险威胁 / 安全事件处理 ▸ D-03 ⑤` ``。<br><br>**【形态分流】**<br>① **单个长文本** → 截断 ＋ 省略号 `…`，**悬浮后展示完整文本** `` `SASE · 应用管理 ▸ D-03 ⑤` ``；<br>② **多个简单数据** → 空间不足时展示部分数据 ＋ **+N**（N＝未展示数量），悬浮后展示全部：**标签类**以「标签组 ＋ `+N`」收纳 `` `aES · 安全事件 ▸ D-03 ⑤` ``；**纯文本对象类**以「顿号分隔 ＋ `+N`」收纳（效果雷同）；<br>③ **多条复杂数据**（每条含多个字段 / 复杂结构 / 操作）→ 单元格**只展示汇总数量**，**点击后下钻**查看明细 `` `aES · 任务中心 ▸ D-03 ⑤` ``。 | **【选型依据】** 行高固定（`40px`）不被个别长值破坏，保证整表扫视节奏；数据复杂度决定"看全文 / 看全量 / 看明细"的下一步动作。<br>**【阈值】** 单值长度超出列宽即截断；多简单值用 `+N` 收纳；多复杂值用"数量 + 下钻"。<br>**【覆盖局限】** 分支 ①②③ 均有产线样本（② 纯文本逗号变体与标签变体同法）。 | 🤖 推理 ＋ 👤 人工 |

### 场景 ⑪ 次要 / 高级字段该平铺还是默认折叠，何时应该折叠？

> 📐 本场景原有 35 页**未见**高级设置折叠；本轮补采 **aTrust 新增用户**，取到「更多用户属性」默认折叠样本，本域该空白已补齐。

| 分流分支 / 取值档 | 产线 | 模块 | 配置项规模 | 结构骨架（切分 ➔ 位次） | 承载形态与关键规格 | 该样本的独有取舍与实测交互 |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **⑪A 高级设置默认收起** | aTrust | 用户与角色 · 新增用户 | 配置项 >10，首屏收敛至 ≤8 | `[表单：核心配置项（首屏）] ➔ [「更多用户属性」折叠区（默认收起，点击展开）] ➔ [底部 保存/取消]` | **高级设置默认收起**：非核心 / 低频 / 有默认行为且不配也能完成主任务的配置项收敛其中；已填值保留、展开状态可不记忆 | `⚠️ 本轮未复采`（存量样本，源自 D-02 取证）；低频 ≠ 低风险，高风险配置不得仅因低频隐藏 |
| **⑪B 平铺不折叠** | SASE / aES / XDR | 高级配置 / 安全策略新增 / 运营规则新增 | 字段少 | `[表单字段平铺（无折叠区）]` | 字段少 → 全部平铺，不引入折叠 | `⚠️ 本轮未复采`；不满足收敛条件（配置项 ≤10）时平铺 |

* **共用 Why**：高级设置用于降低首屏复杂度，而非隐藏高频或高风险项；三条件（非必填/有默认 · 非核心 · 不配也能完成主任务）同时满足才收敛。
* **蒸馏日期 / 覆盖局限**：2026-10-10 ｜ ⑪A 为存量样本（aTrust 新增用户）；其余三产线表单字段少，均平铺。
