# 通用设计决策 · 索引与决策域

> 💡 **横向库定位**：沉淀**跨需求类型复用**的通用设计决策。本文件与 [`需求大类设计决策/00-总览与类型定性.md`](../需求大类设计决策/00-总览与类型定性.md) 是一对中枢：
> * **需求大类库**：按「需求类型」分册，回答"**这类需求，标杆怎么做**"（候选经验池）；
> * **本库**：按「决策域」归档，回答"**这个设计点，什么条件下该选哪个**"（裁决尺 + 兜底网）。
>
> 🧭 **一条决策 = 一个可判定的场景**——决策域只是目录，真正可检索、可裁决的单位是决策场景（域内记作 `① ② …`）。
>
> 🔗 上游调度见 [`../2.0-设计决策总览与调度.md`](../2.0-设计决策总览与调度.md)。
> 🧩 **与设计资产的分工**：本库只沉淀「**判断 + 蒸馏证据**」，不挂资产归口；`patterns / components / tokens` 等规格由《设计说明书》在输出层引用 [`03-design-assets/`](../../../03-design-assets/) 合成。

## 一、决策域全景（D-01 ~ D-10）

> 📌 **决策域 ≠ 需求类型**：需求类型回答"这是什么业务"（对象管理？配置同步？排障？）；决策域回答"在这个设计点上该选哪种"。
> 同一个决策域会**横跨多个需求类型**——例如"承载选型"既出现在对象管理台账，也出现在任务清单、事件列表、策略清单里。这正是本库"通用"的含义。
>
> 🪜 **D-01 是前置上层**：先由它定整体信息架构，再进入 D-02~D-10 的局部承载与交互判断。

| 编号 | 决策域 | 解决什么核心问题（本质 / 边界） | 常见的真实设计场景举例 |
| :---: | :--- | :--- | :--- |
| **D-01** | 信息架构 | **这个需求有多少页面、信息层级如何**——采用一级菜单 / 子页面 / 下钻页面的形态；每个能力 / 配置挂到哪一层、导航层级如何组织；每一层的次级结构用什么形态呈现<br><br>**边界**：只回答"信息架构怎么搭（页面与能力归属到哪一层、层内次级结构用什么形态）"，到定出页面与导航层级为止，不含每块内容的承载壳选型 | • 这个需求有多少页面、信息层级如何？（单页聚合 / 多页拆分 / 主从同屏 / 分层）<br>• 每个能力 / 配置该挂到哪一层？（一级菜单 / 二级菜单 / 菜单下 Tab / 页内轻入口）<br>• 模块内部的次级结构该用什么形态？（顶部 Tab / 左侧子导航 / 页内分段） |
| **D-02** | 信息承载与容器选型 | 为**一块内容**（台账 / 表单 / 详情 / 一组配置项）选定**物理承载形态**（用哪个壳），让信息量级、字段特征与上下文保留互相匹配<br><br>**边界**：只回答"一块内容用哪个壳装"，到选定承载壳为止，不含壳内部的信息排布 | • 资产 / 任务 / 事件台账：用高密表格、卡片流还是左树+表格？<br>• 对象新增 / 编辑：独立页、右侧抽屉、居中弹窗还是步骤条？<br>• 对象查看 / 详情：下钻详情页、侧滑抽屉还是弹窗？<br>• 检测任务 / 批量巡检台账：卡片流、表格还是左树+表格？<br>• 表格行额外信息 / 父子层级信息：就地展开还是另开详情容器？<br>• 表单 / 详情内的从属明细用什么容器？ |
| **D-03** | 信息密度与可读性 | 让**海量数据在有限视口内可扫视、可比对、可快速定位**，避免滚动与翻页打断阅读动线<br><br>**边界**：只回答"承载壳已定后，壳内数据在条数多 / 字段多时怎么排布与切分"，不含承载壳本身的选型 | • 上千条列表：分页、虚拟滚动还是"加载更多"？<br>• 列很多时：冻结哪几列（对象名 / 操作列）？<br>• 对象的信息：什么时候平铺、分组还是拆局部 Tab？<br>• 概览与明细：何时上下切分、何时左右分屏？<br>• 宽表：列设置自定义还是固定列集？<br>• 行高 / 密度：紧凑、默认还是宽松？<br>• 卡片流：单列还是多列网格？<br>• 指标单元格：纯数值，还是内嵌可视化（迷你趋势线 / 进度条 / 占比条）？<br>• 长表单：单页平铺、分组分区还是左侧定位导航？<br>• 次要 / 高级字段：平铺还是默认折叠，何时应该折叠？ |
| **D-04** | 状态与反馈表达 | 把"**正在发生什么 / 结果如何 / 为什么不能做**"如实且有分级地告诉用户，消除黑盒与盲等<br><br>**边界**：只回答"如何如实告知系统状态与结果"，不含对操作的拦截与否决 | • 首次加载：骨架屏还是加载态？<br>• 空态：初始无数据、筛选无结果、无权限三种如何区分与引导？<br>• 操作反馈：成功 / 部分失败 / 全部失败如何分级呈现？<br>• 异步进行中：进度、耗时、剩余量如何就地暴露？<br>• 请求失败 / 超时：整页错误页、局部占位还是轻提示 + 重试？<br>• 提交进行中：按钮 loading、遮罩还是乐观更新？<br>• 实时列表：新增 / 变更行如何被察觉（高亮 / 置顶 / 静默）？<br>• 校验失败：字段内联、顶部汇总还是自动定位首个错误？<br>• 加载偏慢：静默加载、中途补提示（正在努力加载…）还是超时前提示？<br>• 对象 / 记录的状态如何表达（纯文本 / 状态标签 / 色点 + 文案 / 顶部计数指标条）？ |
| **D-05** | 操作确认与防错 | 在高风险 / 不可逆操作前建立**恰当的阻力与可预知的影响面**——该拦的拦住、该放的不啰嗦<br><br>**边界**：只回答"高风险 / 不可逆操作要不要拦、拦到什么程度"，不含纯状态与进度的告知 | • 删除 / 下线：要不要二次确认？用气泡、阻断弹窗还是输入口令？<br>• 无权限操作：隐藏还是置灰并说明原因？<br>• 批量操作：不满足条件的对象如何跳过、如何告知？<br>• 变更类操作：是否先给影响面清单 / 配额试算再放行？<br>• 批量删除 / 禁用：要不要二次确认、确认到什么程度？<br>• 编辑未保存：离开 / 关闭要不要拦截？<br>• 低频可逆操作：用事后撤销替代事前确认？<br>• 高风险操作：危险色按钮还是危险区隔离？<br>• 破坏性删除：要不要回收站 / 软删除兜底？<br>• 敏感数据查看 / 导出：要不要二次身份校验？<br>• 策略变更：直接生效还是试运行 / 灰度？ |
| **D-06** | 层级与动线 | 回答"层级怎么走、上下文怎么留"——下钻层级与浮层叠放；返回与上下文保留；跨模块跳转<br><br>**边界**：只回答"层与层怎么叠、往返路径与上下文如何保留"，不含承载形态本身的选型 | • 页面 → 抽屉 → 弹窗最多叠几层？能否"抽屉开页面"？<br>• 关闭抽屉 / 返回列表：是否保留搜索、筛选、排序、滚动位置？<br>• 多级下钻：面包屑与返回契约如何统一？<br>• 跨模块跳转：如何保持上下文不中断？<br>• 浏览器前进 / 后退：如何与浮层、Tab 对齐？<br>• 页面 / Tab 状态：能否 URL 直达（可分享）？<br>• 操作成功后：退回哪一层、关几层？<br>• 子页改动返回：父页是否自动刷新？<br>• 多入口进入：返回回到哪？<br>• 切换 Tab：是否重置内部状态？ |
| **D-07** | 对象录入与选择 | 回答"字段与对象怎么录、怎么选"——字段控件选型；选择器选型（穿梭 / 多选 / 树 / 弹窗列表页）<br><br>**边界**：只回答"字段录入与对象选取用什么控件"，不含承载这些控件的壳选型 | • 字段控件：输入框、下拉、单选 / 多选、日期选择器如何选型？<br>• 对象选取：穿梭框、多选列表、树选择器、弹窗列表页如何选型？<br>• 海量对象：如何按量级与是否需要多维筛选切换选择器？<br>• 多类型对象混选：如何分组承载？<br>• 字段校验：实时、失焦还是提交时触发？<br>• 条件 / 规则组合输入：条件组、条件构建器还是分步？<br>• 多值字段：标签输入、文本域还是逐条添加？<br>• 字段联动：切换上游后下游重置还是保留？<br>• 数值 / 区间：数字输入、步进器、滑块还是起止区间？<br>• 结构化表达式（正则 / SPL / JSON）：文本域还是代码编辑器？<br>• 子对象集合：行内表格、卡片列表还是弹窗添加？<br>• 字段显隐：常驻、条件显隐还是置灰？ |
| **D-08** | 概览与驾驶舱可视化 | 把**概览 / 驾驶舱**这块内容组织成合适的版面——独立成驾驶舱页还是并入列表顶部统计卡、指标卡与图表怎么分组、多视角怎么切、概览与明细怎么衔接<br><br>**边界**：只回答"概览用什么壳装、版面怎么组织"；图表类型与配色 Token 归资产库，数据取数口径不在本域 | • 概览：独立驾驶舱页还是列表顶部统计卡？<br>• 指标与图表：指标卡组、图表分区还是多视角 Tab？<br>• 时间维度：全局统一时间筛选还是各卡片独立？<br>• 版面：几列栅格、首屏多少卡片、主指标如何置顶？<br>• 卡片间：是否联动（同源筛选 / 下钻明细 / 不联动）？<br>• 卡片排布：固定还是允许用户自定义？<br>• 受众：全局态势还是"我的待办 / 我的任务"？<br>• 概览与明细：点击卡片下钻还是只读 + 跳转？<br>• 刷新与新鲜度：自动定时刷新、手动刷新还是静默刷新 + 时间戳？<br>• 异常指标：常态展示、异常高亮置顶还是独立告警区？<br>• 指标卡：单值、环比、目标进度还是迷你趋势？<br>• 概览是否支持全屏 / 大屏值守？ |
| **D-09** | 检索与筛选 | 回答"用户**怎么把目标数据找出来**"——检索 / 筛选 / 排序的入口形态、条件承载容器、触发时机与条件组织（保存视图、高级表达式、条件回显）<br><br>**边界**：只回答"检索与筛选这**一整块**如何组织与承载"；筛选项内部的**单个控件**选型归 D-07，列表 / 表格壳归 D-02，无结果空态归 D-04 | • 检索 / 筛选入口：常驻列表页（顶部搜索框 / 可展开筛选）还是单独检索页？<br>• 多条件筛选用什么壳承载？（行内筛选条 / 可展开面板 / 抽屉 / 弹窗 / 独立检索页）<br>• 筛选什么时候触发？（即时 / 提交 / 防抖 + 回车）<br>• 筛选条件要不要保存为视图 / 方案？<br>• 高级检索表达式（SPL / 自然语言）怎么暴露？<br>• 视图 Tab 与筛选条怎么分层？<br>• 已生效筛选如何回显与清空？<br>• 排序：列头、多列、独立排序面板还是固定默认序？<br>• 作用范围：全局、模块内还是当前子集，结果内能否再筛？<br>• 关键字：匹配哪些字段、命中如何高亮？<br>• 是否提供搜索历史 / 常用筛选？ |
| **D-10** | 操作入口与批量 | 回答"操作**放在哪、怎么组织与触发**"——单对象 / 单行操作的入口挂载形态；批量操作的组织与触发；导入 / 导出等文件类操作的承载与流程；耗时操作即时执行还是转后台<br><br>**边界**：只回答"操作如何挂载、组织与触发"；**要不要拦、拦到什么程度**归 D-05，操作结果的**状态表达**归 D-04，操作表单内的**字段控件**归 D-07 | • 单对象 / 单行操作入口挂在哪？（行内操作列 / 顶部工具栏 / 选中浮出批量栏 / 「更多」/ 右键）<br>• 批量操作怎么组织与触发？（行内勾选 + 批量栏 / 列表级选择模式 / 筛选结果全选）<br>• 导入 / 导出用什么壳与流程？（弹窗 / 抽屉 / 独立页 / 后台任务）<br>• 耗时操作即时执行还是转后台？<br>• 批量改同一字段：批量弹窗、表格内批量编辑还是逐行？<br>• 「全选」作用于当前页还是全部筛选结果？<br>• 是否提供快捷键 / 行内快捷图标？<br>• 新建是否支持复制 / 克隆已有？ |

## 二、适用范围与定性顺序

### 2.1 什么时候该查本库

> 与 [`../2.0-设计决策总览与调度.md`](../2.0-设计决策总览与调度.md) 的调度规则一致：

| 时机 | 用本库做什么 |
| :--- | :--- |
| 命中某需求类型，但该类型分册内**多个标杆案例做法冲突** | 用本库判据**裁决**该选哪个 |
| 命中的类型分册**未覆盖某个设计点** | 用本库**兜底**推导 |
| 需求**不属于任何 Type-01~07** | **全量**用本库推导 |
| 走在局部细节调优链路上，但触及**结构级选择** | 回查本库对应决策域 |

### 2.2 定性顺序（按"当前在纠结什么"分诊）

> 一条经验要能回答一个可判定的问句；因此先定位"纠结点落在哪个决策域"，再进去取判据。

1. **先问「我在纠结什么」**，据此分诊：
   * 纠结"**一个需求的信息架构怎么搭、能力归属到哪一层**" → **D-01**
   * 纠结"这块内容 / 这个操作**放在哪、用哪个壳装**" → **D-02**
   * 纠结"**数据太多 / 太密**，怎么承载与组织" → **D-03**
   * 纠结"系统**状态 / 结果 / 失败原因**怎么告诉用户" → **D-04**
   * 纠结"这个操作**要不要拦、拦到什么程度**" → **D-05**
   * 纠结"**层级怎么叠、返回怎么不丢上下文**" → **D-06**
   * 纠结"字段 / 对象**用什么控件录与选**" → **D-07**
   * 纠结"**概览 / 驾驶舱**该怎么组织版面" → **D-08**
   * 纠结"**用户怎么把目标数据检索 / 筛选出来**" → **D-09**
   * 纠结"**操作放在哪、怎么组织与触发（入口 / 批量 / 导入导出）**" → **D-10**
2. **一个设计点可同时命中多个决策域**（如"新建表单"同时涉及 D-02 承载与 D-07 控件）——分别落入各自的经验条目，互不重复；跨域边界见各域文件的决策域定位。

## 三、条目骨架 (Entry Schema)

