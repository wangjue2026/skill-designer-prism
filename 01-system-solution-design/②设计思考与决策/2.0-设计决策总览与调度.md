## 二、两库关系：逐页必查坐标 × 可选素材 (Mandatory Scan × Optional Pool)

* **需求大类设计决策 = 可选素材池（默认不再扩充）**：具体、有案例背书，回答"这类需求，标杆怎么做"；只在域内有料且更具体时优先，**不再决定"要不要读横向"**。
* **通用设计决策 = 逐页必查的裁决尺（主依据）**：判据 / 阈值 / 分流，回答"这个页面上的这块东西，什么条件下该选哪种"。
* **协同规则**：先按页面内容要素用横向**定必查域**（不可跳过），再在域内取料——纵向有料优先，否则用横向 EP。**（完整优先级与三层边界见下文【四、调度优先级与三层边界】）**

> 🛑 **不是上下级，而是"候选集 + 选择函数"**：二者既不会互相覆盖，也不会留下空洞。

## 三、调度规则（求解流程）

```text
需求进来
  └─ Triage？（见 00-triage-and-routing/triage-rules.md）
       ├─ 局部细节调优 → 走【局部细节调优】b~c 链路 + 通用设计决策的局部判断
       │                  └─ 触碰结构红线 → 升级为系统设计
       └─ 系统设计
            ├─ 【Part1】1.1 痛点 → 1.2 目标 → 1.3 突破点 → 1.4 草图方向
            │    └─ 🚦 方向闸门：用户选定方向后才继续（未选定 → 停）
            ├─ ① 逐页扫「页面内容要素」→ 定该页必查决策域（横向 D-01~11，必经）
            │    └─ 执行程序：横向库承接与场景拆解桥协议 Step 2.5（特征物检测表）
            │         ⚠️ 这一步不看纵向有没有料，只看页面里画了什么
            ├─ ② 域内取料：纵向命中且有料 → 用 EP-xx（可选加成）；否则 → 用 D0x-EPxx（默认主路径）
            │    └─ 某必查域一个都读不到 → 进 ③ ＋ 登记缺口
            ├─ ③ 自行推导五步（确认真未命中 → 改写事实问题 → 四条理由推「必须存在」→ 定形定位 → 验收留痕）
            │              └─ 执行程序：04-workflows-and-cases/经验未命中处理协议.md
            ├─ 【Part2】4.1：定性 → 场景对标杆主场景 → 草图继承对账 → 页面清单
            ├─ 4.1 逐页：每页判标杆主场景、配经验（页面定下来才判得准）、物料装配、画线框
            └─ 产出方案（5.0 说明书 → 自检 → 共识闸门）
```

> 🔗 **本调度与 Part1 的关系**：**本文件管辖的是 Part2**。Part1 的 1.3 突破点与 1.4 草图方向**不调经验库**——突破点走的是"工作类型经验"（①~④ 思考经验），草图走的是"页面结构分岔"，都不属于双决策库的候选池。
> 🛑 **顺序铁律**：**经验不能决定结构**。先由 1.4 与用户共同定下页面结构，经验才在结构里做填充；反过来"用经验反推骨架"会让方案变成"经验库的拼贴"，而不是针对这个业务的设计。
> 📎 **原 `2.1-设计思考与发力点.md` 已废弃**（2026-10-20）：其"发力点"就是 1.3 的「突破点」，不再单独成环；类型定性 / 严肃度、场景→主场景对齐、逐页经验匹配均已并入 [4.1 业务页面框架选型指引](../④布局与结构/4.1-业务页面框架选型指引.md)。

## 四、调度优先级与三层边界

**总口径**：**决策归经验库（横向定必查域必经、纵向有料加成），材料与规范归资产库（组件 / 模板 / 能力 / 铁律），具体样式数值优先沿用经验库案例 Token。**

### 4.1 优先级（逐页判：先定必查域，再定用哪条）

> 🛑 **2026-11-04 调整：横向定域必经，纵向取料可选。** 需求大类库默认不再扩充，横向库是主依据。过去"纵向未命中才走横向"的顺序，会让有筛选区的页面根本没人读 D-09，直接自由发挥。

```text
1. 逐页列出【页面内容要素】（筛选 / 表格 / 表单 / 批量导入导出 / 统计与图表 / Tab / 状态…）
     → 按桥协议 Step 2.5 特征物检测表定出该页【必查决策域】
     ⚠️ 这一步与纵向有没有料无关，不可跳过、不可凭感觉缩减
2. 对每个必查域取料：
     纵向分册命中且有料 → 采用纵向 EP（做法以纵向为准）
     否则              → 用横向 D0x-EPxx（落地必须带档位/形态）
3. 纵向内部多案例冲突 → 用横向判据裁决
4. 该必查域一个都读不到？
     否  → 按 D0x-EPxx 落地
     是  → 自行推导五步（见 04-workflows-and-cases/经验未命中处理协议.md）
           并交三个标签：经验来源「无经验背书 · 业务独立推导（含未覆盖场景号）」+ 推导过程 + 缺口登记
```

> 🛑 **粒度提醒**：纵向 EP 是**标杆主场景级**的打包做法，横向是**设计点级**的裁决尺。因此不是"整份需求二选一"，而是**一条主场景展开成若干设计问题，每个设计问题各走一遍上面的判定**。

### 4.2 三层边界（谁说了算）

| 层 | 决定什么 | 以谁为准 |
| :--- | :--- | :--- |
| **① 决策层** | **做什么 / 选哪种做法**（主路径、形态选择） | **经验库**：横向定必查域（必经）→ 域内纵向有料优先 → 横向 EP → 都无则**按[未命中协议](../../04-workflows-and-cases/经验未命中处理协议.md)五步推导**（不是「自研」了事） |
| **② 部件层** | **用什么材料与框架**：组件选型、模板选型、**组件的能力与交互方式**、基础框架规范（铁律 / 色板 / 红线） | **设计资产**（[`03-design-assets/`](../../03-design-assets/)） |
| **③ 样式层** | **具体尺寸 / 样式取值**：卡片长宽高、报错样式、间距等 | **优先沿用经验库（纵 / 横）案例的 Token 样式**；资产库通用 Token 表作底 |

> ✅ 三层不冲突：经验库案例本身即真实产线资产，其样式 Token 天然落在资产库色板 / 规范的白名单内。**经验库案例能定"卡片宽 240px"，但定不了"把 Card 换成 Modal"，更定不了"用红色按钮"**——后两者归 ① / ②。

### 4.3 可视化入口分流（D-08 ↔ D-11）

需求涉及"概览 / 图表 / 示意图"时，**先判这块可视化在页面里的角色**，再决定进哪个域：

| 角色 | 判据（分析维度取值） | 归属 |
| :--- | :--- | :--- |
| **独立成页（可视化是页面主体）** | 概览服务**跨对象的整体态势 / 多业务子域**（**指标组 ≥3** 或**跨多个子域**）；或需多视角总览 / 大屏值守 | **D-08 页面级可视化** |
| **局部嵌入（可视化是页面里的局部件）** | 概览**只服务当前主内容**（**指标 ≤4**、语义＝"当前结果集的汇总"）；或配置页图解 / 详情图表块 | **D-11 可视化件选型与还原** |

> 📌 **来源**：该判据由 D-08 原 `EP-01` 上收而来（拆分前混在域内），现作为 D-08 / D-11 的**共同入口**。
> 🔁 **兜底**：若概览既需全局态势、又需当前结果集 → 允许**二者并存**（独立概览页 + 列表顶统计卡），分别落 D-08 / D-11。
> 🧭 **配套分界**：**表格单元格内的内嵌可视化**（迷你趋势线 / 进度条 / 占比条）归 **D-03**；**配置表单单个字段控件**归 **D-07**。
> 📊 **图表分支**：判为局部件后，D-11 母尺 **②** 再分一次流——**内容可视化**（走 ②.1，件型键 `VIZ-0x`）还是**图表可视化**（走 ②.2：2a 选图形 `CHART-*` ／ 2b 选容器复用 ③）。图形资产见 [`03-design-assets/visual-styles/图表件/`](../../03-design-assets/visual-styles/图表件/README.md)。

## 五、共享坐标系（硬前提）

两个库**共用同一套分析维度**（量级 / 列数·字段数 / 配置项数量 / 控件体量 / 是否需保留上下文 / 业务严肃度 / 使用频次 / 是否主路径 / 对象量级 / 可逆性 / 影响面大小 / 加载耗时 / 层级深度 …，各决策域从中取用子集），且需求大类经验须带**机读的适用条件标签**——否则通用设计决策无从裁决。

> 📌 **分析维度清单待锁定**；清单一旦冻结，即作为两库共同的元数据坐标系。
