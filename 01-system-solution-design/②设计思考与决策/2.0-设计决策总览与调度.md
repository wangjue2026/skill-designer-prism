## 二、求解模型：逐页定域 × 域内取料

* **通用设计决策 = 逐页必查的裁决尺**：判据 / 阈值 / 分流，回答"这个页面上的这块东西，什么条件下该选哪种"。
* **需求大类设计决策 = 留档素材**：2026-11-10 起 `EP-xx` 不再进入任何执行环节。
* **协同规则**：先按页面内容要素用横向**定必查域**（不可跳过），再在域内取 `D0x-EPxx`（**必须带档位**）。**（完整优先级与三层边界见下文【四】）**

> 🛑 **不再有"候选集 + 选择函数"，只有一把尺子**：纵向库曾作为"有料则优先"的加成，实测分册多为空壳、命中率低、读取成本高，故整体退出执行流。

## 三、调度规则（求解流程）

```text
需求进来
  └─ Triage？（见 00-triage-and-routing/triage-rules.md）
       ├─ 局部细节调优 → 走【局部细节调优】b~c 链路 + 阶段 1.5 决策域校准（执行程序见 `02-detail-tuning-design/细节调优中枢调度指南.md`）
       │                  └─ 需重做需求理解与分析 → 升级为系统设计
       └─ 系统设计
            ├─ 【Part1】1.1 痛点 → 1.2 目标 → 1.3 突破点 → 1.4 草图方向
            │    └─ 🚦 方向闸门：用户选定方向后才继续（未选定 → 停）
            ├─ ① 逐页扫「页面内容要素」→ 定该页必查决策域（横向 D-01~11，必经）
            │    └─ 执行程序：横向库承接与场景拆解桥协议 Step 2.5（特征物检测表）
            │         ⚠️ 这一步不看库里有没有料，只看页面里画了什么
            ├─ ② 域内取料：命中 → 用 D0x-EPxx（必须带档位）
            │    └─ 某必查域一个都读不到 → 进 ③ ＋ 登记缺口
            ├─ ③ 自行推导五步（确认真未命中 → 改写事实问题 → 四条理由推「必须存在」→ 定形定位 → 验收留痕）
            │              └─ 执行程序：04-workflows-and-cases/经验未命中处理协议.md
            ├─ 【Part2】4.1：定性 → 草图继承对账 → 页面清单
            ├─ 4.1 逐页：扫必查域取料（页面定下来才判得准）、物料装配、画线框
            └─ 产出方案（5.0 说明书 → 自检 → 共识闸门）
```

> 🔗 **本调度与 Part1 的关系**：**本文件管辖的是 Part2**。Part1 的 1.3 突破点与 1.4 草图方向**不调经验库**——突破点走的是"工作类型经验"（①~④ 思考经验），草图走的是"页面结构分岔"，都不属于经验库的候选池。
> 🛑 **顺序铁律**：**经验不能决定结构**。先由 1.4 与用户共同定下页面结构，经验才在结构里做填充；反过来"用经验反推骨架"会让方案变成"经验库的拼贴"，而不是针对这个业务的设计。
> 📎 **原 `2.1-设计思考与发力点.md` 已废弃**（2026-10-20）：其"发力点"就是 1.3 的「突破点」，不再单独成环；类型定性 / 严肃度、逐页决策域匹配均已并入 [4.1 业务页面框架选型指引](../④布局与结构/4.1-业务页面框架选型指引.md)。

## 四、调度优先级与三层边界

**总口径**：**决策归横向经验库，材料与规范归资产库（组件 / 模板 / 能力 / 铁律），具体样式数值以资产库 Token 为准。**

### 4.1 优先级（逐页判）

```text
1. 逐页列出【页面内容要素】（筛选 / 表格 / 表单 / 批量导入导出 / 统计与图表 / Tab / 状态…）
     → 按桥协议 Step 2.5 特征物检测表定出该页【必查决策域】
     ⚠️ 不可跳过、不可凭感觉缩减
2. 对每个必查域取料：用横向 D0x-EPxx（落地必须带档位 / 形态）
3. 该必查域一个都读不到？
     否  → 按 D0x-EPxx 落地
     是  → 自行推导五步（见 04-workflows-and-cases/经验未命中处理协议.md）
           并交三个标签：经验来源「无经验背书 · 业务独立推导（含未覆盖场景号）」+ 推导过程 + 缺口登记
```

> 🛑 **粒度提醒**：横向是**设计点级**的裁决尺——一条主场景展开成若干设计问题，每个设计问题各走一遍上面的判定。

### 4.2 三层边界（谁说了算）

| 层 | 决定什么 | 以谁为准 |
| :--- | :--- | :--- |
| **① 决策层** | **做什么 / 选哪种做法**（主路径、形态选择） | **横向经验库** `D0x-EPxx` → 读不到则**按[未命中协议](../../04-workflows-and-cases/经验未命中处理协议.md)五步推导**（不是「自研」了事） |
| **② 部件层** | **用什么材料与框架**：组件选型、模板选型、**组件的能力与交互方式**、基础框架规范（铁律 / 色板 / 红线） | **设计资产**（[`03-design-assets/`](../../03-design-assets/)） |
| **③ 样式层** | **具体尺寸 / 样式取值**：卡片长宽高、报错样式、间距等 | **资产库 Token 表**（[`tokens-cheatsheet.md`](../../03-design-assets/tokens-cheatsheet.md)）＋ `comp-*` 组件规范 |

> ✅ 三层不冲突：横向经验能定"这里该用复合搜索而不是普通输入框"，但定不了"把 Card 换成 Modal"，更定不了"用红色按钮"——后两者归 ① / ②。

### 4.3 可视化入口分流（D-08 ↔ D-11）

需求涉及"概览 / 图表 / 示意图"时，**先判这块可视化在页面里的角色**，再决定进哪个域：

| 角色 | 判据（分析维度取值） | 归属 |
| :--- | :--- | :--- |
| **独立成页（可视化是页面主体）** | 概览服务**跨对象的整体态势 / 多业务子域**（**指标组 ≥3** 或**跨多个子域**）；或需多视角总览 / 大屏值守 | **D-08 页面级可视化** |
| **局部嵌入（可视化是页面里的局部件）** | 概览**只服务当前主内容**（**指标 ≤4**、语义＝"当前结果集的汇总"）；或配置页图解 / 详情图表块 | **D-11 可视化件选型与还原** |

> 📌 **来源**：该判据由 D-08 原 `EP-01` 上收而来（拆分前混在域内），现作为 D-08 / D-11 的**共同入口**。
> 🔁 **兜底**：若概览既需全局态势、又需当前结果集 → 允许**二者并存**（独立概览页 + 列表顶统计卡），分别落 D-08 / D-11。
> 🧭 **配套分界**：**表格单元格内的内嵌可视化**（迷你趋势线 / 进度条 / 占比条）归 **D-03**；**配置表单单个字段控件**归 **D-07**。
> 📊 **图表分支**：判为局部件后，D-11 母尺 **②** 再分一次流——**内容可视化**（走 ②.1，件型键 `VIZ-0x`）还是**图表可视化**（走 ②.2：2a 选图形 `CHART-*` ／ 2b 选容器复用 ③）。图形资产见 [`03-design-assets/visual-styles/图表件/`](../../03-design-assets/visual-styles/图表件/README.md)。

### 4.4 经验可信度分级（A / B / C）与三层修正边界（2026-11-27 新增）

> 🛑 **核心原则**：经验库不是教条——**经验自身必须正确，若经验过时、与最新组件规范冲突、或不适用于当前业务范式（如 AI-Native 研判），允许显式放弃并留痕**（`D0x-OVERRIDE`）。

**① 决策域可信度分级（决定“刚性纠偏”还是“启发参考”）**：

| 等级 | 覆盖域 | 成熟度说明 | Part2 使用策略 |
| :---: | :--- | :--- | :--- |
| **A 级（高置信）** | `D-02` / `D-03` / `D-09`（①~⑨）/ `D-10` | 三产线盲扫 + 专家经验已核 | **优先作为修正 Part1 局部体验硬伤的硬依据** |
| **B 级（部分覆盖）** | `D-01` / `D-08` / `D-11`（仅 5 类在册件型） | 部分场景已落库、部分待补 | 命中已实测条目则采纳；未覆盖或规范外可视化走 `REF` 保骨微调 |
| **C 级（待完善）** | `D-04` / `D-05` / `D-06` / `D-07` | 母尺覆盖不全、多条 EQ 待销 | 仅作防漏检查清单与启发参考，不强迫硬套未验证结论 |

**② 基于通用经验修正 Part1 的三层裁决边界**：
- **L1 必纠与必补（体验基线修正）**：Part1 存在明确违背 A 级经验或基础组件规范的局部缺陷（如筛选 >4 项未用 `IxProSearch`、时间筛选用分段按钮、高危删除缺影响面预演、关闭抽屉丢列表上下文、缺七态异常与字段校验），**Part2 直接修正并补齐**，记入 4.1 装配台账；
- **L2 甄别与放弃（`D0x-OVERRIDE` 合法出口）**：经审视发现某条通用经验过时、有误、与组件规范冲突或不适用当前创新范式时，在映射清单显式标注 `<span class="deriv">经验已审视放弃（D0x-EPxx：放弃理由）</span>`（`D0x-OVERRIDE`），`SP-W-10` 予以放行；
- **L3 保护核心创新骨架（严禁压扁）**：Part1 已获用户确认的核心产品范式与形态分岔（如“融合时间轴消灭二级抽屉”），不得借传统经验将其退化回老三样。
