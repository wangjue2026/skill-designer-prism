# 设计决策总览与调度 (Design Decisions Hub)

> 🔙 所属：【方案系统设计主线】步骤 2 · 设计思考与决策
> 💡 本文件是织雨执行步骤 2 时的**双库总入口与调度中枢**：定义三种用途的定位，以及两个决策库在求解时的协同规则。

## 一、三种用途 (Three Usages)

| 用途 | 所在位置 | 定位 |
| :--- | :--- | :--- |
| **需求大类设计决策** | [`需求大类设计决策/`](./需求大类设计决策/) | **纵向 · 候选经验池**：按需求大类（`Type-01~07`）沉淀、有标杆案例背书的方案级经验 |
| **通用设计决策** | [`通用设计决策/`](./通用设计决策/) | **横向 · 裁决尺与兜底网**：跨类型的通用设计决策（信息架构 / 信息承载与容器选型 / 信息密度与可读性 / 状态与反馈表达 / 操作确认与防错 / 层级与动线 / 对象录入与选择 / 概览与驾驶舱可视化 / 检索与筛选 / 操作入口与批量） |
| **局部细节调优** | [`02-detail-tuning-design/`](../../02-detail-tuning-design/) | **局部像素级修补**的执行链路（b~c） |

## 二、两库关系：候选池 × 裁决器 (Candidate Pool × Adjudicator)

* **需求大类设计决策 = 候选经验池**：具体、有案例背书，回答"这类需求，标杆怎么做"。
* **通用设计决策 = 裁决尺 + 兜底网**：判据 / 阈值 / 分流，回答"什么条件下该选哪种"。
* **协同规则**：素材上首选方案经验（具体优于抽象）；但"选哪一个、够不够用"由通用设计决策的判据裁决。

> 🛑 **不是上下级，而是"候选集 + 选择函数"**：二者既不会互相覆盖，也不会留下空洞。

## 三、调度规则（求解流程）

```text
需求进来
  └─ Triage？（见 00-triage-and-routing/triage-rules.md）
       ├─ 局部细节调优 → 走【局部细节调优】b~c 链路 + 通用设计决策的局部判断
       │                  └─ 触碰结构红线 → 升级为系统设计
       └─ 系统设计
            ├─ 定性需求大类（见 需求大类设计决策/00-总览与类型定性.md）
            ├─ 命中需求大类设计决策？
            │    ├─ 命中 → 以大类经验为候选素材
            │    │         ├─ 用【通用设计决策】判据裁决候选 / 裁决大类内多案例冲突
            │    │         └─ 大类未覆盖的设计点 → 【通用设计决策】兜底
            │    └─ 未命中 → 全量用【通用设计决策】推导
            └─ 产出方案
```

## 四、共享坐标系（硬前提）

两个库**共用同一套分析维度**（量级 / 列数·字段数 / 配置项数量 / 控件体量 / 是否需保留上下文 / 业务严肃度 / 使用频次 / 是否主路径 / 对象量级 / 可逆性 / 影响面大小 / 加载耗时 / 层级深度 …，各决策域从中取用子集），且需求大类经验须带**机读的适用条件标签**——否则通用设计决策无从裁决。

> 📌 **分析维度清单待锁定**；清单一旦冻结，即作为两库共同的元数据坐标系。
