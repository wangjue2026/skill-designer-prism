| 用途 | 所在位置 | 定位 |

## 二、两库关系：候选池 × 裁决器 (Candidate Pool × Adjudicator)

* **需求大类设计决策 = 候选经验池**：具体、有案例背书，回答"这类需求，标杆怎么做"。
* **通用设计决策 = 裁决尺 + 兜底网**：判据 / 阈值 / 分流，回答"什么条件下该选哪种"。
* **协同规则**：素材上首选方案经验（具体优于抽象）；但"选哪一个、够不够用"由通用设计决策的判据裁决。**（完整优先级与三层边界见下文【四、调度优先级与三层边界】）**

> 🛑 **不是上下级，而是"候选集 + 选择函数"**：二者既不会互相覆盖，也不会留下空洞。

## 三、调度规则（求解流程）

```text
需求进来
  └─ Triage？（见 00-triage-and-routing/triage-rules.md）
       ├─ 局部细节调优 → 走【局部细节调优】b~c 链路 + 通用设计决策的局部判断
       │                  └─ 触碰结构红线 → 升级为系统设计
       └─ 系统设计
            ├─ 定性需求大类（见 需求大类设计决策/00-总览与类型定性.md）
            ├─ 命中需求大类设计决策？
            │    ├─ 命中 → 以大类经验为候选素材
            │    │         ├─ 用【通用设计决策】判据裁决候选 / 裁决大类内多案例冲突
            │    │         └─ 大类未覆盖的设计点 → 【通用设计决策】兜底
            │    └─ 未命中 → 全量用【通用设计决策】推导
            │              └─ 执行程序：04-workflows-and-cases/横向库承接与场景拆解桥协议.md
            └─ 产出方案
```

## 四、调度优先级与三层边界

**总口径**：**决策归经验库（纵向优先、横向补缺），材料与规范归资产库（组件 / 模板 / 能力 / 铁律），具体样式数值优先沿用经验库案例 Token。**

### 4.1 优先级（对每一个【设计问题】依次判定）

```text
1. 需求命中需求大类吗？
     否  → 全走横向（见 04-workflows-and-cases/横向库承接与场景拆解桥协议.md）
     是  → 下一步
2. 该分册已蒸馏 且 该设计问题落在其 Job / 场景节点覆盖范围内吗？
     否  → 该设计问题走横向
     是  → 采用纵向 EP（做法以纵向为准）
3. 纵向内部多案例冲突 → 用横向判据裁决；纵向缺口 → 横向兜底
```

> 🛑 **粒度提醒**：纵向 EP 是**场景 / Job 级**的打包做法，横向是**设计点级**的裁决尺。因此不是"整份需求二选一"，而是**一个 Job 场景展开成若干设计问题，每个设计问题各走一遍上面的判定**。

### 4.2 三层边界（谁说了算）

| 层 | 决定什么 | 以谁为准 |
| :--- | :--- | :--- |
| **① 决策层** | **做什么 / 选哪种做法**（主路径、形态选择） | **经验库**：纵向优先 → 横向补缺口 → 都无则自研 |
| **② 部件层** | **用什么材料与框架**：组件选型、模板选型、**组件的能力与交互方式**、基础框架规范（铁律 / 色板 / 红线） | **设计资产**（[`03-design-assets/`](../../03-design-assets/)） |
| **③ 样式层** | **具体尺寸 / 样式取值**：卡片长宽高、报错样式、间距等 | **优先沿用经验库（纵 / 横）案例的 Token 样式**；资产库通用 Token 表作底 |

> ✅ 三层不冲突：经验库案例本身即真实产线资产，其样式 Token 天然落在资产库色板 / 规范的白名单内。**经验库案例能定"卡片宽 240px"，但定不了"把 Card 换成 Modal"，更定不了"用红色按钮"**——后两者归 ① / ②。

### 4.3 可视化入口分流（D-08 ↔ D-11）

需求涉及"概览 / 图表 / 示意图"时，**先判这块可视化在页面里的角色**，再决定进哪个域：

| 角色 | 判据（分析维度取值） | 归属 |
| :--- | :--- | :--- |
| **独立成页（可视化是页面主体）** | 概览服务**跨对象的整体态势 / 多业务子域**（**指标组 ≥3** 或**跨多个子域**）；或需多视角总览 / 大屏值守 | **D-08 页面级可视化** |
| **局部嵌入（可视化是页面里的局部件）** | 概览**只服务当前主内容**（**指标 ≤4**、语义＝"当前结果集的汇总"）；或配置页图解 / 详情图表块 | **D-11 局部嵌入式可视化** |

> 📌 **来源**：该判据由 D-08 原 `EP-01` 上收而来（拆分前混在域内），现作为 D-08 / D-11 的**共同入口**。
> 🔁 **兜底**：若概览既需全局态势、又需当前结果集 → 允许**二者并存**（独立概览页 + 列表顶统计卡），分别落 D-08 / D-11。
> 🧭 **配套分界**：**表格单元格内的内嵌可视化**（迷你趋势线 / 进度条 / 占比条）归 **D-03**；**配置表单单个字段控件**归 **D-07**。

## 五、共享坐标系（硬前提）

两个库**共用同一套分析维度**（量级 / 列数·字段数 / 配置项数量 / 控件体量 / 是否需保留上下文 / 业务严肃度 / 使用频次 / 是否主路径 / 对象量级 / 可逆性 / 影响面大小 / 加载耗时 / 层级深度 …，各决策域从中取用子集），且需求大类经验须带**机读的适用条件标签**——否则通用设计决策无从裁决。

> 📌 **分析维度清单待锁定**；清单一旦冻结，即作为两库共同的元数据坐标系。
