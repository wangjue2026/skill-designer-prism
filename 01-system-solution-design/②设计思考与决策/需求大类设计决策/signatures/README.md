# 需求大类设计决策特征物签名契约说明 (Feature Signature Manifests)

## 📌 架构定位与解耦原则
本目录存放 7 大需求类型（`Type-01` ~ `Type-07`）中，沉淀的高保真标杆设计经验（`EP-xx`）所对应的**可机器校验物理特征指纹（Physical Feature Signatures）**。

### 为什么必须独立于自检脚本？
1. **彻底解耦**：自检工具 `tools/design-spec-selfcheck.sh` 是平台级通用基础设施，严禁在脚本内硬编码任何特定业务、特定需求类型或特定 EP 的校验逻辑。
2. **多赛道自适应**：
   - 当校验一份 `Type-07`（检测任务类）说明书时，自检脚本**动态加载** `Type-07.json`，仅核验该文档声明的 Type-07 EP 指纹；
   - 当校验一份 `Type-01`（对象与资产管理类）说明书时，自检脚本**动态加载** `Type-01.json`，绝不会用 Type-07 的进度条或分栏规则去错误约束 Type-01！
   - 若某种需求类型（如 Type-04、Type-05）尚未配置签名契约文件，自检引擎**优雅放行**，仅核验 1~8 项全局通用基线，绝不产生误报。

## 🛠️ 签名契约规范格式

每个 `<Type-xx>.json` 文件结构如下：

```json
{
  "type": "Type-01",
  "name": "对象与资产管理类",
  "description": "多源资产去重、拓扑关系、分类分级与资产详情特征物指纹",
  "signatures": {
    "EP-01": {
      "name": "经验项标题",
      "required_patterns": [
        "正则表达式1",
        "正则表达式2"
      ],
      "error_msg": "当说明书声明了该 EP 但未还原对应特征物时，自检工具向设计师报告的明确指引"
    }
  }
}
```

### 字段说明：
- `type`: 对应 `Type-01` ~ `Type-07`。
- `signatures`: 字典对象，Key 为经验项编号（如 `EP-01`, `EP-06`）。
- `required_patterns`: 必须全部匹配的正则表达式数组（全部命中才算通过）。
- `error_msg`: 缺失时的报错文案，必须明确指出“缺了什么关键物理结构”。

## 🧩 可视化件声明契约（`viz-signatures.json`）

> 与 `Type-xx.json` 并列的**第 8 类通用契约**，服务于【可视化件】（D-11 局部嵌入式可视化 / D-08 页面级可视化）。

- **校验对象**：设计说明书第四章节的《可视化件声明》块（HTML `class="viz-decl"`）。
- **结构**：不走 `signatures[EP]` 指纹正则可，而是**字段完整性契约**——`required_fields` 列出声明块必须齐备的字段。
- **消费方**：`tools/design-spec-selfcheck.sh` 第 11 项「可视化件声明完整性」。
- **自适应**：说明书中未出现任何 `viz-decl` 块时，本项优雅放行（不算失败）。

| 字段 | 说明 |
| :--- | :--- |
| `required_fields` | 每个 `viz-decl` 块必须出现的字段标签名（如 件型 / 图形编码规则 / 风格规范 / 交互与退化 / 可替代性） |
| `field_hints` | 各字段的取值提示（给人看，供撰写说明书时对齐；自检不强制匹配其内容） |
