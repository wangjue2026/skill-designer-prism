## 二、极简三步执行流（告别 9 表重复与空转门禁）

### Step 1：产出 1 份轻量《Part2 装配台账》（`_output/<业务名>/04-装配台账-<业务名>.md`）
仅维护 **3 张核心账本**（只过滤 **Part1 选定方案** 的页面、视图、`CAP` 与 `DX`，不再维护 9 张冗余表，**不再单独跑空转的 `gate-ex.sh 4.1`**）：
1. **表 1 · 承接与补漏总账**：逐页核对 选定方案页面/所属菜单/模板 ID + `ph-ledger` 展开控件 + 字段落位 + Part1 交互联动微契约 + 七态异常与校验补齐；
2. **表 2 · 经验扫读与修正/放弃账**：按桥协议 Step 2.5 逐页扫特征物 → 标 A/B/C 可信度 → 写命中 `D0x-EPxx`（带档位）或 `D0x-OVERRIDE`（放弃理由）→ 记清对 Part1 的 L1 修正点；
3. **表 3 · 可视化分流清单**：在册 5 类写 `VIZ-xx-<形态>`；规范外写 `REF / 资产未覆盖` + 语义 + Part1 溯源 + 4 项微调要点。

### Step 2：产出「规范级高保真《设计说明书》」（`_output/<业务名>/design-spec-<业务名>.html`）
严格基于 [`5.0-设计说明书标准模板.md`](../⑤设计说明书/5.0-设计说明书标准模板.md) 装配：
- **Part1（1~5 节）**：默认折叠进 Part1 Tab；角色 `1~2` 张、场景 `1~5` 条（1 条合法）、5.1 页面清单带「所属菜单」列（与 1.4 选定方案逐字一致）、**5.2 改轻量化外链指向 `./草图-<业务名>.html`**（不再内嵌 140KB 源码）；
- **Part2（6~7 节，默认选中）**：
  - 6.1 开头必写 `🛑 方案来源：用户选定 方案一/二 · <路线名>`（供门禁自动过滤选定方案台账）；
  - 7.x 按 5.1「所属菜单」分组（`<h4 class="domain">7.x 菜单名</h4>` → `<h5 id="page-0x">Page-0x …</h5>`）；
  - 每页固定结构：① 定位与模板 → ② **规范级高保真 UI 详细设计**（多 Tab 用 `.wf-tabs` + `[data-wf-pane]` 支持浏览器内点击切换，源码保留全部面板，打印自动全展开；**🛑 子 Tab 防缩水铁律：每个子 Tab 面板的列数、条目数、多模态附件卡、高亮证据与链路图形完整度必须 ≥ Part1，且与 Tab 标题括号计数 100% 账实相符，严禁标题写 `（4）` 却只画 1~2 行凑数**，机检 `SP-W-09`）+ 底部 `wf-annotation`（含「进入 / 去向」）→ ③ 默认收起的 `<details class="sec-fold">` 映射清单（+ 可视化件声明）；
  - 文末补齐 **六节自包含编码契约**（① **交互逻辑与状态机（必含结构化交互行为表 `<table>`，覆及全部 `Page-0x` 与子 Tab 的触发/联动/边界反馈）** / ② 数据口径与演示数据集 / ③ **组件、Token 与全局样式（必含引用 `design-motion.md` 的动效微契约）** / ④ 固定文案与状态词表 / ⑤ 验收清单 / ⑥ 实现边界），确保 Part3 生成 Demo 时交互与动效 100% 有据可依。

### Step 3：一次运行 `gate-sp.sh` 准出 + 停在共识闸门
```bash
bash tools/gate-sp.sh _output/<业务名>/design-spec-<业务名>.html _output/<业务名>/草图-<业务名>.html
```
- **三段全绿即准出**：`gate.js sp`（自动按选定方案过滤 `CAP`/`DX`）+ `design-spec-selfcheck.sh`（8 项精准版）+ `visual-audit.js --profile=wireframe`（V 组对齐 `tokens-cheatsheet` 唯一真源：圆角 `{0,2,4,6,8}`、字重 `{400,500,600,700}`）；
- **交付汇报**：门禁结论与确认话术**只在对话里给（3~5 行）**，不写进 HTML 文档；等用户明确回复【确认】后才进入 Step 6 前端 Demo 编码。
