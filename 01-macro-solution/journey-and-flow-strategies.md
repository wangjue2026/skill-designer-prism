# 宏观方案经验：用户旅程闭环与流程顺畅度策略 (Journey & Flow Strategies)

> 💡 **宏观方案定位**：
> 本文档提炼资深 B 端体验设计师在**复杂业务流程、可观测性排障链路与交互闭环**方面的实战经验。
> 专门解决规划人员经常遇到的“流程走不通”、“操作断层跳页”、“假智能假定界不可信”、“配置过于分散”等宏观方案痛点。

---

## 一、 宏观用户旅程与设计哲学 (Journey Mental Model)

在处理 B 端运维、监控、网络加速等重型业务场景时，Prism遵循以下 **四大旅程闭环黄金法则**：

### 1. 🎯 图内就地闭环，视线零距离 (In-situ Interaction & Context Anchoring)
* **核心痛点**：很多初版设计把“展开全部”、“重置过滤”或“下钻详情”做在页面右上角的全局工具栏，用户在看图表时视线被迫上下反复横跳，产生严重的“操作距离断层”。
* **设计策略**：
  * **非必要不跳页，非必要不离图**：操作控制器必须直接长在业务对象内部；
  * 展开/收起控制器设计为**“虚线 Ghost 胶囊卡片”**，直接占位在拓扑图列的第 5 个槽位，点击就地展开；
  * 点击任意节点排障时，优先使用**“就地下钻 Tab 表格”**或**“右侧滑出抽屉 (Drawer)”**，而不是整页重定向。

### 2. 🔍 务实可观测性证据链，坚决抵制“假智能/假定界” (Pragmatic Observability)
* **核心痛点**：AI 或初版 PRD 喜欢设计花哨的“一键 AI 根因定界”大卡片，实际当前后端并没有对应的模型支撑，导致落地变成不可信的“黑盒假卡片”。
* **设计策略**：
  * **可解释性大于黑盒概念**：不搞假定界，而是提供扎实的**可观测性证据链**；
  * 将“定界卡片”重构为**“上下文联动查询”**：点击异常节点/连线 ➔ 自动提取元数据 ➔ 下沉为下方表格的筛选条件 ➔ 自动过滤出该线路下受影响的具体分支与用户；
  * 为规划人员与最终用户提供“看得到、查得清、能溯源”的扎实排障路径。

### 3. 🧱 同源数据聚合与配额实时防呆 (Grouped Data & Safe Controls)
* **核心痛点**：多规则配置页面平铺了 20+ 个源站条目，字段分散、页面极长，规划人员看后觉得“太散、很累、易配错”。
* **设计策略**：
  * **宏观归纳降低认知负荷**：相同源站或相同地域的配置项，系统自动聚合进一个“聚合大卡片”；
  * 卡片 Header 展示分组名与子规则计数，支持批量折叠/展开；
  * **实时配额自动计算与防呆**：卡片底部配备实时计算器，当划拨带宽超出全网剩余可用配额时，即时红色拦截并高亮警告。

### 4. 🔗 三级排障联动数据流与上下文提示条 (3-Tier Linkage Data Flow)
* **核心痛点**：用户在趋势图点击了异常点，但不知道下面的拓扑和表格有没有同步变动，缺乏状态反馈。
* **设计策略**：
  * 构建标准的 **“时间趋势 (L1) ➔ 拓扑健康度染色 (L2) ➔ 异常明细表格 (L3)”** 三级单向数据流；
  * **必须常驻显式联动提示条**：在表格上方显示 `🔍 正在查看时刻 10:25 关联的异常链路数据 (共筛选出 3 个异常分支)`，并提供清晰的 `一键清除联动 (×)` 按钮，确保用户随时能自由穿梭与返回全局。

## 二、 宏观业务场景转译决策对照表 (Macro Translation Strategies)

| 规划宏观吐槽 / 业务诉求 | 宏观设计病因诊断 | Prism宏观解题策略 (Design Strategy) |
| :--- | :--- | :--- |
| **“配置项太散了，源站相同的能不能合在一起”** | 相同业务属性的条目平铺导致界面冗长，认知负荷大，缺乏层级归纳。 | ➔ **同源卡片聚合模型**：按源站/区域外层聚合，Header 展示规则统计与折叠箭头，底部实时汇总该组划拨带宽与剩余配额。 |
| **“展开按钮在最顶上很怪，和图是割裂的”** | 全局工具栏按钮与局部画布产生操作距离断层，破坏了视觉连贯性。 | ➔ **图内 In-situ 就地闭环**：外部按钮移入图内，用“虚线胶囊卡片”作为占位控制器，点击就地展开/收起，保持交互聚焦。 |
| **“定界卡片太假了，我们现在做不到一键定界”** | 黑盒假智能不符合当前技术底座，降低了 B 端产品的专业度与可信度。 | ➔ **务实联动条件查询**：将假定界重构为上下文联动，点击节点自动提取元数据下沉为表格过滤条件，展示扎实证据链。 |
| **“点完节点后页面跳来跳去，找不到刚才看的内容”** | 视图缺乏锚定机制，页面跳转打断了排障思维流。 | ➔ **局部聚焦与原地抽屉**：点击异常节点高亮关联链路（100%）并淡化无关链路（25%），右侧滑出抽屉或下方就地滚动下钻。 |
| **“状态是同步中/异常，怎么还能点暂停或删除”** | 操作入口未受业务状态机约束，缺少防呆控制。 | ➔ **状态驱动操作可用性**：根据状态动态禁用按钮（变灰），并悬浮 Tooltip 说明原因（如“配置下发中，暂不可操作”）。 |
| **“现在是一格一格的方块，看不出全天趋势”** | 离散切片方块无法连续反映指标劣化坡度与拐点。 | ➔ **散点折线趋势看板**：升级为散点+折线，背景划分为红/黄/绿三段水位区间，异常点标红放大并支持点击一键联动。 |

## 三、 宏观方案设计的交付验收准则 (Macro Acceptance Criteria)

在完成宏观业务方案设计与 Prompt 输出时，必须满足以下 5 条宏观验收标准：
1. **旅程闭环**：用户的核心任务（如排障、配置、发布）在当前视图内形成闭环，无断流跳页；
2. **状态可逆**：任何联动筛选、聚焦高亮必须配备显式的“清除/重置”入口；
3. **真实可信**：不设计无法落地的假智能概念，提供扎实的数据证据链与上下文说明；
4. **防呆拦截**：对于配额超限、状态互斥等高危操作，必须在前端实现即时计算与操作拦截；
5. **结构清晰**：卡片嵌套不超过 2 层，严禁大框套小框，信息密度适中。
