# 宏观方案模板：0 到 1 需求转译与全页面生成 Prompt 模板 (Macro Prompt Template)

> 💡 **宏观模板定位**：
> 当规划人员提供 **全新业务功能描述、粗略 PRD、或提出全页面重构需求** 时，Prism调用本模板合成双重交付成果：
> 1. **输出 A**：向规划人员通俗解释宏观信息架构、用户旅程与业务价值；
> 2. **输出 B**：向 Coding AI 提供包含整体骨架、业务范式、组件装配与数据联动的高保真代码 Prompt。

---

## 📤 输出 A：面向规划人员的宏观设计思考解释模板 (Planner Explanation)

向规划人员交付时，必须使用通俗易懂的业务语言，阐述架构设计的因果关系：

```markdown
### 💡 Prism设计思考：[页面/功能名称] 架构设计方案

#### 1. 业务痛点与用户旅程洞察
- **原设计/痛点**：[分析规划原始想法中可能存在的旅程断层，如：信息分散导致找指标累、跳页排障打断思路、配置太散易出错]；
- **Prism的设计定位**：[明确本页面的核心设计目标，如：构建从宏观大盘到微观排障的就地闭环旅程]。

#### 2. 核心架构与四大设计动作
- 🌐 **信息架构与分区**：[阐述页面如何划分顶部KPI总览、中部核心业务拓扑/图表、底部明细数据表格]；
- 🎯 **操作就地闭环 (In-situ)**：[阐述如何在图内/卡片内完成展开、筛选与下钻，避免跳页]；
- 🧱 **同源数据聚合**：[阐述相同区域/源站的自动聚合策略与实时配额防呆]；
- 🎨 **视觉降噪与审美提升**：[阐述如何运用中性灰底与 Outfit 数字字体，提升专业科技感]。

#### 3. 预期业务价值与体验收益
- 规划/运维人员能够一秒锁定核心异常，排障效率提升 50% 以上，配置错误率显著降低。
```

## 💻 输出 B：面向 Coding AI 的从 0 到 1 高保真执行 Prompt 模板 (Coding Prompt)

```markdown
### 🎯 任务目标：从 0 到 1 构建 [页面/模块名称] 高保真 B 端业务页面

---

#### 🏗️ 一、 页面整体 Shell 与骨架布局 (Layout & Shell)
1. **外层容器**：
   - 采用标准 B 端控制台布局，主背景色为 `bg-[#F7F9FC]`，内边距 `p-6 (24px)`，最大宽度 `max-w-[1600px] mx-auto`；
   - 纵向模块间距使用 `space-y-6 (24px)`。

2. **双底座 Shell 预占位（防跳动 FOUC）**：
   - 顶部 Header 占位：`h-14 bg-white border-b border-[#E1E5EB] shrink-0`；
   - 左侧 Sider 占位：`w-60 bg-[#272E38] shrink-0`。

---

#### 📊 二、 顶部概览区：多维 KPI 指标总览卡片 (参考 business-patterns.md 范式二/四)
1. **结构与栅格**：
   - 使用 `grid grid-cols-4 gap-4` 并排展示 4 联指标卡片；
   - 单卡片样式：`bg-white border border-[#E2E8F0] rounded-[2px] p-4 shadow-xs hover:shadow-sm transition-all`。
2. **字阶与数据表现**：
   - 标签文字：`text-xs text-[#64748B]`；
   - 主指标数值：`text-2xl font-bold font-outfit text-[#1E293B]`，配置数字等宽 `tabular-nums`；
   - 底部同环比胶囊：`inline-flex items-center gap-1 px-1.5 py-0.5 rounded bg-[#FEF2F2] text-[#D9363E] text-[11px]`。

---

#### 🧩 三、 中部核心区：[业务拓扑 / 趋势图 / 聚合卡片] (参考 business-patterns.md)
1. **业务复合范式选择**：
   - [若为拓扑图]：采用实线普通节点（白底）+ 虚线展开控制器（浅灰底 `fill="#F8FAFC"`），支持就地展开与选中局部聚焦（相关链路 `opacity-100`，无关链路 `opacity-25`）；
   - [若为切片看板]：采用 SVG 散点+趋势折线，背景划分绿/黄/红 3 段水位色带，异常散点放大至 6px 并施加 `animate-pulse`；
   - [若为多规则配置]：按源站分组聚合为大卡片，卡片底部提供实时配额计算与超限拦截。

---

#### 📋 四、 底部明细区：高级数据表格与联动查询 (参考 components/comp-table.md)
1. **表格硬性尺寸与规范**：
   - 表头高度固定 `32px`（背景 `bg-[#EDF1F7]`，文字 `text-xs text-[#454C59]`，无圆角）；
   - 内容区单行行高固定 `40px`，文字 `text-xs text-[#2F3540]`；
   - 对齐规则：文本左对齐、数字列右对齐、序号/多选居中、操作列文字统一使用链接蓝 `text-[#1C6EFF]`；
   - 横向滚动时操作列必须冻结 `sticky right-0`。
2. **三级联动数据流与提示条**：
   - 表格上方常驻联动提示条：`bg-[#E8F4FF] border border-[#B3D8FF] p-2 text-xs text-[#1C6EFF] rounded flex justify-between`；
   - 具备清晰的“一键清除联动 (×)”按钮。

---

#### 🚫 五、 全局防破坏与安全约束 (Regression Guard - 强制)
1. **Shell 稳定性**：严禁修改外层侧边栏和顶栏的尺寸，保持响应式布局；
2. **边界与容错**：极端长文本必须补充 `truncate` 与 Tooltip，配置标准 Empty 空状态与 Loading 骨架屏；
3. **状态机约束**：操作按钮可用性严格受数据状态驱动（同步中状态置灰并 Tooltip 解释）。
```
