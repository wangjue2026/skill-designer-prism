## 一、关键发现：iDux 只有 3 个图表组件

设计源列的 8 个家族，在 iDux 里**并不是 8 个组件**，而是 **3 个组件 + 配置分支**：

| 设计源家族 | iDux 组件 | 表达方式 |
| :--- | :--- | :--- |
| 柱状图 | `IxBarChart` | 原生 |
| **折线图** | `IxLineChart` | 原生 |
| **面积图** | `IxLineChart` | **加 `areaStyle` 即变面积图**（不是独立组件） |
| **平滑折线 / 平滑面积** | `IxLineChart` | 加 `smooth: true` |
| **堆叠折线 / 堆叠面积** | `IxLineChart` | 加 `stack` |
| **多 Y 轴 / 双 Y 轴** | `IxLineChart` | 走 ECharts 多 `yAxis` 配置（不在 props 表内）🚧 |
| **饼图 / 环形饼图** | `IxPieChart` | 原生；环形 = `radius` 双值（默认 `['70%','80%']` 已是环形） |
| **南丁格尔玫瑰图** | `IxPieChart` | 加 `roseType` |

> 🔑 结论：**资产里的「家族」应按设计语义分，落地时按“3 组件 + 配置”还原**。所以亚型键仍是 `CHART-折线图·*`、`CHART-饼图·*`，但实现列统一指到 3 个组件。

## 二、三个组件的 Props（A 级 · API 页原文）

### 2.1 `IxLineChart` / `LineChartProps`

| Prop | 说明 | 类型 | 默认值 | ECharts |
| :--- | :--- | :--- | :--- | :--- |
| `data` | 数据内容 | Array | — | `series-line.data` |
| **`areaStyle`** | 区域填充样式 | AreaStyleOption | — | **设置后显示成面积图** |
| `label` | 图形上的文本标签 | SeriesLabelOption | — | `series-line.label` |
| `name` | 系列名称（tooltip / 图例筛选） | string | — | `series-line.name` |
| `markArea` | 图表标域 | MarkAreaOption | — | `series-line.markArea` |
| **`smooth`** | 是否平滑曲线 | boolean | — | `series-line.smooth` |
| `stack` | 数据堆叠 | string | — | `series-line.stack` |

函数：`useLineOption(props, attrs) → ComputedRef<LineChartProps>`

### 2.2 `IxPieChart` / `PieChartProps`

| Prop | 说明 | 类型 | 默认值 | ECharts |
| :--- | :--- | :--- | :--- | :--- |
| `data` | 数据内容 | Array | — | `series-pie.data` |
| `center` | 圆心坐标 | Array | — | `series-pie.center` |
| `label` | 图形上的文本标签 | SeriesLabelOption | — | `series-pie.label` |
| `name` | 系列名称 | string | — | `series-pie.name` |
| `markArea` | 图表标域 | MarkAreaOption | — | `series-pie.markArea` |
| **`radius`** | 饼图半径 | number \| string \| Array | **`['70%','80%']`** | `series-pie.radius` |
| **`roseType`** | 是否玫瑰图 | boolean | — | `series-pie.roseType` |

函数：`usePieOption(props, attrs) → ComputedRef<PieChartProps>`

> ⚠️ **注意默认值**：iDux 饼图**默认就是环形**（`radius: ['70%','80%']`）。要做**实心饼图**必须显式把内半径设为 `0`（如 `radius: ['0%','80%']`）。这与“默认是实心饼”的直觉相反，落地时最容易错。

## 三、选型阈值（直接可判，来自指南页原文）

| 判断 | 结论 | 原文依据 |
| :--- | :--- | :--- |
| 要比**多个分类的大小** | → **柱状图** | 柱状图用于多个分类间的数据（大小、数值）对比 |
| 要看**时间或有序分类的趋势** | → **折线图** | 折线图反映事物随时间或有序类别变化的趋势 |
| **分类不存在顺序** | **不得用折线图** | “分类间的数据比较，如果分类不存在顺序，那么不要使用折线图” |
| 要看**占比且总和 100%** | → **饼图** | 每个区块表示占总体比例，所有区块和为 100% |
| 饼图**分类数** | **≤ 10 种** | “常用于不超过 10 种分类，且总和为 100% 的分类对比” |
| 饼图**分类多**（>10） | → **玫瑰图** | 玫瑰图“比基础饼图和环形饼图展示更多的分类数据” |
| 要**表现力更强 / 表示上下限** | → **面积图** | 面积图可表示温度的最小值、最大值 |
| 柱状图**分类数** | **≤ 20 条**；多组系列 **≤ 10 组** | 柱状图指南页 |
| **风险等级**类配色 | 走**语义色板** | 饼图指南「语义色板」：用于风险等级的配色等 |

**平滑 vs 折线 的选择规则（指南原图原文）**

> ① 数据反馈为**整体趋势**时建议使用**曲线**（平滑），尤其数据波动较大，用折线会让整体较混乱；
> ② 如果**不需要表达更精准的数据**，用曲线会更加精美。

即：**要读准确值 → 折线（不平滑）；看整体趋势且波动大 → 平滑**。

### 5.2 环形带总数（总数居中）的落地结构

> ⚠️ **此前画错的三处**（2026-11-03 按设计源 CSS 与批注纠正）：① 只有一层圆底 → 实际**两层**；② 数字 20px → 实际 **24px ALIBABA Font**；③ 图例单列 → 实际**两列且带数值**。

**层次结构**

```text
┌ 外圆底色 144×144（180deg #458fff14 → #458fff02）
│   ┌ 环形扇区（radius 70%~80%，六色 270deg 渐变 + 1px 白描边）
│   │   ┌ 内圆底色 80×80（180deg #458fff1a → #458fff00 + 渐隐描边）
│   │   │      · 中心数字 24px ALIBABA Font  #2F3540
│   │   │      · 「风险资产总数」12px #6F7785

图例（右侧，两列，每项 = 色块 + 名称 + 数值）
```

| 项 | 规格 | 依据 |
| :--- | :--- | :--- |
| 外圆 | 基准 144×144，`linear-gradient(180deg,#458fff14,#458fff02)`，**始终与环同心、比环略大**；**等比缩放**（= 容器短边 100%） | 设计源 CSS + 缩放确认 |
| 内圆 | 基准 80×80（`left/top:32`），`linear-gradient(180deg,#458fff1a,#458fff00)` + `border-image: linear-gradient(180deg,#458fff29,#458fff00)` 1px；**等比缩放**（= 容器短边 55.6%，即 80/144） | 设计源 CSS + 缩放确认 |
| 中心数字 | **24px / 24px**，`ALIBABA Font`，normal，居中，`#2F3540` | 设计源 CSS |
| 数字位置 | **与圆环正居中重合** | 设计源批注：「资产总数要居中，与圆环正居中」 |
| 图例 | **两列**，每项「**图标 + 对象名 + 数字**」三段紧邻；色块用该系列的 270deg 渐变 | 设计源批注 |
| 图例·行间距 | **上下 12px** | 设计源批注 |
| 图例·列间距 | **左右 16px** | 设计源批注 |
| 图例·数字对齐 | **右对齐**（同列数字右边缘对齐） | 设计源批注 |
| 图例·名称↔数字 | **8~48px**（下限 8、上限 48） | 设计源批注 |
| 图例·溢出 | **按可用空间自适应行数**（2 列 × N 行）；**行数超出容器高度才翻页** | 已裁决：覆盖 iDux「超过两行翻页」的死规则 |
| 图例↔饼图主体 | **24~64px 自适应**（按可用空间取值） | 设计源批注：「根据空间来自适应」 |

> 📌 图例用 ECharts 内置 `legend` 做不出“两列 + 每项带数值”的排布，建议**用 DOM 图例**（ECharts 只画环，图例独立用 HTML 栅格）——回归预览即按此实现。
>
> 📐 **缩放口径（已确认）**：外圆 = 容器短边 100%、内圆 = 容器短边 55.6%，两者随容器**等比缩放**，不是固定 144/80 像素；环仍是 `radius:['70%','80%']` 百分比，因此三者在任意尺寸下相对关系不变。

## 七、正常态还原判据

1. **折线**：X 轴必须有序（时间或有序分类）；无序分类不得用折线；
2. **面积**：不是独立组件，是 `IxLineChart + areaStyle`；填充需弱于描边，避免压住网格；
3. **饼图**：先确认要实心还是环——iDux **默认环形**（`radius: ['70%','80%']`），实心必须显式 `radius: ['0%',...]`；
4. **分类数**：饼图 ≤10；柱状 ≤20；多组系列 ≤10；
5. **图例**：折线/饼图**图例必填**（可选项列表里饼图图例是必选构成）；
6. **玫瑰图**：仅在分类多或需半径对比时使用，不得作为“好看”的替代。

## 九、官方实现要点（源码级 · 点示例右上角 `<>` 取得）

> 包名 `@idux/charts`；折线组件 `<IxLineChart>`、饼图 `<IxPieChart>`。以下取自折线图「条纹面积图」demo 源码与注释。

### 9.1 折线的三个“高级效果”对应的官方函数

| 效果 | 官方函数 / 配置 | 说明 |
| :--- | :--- | :--- |
| **条纹填充**（条纹面积图） | `use(AriaComponent)` + `useLineChartAreaStripe(chartRef)` → `lineChartAreaStripeConfig` | 借助 ECharts 无障碍插件实现纹理；配置对象直接展开进 `series` |
| **线条两端透明、中段实色** | `useLineStyleColor` | 赋给 `series.lineStyle.color` |
| **区域渐变填充**（阴影效果） | `useLinearGradient` | 赋给 `series.areaStyle.color` |
| 颜色加透明 | `getAlphaColor` | 生成同色带透明度，做渐变的淡端 |

### 9.2 折线图必备的两个轴/点配置（源码出现）

~~~ts
xAxis: {
  boundaryGap: false,   // ← 折线图 X 轴必须贴边（柱状图是 true）
  data: [...],
},
series: [{
  ...lineChartAreaStripeConfig.value,  // 条纹面积时才需要
  showSymbol: false,                   // 不显示数据点标记
  smooth: true,                        // 平滑（看趋势时开）
}]
~~~

> 📌 **柱状 vs 折线的轴差异**：柱状图 `boundaryGap` 为默认（分类柱居中、两侧留白）；折线图必须 `boundaryGap: false`，否则首尾点会悬空。这是最容易做错的一处。

### 9.3 面积图=/=独立组件（再次确认）

折线的面积形态通过这些方式实现，**没有 IxAreaChart**：
- 基础面积：`series.areaStyle` 存在即填充；
- 阴影/渐变面积：`series.areaStyle.color = useLinearGradient(...)`；
- 条纹面积：`useLineChartAreaStripe` + `AriaComponent`。

**饼图图例与标题的位置（源码实测，与柱状图不同）**


**中心总数的写法（要点）**

~~~ts
import { graphic } from 'echarts/core'
const getLinearGradient = (start, end) =>
  new graphic.LinearGradient(0, 0, 1, 1, [{ offset: 0, color: start }, { offset: 1, color: end }])
// 再用循环生成点状数据拼出环形刻度，itemStyle.color 逐段上色
~~~

> 🚧 `getDotData()`（100 段点环）的完整参数未逐行核对，属“装饰性刻环”，还原时可按需简化。
