# 可视化样式资产 · visual-styles（总入口）

> **一句话**：本目录只回答两个问题——**「内容块长什么样」**（内容件 `VIZ-*`）与**「图表画什么图形」**（图表件 `CHART-*`）；两者共用的色 / 字 / 阴影 / 渐变值单独放 `token/`。
> **服务对象**：设计说明书第四章《[可视化件声明](../../01-system-solution-design/⑤设计说明书/5.0-设计说明书标准模板.md)》、步骤 3 的 [4.2 组件选型](../../01-system-solution-design/④布局与结构/4.2-业务能力与组件选型指引.md)、步骤 5 的 coding 绘制。
> **上游经验库**：[D-11 可视化件选型与还原](../../01-system-solution-design/②设计思考与决策/通用设计决策/D-11-可视化件选型与还原.md)（回答"什么时候用哪个件"）。

## 一、分类法：两个分块 + 一个值层

本目录此前把「内容件」和「图表」混在一层（根目录写内容件、`charts/` 写图表、token 散在两边），一键查不到家。现按**件的职责**分三区，判据只有一句话：

| 分区 | 回答什么问题 | 键前缀 | 目录 | 判定问题（需求来了问自己） |
| :--- | :--- | :--- | :--- | :--- |
| **内容件** | 装**什么信息**、装在哪、多大、怎么退化 | `VIZ-*` | [`内容件/`](内容件/README.md) | 这一块是"信息块"吗（指标概览 / 对象身份 / 原理说明 / 步骤引导 / 配置图解 / 实时预览 / 状态流程 / 链路拓扑 / 条目摘要榜 / 状态分布条） |
| **图表件** | **画什么图形**、怎么配色、什么比例 | `CHART-*` | [`图表件/`](图表件/README.md) | 这一块的核心是"读图形"吗（趋势 / 分类对比 / 构成占比 / 累加构成 / 两组对比） |
| **值层** | 这个色 / 字 / 阴影 / 渐变**是多少**、叫什么名 | — | [`token/`](token/README.md) | 只取值，不描述件型 |

**三条不重叠原则**（原目录结构混乱的根因，逐条堵住）：

1. **值层只管取值**：件型文档只引用命名 token（如 `灰阶色/二级背景颜色`），裸 hex 必须同时给出命名；`token/` 不描述任何件型的解剖。
2. **内容件与图表件共存、不互相替代**：内容件决定"装在哪、多大、收不收"，图表件决定"图形怎么画"。典型组合——`VIZ-01-C`（分析型双区）＝ 内容件容器 ＋ `CHART-*` 图形；图表嵌在卡片里再套 `CHART-柱状图·卡片化`。
3. **一个键只登记一处**：件型键登记在 [`内容件/README.md`](内容件/README.md) §二；图表键登记在 [`图表件/README.md`](图表件/README.md) §二；机读镜像分别落 `token/基础-tokens.json` 与 `token/图表-tokens.json`。**其他文件一律引用、不再复述整表。**

## 四、全局铁律（三分区共同遵守）

1. **不许裸色值**：配色必须落在 [`token/基础-token.md`](token/基础-token.md) 白名单内，写 `#EDF1F7` 必须同时写命名 token `灰阶色/二级背景颜色`；表外颜色一律视为自造。
2. **状态一律三元组**：浅底 + 深字 + 浅边框，禁止原生高饱和纯色。
3. **不许拿实现层值冒充设计源值**：设计源与实现层是两个口径（见 `内容件/` 两文件分工），冲突以**设计源**为准，偏差记入台账。
4. **图标风格全局统一**：线性 / 面性、线宽、圆角一致；查无的业务专属图标标"需按风格绘制"，**严禁杜撰图标名**（见 [`../components/icon-map.md`](../components/icon-map.md)）。
5. **视觉权重默认弱于主内容**（D-11 母尺 ⑪）：可视化件是辅读件，不得压过主内容。
6. **一值一出处**：同一个数值只在一处定义（值层或某家族规范），别处一律引用。
8. **容器语气默认走「风格档 B（SASE）」**：无框或白边 `1px #FFFFFF`、蓝调柔光 `glow-blue-s1` `0 4px 20px rgba(117,157,218,.15)`、圆角 `2`；档 A（设计源 `graphite-l20` + `dropshadow-s1` + `r4`）为可切换档。整页同档不得混用，切档只换这组 token 不动结构（详规见 [`token/README.md`](token/README.md) §六）。
7. **只沉淀框架层，不沉淀业务逻辑**：能进的是结构 / 几何 / 配色 / 状态编码方式 / 交互退化 / 空态表现；**不进**的是「某个业务对象该不该有某状态、指标怎么算、字段什么含义」这类需求侧规则。判据一句话——**换一个业务、换一组数据，这条还成立吗？** 成立才进本库，否则归说明书第四章 / TR1。

## 五、填充机制（由蒸馏填充，非纯人工）

> 本目录与 [D-11 经验库](../../01-system-solution-design/②设计思考与决策/通用设计决策/D-11-可视化件选型与还原.md) **同源同批**：一次蒸馏取证产出**两份**——① **经验**（选哪种件、怎么嵌 / 联动 / 退化）落 D-11；② **样式规范**（这个件长什么样）落本目录对应分区。

| # | 规则 | 说明 |
| :---: | :--- | :--- |
| 1 | **有样本才填** | 只写从真实页面 / 截图 / DOM **实测**到的读数（色值 / 线宽 / 圆角 / 间距 / 图标形态 / Token）；**无样本一律标 🚧 待取证，严禁脑补** |
| 2 | **实测 + 归纳** | 可测项（配色 / 尺寸 / Token 映射）直接取数；判断项（线性 or 面性、是否统一、图形语言）由多产线样本**归纳** |
| 3 | **多风格 → 人工指定 / 分叉** | 多产线风格不一致时，先收敛为「统一基线」；若确有两种以上正当风格，分叉为「风格档 ① / ②…」并由规划人员**指定默认档** |
| 4 | **与经验同锚** | 每条风格规范须挂到 D-11 对应决策场景的样本行，与经验证据互为佐证 |

| 分区 | 覆盖到哪一步 | 明细 |
