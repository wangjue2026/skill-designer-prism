# 内容件 · 件型线框与几何（可还原版）

> **定位**：`内容件/` 的**落地层**。每个件型给「结构线框 + 几何表 + 状态矩阵 + 还原判据」四件套——[`件型样式卡.md`](件型样式卡.md) 回答"这个件由哪几层组成、用哪条 token"，本文件回答"**每一层多大、间距多少、什么态下长什么样**"。对齐 `../图表件/柱状图-亚型规范.md` 的线框做法。
> **为什么要有这份**：样式卡只有文字解剖（`容器 ▸ [指标项 × N] ▸ …`），没有线框与数字，coding 只能猜；本文件补的正是这一层。
> **配色口径**：颜色一律写 [`../../global-styles/design-color.md`](../../global-styles/design-color.md) 的命名 token（`graphite-*` / `blue-*` / `red-d10`…），不写裸 hex；示例稿原值见 §二 映射表。

## 一、通用约定

| 项 | 约定 |
| :--- | :--- |
| 单位 | 全部 `px`（逻辑像素，1×） |
| 颜色写法 | 命名 token，**不写裸 hex** |
| 数字字体 | 计数 / 规模 / 指标值一律等宽数字，右对齐（保证竖排成列） |
| 行即卡 | 摘要行、分布行统一「浅底 + 4px 圆角 + 无边框」，hover 才出描边——避免一屏全是框 |
| 截断方向 | **标识与计数不截断，说明文案可截断**（读数优先级：是谁 > 多少 > 为什么） |
| 容器 | 件容器底 `graphite-l40`（设计源）／`graphite-l50`（部分实现层），描边 `graphite-l30 #E1E5EB`，圆角 `4`，阴影 `dropshadow-s1` |
| 视觉权重 | 件弱于主内容：件内最大字号不超过主内容标题一档 |
| 证据列 | `A-实现层`／`A-示例`／`设计源`／`🚧` 逐项标注 |

**只沉淀框架层**（本库准入红线）：

| 能进本库 | 不进本库 |
| :--- | :--- |
| 结构（分区 / 位次 / 节点与段的组成）、几何（尺寸 / 间距 / 圆角）、配色归位、状态的**编码方式**（色 + 形双重编码）、交互与退化、空态与无数据的**表现** | 某个业务对象**是否**有某状态、某个指标的汇总口径与算法、字段的业务含义、某条业务规则（"谁必须红、谁不许红"） |

> 判据一句话：**换一个业务、换一组数据，这条还成立吗？** 成立 → 框架层，进本库；不成立 → 业务层，归需求侧文档（说明书第四章 / TR1），**不进样式库**。
>
> 📌 **读法约定**：本文件线框里出现的**对象名、字段名、数值、状态词**（如 `终端 / POP / 连接器`、`未安装`、`R2 198ms`）一律是 **示例数据或证据溯源**，**可整块替换**，不构成规范；规范只由「结构 / 几何 / 配色 / 编码方式 / 交互 / 退化」六类字段承载。换业务时：**换示例、不换结构**。

**两种风格档 · 默认档 B**：

| 档 | 卡片描边 | 阴影 | 圆角 | 面板 / 条目底 |
| :--- | :--- | :--- | :--- | :--- |
| **B · SASE 款（默认）** | 白边 `1px #FFFFFF` 或完全无框 | **`glow-blue-s1` ＝ `0 4px 20px rgba(117,157,218,.15)`**（扁平件可 `none`） | `2` | `graphite-l50`，选中 `#FFFFFF` |
| A · 设计源款 | `graphite-l30 #E1E5EB` | `dropshadow-s1` | `4` | `graphite-l40` |

> 两档是**语气差异**不是对错；**默认 B**，整页同档、不得混档；切档只换这 6 项，结构与几何不变。详规见 [`../token/README.md`](../token/README.md) §六。

**位图件的特殊约定**（③⑤⑧A）：这类件**不靠"画"还原**，靠"带走素材"。线框只定义**容器位**（宽高、内距、是否可收起），图本体按素材原样贴入，**禁止 DOM 重绘**。素材登记见 §十三。

## 二、示例稿色值 → 命名 token 映射（沉淀前必经）

> 映射目标 = [`03-design-assets/global-styles/design-color.md`](../../global-styles/design-color.md)（**全局样式库命名**：`graphite-*` / `blue-*` / `red-d10`…）。它与 [`../token/基础-token.md`](../token/基础-token.md) 的**设计源命名**是同一套色的两种叫法，一一对应，例：`graphite-l40` ＝ `灰阶色/二级背景颜色`、`graphite-d40` ＝ `灰阶色/正文&标题`、`turquoise-d10` ＝ `在线&健康`。写规范时**优先用全局样式库名**，需要溯源设计源时再补设计源名。

### 3.6 还原判据

1. 项高 `72±2`、左内距 `32`、右内距 `12`（A-实现层口径，引用时须标明）；
2. 数值 `24/700`、标签 `12/20`；数值与标签的**字重差不低于 300**，形成"值先行"；
3. 异常指标**图标与数值同色**，不得只改一项；
4. 容器底与页面底必须不同层（`l40` vs `l50`），否则件"浮不起来"；
5. 三档形态不得混用：扁平条不带维度树、分组卡必须有树、分析型必须有图；
6. 指标 ≤2 时必须退回文字（这是上游判据，不是样式选择）。

### 3.7 反例

- 指标只有 2 个还套概览条 → 版面浪费，读数变慢；
- 用高饱和纯色做指标值 → 违反状态三元组；
- 异常只改数字颜色、图标仍是常态色 → 语义不一致；
- 分组卡里再嵌一层卡片（卡套卡）→ 层级过深；
- 把"分析型双区"的图画成位图 → 图应来自图表件，须可随数据变。

### 3.8 线框 A2 · 扁平指标条（标签在上 · 可点筛选）

> 来源：SASE 应用列表（A-实测）。与 A 的差别：**标签在上、数值在下**，图标 `16px` 内联在标签前；整条**无边框 / 无阴影 / 无圆角**；每格是**筛选入口**，选中格转白底。

```text
┌ 1176 × 73 · 无框 · 6 格等分无缝 · mb8 ─────────────────────────────────┐
│ ┌ 196×72 底 l50 内距 32/12 ─┐┌ 196×72 选中=白底 ─┐┌ … ┐                 │
│ │ ▣16  标签 12/400 d40 mb4 ││ ▣16  全部 14      ││   │                 │
│ │      数值 24/700 d40 ml20││      数值 24/700   ││   │                 │
│ └──────────────────────────┘└───────────────────┘└───┘                 │
└────────────────────────────────────────────────────────────────────────┘
   ↑ 数值 ml20 = 图标 16 + gap 4，正好对齐标签文字起点
```

| 项 | 值 |
| :--- | :--- |
| 条尺寸 / 内距 | `1176 × 73`、`mb 8`；无圆角无阴影无描边 |
| 单格 | `196 × 72`，内距 `0 12 0 32`，6 格等分 |
| 格底 | 常态 `graphite-l50`；**选中 `#FFFFFF`** |
| 标签行 | `12 / 400`，`graphite-d40`，行高 `16`，`mb 4` |
| 内联图标 | `16 × 16`，`mr 4` |
| 数值 | `24 / 700`，`graphite-d40`，`ml 20` |
| 状态色 | 标签前的图标按状态语义着色（绿/红/橙/蓝/灰），**文字不变色** |

**判据**：① 6 格宽度必须等分且无缝；② 数值 `ml 20` 与标签文字左对齐；③ **默认不得预选任何一格**——四格是同等信息，一上就被反白的那格会被读成"更重要"；④ 选中态用**弱提示**（底部 2px 主色内线 / 仅文字转主色），**禁止整格反白造成强弱差**；⑤ 每格可点且点击后列表同步筛选；⑥ 图标 16 / 标签 12 / 数值 24 三级，不得互相抢；⑦ **分组不拆容器**：指标分属两个语义组时，**仍在同一个条容器内**，只在"相邻内容之间"加 `1px graphite-l20` 竖线（高 `40`、垂直居中、两端留白 `16`），**不得拆成两块卡片**；实现上**整条只铺一次底、各格 `transparent`**——若每格各自铺底，格间缝隙会露出页底，形成"白缝 + 一条线"，视觉上仍是两块容器；⑧ **竖线的适用边界**：竖线只服务"同一容器内的相邻内容"；**已经用间距分开的两块（两张卡）不要再画线**——线 + 间距叠加等于双重分隔，读者会读成"两个容器 + 一条多余的线"；⑨ **单值组不得压窄**：单值格的宽度**不低于**任一多信息格（本例 `276` vs `281`），否则像"留了个空槽"，显局促；多信息组内部只靠内距分读，不再加线。
**反例**：格宽按文字自适应（读数错位）；选中用蓝色描边（与筛选条样式混淆）；数值与标签同字号（失去"值先行"）；**默认把第一格做成白底（其余灰）**——同等信息被做成主次关系，属严重误导；**一格单值 + 三格带分布仍等宽平铺**（左侧过空、右侧拥挤，轻重失衡）；**把条拆成"窄组 + 宽组"两块卡片**（单值区被压成一条窄缝，显局促小气）；**先用间距分区、又补一条竖线**（双重分隔，读成两张卡）；**每格各自铺底、竖线落在格间缝隙里**（白缝 + 线 = 还是两块容器，只是多了一条线）。

#### 3.8.1 组合用法：指标格内嵌迷你分布条（`VIZ-01-A2` ＋ `VIZ-10`）

> 当某个"指标"本质是**分类构成**（按系统类型、按状态、按等级），既不要在格子里平铺 3 个数字，也不要为它另开一块构件——用"**一格 = 一个维度，格内嵌迷你分布条**"。这是 ① 与 ⑩ 的**正式组合用法**，不是新件型。

| 项 | 值 |
| :--- | :--- |
| 条 | `h 4`、`r full`、**段间无缝无圆角**、宽上限 `196`、轨道 `graphite-l40`；位置占"数值"位（`ml 20`，与标签文字左对齐） |
| 图例 | 紧凑档 `10px`；状态点 `6×6`、间距 `10`；顺序「点名 + 数值」，数值 `500` 等宽 |
| 取值 | 段宽 = 各状态数 ÷ 合计；图例数字与段宽必须自洽（沿用 §12.5 判据 1） |
| 上限 | 状态 **≤3**；>3 改用"数值 + 总数"或退回独立的 ⑩ |
| 格内高度 | 与 A2 同格 `72`：标签行 `16` ＋ 间距 `4` ＋ 条 `4` ＋ 图例 `14` |

**判据**：① 一格只表达**一个**分类维度；② 条与图例同基线（都落在数值位）；③ 状态色沿用 ⑩ 的**有序色阶**（绿 → 橙 → 红），不因数值大小换色；④ 分类维度 >3 或需要逐类精确读数时，**退出组合**，改用独立的 ⑩。
**反例**：一格里塞两组分类（读不出来）；条做到 `8px` 以上（抢主内容）；图例数字与条宽不一致（自相矛盾）；用这套组合表达"趋势"（趋势归图表件）。

**反例**：三步纵向堆叠（占掉首屏）；序号做成圆形徽章（与 ⑦ 阶段节点混）；链接与说明同色（找不到入口）；把原理小图做成可交互（它不是数据件，交互归 ⑧）；**末段接一块没有序号、也没有卡片的图**（读者第一反应是"这里漏了第 4 步"）；三张卡高矮不一（说明行数不同就放任）；**为"填空"加一串无名胶囊**（读者看不懂，反而降低可信度）。

2. **不表达状态的节点用中性色**（`graphite-l10` 描边 + `graphite-d10` 图标），**不得借用"正常"的语义绿**——否则读者会以为它被判定为健康；
3. **数值块的出现条件是"有数据"**，不是"异常"；无数据不编数、不留空位、不打勾；
4. **多级汇总口径自洽**：链路级汇总不得小于任一分段值（本例 `224 ≥ 198` ✓）；若取"最差值"而非"求和"，必须在文案上写明；口径不明即判错；
5. **异常符号全件统一**：现状段 1 用 ✗（10px）、段 2/3 用 ⚠（12px）——**判为缺陷，须统一为一种**；
6. 四件套比例固定：节点 `44` / 徽标 `20` / 线 `h2` / 箭头 `10`；
7. 段宽自适应（`flex-1`），不得定宽——链路节点数变化时靠它伸缩；
8. 状态色只用两档：健康 `turquoise-d10`、异常 `red-d10`（现状用 `red` 主色 `#F52727`，须降档）。

### 10.11 反例 C

- 把线性链路画成网络拓扑（加分支/环路）→ 那是形态 B 的活，段语义会丢；
- **每段都挂数值** → 变成一张表，失去"一眼定位坏在哪段"；
- 多级汇总不自洽（链路值 < 分段值）→ 读者不信任何一个数；
- 给"不表达状态"的节点套语义色 → 中性被读成"正常/异常"，制造虚假结论；
- 一红到底（节点、段、徽标、胶囊全红）→ 读不出坏在哪个环节；
- 异常符号混用 ✗ / ⚠ / ⛔ → 同一件里三种"坏"，语义崩塌。

#### 10.14.3 还原判据

1. **三层级顺序不可乱**：概览卡 → 列标题 → 节点；缺列标题即退化为"一堆卡片堆叠"；
2. 列标题竖条 `2 × 14`、文字 `14 / 600`、色 `#1C6EFF`，三者同源；用深灰字判错；
3. 圆节点 `32` + `1px #D3D7DE` + 图标 `30`，标签 `12 / 20` `#5E6573`；
4. 详情卡**必须有两段底**：标题条 `#F7F9FC` + 内容区 `#FFFFFF`；两段同底即失去"卡头"识别；
5. 指标行 `h32`、行距 `8`、数值 `20 / 700`，行距 ≠8 即密度失真；
6. 分组卡 `r4` + `1px #FFFFFF` 内描边 + `0 2px 10px`，白区内缩 `5`；内描边不可省（否则与白内容区糊成一片）；
7. 组内节点 `72 × 56`、角标 `14` 贴图标右上，不超过 1 位；
8. 连线 `1px #A1A7B3`、箭头 `5 × 5`、端点留 `8`；
9. 画布点阵 `10 × 10`、点 `2`、`#E1E5EB`；点距变 8 或 12 都会与节点密度打架。

#### 10.14.4 反例

- 球 `40` 配角标 `14`（两套口径混拼）→ 角标比例失真；
- 用图例列替代"列标题"（10.13 的图例列 ≠ 本节的列维度标题）→ 读者分不清"分组"与"图例"；
- 详情卡标题条与内容区同底色 → 卡头消失；
- 连线改 `2px` 或换 `#D3D7DE` → 比设计源深一档、比实现层粗一倍；
- 0 值也标红 → "有风险"与"为 0"同色，告警语义崩塌；
- 分组卡用纯白底、省掉内描边 → 与内部白区糊在一起，只能靠阴影硬撑；
- 画布用滚动条代替拖拽/缩放 → 节点被切一半，链路读不全。

#### 10.15.2 状态与交互矩阵

| 态 / 触发 | 表现 | 判据 |
| :--- | :--- | :--- |
| 默认 | 节点常显；连线单色 | 无"选中态"概念 |
| 画布拖拽 | `cursor: grabbing`，可平移 | 内容超出画布时靠拖拽，不出滚动条 |
| hover 节点 | **无任何反馈** | 本形态线上无 hover；重建时不要自行加放大/描边 |
| 点击节点 | 无导航、无浮层、无 DOM 新增 | 节点是展示物；下钻走页面其他入口 |
| 画布绘制反馈 | 🚧 点击后是否有 canvas 重绘未确认 | 需做 canvas 像素前后 diff |
| 图例 / 工具组 | 图例与缩放组常显；展开态 🚧 | 图例点开应有说明浮层（线上未验证） |

| 空值 | 显示 `暂无`、色 `#BEC3CC` | 不隐藏行，保持两行等高 |
| 节点数 > 画布 | 依赖拖拽；无自动布局证据 | 🚧 自动排布规则未采 |

#### 10.15.3 还原判据

1. **平面矩阵必须是纯旋转**（三列正交、模长 1），加了 `perspective` 会近大远小，与素材透视打架；
2. **节点必须做逆矩阵扶正 + 平移还原**，只转不补会让节点飞离原位；
3. 节点用**平面逻辑坐标**定位（间距 181），不要用屏幕像素反推；
4. 图标立体面来自 SVG 素材，**不要用 CSS 3D 重画**；
5. 连线在 canvas 内画，线宽写逻辑像素（本样本 2），落到屏幕会因投影压缩到 ≈1.4；
6. 连线颜色 `#AEB9CB` 是"浅底点阵上刚好可见"的档位，换更深/更浅都会失衡；
7. 工具栏白底 `r2` 无阴影，贴左上内距 12，与节点视觉权重拉开；
8. 命中高亮只落在字段值上（`1px` 双线），不要扩展到整节点。

#### 10.15.4 反例

- 用 `perspective + rotate3d` 硬凑 2.5D → 节点近大远小，与素材自带透视冲突；
- 每个节点各自算一个变换（不复用同一矩阵）→ 节点朝向不一致，像"翻倒的贴纸"；
- 用 SVG 画连线但坐标写屏幕值 → 拖拽/缩放后线与人错位；
- 给节点加 hover 放大或描边 → 线上没有这两种反馈，属自造交互；
- 把 `#AEB9CB` 换成 `#D3D7DE` → 在浅底点阵上几乎看不见；
- 把节点做成卡片（`D` 的形态）再整体倾斜 → 卡片文字被斜切，失去"扶正"的意义；
- 点阵用 CSS `pattern` 画 → 与这里"整图 webp 平铺"的密度/边缘表现不同。

| 态 | A 三态 | B 两态 |
| :--- | :--- | :--- |
| 默认 | 行底 `graphite-l50`，无描边 | 透明底 |
| hover | 底 `white` + `1px blue/40`；类目与状态名转 `blue` | 未实现（🚧 建议同 A 的 hover 只作用于类目名） |
| 点击 | ① 类目区 → 该维度全部；② 状态数值 → 该维度该状态；③ 条段 → 同 ② | 类目 → 该类型设备台账（🚧 未实现） |
| 某状态 = 0 | 该数值显示 `0`，对应段宽 0（**不隐藏标签**，保持三段可比） | 0 → 文字用 `graphite`（弱化），条 100% 单色 |
| 所有状态 = 0 / 未上报 | 🚧 建议：条置 `graphite-l40` 全灰 + 数值显示 `—`（不显示 0，避免误读为"已上报且为 0"） | 🚧 同左 |
| 行列数上限 | `≤3` 行（本样本 3 行）；超出 → 走表格 + 内嵌迷你条 | `≤3` 行 + 1 明细行 |
| 名称过长 | 类目区定宽 `126` → 名称 `truncate`，`title` 兜底 | 名称定宽 `58` → 超 3 字截断（**已知风险**：4 字以上会被切） |
| 加载 | 🚧 未覆盖 | 🚧 |
| 无权限 | 🚧 未覆盖 | 🚧 |

### 12.5 还原判据（照此验收）

1. **比例自洽**：段宽 = 各状态数 / 总数；Σ各状态数 = 总数 = 类目区显示的总数。**三者任一不等即判错**（示例稿分支行 24 vs 22+2+2=26 就是错例，见 §12.6）；
2. 条 `h4`、整条 `r full`、**段间无 gap 无圆角**；条高 >6px 判抢主内容；
3. 状态色固定有序：`green` → `orange-l10` → `red-l10`（B 形态 `turquoise-d10` → `red-d10`），不因占比大小换色；
4. 数值行在条**上方**，状态名左对齐、数字右对齐，三段定宽 `70/52/44`，竖排数字能对齐成列；
5. 层级成立：类目 `graphite-d40` > 状态数 `graphite-d20` > 总数 `graphite-d10`；
6. 行高 `36` / 行距 `8` / 行底 `graphite-l50` / 圆角 `4`（B 形态行高 `24`、无底）；
7. 点击粒度到「维度 × 状态」，不是只到维度；
8. `0` 值得弱化不隐藏；`未上报` 与 `0` 必须是两种不同表达。

### 12.6 反例

- **用环/饼替它**：多类目要 N 个环，横向比长短比比角度更准；
- **段间留白或加圆角**：比例失真，且视觉上出现"假间隙"；
- **条宽按"数值/最大值"归一**：必须 `100%` 堆叠，否则类目之间不可比；
- **状态数之和 ≠ 总数**：示例稿「分支 24 个 / 22 + 2 + 2」自相矛盾，且条宽写死 `70/15/15` 与数值不符 → 录入错误，**不复刻**；
- **用红色表示「0 异常」**：制造虚假告警，`0` 必须弱化；
- **三段以上仍用横条**：状态 >4 → 换堆叠柱 / 100% 堆叠图表件；
- **把条做成可拖拽/可悬停 tooltip 才能读数**：紧凑件要求"不用交互就能读"，数值必须常显。
