> 被测页面：`design-spec-白板测试.html`（同一目录）。该页是最小验证页，不是完整说明书，故自检的「章节数」一项不适用。

## 四、边界判定（关键取舍）

| 场景 | 判定 | 理由 |
| :--- | :--- | :--- |
| 是否用 `VIZ-01-A2`（可点筛选扁平条） | 否，用 `VIZ-01-A` | A2 的前提是"点格即筛下方列表"，本白板页下方只有用户明细表、无终端列表，筛选无承接对象 |
| 若指标只有 2 个 | 退回纯文字 | EP-01 负向门槛：≤2 个纯数值不套概览条；本需求因"异常/未纳管"拆出 4 个指标才成立 |
| 是否用 `VIZ-08-B`（研判型拓扑） | 否，用 `VIZ-08-C` | B 是图状分支（有汇聚），本路径为线性；且 B 为 `pending` 无实测值 |
| 平台构成是否用表格 | 否，用 `VIZ-10-A` | 类目 × 互斥状态构成、行内横向对比，表格读不出占比 |

## 六、本次测试暴露并修正的问题

| # | 问题 | 处理 |
| :---: | :--- | :--- |
| 1 | `style_must` 仍要求写容器尺寸（390/774/1176/499/644 等），与"容器自适应"冲突 | 10 个键的 `style_must` 重写：删容器组，只留元素级/色阶/字阶 |
| 2 | 渲染输出通不过自身机检（`h4` vs `h 4`、`16×16` vs `16px`） | 正则补实际写法（`h4`/`h2`/`16×16`），已全键校验一致 |
| 3 | `VIZ-10-A/B` 数值无 `px` 单位，风格规范不可直接执行 | 补单位（36px / 126px / 70/52/44px） |

| 5 | `viz-audit` 把第一个 `wf-annotation` 当线框区终点，批注穿插导致后面的件被漏检 | 改为线框区到首个《可视化件声明》为止，并在检测前剔除批注 |
| 6 | `VIZ-01-A` 容器底用了实现层 l50（与页面底同层，件浮不起来）、描边填 `#CBD5E1`、`pad` 上下为 0（内容贴边） | 按 token 字典修正：底 `graphite-l40 #EDF1F7`、描边 `graphite-l20 #D3D7DE`、上下留白 12（项高 92）；`rules.container` 补「容器底必须与页面底分层、内容上下留白 ≥12」，并给 `VIZ-01-A2` 补「格底 l50 须置于白底内容区」约束 |

## 七、结论

1. 白板需求可以稳定走到"命中 3 件、全部 measured、还原包完整"；
2. 判型链路能正确**排除** 7 个不相关件型，包括容易误配的形态（如把访问路径画成流程条、把 2 指标硬套概览条）；
3. 剩余风险只在 `pending` 键（`VIZ-02` / `VIZ-07` / `VIZ-08-B/E/F`）：若需求落到这些键，只能走 `fallback` 降级并标注风险，建议优先补测 `VIZ-02` 与 `VIZ-07`。
