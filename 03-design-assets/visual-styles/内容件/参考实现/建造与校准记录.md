## 三、怎么复用

1. **取 DOM**：从对应文件 `wf-container` 内复制该件根元素（带 `data-viz`）。
2. **取声明**：`<div class="viz-decl">` 里对应那份，七字段已填满，风格规范是整格可粘文本。
3. **重生成声明**（契约或键变动后）：

```
node tools/viz-decl.js VIZ-01-A VIZ-10-A        # 输出声明块
node tools/viz-render.js VIZ-01-A                # 输出完整还原包（结构 / 风格 / 图标 / 溯源）
```

4. **改值只改契约**：`件型落地契约.json` → `node tools/viz-index.js --write` 刷新 D-11 索引。

**自适应硬约束（所有件型通用）**：空间不足时优先「保结构」，按下面四条落地，并在件型声明的「交互与退化」格写明做法——

| # | 规则 | 做法 |
| :---: | :--- | :--- |
| ① | 等分不写死 | 等分单元 `flex:1 1 0` + `min-width` 兜底；容器 `flex-wrap`，放不下换行而非压扁 |
| ② | 超宽不压字 | 图 / 时间轴 / 多列网格给保底宽（如 `min-width:720px`），容器 `overflow-x:auto`，宁可横向滚 |
| ③ | 高度随内容 | 不写死容器高；卡片 `align-items:flex-start`，不靠 `stretch` 拉满 |
| ④ | 字段自动降列 | 字段区 `repeat(auto-fit,minmax(180px,1fr))`，窄屏降单列；超长值单行省略号截断 |

## 六、机检口径补充

`selfcheck` 第 11 项的 token 名单原先只认 `glow-blue-s1` / `bg-blue-wash` / `border-ghost` / `dropshadow-s1` / `graphite-l*` / `r2` / `r4`，认不出 `graphite-l40`、`blue-l50` 这类高频 token——已扩展为 `graphite-[a-z0-9-]+|blue-l\d+`，避免合规写法被误判为空挂。
