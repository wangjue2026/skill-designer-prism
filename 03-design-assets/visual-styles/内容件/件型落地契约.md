# 件型落地契约（两张唯一台账：结构 + 取值）

> **一句话**：一个件型要能被"取用"，必须回答两件事——**长成什么结构**（哪几个类名）与**取哪些 token**（这个件专属的色 / 字 / 尺寸 / 圆角 / 阴影 / 内距）。这两张台账都在 [`件型落地契约.json`](件型落地契约.json)，本文件只讲口径。
> **值不在这里重定义**：`token/基础-token.md` 是数值字典，本台账只**引用命名 token + 附真值**（`graphite-l50 #F7F9FC`）。一值一出处，改值只改 token 层。
> **上游**：[`README.md`](README.md) §二 键表（唯一登记）· [`件型线框.md`](件型线框.md)（几何实测，tokens 的取值出处）· [`件型样式卡.md`](件型样式卡.md)（应该长什么样）。

---

## 一、为什么要这张表（断点在哪）

资产库已有三份资料，但都不是"能直接取用的东西"：`token/` 只知道"某个色等于多少"；`件型样式卡/线框` 是**给人读的 md + ASCII 图**；说明书要交的是 **HTML**。中间那一步"把几何与字阶翻译成 DOM 与取值"过去没有法定产物：

```text
件型键 ──❌ 无结构契约、无取值台账、无校验 ──→ 说明书 HTML
                                              ↑ 每次即兴：结构与取值一起退化
                                              典型产物 = 白卡 + 4 个数字 + 12px 灰标签
```

后果可复现：声明写 `VIZ-01-A2`，线框画成四张白卡——无 `l50` 格底、无 `0 12 0 32` 内距、无标签在上/值 24-700、无 16px 内联图标。评审看到的是"简陋"，机检却是绿的。

**本契约把结构与取值一起钉死**：① 这个键对应哪几个类名；② 缺哪个类名说明画成了别的形态；③ 这个件必须取哪几个 token 值。

---

## 二、取值台账字段口径（`tokens`）

每个键的 `tokens` 固定这些字段，**命名 token 在前、真值在后**；`null` = 该件此项不适用；缺的项列进 `missing`，**不许脑补**。

| 字段 | 取什么 | 示例（`VIZ-01-A2`） |
| :--- | :--- | :--- |
| `bg` | 容器底 / 行底 | `graphite-l50 #F7F9FC`（选中格 `#FFFFFF`） |
| `bd` | 描边 | 无 |
| `shadow` | 阴影 | 无 |
| `radius` | 圆角 | `0` |
| `pad` | 内距 | 格 `0 12 0 32`；条 `mb8` |
| `item` | 项 / 行 / 节点尺寸 | 格 `196×72`，条 `1176×73`，6 格等分 |
| `title` | 标题字阶 | 不适用 |
| `value` | 主数值字阶 | `24/700 graphite-d40`，`ml20` |
| `label` | 标签 / 说明字阶 | `12/400 graphite-d40`，`lh16`，`mb4` |
| `icon` | 图标尺寸与对齐 | `16×16` 内联，`mr4` |
| `statusColor` | 状态色归位（色 + 形双重编码） | 标签前图标按语义着色，文字不变色 |
| `special` | 该件特有的硬指标 | 整条只铺一次底；默认不预选任何一格 |
| `status` | `measured` / `partial` / `pending` / `resource` | `measured` |
| `src` | 取值出处（几何节号） | `件型线框.md §3.8`（A-实测） |
| `missing` | 还缺哪几项 | 空 |

> 🛑 **`status: pending` 的键不许直接用**：要么先补测（按 `件型线框.md` 的待补测表），要么在说明书里显式写"该项无实测值，按 `token/基础-token.md` 通用值推定"，不许静默编一个数。

## 三、覆盖状态（12 / 25 有实测值）

| 状态 | 件型键 | 能不能直接取用 |
| :--- | :--- | :--- |
| ✅ `measured`（12） | `VIZ-01-A` / `01-A2` / `01-B2` / `01-C` / `04` / `04-B` / `08-C` / `09-A` / `09-B` / `09-C` / `10-A` / `10-B` | 可直接取，值有实测出处 |
| 🟡 `partial`（5） | `VIZ-01-B` / `05` / `06` / `08-D` / `08-G` | 主体可取，`missing` 里的项须自证或补测 |
| 🚧 `pending`（6） | `VIZ-02` / `03-T` / `07` / `08-B` / `08-E` / `08-F` | **只知结构、不知取值**，用前必须补测 |
| 🎨 `resource`（2） | `VIZ-03` / `08-A` | 素材件（SVG / 位图），无独立 token，按素材原样贴 |

**最缺的三件**（按影响面排）：`VIZ-07` 状态流程条（列表详情都常用，全字段空白）、`VIZ-02` 对象信息卡（详情页头图，全字段空白）、`VIZ-08-B/E/F` 三种拓扑几何。

## 四、怎么用（四步，不许跳）

```text
① 判型：D-11 母尺 ①（要不要做）→ ②.1（用哪个件型）
② 取键：README §二 查键 → VIZ-xx-<形态>（形态不许省，A 与 A2 是两个件）
③ 取结构：契约 root_class + required → 线框根元素写 class + data-viz="<键>"
④ 取取值：契约 tokens 逐项抄进《可视化件声明》的「风格规范」格
          status=pending 的键 → 先补测，或在声明里写明"无实测值，按通用值推定"
```

**示例（`VIZ-10-A` 的取值格应当写成）**：

```text
档 B ／ 行底 graphite-l50 #F7F9FC ／ 描边无 ／ 无阴影 ／ 行 r4、条 r full
／ 行高 36、内距 0 14 ／ 类目定宽 126 ／ 构成区 ml16 max216 ／ 条 h4 段无缝
／ 标题 12/700、类目 13/400 d40、数值 12 d10、图标 14 ／ 段色 green→orange-l10→red-l10
／ 段宽 = 各状态数 ÷ 合计
```

判据：**把这一格单独交给另一个 AI，他能一次写出 CSS，且不需要再问"字多大、条多高、内距多少"。**

## 五、机检口径（`tools/viz-audit.js` / `SP-W-12`）

逐页比对线框与本页《可视化件声明》，六条任一不过即 FAIL：

| # | 判据 | 典型症候 |
| :---: | :--- | :--- |
| V1 | 键在册：`data-viz` 与声明里的键必须在契约里查到 | 杜撰键 `VIZ-13-T3` |
| V2 | 件数对账：页内 `data-viz` 实例数 = 该页 `viz-decl` 块数 | 两个件只交一份声明 |
| V3 | 未打标：出现件型原语类名却没有 `data-viz` | 画了但没登记 |
| V4 | 形态一致：`strict` 键的 `required` 全在，单元数 ≥ `min_items` | 声明 A2 画白卡；只画 2 格 |
| V5 | 值到位：声明「风格规范」命中该键 `style_must` 每组一个 | 只写"档 B（详见 token/README）" |
| V6 | 取值可追溯：声明须引用 `src` 节号或写明"无实测值推定" | 编一个数但说不出出处 |

> 📌 新增件型 = ① 改 `README.md` §二 键表；② 在契约加一行（含 `tokens` 与 `src`）；③ 有实测才填值，没有就 `pending` + `missing`。三处缺一处，门禁按"杜撰键"退回。
