## 1. 文档定位
本文档用于指导页面设计时的菜单归属、页面拆解和信息层级组织，帮助判断一个能力应该独立成菜单，还是作为菜单下的页面、Tab、抽屉或弹窗来承载。本文档也用于明确对象信息如何分层展示，以及页面、抽屉、弹窗之间的层级边界。在菜单归属确定后，进一步覆盖菜单组织规则、页面类型选择决策链和对象信息的分层落位，使页面拆解结果能落到具体页面类型与信息组织方式。

## 2. 菜单与页面拆解
页面拆解时，先判断一个能力是否属于独立业务旅程的主路径，还是更适合作为某个菜单下的局部能力来承载；核心业务能力优先独立成菜单或主页面，非核心能力优先挂在相关对象页或相关业务页中，不要因为能力名称独立就默认拆成独立菜单或独立页面。

### 2.1 独立菜单页面
当能力本身就是用户高频进入的主业务、承担完整闭环操作、需要长期独立管理，或者信息量和操作复杂度已经明显超过页面内入口所能承载时，才考虑独立成菜单页面。此类页面通常对应核心业务旅程、主对象管理、独立流程管理或需要完整列表-详情-配置闭环的场景。

### 2.2 菜单下Tab页面
当某个能力不是独立业务旅程，而是属于某个菜单下的子任务、子视图或同一对象的不同内容面时，优先作为该菜单下的Tab页面承载，而不是再单独拆成新菜单。局部Tab只有在确实需要切换局部内容时才使用，避免形成复杂嵌套。

- 本节 Tab 指菜单/路由层级的 Tab 页面，用于承载同一菜单下相对独立的内容面；区别于详情页内的局部 Tab（见 [3.1.2 详情页内信息平铺和Tab切换](#312-详情页内信息平铺和tab切换)）。
- 菜单下 Tab 页面使用 `IxTabs` 的导航型（`type="line"`），切换后需明确内容刷新、筛选重置或状态保留规则（联动 [组件映射表](../05-components/idux-component-map.md) 的标签页规则）。
- 菜单下 Tab 与页面内局部 Tab 叠加时，避免形成“Tab 套 Tab”的深层嵌套；页内 Tab 只在单个内容面内部确实需要再切换时才使用。

### 2.3 非核心配置的轻量入口
- 识别信号：功能配置独属于某个菜单页面，其他页面不会用到该功能时，作为该菜单页面的轻量配置入口，例如设备管理页面的标签管理、设备升级页面的带宽保护设置、POP 管理页面的全局地址池管理。
- 这类能力不需要单独起菜单，直接在该菜单的工具栏增加按钮作为入口；配置项通常在 10 个左右，使用弹窗表单页承载，未命中例外条件时默认使用弹窗表单页，抽屉表单页仅在用户额外说明或业务设计特别说明时使用（判断依据见 [配置页容器选择规则](../02-template/01-page-types.md#配置页容器选择规则)）。
- 拆解页面时，不要因为存在一个辅助配置能力，就默认拆成独立菜单或独立页面。

### 2.4 菜单组织规则
菜单拆分完成后，按以下规则组织菜单层级、分组与命名，避免菜单过深、过碎或重名。

- 菜单层级深度：常规控制在三级以内（一级菜单 → 二级菜单 → 三级菜单/叶子页面）。超过三级时优先收敛：拆成 Tab 页面承接同一菜单下的子视图，或用分组标题做视觉分组，不继续增加可进入的导航层级。
- 分组标题：仅用于对同级菜单做视觉分组，不属于可进入导航层级，不生成独立页面路径；分组标题命名应能概括组内菜单的共同业务主题。
- 命名与重名：同一菜单或同一 Tab 容器下避免出现重名页面；相同名称仅在不同菜单路径下承载同类任务或对象管理时允许，并必须保留完整导航路径作为区分。新页面命名应参考对应产品的已有命名规律（联动 [产品导航索引](../06-product-navigation/navigation-index.md) 与 [文案术语规范](06-copywriting-terminology.md)）。
- 汇总判断：新增能力优先按“独立菜单页面 → 菜单下 Tab 页面 → 页面内入口/轻量入口”的顺序收敛，不要默认拆成新菜单或新页面。

### 2.5 页面类型选择决策链
菜单归属确定后，将对象承载方式落到 [页面类型与页面元素说明](../02-template/01-page-types.md) 的具体页面类型。决策链如下：

0. 先判定需求动作类型：
   - 需求为配置/设置单条规则、参数、阈值、开关等（单条、全局唯一、不可枚举）→ 属于配置类能力，跳过列表类判断，直接进入第 3 步按 [配置页容器选择规则](../02-template/01-page-types.md#配置页容器选择规则) 选择表单容器。
   - 需求为维护一批同类对象（多条、可枚举，含搜索、批量操作、新增/删除管理）→ 进入第 1 步选择列表类页面。
1. 列表类页面按承载层级分两类判断（承载层级由菜单拆解阶段确定）：
   - 第一类：有独立菜单、独立 Tab 页或下钻页承载 → 选择表格类列表页，按数据关系选择 [基础表格页](../02-template/01-page-types.md#11-基础表格页)、[左树表格页](../02-template/01-page-types.md#12-左树表格页)（存在组织、分组或层级关系）、[概览表格页](../02-template/01-page-types.md#13-概览表格页)（需同时展示总体情况与明细）或 [概览左树表格页](../02-template/01-page-types.md#14-概览左树表格页)。
   - 第二类：作为辅助功能、非核心配置的轻量入口承载，或表格某特定字段的数据展开列表，或当前操作中临时查询并选择对象 → 使用 [弹窗列表页](../02-template/01-page-types.md#15-弹窗列表页) 或 [抽屉列表页](../02-template/01-page-types.md#16-抽屉列表页)：数据量小（正常场景少于 20 个）时使用弹窗列表页，例如标签管理；数据量较大（可达 20 个以上、几十或几百）时使用抽屉列表页。
2. 行内数据是否需要完整查看：
   - 需要独立承载完整信息 → 选择 [下钻详情页](../02-template/01-page-types.md#17-下钻详情页)、[抽屉详情页](../02-template/01-page-types.md#18-抽屉详情页) 或 [日志详情页](../02-template/01-page-types.md#19-日志详情页)（判断依据见 [3.1.1 判断是否需要详情页](#311-判断是否需要详情页)）。
3. 配置类能力需要承载新增、编辑或配置表单时，按 [配置页容器选择规则](../02-template/01-page-types.md#配置页容器选择规则) 选择 [配置表单页](../02-template/01-page-types.md#110-配置表单页)、[下钻步骤条配置页](../02-template/01-page-types.md#111-下钻步骤条配置页)、[弹窗表单页](../02-template/01-page-types.md#112-弹窗表单页) 或 [抽屉表单页](../02-template/01-page-types.md#113-抽屉表单页)。

## 3. 信息层级组织
页面中的信息先按对象主信息、关联信息、扩展信息和历史信息进行分层，再决定是集中展示、分区展示还是通过Tab切换。对象级信息优先放在顶部主信息区，扩展信息和关联信息按模块分组，信息量较多时通过分区或Tab组织，避免把所有内容堆在同一层级。

### 3.1 详情页设计

#### 3.1.1 判断是否需要详情页
先判断是否需要单独做详情页，再判断详情页类型。

- 需要单独做详情页的情况：
  - 表格字段较多，超过7个字段后无法完整展示所有信息。
  - 某些字段内容很长，表格无法完整展示。
  - 表格打开的详情页需要完整展示表格的所有字段信息，包括表格中隐藏但未展示的字段，不能遗漏；表格默认显示列与详情字段保持一致，规则见 [02-table-patterns.md](02-table-patterns.md#7-表格字段与列设计)。
  - 某些内容在表格里没有展示完整，例如数量较多的标签、服务器等，详情页里要完整展开展示。
  - 需要复杂的视觉效果来展示对象信息，例如进程链、流程图。
  - 需要作为局部统计数字的延伸展示，例如点击表格中的统计数字后查看对应的对象列表详情。
  - 表格字段很多，同时表格里还有局部数字需要延伸展示时，应该仍然只做一个主详情页，再通过主详情页里的 Tab 承接数字延伸出来的内容，不要在同一行数据里点击不同位置打开多个不同详情页。

- 通常不需要单独做详情页的情况：
  - 策略或规则类对象的详情和编辑字段基本一致，直接复用编辑容器承接查看。
  - 表格字段较少。
  - 部分字段通过悬浮面板即可完整查看。
  - 查看内容只是同一组信息的只读态时，复用表单只读状态即可，不拆详情页；只有包含状态、关联策略、运行记录、告警统计等额外信息时才拆为抽屉详情页或下钻详情页（联动 [交互反馈与风险控制](04-interaction-patterns.md) 的“新增、编辑、查看”规则）。

- 详情页类型主要有三种：
  - 下钻详情页：用于对象信息完整、需要持续浏览、且适合独立承载的场景。
  - 抽屉详情页：用于需要保留当前列表或当前页面上下文、快速查看对象细节的场景。
  - 日志详情页：用于日志、事件等以描述列表为主的详情场景，通常采用单列或双列方式展示并按信息块分组。

#### 3.1.2 详情页内信息平铺和Tab切换
平铺和局部Tab的判断重点是：是否需要在同一视图内一次看完，还是需要按模块分开切换浏览；如果信息密度较高，可以采用“Tab + Tab 内分组平铺”的组合方式。

- 适合平铺的情况：
  - 信息以基础描述列表形式展示且字段数量在 20 个以内时，在同一页展示完，不需要分 Tab。
  - 描述列表有明显分类时，增加分组标题解决易读性问题；每个分组字段数量保持在 6 个以上，避免因分组把字段拆得过碎。
  - 模块之间关系紧密。
  - 用户希望快速扫一眼全部信息。
  - 平铺信息较多时，可以再用小标题做分组展示，但仍然保持在同一页面内。

- 适合局部Tab的情况：
  - 同一对象下存在多个相对独立的内容面。
  - 继续平铺会让页面过长。
  - 继续平铺会让阅读成本过高。
  - 展示信息比较复杂时单独用 Tab 承载，例如左树+表格的联动视图、可视化画布区域等。
  - Tab 拆分要克制，一般控制在 3 个左右。
  - 不同 Tab 之间要有明显区分，避免只是把同一内容简单拆开。
  - 拆成 Tab 后，每个 Tab 内也可以继续做信息平铺，不要求每个 Tab 都只放单一块内容。

- 详情页内局部 Tab 属于内容组织层级，区别于菜单下 Tab 页面（见 [2.2 菜单下Tab页面](#22-菜单下tab页面)）；组件上使用 `IxTabs` 的导航型（`type="line"`），切换后明确内容刷新、筛选重置或状态保留规则（联动 [组件映射表](../05-components/idux-component-map.md) 的标签页规则）。

### 3.2 信息分层与落位
详情页或内容页面确定承载方式后，按对象信息类型分层落位，避免把不同性质的信息混在同一区域。

- 对象主信息：对象名称、类型、状态、关键属性等核心字段，放在顶部主信息区或单对象详情概览卡片（参考 [页面类型与页面元素说明](../02-template/01-page-types.md#21-单对象详情概览卡片)），优先展示，不放入 Tab。
- 主信息去重：对象主信息已在顶部主信息区或单对象详情概览卡片展示后，下方内容区不再重复展示同一字段，避免同一信息在页面上出现两次（去重口径见 [页面类型与页面元素说明](../02-template/01-page-types.md#21-单对象详情概览卡片)）。
- 关联信息：与对象存在引用、绑定关系的其他对象或策略，放在内容卡片的分区中；数量较多或需要独立管理时拆为独立 Tab。
- 扩展信息：配置明细、补充属性等次要内容，内容量小时以分组平铺展示，量大时放入独立 Tab 或抽屉承接。
- 历史信息：操作记录、审计日志、变更历史等时间序列信息，通常独立 Tab 或下钻承载，不与主信息混排。
- 概览统计区：概览表格页中用于展示总体情况的统计卡片位于列表上方，属于页面级概览，不作为对象主信息区（参考 [概览表格页](../02-template/01-page-types.md#13-概览表格页)）。
- 左树+表格的层级落位：作为页面类型时是“树 → 列表 → 详情”的独立页面层级；作为详情页内的单个内容面时，左树+表格整体作为一个 Tab 承载，不再继续嵌套局部 Tab。

### 3.3 多层级下钻
常规层级顺序优先使用“页面 → 抽屉 → 弹窗”。不建议出现“抽屉打开页面”或“弹窗打开抽屉/页面”。如果业务层级较多，可以使用“页面 → 页面 → 抽屉 → 弹窗”或“页面 → 抽屉 → 抽屉 → 弹窗”，最多控制在4个层级以内。

- 嵌套限制：弹窗内不再打开弹窗或抽屉；抽屉内尽量不打开抽屉，确需继续下钻时优先降级为页面内下钻或弹窗承载。
- 关闭与返回行为：抽屉详情页关闭后保留原列表的搜索、筛选、排序和滚动位置；下钻详情页返回时回到原列表位置，不重置筛选条件。
- Tab 切换行为：切换 Tab 时明确内容刷新、筛选重置或状态保留规则，避免切换后丢失用户已做的筛选或滚动位置（联动 [组件映射表](../05-components/idux-component-map.md) 的标签页规则）。
