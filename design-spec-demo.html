一、需求洞察与体验目标

1. 目标用户角色与现状核心痛点

  • 目标用户角色：网络运维专家（一线 on-call + 二线专家）
  • 痛点 1：时延、拓扑、日志分散在 3 个以上系统，无法形成单一时序因果链。
  • 痛点 2：排障平均跳页 6 次，视线严重断流，需跨系统复制 IP 比对。
  • 痛点 3：策略下发缺乏配额试算与超限拦截，历史发生过 2 次超配额导致业务中断。

4. 体验目标（务实版 · 源自主场景痛点）

统一体验目标定调：聚焦"告警后快速定界并安全止血"这一核心 Job，让一线运维从跨系统拼图走向单屏因果闭环。

  • 目标 1（偏业务闭环 / 结果确定性）：将时延、拓扑、日志三处证据收敛进单一监控大盘的时序因果链，用户无需跨系统比对即可在 1 步内定位受损业务线与根因节点，消除平均跳页 6 次的视线断流（解决 🚩 S1-P2）；故障定界耗时由 1.5 小时压缩至 ≤ 10 分钟。
  • 目标 2（偏用户能力跃迁 / 独立性）：以图形化证据链替代登录跳板机敲 CLI，一线运维不再依赖二线专家即可独立完成根因研判与止血下发（解决 🚩 S1-P3）；跨角色协作依赖降至 0 次，新手首次独立定界成功率 ≥ 90%。
  • 目标 3（偏防错确定性 / 效果感知）：在策略下发前对目标地域实时做配额试算与冲突预检，超限即红色拦截并给出调整建议，用户在下发前即可确认影响面（解决 🚩 S1-P4 / S2-P2）；超限下发事故降为 0 起，预检覆盖率达 100%。

Wow 画面感剧本

过去：告警群刷屏，运维在监控、拓扑、日志三个系统间反复复制 IP，1.5 小时才定位，还得叫二线专家登机敲命令。现在：告警一响，大盘 3 秒定界受损业务线，点击拓扑节点就地展开证据链，配额预检通过后就地下发，10 分钟内闭环，全程无需跨角色。

上线验证指标

  • MTTD：20 分钟 ➔ 秒级；关键风险识别 ≤ 3 秒
  • 排障跳页次数：6 次 ➔ 0 次；定界耗时 1.5 小时 ➔ ≤ 10 分钟
  • 跨角色协作依赖：0 次；超限下发事故：0 起；预检覆盖率 100%

二、业务定性与设计选型

  • 业务属性与严肃程度：可视化运维 / 极高严肃度 (Mission-Critical)
  • 色彩与审美基调：深沉石墨冷灰、去框线化，色彩只留给红/黄/绿告警脉冲
  • 选定专家范式：P-01 端到端拓扑链路 P-02 KPI 四联驾驶舱 P-05 多维下钻联动排障

核心设计发力点

  • 图内虚线胶囊就地展开，拒绝跳页断流；
  • 同源地域数据聚合为大卡片，防止海量条目离散；
  • 策略下发前实时配额试算，超限红色拦截。

五、关键界面布局与交互细节说明

  • 栅格与空间骨架：24 栅格，左侧拓扑 16 栅格，右侧证据链 8 栅格。
  • 关键交互态：Hover 微悬浮、点击节点高亮呼吸动效、异步 Loading 骨架屏。
  • 异常与防呆控制：配额超限红色拦截提示；同步中按钮禁用并挂载 Tooltip。
  • 就地闭环：详情与下发优先用右侧抽屉，不跳新页面。

六、页面体验与异常保护规则

  • 🛑 外层 Shell 保护：严禁破坏页面导航栏与全局响应式容器边界。
  • 🛑 数据绑定保护：所有组件严格绑定状态机，确保前后端数据通道完整。
  • 🛑 极限边界截断：长 ID 与 URL 必须包含 truncate + Tooltip 提示。
  • 🛑 空状态保底：每个数据容器均配备符合规范的 Empty 空状态。
