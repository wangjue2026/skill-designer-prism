# 微观细节转译词典：规划口语 ➔ 专业设计指令映射 (Detail Tuning Dictionary)

> 💡 **微观细节定位**：
> 本文档是Prism 体验设计智脑针对 **微观细节吐槽、样式优化、间距排版、局部易用性** 的实战转译词典。
> 专门用于将规划人员的感性大白话（如“太挤了”、“好土”、“看不清”）精准映射为具体的 CSS/DOM 修复指令。

---

## 一、 空间、容器与信息密度类 (Layout & Spacing)

| 规划原始吐槽 | 真实设计病因诊断 | Prism 设计智脑专业设计决策 (Design Rationale) | 面向 Coding AI 的精确 Prompt 片段 |
| :--- | :--- | :--- | :--- |
| **“这里太挤了 / 密密麻麻的”** | 缺少 8px 网格留白，元素紧贴边缘，行高过低造成视觉压迫。 | 采用 8px 网格规范，加大父容器与卡片内边距，正文行高提升至 `1.5~1.6`，模块间增加留白。 | `主卡片内边距统一为 padding: 16px (p-4)；子项纵向间距使用 gap-3 (12px) 或 space-y-3；文字行高设为 leading-relaxed (1.625)；模块间增加 16px 留白。` |
| **“页面太散了 / 空荡荡的”** | 信息密度过低，字段缺乏业务内聚，栅格跨度过大导致视线游离。 | 将分散的独立字段按业务相关性聚合为结构化卡片；关键指标水平并排并配置浅色背景容器包裹。 | `将孤立展示的字段重构为 Inline 键值组 (flex items-center gap-2)；添加背景底色 bg-[#F8FAFC] 与 1px 细边框 border-[#E2E8F0] 进行视线包裹。` |
| **“小标题框在卡片里太碎了，好多线，不简洁”** | 外层大卡片套内层小卡片，造成多层无意义边框与分割线嵌套。 | 坚决去框线化：小标题从卡片内移出至外部上方，去除外层包裹大框及其内部 `border-b`，内部指标卡直接作为一级白底卡片平铺。 | `移除外层包裹卡片与内部 border-b；小标题独立置于外部上方 (flex items-center gap-2 mb-2 text-xs font-semibold)；指标卡直接作为一级卡片并排 (bg-white p-3 rounded-[2px] border border-[#EAEEF4] shadow-xs)。` |
| **“页面还有空间 / 页面显示的很空 / 间距拉得太开”** | 1. 间距定义过大造成视觉空洞；<br>2. 间距写法存在 CSS Bug（如容器被无意义的 `flex-1` / `justify-between` / `height: 100vh` 撑开，margin 穿透累加，实测像素远超 8px 网格标准的 12/16px）。 | 间距收敛与修复布局撑开 Bug：去除无意义的 `justify-between` / `flex-1` 纵向拉伸，容器设为内容自适应高度（`h-fit`）；模块级间距收敛为 `16px` (`gap-4`)，卡片内子项收敛为 `8~12px` (`gap-2 ~ gap-3`)。 | `排查并修复间距膨胀与空隙撑开 Bug：移除导致内容被动拉散的 flex-1 与 justify-between，容器改用 flex-col justify-start gap-4 (16px)；卡片内部子项间距收敛至 gap-3 (12px) 或 gap-2 (8px)；容器高度设为 h-fit，严格遵循 8px 网格规范收敛留白。` |
| **“搜索框怎么看着这么大 / 笨重”** | 控件高度超标（直出了 C 端 44px+ 输入框）或宽度占满整行。 | 紧凑化重构：收紧高度至 B 端标准 32px（`h-8`），宽度固定 240px，前置绝对定位放大镜微图标，Focus 时添加微蓝光圈。 | `外层 relative flex items-center w-60；前置图标 absolute left-2.5 w-3.5 h-3.5 text-[#94A3B8]；输入框 pl-8 pr-7 py-1 h-8 text-xs bg-[#F8FAFC] border border-[#CBD5E1] rounded-[2px] focus:ring-2 focus:ring-[#1C6EFF]/20 focus:border-[#1C6EFF]。` |
| **“按钮太大了 / 不像后台系统的按钮”** | 按钮高度过大，内边距过宽，使用了无约束的 C 端样式。 | 紧凑化重构：双字按钮固定 56px 宽度，高度 32px，字号 12px，圆角 2px，清除径向扩散阴影。 | `双字按钮设置 w-14 (56px) h-8 text-xs font-normal rounded-[2px]；主按钮使用 bg-[#1C6EFF] hover:bg-[#4FA1FF] active:bg-[#1458CC]；普通按钮使用 bg-white border border-[#D3D7DE] text-[#2F3540]。` |

## 二、 视觉层级与色彩强调类 (Hierarchy & Colors)

| 规划原始吐槽 | 真实设计病因诊断 | Prism 设计智脑专业设计决策 (Design Rationale) | 面向 Coding AI 的精确 Prompt 片段 |
| :--- | :--- | :--- | :--- |
| **“界面太花哨了 / 颜色过多 / 不够轻量”** | 1. 视觉主次缺失：在大量非核心标签、文字、边框、图标上过度堆叠彩色与装饰线，缺乏视觉焦点；<br>2. 色彩厚重且饱和度过高：使用大面积深色背景或重色块，缺乏中性底色沉底和通透呼吸感，导致“元素多而杂、缺乏高级感与品质感”。 | 实施“视觉减负降噪法则 (Visual De-cluttering)”：遵循 60-30-10 配色定律（60% 基础浅底、30% 文本灰阶、10% 核心主题色）；坚决去装饰线与去重色块；非核心标签降阶为微浅底（如 `bg-blue-50 text-blue-600`）或中性灰（`#F1F5F9`），辅助图标统一中性灰化（`#64748B`）。 | `全面视觉降噪与轻量化重构：移除所有非必要的装饰性色彩背景与多余分割线；非核心状态标签统一降阶为超轻浅底 (如 bg-[#E8F4FF] text-[#1C6EFF] border-[#B3D8FF])；辅助图标统一降噪为 text-[#64748B]；卡片统一纯白底配合微边框 (#EAEEF4)；全屏确保仅保留 1 个核心主视觉焦点，提升通透感。` |
| **“重点不够突出 / 一眼看不到关键信息”** | 字号字重均一（全是 12/14px 纯黑字），缺少主次字阶阶梯，缺乏主题强调色。 | 核心指标放大至 24~28px Semibold 并搭配专用数字字体（Outfit/DIN），辅助文本降噪为 11~12px 灰阶（#64748B）。 | `主数值升级为 text-2xl font-bold font-outfit text-[#1E293B]；次级标签与单位使用 text-xs text-[#64748B]；核心卡片增加左侧 3px 品牌色强调条 (border-l-3 border-[#1C6EFF])。` |
| **“页面看起来很土 / 像老系统”** | 使用了高饱和原生红绿蓝、纯黑纯白硬切、缺乏阴影与圆角层次。 | 建立现代化 B 端色阶：区分页面底色（#F7F9FC）与卡片底色（#FFFFFF）；引入 2~4px 紧凑微圆角与浅微投影（shadow-xs）；状态色使用柔和语义色阶。 | `页面背景更换为 bg-[#F7F9FC]，卡片统一使用 bg-white rounded-[2px] border border-[#E1E5EB] shadow-xs；状态标签采用浅底+深字（bg-[#FFF1F0] text-[#D9363E] border-[#FFA39E]）。` |
| **“告警要红一点，一眼看出故障”** | 规划想突出警示，但容易做成大面积刺眼纯红背景，造成视觉疲劳与不可读。 | 采用“局部警示聚焦法”：卡片保持白底，仅在异常指标数值、状态徽标、拓扑节点边框施加红色高亮，并添加外圈脉冲光环（Pulse Halo）。 | `禁止大面积红底！卡片仅左侧添加 3px 红色条 border-l-[#D9363E]；异常数值标红 text-[#D9363E]；异常节点/散点增加微外环: absolute rounded-full border border-[#F52727]/40 animate-pulse。` |
| **“提示说明太长了，一整坨看着累”** | 纯文本堆砌，用户无法快速扫视出关键风险与操作指引。 | 两段式结构化重构：拆分为带数字标号的要点（1. 业务原因/前置条件 2. 建议操作/风险后果），配合浅蓝底提示卡片展示。 | `提示容器采用 bg-[#E8F4FF] border border-[#B3D8FF] p-3 rounded-[2px] text-xs text-[#2F3540]；内部分段为 <p>1. <b>前置提示：</b>...</p><p class="mt-1">2. <b>处理建议：</b>...</p>。` |

## 三、 数据可视化与图表细节类 (Data Visualization)

| 规划原始吐槽 | 真实设计病因诊断 | Prism 设计智脑专业设计决策 (Design Rationale) | 面向 Coding AI 的精确 Prompt 片段 |
| :--- | :--- | :--- | :--- |
| **“折线太粗太黑了，像刷子一样”** | 图表线条 stroke 宽度过大（3px+）或使用了纯黑色（#000000），缺乏平滑曲线与精致感。 | 调整折线宽度至 `1.5px` 或 `1.0px`，开启贝塞尔平滑曲线，开启下方超浅渐变填充（Opacity 8% -> 0%），坐标轴文字使用浅灰 11px。 | `折线配置 stroke="#1C6EFF" stroke-width="1.5" fill="url(#blue-gradient)"；坐标轴与网格线改为 stroke="#F1F5F9" stroke-dasharray="4 4"；文字 text-[11px] text-[#94A3B8]。` |
| **“图表看不懂具体是哪一分钟出的问题”** | Tooltip 缺失或静态固化，散点缺乏交互响应。 | 增加跟随鼠标 Hover 的悬浮浮层（Tooltip），显示精确时间戳、健康度状态、TTFB 耗时与协议层网络指标。 | `散点绑定 @mouseenter/@mouseleave 事件；动态计算 Tooltip 的绝对坐标；浮层采用深色微透卡片 (bg-[#1E293B]/90 text-white text-xs px-2.5 py-1.5 rounded shadow-xl)。` |

## 四、 表格与组件微观细节类 (Table & Component Details)

| 规划原始吐槽 | 真实设计病因诊断 | Prism 设计智脑专业设计决策 (Design Rationale) | 面向 Coding AI 的精确 Prompt 片段 |
| :--- | :--- | :--- | :--- |
| **“表格操作列很乱，颜色五颜六色的”** | 操作列按钮使用了红黄蓝多种颜色，破坏了视觉秩序。 | 操作列文字统一使用链接蓝 `#1C6EFF`，禁止使用其他杂色；仅在“删除/阻断”二次确认时使用危险红。 | `操作列操作项统一使用 text-xs text-[#1C6EFF] hover:underline cursor-pointer；危险操作仅在点击弹窗内标红；同列文字左对齐保持一致。` |
| **“表格里的数字看起来很难比对”** | 数字列使用了默认左对齐，且使用了不等宽字体，导致小数点与位数参差不齐。 | 数字列一律强制**右对齐**，表头与内容列保持一致，配置数字等宽字体。 | `表头与内容单元格统一增加 text-right font-mono tabular-nums；金额、流量、时延等数值列严格右对齐。` |
| **“表格有横向滚动时操作列看不到了”** | 操作列未做固定冻结，滚动时滑出屏幕外。 | 操作列配置右侧粘性定位，并添加微阴影与左侧内容区区隔。 | `操作列配置 sticky right-0 bg-white shadow-[-4px_0_8px_rgba(0,0,0,0.06)] z-10。` |
| **“文字排版不规范，中英文贴在一起”** | 文案缺少半角空格分隔，数字与单位粘连。 | 严格执行 B 端文案排版规范：中文与英文/数字之间留半角空格，数字与物理单位留半角空格。 | `修正所有文案格式为："共 3 个异常"、"耗时 68 ms"、"带宽 100 Mbps"、"较昨日 ↑ 14.2%"。` |
