# 微观细节模板：局部调优与吐槽修复 Prompt 模板 (Micro Prompt Template)

> 💡 **微观模板定位**：
> 当规划人员针对已有 Demo 提出 **“太挤了”、“颜色土”、“搜索框笨重”、“表格操作列太乱”、“按钮太大”** 等细节吐槽时，Prism调用本模板合成双重交付成果：
> 1. **输出 A**：向规划人员通俗解释病因与改动细节；
> 2. **输出 B**：向 Coding AI 提供像素级、带四重安全带的精准补丁修改 Prompt。

---

## 📤 输出 A：面向规划人员的微观细节调优解释模板 (Planner Explanation)

```markdown
### 💡 Prism设计思考：[调优模块名称] 细节优化说明

1. **为什么这么改？（痛点病因）**
   - [指出原版问题，例如：控件高度撑大至 44px 导致视觉笨重、缺少 8px 网格留白导致找数据费劲、操作列杂色过多造成视线杂乱]。

2. **Prism做了哪些精细升级？**
   - 🌿 **空间与呼吸感**：[阐述收紧/放大 padding 与 gap 的具体效果]；
   - 🎨 **色彩与视线降噪**：[阐述换用中性灰底与柔和三元色，去除多余粗框线]；
   - 🔤 **排版与对齐**：[阐述数值启用 Outfit 等宽字体，数字列右对齐，操作列统一链接蓝]；
   - ⚡ **交互与微反馈**：[阐述添加 Hover 轻微阴影与 Focus 蓝光圈]。

3. **预期效果**：界面变得清爽通透，视线一秒锁定关键内容，符合专业 B 端设计审美。
```

## 💻 输出 B：面向 Coding AI 的局部调优执行 Prompt 模板 (Coding Prompt)

```markdown
### 🎯 任务目标：针对 [模块名称/组件名称] 进行局部精细化调优与情境量体裁衣

---

#### 🛠️ 一、 [修改子项 1：如搜索框 / 顶部工具栏] (按现场空间量体适配)
1. **DOM 结构与尺寸规范**：
   - 容器宽度：独立工具栏推荐基准 `w-60 (240px)`；若处于自适应 Flex 栅格中，则使用 `flex-1 max-w-xs` 确保不挤压右侧操作区；
   - 控件高度：统一收紧至 B 端标准 `h-8 (32px)`，前置放大镜微图标 (`w-3.5 h-3.5 text-[#94A3B8] left-2.5`)；
   - 交互反馈：`focus:ring-2 focus:ring-[#1C6EFF]/20 focus:border-[#1C6EFF]`，右侧若有值支持一键清除。

---

#### 🛠️ 二、 [修改子项 2：如表格 / 按钮 / 指标卡片] (根据载体与场景选择最佳手法)
1. **组件规范与情境变通**：
   - **[若为按钮]**：纯双字按钮固定 `w-14 (56px) h-8 text-xs rounded-[2px]`；带图标按钮改用 `px-3 h-8 gap-1.5` 自适应宽度；表格操作列纯文字按钮禁止设置固定宽度，统一使用 `text-xs text-[#1C6EFF] hover:underline`；
   - **[若为表格]**：表头吸顶固定 `32px bg-[#EDF1F7]`，单行行高 `40px`；数值与时延严格右对齐 `text-right font-mono tabular-nums`；列宽合理规划，确保在 1440px 分辨率下无多余横向滚动条；
   - **[若为指标卡/概览]**：坚决移除多层嵌套边框；主数值采用 `text-2xl font-bold font-outfit text-[#1E293B]`；若概览数据与下方表格重复，则升维为趋势图或果断移除节约首屏高度。

---

#### 🛠️ 三、 视觉降噪与状态分级 (严禁无脑全红，按重要度分层)
* **告警与状态色彩分层准则**：
  - **核心单点异常 / 真正阻断故障**：采用聚焦三元组（`bg-[#FFF1F0] text-[#D9363E] border-[#FFA39E]`），圆形节点采用外圈轻量向外微脉冲，内部保持白底；长方卡片采用左侧 2px 浅红边框；
  - **常规待处理 / 次要状态**：严禁大红！统一降噪为石墨深灰文字（`#475569`）配合浅灰中性胶囊（`bg-[#F1F5F9] text-[#64748B]`）；空间拥挤时降阶为纯文本加微圆点；
  - **已恢复 / 正常状态**：彻底剥离显眼彩色标签，弱化为中性纯文本或默认折叠。

---

#### 🚫 四、 防破坏与情境安全带 (Regression Guard - 强制)
1. **技术栈原生兼容**：严格沿用当前宿主代码的样式风格（Tailwind 类名、纯 CSS 还是内联样式），禁止引入异构类名或破坏宿主变量；
2. **结构与布局安全**：仅修改目标内部节点，严禁误触外层 Shell、主布局滚动容器与响应式 Flex/Grid 流；
3. **数据与交互完整**：完整保留既有字段数据绑定（`v-model` / 数据插槽）与事件监听；长文本强制配置截断防护。
```
