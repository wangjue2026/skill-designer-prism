# 资料投喂与经验蒸馏手册 (Inbox & Distillation Guide)

> 💡 **核心定位：纯临时过程暂存区 (Inbox / Staging Area)**
>
> 本目录 **不是** 长期索引的资料库，而是规划人员向织雨随时投喂原始资料的 **“过程暂存池 / 收件箱”**：
> 1. **零门槛随手扔**：原始 PRD 片段、评审会议纪要、设计推演草稿、吐槽复盘，无需复杂分类，直接作为 `.md` / `.txt` 丢在此目录下；
> 2. **织雨深度蒸馏**：唤起织雨研读，按下方【路由表】分诊到对应主线，把经验永久沉淀到 `01` ~ `04` 核心模块；
> 3. **随学随清**：一旦经验成功蒸馏并合入核心模块，本目录下的过程文件即可随时删除，保持工程轻量。

## 🧭 资料分诊路由表 (Routing)

> 织雨拿到投喂资料后，先判断“它是什么”，再按对应主线的指南作业。

| 资料类型（识别信号） | 遵循哪份指南 | 落到哪里 |
| :--- | :--- | :--- |
| **方案级业务经验**——某业务模块的完整方案 / 页面族 / 标杆案例（对象管理、配置同步、监控驾驶舱、链路排障 …） | [`需求大类标杆案例蒸馏指南.md`](需求大类标杆案例蒸馏指南.md) | `01-system-solution-design/②设计思考与决策/需求大类设计决策/` 对应类型分册 |
| **跨产线通用选型决策**——同一设计场景下多产品的做法对比、选型判据与阈值（卡片 vs 表格、弹窗 vs 抽屉、置灰 vs 隐藏 …） | [`通用设计案例蒸馏指南.md`](通用设计案例蒸馏指南.md) | `01-system-solution-design/②设计思考与决策/通用设计决策/` 对应决策文件 |

| **经典范例与前后对比**——代表性极高、可供“举一反三”的完整案例 | 无专属指南，直接收录 | `04-workflows-and-cases/few-shots.md` |

## 🚀 投喂与蒸馏 Quick SOP

1. **投喂**：将包含推演过程或项目经验的任意文件直接丢在 `learning-materials/` 下（如 `learning-materials/temp-demo-cases.md`）；
2. **指令**：在对话中对织雨说——“织雨，请学习 `learning-materials/temp-demo-cases.md` 中的设计推演过程，按蒸馏大纲提取经验并更新到 01~04 模块中”；
3. **闭环**：织雨更新完核心文件并向你汇报后，你即可直接 `rm` 删除该暂存文件，零负担维护。
